# 技术栈优先级

本清单是优先级参考，不自动生成每日任务；主线暂停时，嵌入式保留为暂存技能。

## P0：主线阶段 · Agent 工程最小闭环

1. Python 工程：虚拟环境、配置/密钥环境变量、函数、类型、异常、日志、`pytest` 和 Git。
2. LLM 基础：多轮上下文、系统约束、结构化 JSON 输出、超时/限流/无效响应处理。
3. Agent 工具层：函数调用、受限文件读取与检索、参数校验、允许目录、只读默认和人工确认边界。
4. 质量闭环：固定评测集、引用有效性、拒答、工具错误率、延迟、失败样例和回归测试。
5. 服务与表达：FastAPI、JSON/HTTP、接口测试、README、运行脚本和限制说明。

## P1：四周交付后，按复盘选择深化

1. 先补 Agent 项目的单一短板：检索质量、工具可靠性、评测、服务化或部署，禁止同时开启多 Agent、浏览器自动化和复杂前端。
2. Linux、Shell、HTTP、数据库或 C++ 按项目需要择一补强；算法持续完成数组、哈希、链表、树等基础题复盘。
3. 根据四周适配评分和岗位样本，决定继续深化 Agent、转向 AI 应用/后端，或重新启用嵌入式/Linux 主线。

## P2：后续分支阶段 · 按岗位样本选择

1. 根据两周岗位样本，在 ROS2、后端系统、边缘部署中选择一个短分支；不要并行全学。
2. 课程任务继续补 Python、NumPy、PyTorch，并以独立 MLP 和一次受控变量实验作为验收。
3. DQN/PPO 只有在 MLP 闭环和实验记录通过后再做可复现对照，不把它们提前包装成算法实习资格。
4. FPGA/数字验证后置到寒假或大二下的低成本实验，不作为大二上固定任务。

## 暂时不要做

- 同时完整学习 SLAM、导航、强化学习、视觉、大模型和多个 MCU 平台。
- 反复通读教程而不设验收标准。
- 让 Agent 一次生成整个项目。
- 为了追热点放弃 Python、Linux、接口、测试和调试基本功。

## AI/Codex 工作流

每次任务按“背景—现象—已尝试—约束—验收标准”提问。先让模型列出假设和验证实验，再自己修改；修改后让模型做审查、补测试和检查边界条件。强模型用于架构和疑难 bug，便宜模型用于解释、样例和文档。每个有效修改都提交 Git，并记录原因。
