# 03 · 开源协议选择指南（开发者向）

> 你要在 GitHub 上做大模型应用项目（简历的一部分），迟早遇到两个问题：**我的项目挂什么协议？我能抄/二改别人的代码吗？** 这一篇 10 分钟讲清。

---

## 一、七大常用协议对比

| 协议 | 可商用 | 二改/衍生须开源？ | 须保留版权声明？ | 明示专利授权 | 一句话定位 |
|---|---|---|---|---|---|
| **MIT** | ✅ | 否（可闭源） | ✅（附 LICENSE 全文） | 否（仅隐含） | **最宽松省心，个人项目默认选它** |
| **Apache-2.0** | ✅ | 否 | ✅ + 修改处标注、保留 NOTICE | **✅** | 企业友好；想拿到专利授权选它 |
| **BSD-3-Clause** | ✅ | 否 | ✅ | 否 | 似 MIT + 不得用作者名义推广 |
| **MPL-2.0** | ✅ | **文件级**：改动的源文件须开源；可与专有代码混编 | ✅ | ✅ | 折中方案（Firefox 用） |
| **LGPL-3.0** | ✅ | 库本身修改须开源；**动态链接调用可闭源** | ✅ | ✅ | 给闭源软件用的开源库 |
| **GPL-3.0** | ✅（分发时） | **是，传染**：分发衍生品须以 GPL 开源并附源码 | ✅ | ✅ | Linux 用；想强制开源选它 |
| **AGPL-3.0** | ✅ 但最苛 | **网络提供服务（不分发）也须开源** | ✅ | ✅ | SaaS 场景也传染（MongoDB 用） |

> 专利条款注意：MIT/BSD/GPLv2 **不含**明示专利授权，Apache-2.0/GPLv3 **含**（阮一峰文内观点）——做 AI 项目尤其留意，模型/推理相关专利纠纷是这个领域真实的坑。

## 二、给自己的项目选协议（30 秒决策）

```
想让别人随便用、简历作品只求被看到？            → MIT
想被公司放心采用、避免专利讹诈？                → Apache-2.0
想强制"用我代码的人也开源"？                    → GPL-3.0
做了个 SaaS/平台（别人部署对外服务），不想被白嫖？→ AGPL-3.0
```

**操作**：GitHub 新建仓库时 Add a license 直接选；或打开 [choosealicense.com](https://choosealicense.com)（GitHub 官方出品，源码仓库 [github/choosealicense.com](https://github.com/choosealicense.com)，4,203★，已核验）答三道题自动推荐。中文对照：[ChooseLicense 中文站](http://choosealicense.online)（88★）/ [choosealicense-cn](https://github.com/choosealicense-cn/choosealicense-cn.github.io)（12★，译文谨慎参考）。

**经典中文文章**：阮一峰《如何选择开源许可证？》（ruanyifeng.com/blog/2011/05/how_to_choose_free_software_licenses.html，一张流程图两分钟定协议）。

## 三、引用/二改别人代码的合规四步

1. **先看有没有 LICENSE**：无 LICENSE 的公开仓库 = **默认保留所有权利**，不可直接照搬（尤其商用）；
2. 有 LICENSE → **保留原协议与版权声明**（你的 LICENSE 文件里注明基于 XX 修改）；
3. Apache/MPL 系 → 修改过的文件按要求**标注修改**；
4. GPL 系 → 分发时**附上源码**、协议传染。

> 区分两件事：**复制代码**受原协议约束；**看思路自己重写**一般不侵权，但注意专利与"实质性相似"。写简历项目时，"基于 Dify 二次开发"大方写出来 + 遵守其协议，比偷偷抄更安全也更加分。

## 四、与你的求职线直接相关的三件事

1. **简历项目协议一致性**：面试官真会问"你这个项目什么协议、为什么"——选协议本身就是技术判断题；
2. **竞赛作品**：注意赛事章程的知识产权归属条款（有的赛事要求参赛作品开源或授权组委会）；
3. **引用大模型生态项目**：Dify（Apache 修改版条款以仓库为准）/RAGFlow（Apache-2.0）/FastGPT（附加条件的开源协议，商用前读 README）等国产项目协议各不相同，二开前花 5 分钟读 LICENSE 与 README 的商用说明（各仓库星标与协议核验见 [`03库/开源之夏与开源贡献指南`](#/doc/d070)）。
