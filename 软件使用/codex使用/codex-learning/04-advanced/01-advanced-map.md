# 进阶能力地图

先知道这些能力解决什么问题，不需要第一周全部掌握。

## AGENTS.md

用途：给 Codex 的项目级规则说明书。

适合写：

- 项目怎么启动、测试、构建。
- 代码风格。
- 禁止修改的文件。
- 修改前后必须做的检查。
- 特定目录的约束。

什么时候用：只要一个项目会被反复使用，就值得建 `AGENTS.md`。

## Skills

用途：把重复流程包装成可复用能力。

适合：

- 经常生成 README。
- 经常做 PR review。
- 经常整理学习资料。
- 经常生成某类报告、文档、表格、PPT。

判断标准：同一个提示词或工作流重复 3 次，就考虑 Skill。

## Plugins

用途：打包工作流能力，可能包含 skills、apps、app templates。

适合：

- 连接 GitHub、文档、表格、演示文稿等工具。
- 使用官方或团队提供的固定工作流。
- 让 Codex 访问经过授权的数据或动作。

注意：插件可见不代表能力一定可用，还取决于计划、工作区、角色、底层 app 权限和所在入口。

## MCP

用途：给 Codex 接外部工具和数据源。

常见类型：

- 文档 MCP：查询官方文档和 API。
- GitHub MCP：读取 issue、PR、仓库信息。
- Figma MCP：读取设计稿。
- 数据库/内部系统 MCP：读取受控数据。

学习顺序：先会普通任务和 Git，再学 MCP。MCP 会扩大 Codex 能力，也会扩大权限和错误面。

## 自动化

用途：让 Codex 按计划或触发条件做重复工作。

适合：

- 定期巡查项目。
- 定期生成报告。
- 监控失败任务或 CI。
- 长期跟踪资料更新。

不适合：

- 你还不会验收的任务。
- 会修改生产数据的任务。
- 没有明确停止条件的任务。

## GitHub / Cloud

用途：把任务放到云端环境、仓库、分支、PR 流程里处理。

适合：

- 已经在 GitHub 上的项目。
- 多任务并行。
- 需要 PR review 的代码。
- 本机环境不想长时间占用的任务。

先决条件：

- 会看 Git diff。
- 会理解分支和 PR。
- 知道哪些仓库、密钥和环境变量能授权。

## Subagents / 多代理

用途：把一个大调查拆成多个独立子问题。

适合：

- 大型代码库定位问题。
- 多方案对比。
- 同时检查前端、后端、测试。

风险：子代理越多，越需要主线汇总和最终验收。不要把不可验证的复杂判断直接交给并行代理。

## Hooks

用途：在生命周期节点强制执行规则，比如命令前检查、提交前检查、禁止危险命令。

适合：

- 团队规范。
- 高风险仓库。
- 想强制保护某些文件或命令。

不建议新手第一周折腾。先把口头规则和 `AGENTS.md` 用顺，再考虑 hooks。
