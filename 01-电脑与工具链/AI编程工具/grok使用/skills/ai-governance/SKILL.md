# AI 实现前治理

坚持：先判定，先复用，先确认，再实现，最后用证据收口。

## 开始前

1. 读取仓库根目录及适用子目录中的 `AGENTS.md`、README、现有计划和项目规则。
2. 检查项目是否已有 `.ai-governance/`、需求/任务目录或其他治理流程；与现有约定兼容，不另造平行体系。
3. 读取 `references/evidence-spec.md`。任何“已确认”“不存在”“无可复用”结论都必须带证据。
4. 若任务只要求解释、审查或诊断且不授权改动，保持只读；提供证据和结论，不进入实现门禁。

## G1：复杂度判定

对任何需要写或改项目文件的请求执行 G1：

1. 读取 `references/complexity-rules.md`。
2. 用搜索、引用查询和项目检查确定实际影响文件，不凭用户描述估算。
3. 逐条核对 H1-H10，记录“命中/未命中 + 证据”。
4. 输出复杂度等级和下一步。

使用固定摘要：

```text
[复杂度判定]
- 涉及文件：<数量和清单/搜索证据>
- 硬条件命中：<H 编号 + 依据，或无>
- 未命中项：<H 编号>
- 判定结果：微小 / 小 / 中 / 大
- 下一步：直接实现 / 进入 G2 / 继续调查
```

判定依据不足时继续调查，不给猜测等级。微小/小任务可进入实现；中/大任务必须进入 G2。

## 需求与任务文档

需要把原始诉求正式化时：

1. 用 `assets/templates/requirement.md` 生成需求文档。
2. 用 `assets/templates/task.md` 拆分任务：
   - `R`：先核对事实、现状和复用，未完成前不实现。
   - `D`：方向已明确，可进入设计或开发准备。
   - `C`：业务口径未定，必须由用户确认，未确认前禁止固化实现。
3. 按 `references/workflow-lifecycle.md` 放入正确状态目录；若项目已有不同目录约定，以项目约定优先并记录映射。

不要把需求背景复制进每个任务。需求文档负责“为什么和做什么”，任务文档负责“本轮怎么落地和怎么验收”。

## G2：能力地图与实现前设计

仅中/大任务必须执行：

1. 读取 `.ai-governance/capability-map.md`；不存在时从 `assets/templates/capability-map.md` 初始化。
2. 逐类核对复用能力，结论只能是 `复用 / 扩展 / 新增 / 不涉及`。
3. 选择“新增”时，写出无法复用的证据和理由。
4. 用 `assets/templates/pre-implementation-design.md` 编写实现前设计。
5. 至少比较一个未采用方案，明确范围、风险、回滚与可执行验收方法。
6. 向用户提交设计摘要，然后停止实现并等待确认。

使用固定摘要：

```text
[实现前设计已完成]
- 推荐方案：<一句话>
- 复用：<列表>
- 扩展/新增：<列表及无法直接复用的理由>
- 明确不做：<列表>
- 主要风险与回滚：<列表>
- 待确认口径：<C 类问题，若有>

是否确认进入实现？
```

未收到用户确认前，不写实现代码。用户主动要求降级时，记录其原话、跳过项和剩余风险；不得主动建议降低治理强度。命中数据库、权限或资金硬条件时，即使降级也保留影响范围、风险和回滚方案。

## 实现

1. 只实施确认范围内的方案。
2. 复用已识别能力，避免顺手重构无关代码。
3. 遇到新的 C 类问题或设计边界变化时暂停，更新设计并请求确认。
4. 保留用户已有改动，不执行未经授权的 commit、push、部署、发布或外部提交。

## G3：验收与回写

1. 按验收标准逐条执行验证，记录命令/操作、期望结果、实际结果和状态。
2. 检查产物本身，不以进程退出码替代文件、页面、数据或行为验证。
3. 对失败、未运行和无法验证项如实报告。
4. 若形成新的可复用能力，回写 `.ai-governance/capability-map.md`。
5. 按状态目录规则移动需求/任务文档；不要只改文档头部状态。
6. 汇报改动范围、验证证据和剩余风险。

## 禁止事项

- 未完成 G1 就写实现代码。
- 中/大任务未通过 G2 就实现。
- 未查能力地图就断言“无可复用”。
- 把推测、静态阅读或子任务结论包装成当前已验证事实。
- 在 C 类问题上自行决定业务口径。
- 用“时间紧”或“用户说很简单”替代风险判定。
- 用“功能正常”“应该没问题”代替实际验收。
- 未经要求执行 git commit/push、部署或发布。

## 来源与适配

本 skill 从项目外的三份本地模板蒸馏，并借鉴 `zwisgod/ai-governance` 的 G1/G2/G3、复杂度和证据规则。保留本地模板的状态目录及 R/D/C 分层，未引入 Trellis。上游 MIT 许可见 `LICENSE`。
