# 第一周路线

这是一条“快速熟悉操作，但不漏掉高级功能”的路线。每天控制在 45-90 分钟，重点是形成可重复动作。

## Day 1：App 基本操作

目标：熟悉项目、任务、diff、权限、归档。

- 打开一个低风险项目目录。
- 新建一个任务，只让 Codex 读项目，不修改。
- 开第二个任务做一个文档小改。
- 看 review/diff 面板，确认改了哪些文件。
- 归档已完成任务，保持任务列表清爽。

产出：一份项目理解报告 + 一个小文档改动。

## Day 2：提示词边界

目标：把“帮我做一下”改成“目标 + 范围 + 验收”。

- 练习指定文件范围。
- 练习要求它先计划再动手。
- 练习中途插入纠偏。
- 练习让它只检查不继续开发。

产出：`02-daily-workflow/02-prompt-templates.md` 里的模板至少用 3 个。

## Day 3：Git 与回退

目标：任何真实项目都先有回退点。

- 学会 `git status`、`git diff`、`git add`、`git commit`。
- 修改前提交一个 checkpoint。
- Codex 修改后再看 diff。
- 不满意时自己知道可以回滚，别完全依赖 AI。

产出：一个有 commit 记录的小项目。

## Day 4：CLI 补课

目标：知道什么时候从 App 切到终端。

- 了解 `codex`、`codex exec`、`codex review`、`codex resume`、`codex mcp`。
- 进入项目目录再启动，不在 `C:\`、桌面、下载目录、系统目录乱跑。
- 学会 `/status`、`/permissions`、`/diff`、`/review`、`/compact`。

产出：一次 CLI 只读项目报告或小文档修改。

## Day 5：Skill 和 AGENTS.md

目标：把重复要求写成长期规则。

- 让 Codex 根据一个项目生成 `AGENTS.md` 草稿。
- 明确运行命令、风格、禁止事项、验收要求。
- 看 `Skill` 与普通提示词的区别：重复流程适合 Skill，一次性任务适合提示词。

产出：一个可复用的 `AGENTS.md` 草稿。

## Day 6：Cloud / GitHub 只了解，不急用

目标：知道 Cloud 解决什么问题。

- Cloud 适合 GitHub 仓库任务、PR、远程并行和不占用本机的长任务。
- 不适合没有 Git 基础、没有备份的本地练习、生产数据库迁移。
- 不要把 API Key、密码、token 写进任务描述。

产出：一张“本地任务 vs 云端任务”的判断表。

## Day 7：复盘并沉淀

目标：形成你自己的 Codex 操作规范。

- 记录本周最常用的 5 个提示词。
- 记录 3 个容易出错的地方。
- 把“每次都要提醒 Codex 的事”沉淀进项目规则或个人模板。

产出：一份你的个人 Codex 操作清单。
