# 同类玩法迁移到 Today 指南（个人智能体系列 · 10）

> 本篇读者：已经把 **Today AI** 装在电脑端 + 手机端并双端互通的同学（参考 [02-Today-AI-完整使用指南](/23-个人智能体指南/02-Today-AI-完整使用指南)）。
> 你看过 Grok Bot 的玩法（[03-Grok-Bot-完整使用指南](/23-个人智能体指南/03-Grok-Bot-完整使用指南)、[05-实战工作流与玩法案例](/23-个人智能体指南/05-实战工作流与玩法案例)），想把那些玩法搬到 Today 上用——本篇就是干这个的。
> 信息基准日期：2026-10-20。Today 国内版 9 月 24 日才上线、迭代极快，所有能力判断均附证据，**做不到的点明说，不硬编**。

---

## 0. 先说清两个产品的底层差异（映射前必读）

在逐行映射之前，先理解为什么有些 Grok 玩法在 Today 上天生没有对应物：

| 维度 | Grok Bot | Today AI |
|---|---|---|
| 交互模型 | 左栏 Bot 列表：一个账号养 N 个 Bot，可拉群 @分工 | **单长对话 + 单个助理**：没有 Bot 列表、没有群聊，所有事在一段对话里继续（极客公园，2026-10-01） |
| 数字员工 | 原生：每个 Bot 有独立岗位、记忆、资料库 | **不支持**：你和它只有「你俩」的关系；它可以改名/选形象/选风格，但那是**同一个人**换衣服，不是两个员工（极客公园，2026-10-01；晚点 LatePost，2026-10-16） |
| 干活的电脑 | 云端 Linux VM，Bot 可看屏旁观 | 云端电脑（Cloud Computer）24h 在线，可开浏览器/处理文件/跑代码（官网） |
| 主动程度 | 你派活它才干 | **产品原点就是主动**：早晚报、节奏卡片、变化追踪是它的主场 |
| 生态入口 | X @触发、MCP、Marketplace 连接器 | 国内连接器（邮箱/飞书/钉钉/腾讯文档）+ 微信收发（实测）+ 社区 Skill |

一句话：**Grok Bot 像「雇了一支团队」，Today 像「养了一个长在你生活里的搭档」。** 迁移时，凡是「团队协作型」玩法都要降维成「一个搭档 + 任务命名」的组织法；凡是「盯梢、记忆、主动提醒」型玩法，Today 只会更强。

## 1. 玩法迁移映射总表（核心）

图例：✅ = Today 原生支持，直接可用；🔄 = 有替代方案，要换个组织法；❌ = Today 做不到，明说。

| # | Grok 玩法模式 | 三态 | Today 对应能力 | 具体操作路径 |
|---|---|---|---|---|
| 1 | 建多个专职 Bot（数字员工：课代表小郭、盯梢老王……） | ❌→🔄 | 无多 Bot；用「**任务命名 + 定时任务 + 话术分区**」模拟专职岗位 | 见 §1.1 |
| 2 | 人机混编群聊，@不同 Bot 分工 | ❌ | 无群聊、无多 Agent | 用「串行指令链 + 多任务并行」模拟，见 §1.2 |
| 3 | Bot 之间互相 @交接（X监控→选题→写稿→审稿流水线） | ❌ | 不支持 Agent 间自动交接 | 用「一段话流水线指令」让它一个任务内部串行做，见 §1.3 |
| 4 | 手机远程发任务 | ✅ | 手机 App 与电脑端同账号同数据；绑定微信后微信里也能派活 | 见 §1.4 |
| 5 | 手机远程审批步骤（审批卡：放行一次/总是放行/拒绝） | 🔄 | 无审批卡队列；行为模式是「做敏感动作前回对话里问你」 | 见 §1.5 |
| 6 | 接管登录验证码（安全输入框、密码遮蔽、交还控制权） | ❌ | **未检索到**此类安全接管机制 | 见 §4 边界清单 |
| 7 | 云端电脑干活（浏览器/文件/终端） | ✅ | Cloud Computer：开浏览器、处理文件、跑代码，24h 在线 | 见 §1.6 |
| 8 | 控制本地电脑（在自己 Mac/PC 上跑命令、点界面） | ❌ | 无此能力（云端电脑在远端，不是你的电脑） | 见 §4 边界清单 |
| 9 | 在 X（推特）里 @bot 触发任务 | ❌ | 国内版无 X 接入；国际版连接器清单里也未含 X | 替代：用微信触发，见 §1.7 |
| 10 | 在微信里发消息触发任务 | ✅ | 「能力」Tab →「连接聊天工具」；实测可在微信给它发语音/图片/文件并收回复 | 见 §1.7 |
| 11 | 定时日报、例行任务（早8推选题晚8汇报） | ✅ | 「任务」Tab →「定时任务」子页签；实测每天早 9 点自动推送稳定生效 | 见 §1.8 |
| 12 | 盯官网/官宣/教务通知，有更新才喊 | ✅ | 定时任务 + 变化追踪（Proactive）是它的主场 | 见 §1.8 指令模板 |
| 13 | 英文长文/长视频 → 中文学习文档 | ✅ | 直接喂 PDF/链接，它生成结构化笔记 + HTML 页面 | 见 §1.9 |
| 14 | 学习笔记 → 自动生成讲解视频（音画对齐） | ❌ | 无视频生成能力证据 | 替代：让它出「口播稿 + HTML 学习页」，视频你自己用别的工具录，见 §1.9 |
| 15 | 手机遥控云电脑跑代码（clone→装依赖→跑通→日志回传） | 🔄 | 云端电脑可跑代码/构建（实测游戏 mod 汉化调 Claude Opus 5），但**无独立终端视图旁观**、无 Herdr/Codex 接管 | 见 §1.10 |
| 16 | Teach a Task 录屏示教（录一遍操作自动成 Skill） | ❌ | 未检索到此功能 | 替代：把 SOP 写成文字指令 + 一个示范例子喂给它，见 §1.11 |
| 17 | Bot 模板市场 / 分享 Bot 模板 | ❌ | 无 Bot 模板市场；但有社区 Skill 生态（深度研究/HRV 分析/会议纪要等） | 替代：装现成 Skill + 把你的指令存进记忆，见 §1.12 |
| 18 | 连接器 Marketplace（Notion/1Password/MCP……） | 🔄 | 国内版：邮箱、飞书、钉钉、腾讯文档；国际版另含 Gmail/GCal/Notion/Slack/GitHub/Figma/Dropbox/Microsoft | 按 §4 表格接，见 02 分册 §4.6 |

| 20 | 自定义审批规则（Auto-Review 自然语言规则） | ❌ | 无规则配置界面 | 替代：把规则写进对话指令 + 记忆，见 §1.14 |

> 注：#1/#9 标 ❌ 但均给出可执行替代，故单列在 🔄 统计中——按「Grok 原玩法」计 8 项做不到，按「迁移后可用方案」计 6 项有替代。

### 1.1 替代「多 Bot 数字员工」：单助理三岗位命名法

Grok 里你建「课代表小郭」「盯梢老王」「财政大臣」三个 Bot；Today 里你只有一个它。替代组织法：

1. **岗位写进记忆，靠任务名分区**——在主对话里一次性立规矩：
   ```
   我把你当成三个岗位轮值，但对话只有一个。以后任务名带前缀：
   【课代表】= 课程资料整理与复习线；
   【盯梢】= 竞赛/实习/行业信息追踪；
   【管家】= 死线、账单、日程收束。
   每个岗位的上下文分开记：聊【课代表】的事不要带进【盯梢】的判断里；
   如果你不确定某条记忆属于哪个岗位，先问我一句再用。
   ```
2. **复杂任务让它自己拆到「任务」栏**：晚点访谈确认，Today 会主动识别复杂任务、移到独立任务里跑，结果同步回主对话（2026-10-16）。右侧「任务」Tab 里每个任务自带标题，这就是你的「分身工位」。
3. **记忆审计按岗位翻**：每周进「记忆」Tab 改错时，按上面三个前缀分类处理。
4. **诚实边界**：这是「话术级隔离」，不是真隔离——它共享同一套 Living Memory，串味的概率比 Grok 多 Bot 高。所以**敏感互斥的事（如兼职信息 vs 学生身份）不要同时养**。

### 1.2 替代「人机混编群聊 @分工」：串行指令链

Grok 群聊里你 + 4 个 Bot @交接；Today 里你发一段话，把流水线写死：

```
帮我做一份 STM32 PID 调研，按顺序一个人做完，分四步，每步做完给我看一眼再继续：
第一步：GitHub 按 star 挑 5 个相关开源项目，列 README 要点；
第二步：整理成对比表（语言/协议/star/最近更新/适合新手程度）；
第三步：写成 800 字推荐报告；
第四步：按「事实、来源链接、时效」自己审一遍，缺来源的标「未核实」。
最后生成一个 HTML 页面发我。
```

- 预期：它把这件事拆成后台任务串行执行（实测多任务并行无压力，极客公园 2026-10-01），交付 HTML 可一键分享（同上）。
- 与 Grok 的差别：Grok 是四个 Bot 接力、你能看到每个环节的中间产物；Today 是一个任务内部跑完——**过程透明度低一些**，所以上面指令里写死了「每步给我看一眼」。

### 1.3 Bot 互 @ 交接 → 不存在，但你不需要

Grok 群聊的核心爽点是 X监控 Bot 抓料 → 选题 Bot 挑 → 写稿 Bot 写 → 审稿 Bot 打回。Today 迁移：把「监控」挂成**定时任务**（自动每天跑），把「写稿+自审」写成一条任务指令。你仍然是人肉产品经理，只是队员从四个变成一个。

### 1.4 手机远程派活（✅ 原生）

- **手机 App**：登同一账号，对话、任务、记忆全部同步（实测用户手机端和电脑端并用，极客公园十天实测）。
- **微信入口（更顺）**：绑定微信后，在微信里直接发语音/图片/文件给它，它在微信里回你——实测用户后来不再打开 Today App，把它当微信列表里的一个好友（极客公园十天实测，2026-10-08）。
- 教室/路上掏出手机丢一句「把昨天那个课件整理成笔记」，它在云端开工，你回宿舍开电脑看结果。

### 1.5 远程审批（🔄：它会停下来问你，但没有审批卡）

- 实测行为：「真要发邮件、改日历，还是得先回来问你」（抖音技术拆解，2026-10-10）；「对我明确要求不要创建的虚构日历事项，则只给了待确认摘要」（抖音实测，2026-09-26）。
- 迁移结论：Grok 的审批卡队列（放行一次/总是放行/拒绝 + 10 分钟过期）**没有对应物**；Today 的模式是「敏感动作前在对话里停下来等你说 yes」。
- 你的操作：它问「要不要我把这条发到群里？」时，在手机或电脑上回「发」/「别发」即可。**不要默认它会自己批**——收到确认请求尽快回，不然它就停在那。

### 1.6 云端电脑干活（✅ 原生）

- 官方：Cloud Computer 24 小时在线，打开浏览器、处理文件、运行代码（官网）。
- 实测：发一个游戏 mod 的 zip 给它，它自行拆包读文档、调前沿模型（实测 Claude Opus 5）完成汉化，15 分钟出活，过程在侧边栏可见（极客公园十天实测，2026-10-08）。
- 操作路径：电脑端对话框直接发文件/链接 + 指令；它会把这件事挂上云端任务跑。

### 1.7 在微信里 @ 触发任务（✅）

- 配置路径：电脑端右侧「能力」Tab →「连接聊天工具」→ 按引导绑定微信（实测路径，界面可能随版本变化，以 App 内引导为准；极客公园十天实测证实功能存在）。
- 绑定后：微信里给它发语音「帮我把上周那三篇论文读一下」、甩一张课件截图、发一个 PDF，它在微信里回结果。
- 注意：微信里收发消息 ≠ 它能读你的微信聊天记录，别假设它知道你和别人聊了什么。

### 1.8 定时日报 / 盯官网（✅ 原生，Today 主场）

- 入口：电脑端右侧「任务」Tab →「定时任务」子页签（极客公园实测截图可见双 Tab）。
- 可复制指令（盯国内竞赛/教务）：
  ```
  【盯梢】每周一早上 8 点跑一次：检查 [全国大学生电子设计竞赛官网通知栏]、
  [本校教务处通知页]、[牛客网嵌入式竞赛板块]，对比上周记录，
  有新通知就摘要成 3 条中文要点 + 原文链接发我；没有就只回一句「本周无更新」。
  其他时间不要打扰我。
  ```
- 可复制指令（晚报收束）：
  ```
  【管家】每天晚上 10 点给我晚报：今天推进了什么、还有什么没收尾；
  距离任何死线不足 7 天时置顶提醒。输出 150 字以内。
  ```
- 依据：官网定时任务示例（邮件整理每 2 小时、西班牙语练习周二/周四 20:30）；实测「每天早 9 点推选题」长期生效（极客公园十天实测）。

### 1.9 英文长文 → 中文学习文档（✅ 原生；视频部分 ❌）

- 中文文档：直接把 PDF/链接拖进电脑端对话框，配指令：
  ```
  这是一篇英文论文 [发文件/链接]。要求：
  1. 产出结构化中文学习笔记：按概念分节，关键术语中英对照；
  2. 提炼 10 个知识点，每个写 3 句「讲给零基础同学听」的口播稿；
  3. 最后生成一个 HTML 学习页面发我。
  ```
- 讲解视频：Today **没有证据表明能自动生成讲解视频**（Grok 社区玩法里那套「音画对齐 HTML 学习页」本质也是 HTML 不是视频）。替代：口播稿拿到后，你自己用剪映/录屏照着念一遍，这一步省不掉。

### 1.10 云端跑代码（🔄：能跑，但接管方式不同）

- Grok 玩家玩法：手机派活 → 云电脑 clone 仓库 → 建 venv → 跑通 → 日志回传（重度用户主流玩法）。
- Today 迁移：可以做，但边界不同——
  ```
  把这个仓库 [GitHub 链接/zip] 克隆到你的云端环境：
  读 README、建 venv、装依赖、跑通 main，把运行日志贴给我；
  依赖装不上先换国内镜像源，仍失败才停下来问我。
  过程中如果涉及路径、配置这类硬知识，先查官方文档再回答。
  ```
- 与 Grok 的差别：①Today **没有可旁观的云桌面视图**（Grok 能实时看它点鼠标），过程靠它主动汇报；②**接不了 Codex CLI/Herdr**；③它自信给错指令的前科（汉化 mod 时折腾用户一小时，极客公园十天实测）——所以指令里必须带「先查官方文档再回答」。

### 1.11 Teach a Task 录屏示教（❌ → 文字 SOP 替代）

- Today 未检索到录屏示教功能。替代：把 SOP 写成文字 + 一个示范例：
  ```
  以后每周日帮我导出一次课程表总结，按这个固定 SOP：
  第一步……第二步……（写清楚）。这是上周你做过的一份示范 [贴上次结果]，
  以后照这个格式做，不要每次重新发明。
  ```

### 1.12 模板市场（❌ → 社区 Skill + 记忆沉淀）

- Today 无 Bot 模板市场；但官方提及社区 Skill 生态（深度研究、HRV 分析、会议纪要——官网）。
- 替代：①电脑端「能力」Tab 里看可添加的 Skill；②你调好的指令写法，直接说一句「以后我每周都要做这件事，按今天这个流程」，它会记进记忆——你的「模板」就是它的记忆。

### 1.13 资料库（🔄 → HTML 交付物 + 对话记录）

- Grok 右栏「资料库」集中管文件；Today 没有独立文件仓库 Tab。
- 替代：让它把重要成果**每次都生成 HTML 页面**（一键分享链接），长结果在电脑端验收；云端电脑里的中间文件，需要时让它打包发回对话。

### 1.14 自定义审批规则（❌ → 话术写进记忆）

- Grok 的 Auto-Review 自然语言规则配置没有对应物。
- 替代：在自我介绍里写死规则，它会长期遵守（实测文风/标准会被记住，抖音技术拆解 2026-10-10）：
  ```
  铁律记下来：①发邮件、发群消息、改日历之前，必须先问我，我同意了才做；
  ②涉及钱的动作一律先停下来问我；③拿不准的事实标「未核实」，不许编。
  ```

## 2. 双端协同专题（电脑端 vs 手机端）

### 2.1 两端各自适合做什么

| 端 | 最适合 | 不适合 |
|---|---|---|
| 电脑端（Mac/Windows/Linux） | 重活：拖 PDF/zip 喂资料、看任务过程、验收 HTML 长结果、配置连接器、做记忆审计 | —— |
| 手机端（iOS/Android） | 随手派活：语音丢一句、拍照发课件、微信里发文件、收早报和提醒、它问你时回「同意/拒绝」 | 看长报告细节（屏幕小，验收回电脑端做） |
| 微信（绑定后） | 最快入口：不用开 App，语音/图片/文件直达 | 复杂任务指令还是用电脑端发清楚 |

### 2.2 三条典型双端接力工作流

**工作流 A：手机随手丢资料 → 云端后台处理 → 电脑端验收**
1. 上课路上（手机）：拍照课件页 / 把 PDF 从微信文件传输助手转发给 Today；
2. 指令（手机语音）：「这是信号与系统新一节课件，整理进复习线」；
3. 云端电脑后台跑整理；
4. 晚上回宿舍（电脑端）：打开右侧「任务」看它交付的 HTML 笔记，验收、改错。

**工作流 B：睡前手机派任务，上课手机收审批**
1. 睡前（手机）：「明早 8 点前帮我把 STM32 这篇英文资料读完出笔记」；
2. 夜里它在云端跑；
3. 早上它在对话里问「要不要把笔记摘要发到咱们微信文件传输助手？」——你上课时手机回一句「发」。

**工作流 C：提醒与审批只走手机**
- Today 的早晚报、变化提醒、「今天压着的活」卡片，主要消费场景就是手机锁屏；电脑端只用来「看详情 + 做配置」。

### 2.3 同步与通知设置要点

- 双端数据实时同步（同一账号，实测手机/电脑/Android 三台设备同在线见极客公园十天实测截图：设备列表显示 3 台在线）。
- **通知建议**：手机端全开（早晚报、任务完成、请求确认）；电脑端只留「任务完成」和「请求确认」，早晚报类推送在电脑端会打断写代码。
- 绑定微信后，它的回复和提醒会同时出现在微信——如果嫌吵，明确说「进展类结果发微信即可，提醒类不要发微信」。

### 2.4 通知开关建议（按端）

| 通知类型 | 手机端 | 电脑端 | 微信 |
|---|---|---|---|
| 早晚报 / 当日简报 | 开（锁屏看一眼） | 关（写代码时被打断） | 按需 |
| 任务完成 | 开 | 开 | 开 |
| 请求你确认（发信/改日历前） | 必开 | 开 | 开 |
| 变化追踪（竞赛/账单有新动静） | 开 | 关 | 按需 |

原则：**手机收提醒，电脑看详情**。微信只留「你主动找它」的入口，不让它反过来刷屏。

## 4. 学生场景迁移实例（本校电子信息/计算机背景，6 个）

每个：Grok 玩家玩法 → 你在 Today 这样配；指令原文；电脑端操作；手机端操作；预期结果；验收方法。

### 实例 1：STM32 资料追踪线（对应 Grok「盯梢老王 Bot」）

- **Grok 玩法**：建一个 X监控 Bot + GitHub 监控 Bot，群里每小时抓料。
- **Today 配置**：
  ```
  【盯梢】每周一早上 8 点跑一次：检查 [STM32 相关 GitHub trending]、
  [全国大学生电子设计竞赛官网]、[知乎 STM32 话题新回答]。
  只推两类：(a) 可直接跑的开源项目；(b) 和 PID/电机控制直接相关的教程。
  纯新闻不要。每条一句话说清「对我有什么用」，附链接。没有就回「本周无更新」。
  ```
- **电脑端**：右侧「任务」→「定时任务」里挂上这条；接上你的邮箱备用。
- **手机端**：周一早上在手机上读简报，看中的项目回一句「把这个 README 要点展开」。
- **预期**：每周一 8 点自动一份简报，标准写一次以后只改增量（实测第二天发一句修正它就按新标准来，抖音 2026-09-05）。
- **验收**：第三周回看——推的 10 条里有没有 3 条你真的点开过？没有就收紧标准。

### 实例 2：高数死线与复习线（对应 Grok「课代表 Bot + 例行任务」）

- **Grok 玩法**：例行任务每天扫学习进度，群里汇报。
- **Today 配置**：
  ```
  【管家】我这学期的死线：11 月 15 日期中考、12 月 20 日创业项目中期答辩。
  【课代表】高数主要卡在三重积分和曲线积分；我每周会发一次错题截图给你，
  你按周整理「本周易错点清单」；距离死线不足 7 天时早报置顶提醒。
  排学习时间优先保晚上 8-11 点整块给高数。
  ```
- **电脑端**：喂一次教学大纲/历年试卷 PDF；进记忆 Tab 检查它记下的死线对不对。
- **手机端**：做错题时随手拍照发它；晚上收晚报看「还没收尾」。
- **预期**：实测它能记住「优先保晚上学习时间」这类偏好并落实到排期（阑夕 2026-09-24）。
- **验收**：考前一周它有没有主动提醒「三重积分还有 X 个典型题没练」。

### 实例 3：课程论文速读 + 中文笔记（对应 Grok 工作流 1）

- **Grok 玩法**：学习助教 Bot 通读英文长文出 Markdown 进资料库。
- **Today 配置**（指令见 §1.9）：拖论文 PDF 进电脑端对话框。
- **电脑端**：发文件 + 指令；要求它「知识点清单先给我确认再展开全文」。
- **手机端**：路上收到它的 HTML 笔记链接，碎片时间翻一遍。
- **预期**：术语中英对照的分节笔记 + 10 条口播稿。
- **验收**：随机挑 2 条它写的「知识点」，自己翻原文核对——它写错事实不打招呼（汉化 mod 前科）。

### 实例 4：创业团队盯飞书 + 会议纪要（对应 Grok「运营 Bot」）

- **Grok 玩法**：X 监控 Bot 抓舆情 + 总管 Bot 早 8 推选题。
- **Today 配置**（指令见 05 分册工作流 14）：电脑端「能力」→ 连接应用 → 接飞书。
- **电脑端**：让它读近一周飞书文档，确认它读出的「项目卡点」和实际一致。
- **手机端**：开完会在手机上说一句「把刚才会议整理成纪要」；它输出「决策/待办/风险」三段式。
- **预期**：实测同类——接飞书后每天早 9 点自动推选题并追问稿子进度（极客公园十天实测）。
- **验收**：第三天检查——它有没有把「3 天没动的待办」标红？没有就补一句规则。

### 实例 5：云端电脑跑 STM32 仓库代码（对应 Grok 重度玩法「手机派活跑代码」）

- **Grok 玩法**：手机派活 → 云电脑 clone → 装依赖 → 日志回传（重度用户额度烧最快的玩法）。
- **Today 配置**：
  ```
  【实验】把 [GitHub 仓库链接] 克隆到你的云端环境，读 README，
  建 venv 装依赖，跑通 main，把日志贴给我；报错先自己修，修不好再问我。
  涉及路径/配置的硬知识，先查官方文档再回答我。
  ```
- **电脑端**：发链接 + 指令；看右侧任务栏状态。
- **手机端**：下课收到它「跑通了，日志如下」的推送，回复「把改好的 README 发我」。
- **预期**：实测同类 15 分钟出活（mod 汉化案例）。
- **验收**：日志自己在电脑上本地复跑一遍确认——别全信它的「跑通了」。

### 实例 6：账单/订阅异常监控（对应 Grok「财政大臣 Bot」）

- **Grok 玩法**：收件箱分诊 Bot，发信必走审批。
- **Today 配置**（指令见 05 分册工作流 7 Today 版）：接两个邮箱。
- **电脑端**：连接邮箱后先说清规则（只读、可疑标红、每周日汇总）。
- **手机端**：它标红某笔不认识的扣费推送时，手机上回一句「查一下这是什么服务」。
- **预期**：实测——用户长期监管 Cloudflare 账单和车险，漏交/异常续订第一时间通知（阑夕 2026-09-24）。
- **验收**：等下一次续费提醒邮件到来，看它有没有比你自己先发现。

## 6. 迁移常见翻车点与修正（从 Grok 玩家过来必看）

| 翻车点 | 表现 | 修正 |
|---|---|---|
| 把 Grok 的「多 Bot 思路」原样搬来 | 在 Today 里反复说「你是课代表……现在切换到盯梢模式」，它混着答 | 用 §1.1 的岗位前缀法，一次立规矩长期生效；不要每次临场切换 |
| 指望它像 Grok 群聊那样自动交接 | 写了「@写稿Bot 继续」，它不知道你在说谁 | Today 没有 @对象；流水线写在一条指令里，用「第一步……第二步……」串行 |
| 等审批卡 | 派了发邮件的活，以为它会弹出审批卡等你，结果它停在对话里问你，你没看见 | 它的确认请求就是一条普通消息；手机通知全开，看到「要不要……」尽快回 |
| 把验证码贴进微信聊天框 | 它要登录某网站，你直接把验证码发进微信对话 | 铁律不变（与 03 分册一致）：验证码/密码不进任何对话；需要登录墙的环节，要么你先在云端浏览器登录一次，要么那步自己做 |
| 以为它能读你的微信聊天 | 你和同学聊了竞赛信息，指望它知道 | 它只知道你**转发给它**的内容；重要信息手动转发/截图发它 |
| 把 Grok 的「云桌面旁观」期待拿来 | 派了跑代码的活，你想实时看它敲命令的屏幕 | Today 无可视云桌面；指令里写「每步开始前先说一声你在做什么」，靠文字过程追踪 |
| 一次挂太多定时任务 | 早报、晚报、盯梢、陪练、账单全挂上，推送炸了 | 第一周只挂 2 个（§05 分册第九节节奏）；每个任务都写「没有就回一句今日无更新」 |
| 直接拿主邮箱练手 | 敏感邮件全暴露，记忆也攒错了 | 先用学生小号邮箱练一周（02 分册避坑表） |

## 7. FAQ

**Q1：Today 到底能不能建多个分身？**
A：不能。它是单助理单长对话，只能改名/换形象/设风格（极客公园，2026-10-01）。所谓「分身」是 §1.1 的话术分区，共享同一套记忆，有串味风险。

**Q2：它能不能像 Grok 那样替我登录网站、自动过验证码？**
A：不能（未检索到任何安全接管机制）。它要发邮件、改日历前会回对话问你（抖音实测，2026-10-10）；登录墙环节需要你本人处理。

**Q3：手机上它发来的确认请求，多久不回会过期？**
A：未检索到 Today 有 Grok 那种「审批 10 分钟过期」机制。实测它就停在对话里等你——但建议尽快回，不然它后面的活都卡着。

**Q4：我电脑关了，它还在跑吗？**
A：跑。任务在云端电脑（24h 在线）执行，与你本地电脑开关机无关；你关的只是客户端（官网 Cloud Computer 设计）。

**Q5：它能控制我的本地电脑吗？**
A：不能。无任何官方证据；云端电脑在远端。本地要跑的命令自己在本机跑（2026-10-20 专项核实）。

**Q6：微信绑定后，它会看到我的聊天记录吗？**
A：不会。实测支持的是「在微信里跟它收发消息」（极客公园十天实测），不是读取你的微信聊天。别搞混。

**Q7：Grok 那套 Teach a Task 录屏示教，Today 有吗？**
A：未检索到。用文字 SOP + 示范例替代（§1.11）。

**Q8：跑代码的活，Today 和 Grok Bot 哪个强？**
A：重度连续工程任务 Grok 生态（云桌面可视 + Herdr/Codex 接管）更强；Today 适合单次代码处理（汉化、注释翻译、构建验证），且它的优势是跑完还记得你的项目上下文。

**Q9：我两边都在用，任务怎么分配？**
A：盯国内（教务/飞书/微信/账单）→ Today；盯 X、连续重度跑代码、多 Agent 流水线 → Grok Bot（05 分册第八节选型表）。

**Q10：迁移后第一周怎么验收？**
A：按 §4 每个实例的「验收方法」走一遍；一周后做记忆审计（02 分册 §5.8 节奏）：它推的 10 条提醒里真帮上忙的 ≥3 条就算养对了。
