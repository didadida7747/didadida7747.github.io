# 07 隐私安全与避坑指南

> 本篇面向所有把 Today AI、Grok Bot 或开源自建 agent 接入自己生活的同学。
> 信息基准日期：2026-10-20。所有事实来自本资料包 02/03/04 分册及其调研笔记，文末附来源清单。
> 一句话：Personal agent 的价值 = 上下文深度；上下文深度 = 隐私暴露。本篇教你把暴露面控制在可接受范围内。

---

## 1. 权限模型：你的 agent 到底拿到了什么

Personal agent 和你平时用的聊天 AI 最大的区别：聊天 AI 只看你这次发的字；personal agent 拿到的是**一整台机器 + 一串账号**。逐项拆开看：

| 权限类型 | 具体拿到什么 | 代表产品/机制 | 意味着什么 |
|---|---|---|---|
| 浏览器操控权 | 能在真实浏览器里打开网页、点击、填表单、看登录后的内容 | Grok Bot 云电脑里的 Chrome（你可随时开云桌面看它点了什么）（腾讯云教程，2026-10）；Today AI 云端电脑自己开浏览器（官网，2026-10） | 它能模拟你本人上网；登录后的内容（票价、账单、内网）它都看得见 |
| 文件读写权 | 云端电脑上有独立文件夹/终端，产出文件集中存放；自建 agent 则直接读写你本机硬盘 | Grok Bot 右栏「资料库」+ 云电脑终端（内置 bash/read/write/edit/glob/grep 工具）（抖音重度用户，2026-10-10）；OpenClaw 工具默认跑在宿主机上（GitHub README，2026-10-20） | 自建 agent 权限更大——它能碰你硬盘上的任何文件，直到你给它画边界 |
| 连接器授权 | 邮箱、日历、飞书、钉钉、腾讯文档、微信（Today 国内版已接入，极客公园 2026-10-01）；1Password、Notion、Canva、Gmail、GitHub 等 Marketplace 连接器 + MCP 服务器（Grok Bot，腾讯云教程 2026-10） | OAuth 授权令牌 | 等于给厂商发了一把「专用钥匙」，它以你的名义读邮件/文档；官方走连接器比浏览器模拟登录可靠（腾讯云教程建议：有连接器一律走连接器） |
| 云端电脑权限 | 一台 24 小时在线的云端 Linux VM，一个浏览器、一个文件夹、一个终端，**同一账号下所有 Bot 共用** | Grok Bot（腾讯云教程，2026-10-09）；Today Cloud Computer（官网，2026-10） | 浏览器登录态、文件、命令行凭据全部共享：给一个 Bot 的权限 = 给全部 Bot |
| 社交账号身份 | 绑定你的 X 账号后，@你的 bot 名即触发任务，它以你的身份在帖子下公开回复确认 | Grok Bot（腾讯云教程，2026-10-09） | 等于把 X 账号身份交给它操作；第一版官方列出的动作全是「读」，未放开自动发推（抖音科技评论，2026-09-06） |
| 本机命令执行权 | 在你自己电脑上跑 shell 命令，默认每次问你，可改「总是允许/从不允许」 | Grok Bot（腾讯云教程，2026-10-09） | 注意：这个开关**管不住它在云电脑上的行为**，两边要分开设 |
| 聊天软件入口 | bot 挂到 Telegram/Discord 后，理论上任何人都能找到它发消息 | OpenClaw/Hermes（GitHub README，2026-10-20） | 官方设计：陌生 DM 必须走 pairing 配对审批，不要为省事把 Gateway 裸暴露公网 |

**一句话总结权限模型**：官方产品把 agent 关在「厂商的云电脑」里，你通过审批卡控制它出门；开源自建把 agent 放进「你自己的电脑」里，自由度高一个量级，边界全靠你自己画。

## 2. 数据流向：你的对话、记忆、文件分别存在哪

### 2.1 Today AI（云端托管模式）

- **对话与记忆**：存在厂商云端。官方口径是「Today 拥有鲜活的记忆系统……所有上下文都由你掌控」——「掌控」的具体含义是：右侧「记忆」Tab 里每条记忆你都可以查看、修改、删除（官网，2026-10）。
- **云端电脑文件**：它 24 小时在线那台云电脑里的浏览器、文件、代码运行环境，都在厂商基础设施里（官网，2026-10）。
- **连接器读到的内容**：邮件、飞书文档、日历等会被它读取并归纳进上下文（实测：接飞书后它读出你在写的稿子，极客公园十天实测，2026-10-08）。

### 2.2 Grok Bot（云端托管模式）

- **Bot 长期记忆**：存在加密存储里（S3 加密持久化），你可以随时检查它记住了什么，并指令它「忘掉某项目相关的所有委托」（人人都是产品经理，2026-10-17）。
- **云电脑文件与登录态**：浏览器 Cookie、会话、文件全部托管在云上——走官方连接器是「专用钥匙」；走浏览器模拟人登录，等于把你的账号身份（Cookie、会话）托管在云上（抖音科技评论，2026-09-06）。
- **凭证**：官方设计密钥/密码走遮蔽输入框与隔离沙箱（1Password 机制），云电脑读不到明文（人人都是产品经理，2026-10-17）。**这个机制存在的前提是你配合它用——别图省事把验证码贴进聊天框。**

### 2.3 开源自建（OpenClaw / Hermes，本地模式）

- **框架留存归你**：State、memory、credentials 存在你自己的硬件上；OpenClaw 官方声明默认每天只做一次版本检查回传数据，可用 `update.checkOnStart: false` 关掉（GitHub README，2026-10-20）。
- **但提示词仍要过模型商**：你发的每条消息都送给 DeepSeek/OpenAI 等服务商。自建只解决「框架留存」，不解决「模型商留痕」（04 分册 §8.5，基于官方 README 推断）。
- **聊天平台也有一份**：bot 住在 Telegram/Discord 里，消息在那些平台的服务器上同样留痕。

### 2.4 数据归属对比（结论表）

| 维度 | Today AI / Grok Bot 云端模式 | OpenClaw / Hermes 本地模式 |
|---|---|---|
| 对话与记忆 | 厂商云端，按厂商政策留存 | 你的硬盘/VPS |
| 文件产出 | 厂商云电脑 | 你的 workspace 目录 |
| 凭证 | 遮蔽沙箱托管（Grok）/官方连接器（Today） | 本地配置文件，自己保管 |
| 模型商留痕 | 同样存在（它们调的也是第三方前沿模型，实测 Today 汉化时调了 Claude Opus 5） | 同样存在 |
| 你能删什么 | 记忆条目可逐条删（Today）；可指令遗忘（Grok） | 直接删文件 |

### 2.5 学生场景特别提示：学校数据

- **学校邮箱与教务系统**：里面有学号、成绩、选课记录、学籍信息。Grok Bot 分册的社区建议是「学校邮箱/教务系统的授权边界要自己守好」（03 §14）——教学期需要它盯教务网通知栏时，只让它盯**公开通知页**（03 场景 1 就是这么写的），不要把校园内网/VPN 后的系统接给它；云电脑在厂商基础设施里，访问校园内网大概率不通（03 FAQ Q6）。
- **聊天内容**：Today 的微信实测证据只支持「在微信里收发消息」，**不支持「它能读你的微信聊天记录」**（02 附录诚实清单第 5 条）——别因为绑定了微信就默认它知道你和同学聊了什么。
- **简历与项目文档**：喂进「记忆」的文件会长期留在上下文里，其中的个人经历它会反复引用；隐私敏感度低、但错了会一直带歪，所以喂完要核对。

## 3. 最小授权原则与设置清单

### 3.1 总原则

1. **先接不重要的，再接重要的**：先用小号/学习邮箱练手一周，再决定接不接主邮箱（02 分册 §7.1 避坑速查表）。
2. **敏感源头一周不连**：网银、学校统一身份认证、主邮箱，建议先不连（Grok Bot 分册 §14 社区建议，2026-10）。
3. **官方渠道优先于模拟登录**：有 Marketplace 连接器的服务一律走连接器，没有连接器的才让它用浏览器点（腾讯云教程，2026-10-09）。
4. **审批默认从严**：高危动作一律「先询问」，规则冲突时「先询问」优先（腾讯云教程，2026-10-09）。

### 3.2 连接器开/不开决策表（学生向）

| 连接器 | 建议 | 理由（依据） |
|---|---|---|
| 学习邮箱/小号 | ✅ 第一周就接 | 练手低成本（02 §7.1） |
| 日历 | ✅ 可接 | 排早晚报的基础数据；但重要会议以你自己日历为准（实测排期会算错缓冲，抖音 2026-09-26） |
| 飞书/腾讯文档 | ✅ 团队在用就接 | 创业团队文档追踪实测有效（极客公园十天实测） |
| 微信（Today） | ⚠️ 知道边界再接 | 实测只支持「在微信里给它发语音/图片/文件、它在微信里回」；**不能假设它能读你的微信聊天记录**（02 附录诚实清单第 5 条） |
| Gmail（Grok Bot） | ⚠️ 第二次任务时再连 | 第一次建 Bot 弹窗问要不要连 Gmail，先跳过（03 §3 最短路径） |
| 学校教务系统/统一身份认证 | ❌ 先不连 | 登录墙=你的时间墙，且授权边界要自己守好（03 §13/§14） |
| 网银/支付类账号 | ❌ 不连 | 敏感账号建议先不连（抖音科技评论，2026-09-06） |
| X 账号（Grok Bot @ 触发） | ⚠️ 需要再绑 | 非所有地区可用；它以你的身份在公开帖子下回复（腾讯云教程，2026-10-09） |

### 3.3 审批模式怎么设（Grok Bot Auto-Review）

1. 进入：**设置 → 自动审核（Auto-Review）**（03 附录 D 速查表）。
2. 默认开启，由独立审查 Agent 按你写的自然语言规则判断：放行/拦下/交给你。
3. 起步规则照抄：
   ```
   当 Grok Bot 想要替我回复邮件，它应该先询问。
   当 Grok Bot 想要购买任何东西，它必须先询问。
   当 Grok Bot 想要删除任何文件，它必须先询问。
   ```
   （写法依据：腾讯云教程，2026-10-09）
4. 高危动作（发信、发布、购买、删除）弹审批卡，三选项——**永远只点「只放行这一次」**；「总是放行」等于长期敞开一个口（腾讯云教程，2026-10-09）。
5. 注意时限：无人值守产生的审批约 **10 分钟过期**，过期动作不执行，要让 Bot 重试（腾讯云教程，2026-10-09）。
6. **群聊盲区**：审批请求、登录/密钥请求、邮件草稿预览不会出现在群聊里——涉及这些的事必须回到一对一对话处理（腾讯云教程，2026-10-09）。

### 3.4 Today AI 对应的设置动作

1. 高风险动作官方已设计成先问：发邮件、改日历、付款前会先请求确认（抖音实测，2026-10-10）——你要做的是**逐条看它生成的内容再批准**（02 §8）。
2. 邮箱任务实测全程只读：不删、不改、不回（阑夕实测，2026-09-24）。
3. 每周进一次「记忆」Tab 做审计，把推错的提醒明确说「这条以后不用提醒我」（02 §7）。

**记忆审计三步（每周 10 分钟）**：

```
第 1 步：打开右侧「记忆」Tab，从上到下扫一遍它归纳的你的画像。
第 2 步：发现错条 → 直接在条目上改或删（官方原文「所有上下文都由你掌控」）；
        发现删了还影响后续判断的（实测存在：删一句不一定改掉后面的判断）→
        在对话里明确补一句正确说法，让它重写结论。
第 3 步：把最近一周推错的提醒口头关停一次：「这条以后不用提醒我」。
```

## 4. 高危操作清单与防护做法

| 高危操作 | 风险本质 | 防护做法（全部来自分册实测/官方机制） |
|---|---|---|
| 发消息/发邮件 | 以你的身份对外发声，发出去收不回 | Today：它会先请求确认，你看内容再批；Grok：发信必走审批卡，卡内含拟发信件全文，你点 Send email 才真发（人人都是产品经理，2026-10-17）；自建：对 Hermes 下指令「凡是要发消息给别人，先停下来问我确认」（04 场景 D） |
| 下单/付款 | 真实金钱支出 | Grok：支付动作它会在登录/支付环节停下来等你接管（腾讯云教程，2026-10-09）；审批卡永远选「只放行这一次」；大学生涉及真实金钱的购买动作不设「总是放行」（03 §14） |
| 删除文件 | 不可逆 | 删除属高危动作走审批卡；Grok 重置云电脑是从上一快照重建、最近改动会丢——**重置前先去「资料库」确认重要文件已拿走**（腾讯云教程，2026-10-09；FAQ Q5） |
| 社交发帖 | 公开身份风险 | Grok 接入 X 第一版官方动作全是「读」（读帖子、读趋势），尚未放开自动发推（抖音科技评论，2026-09-06）；不要主动要求它自动发帖 |
| 批量/例行操作 | 无人值守时连环出错 | 例行任务挂无人值守前，先手动「测一次」跑通；单 Bot 例行任务上限 50 个、保留最近 20 次运行、两次至少间隔 5 分钟（腾讯云教程，2026-10-09，社区经验）；追踪类任务指令写死「没有就别发」 |
| 登录墙接管 | 密码/验证码泄露 | **铁律：不要把密码和验证码直接贴进聊天框**——用官方安全输入框（凭证遮蔽显示、不进对话记录）（腾讯云教程，2026-10-09） |

## 5. 典型翻车案例与应对

### 5.1 幻觉式错误指令（最常见）

- **真实案例（Today AI）**：用户发游戏 mod 的 zip 让它汉化，汉化完成后它自信地连续给出错误的目录结构指令（「英文不能用大写」「42.0 不能写成 42」等），作者反复重启游戏测试折腾一小时无效；最后直接命令「你去官方文档里查一下官方要求的 mod 文件结构」，它立刻查对并解决（极客公园十天实测，2026-10-08）。
- **应对**：涉及配置、路径、命令这类硬知识，先命令它「先查官方文档再回答」；关键步骤自己复核一遍（02 §7 避坑速查表）。

### 5.2 错误记忆被放大

- **真实案例**：记者实测它对个人情况的归纳「并不完全准确」；有用户发现自己删了 9 条过时身份记忆，但「不知道它为什么这么想，删一句不一定改掉后面的判断」（极客公园，2026-10-01；抖音拆解视频，2026-10-10）。项目取消了它还在每天催（抖音测评，2026-10-02）。
- **应对**：每周一次记忆审计；它推错一次就明确说「这条以后不用提醒我」；追踪类任务指令写死「没有就别发」（02 §7）。Grok Bot 侧对应做法：指令它「忘掉某项目相关的所有委托」（人人都是产品经理，2026-10-17）。

### 5.3 手机端不能操控手机 App

- **真实案例（Grok Bot）**：实测订机票翻车——它打不开携程/去哪儿/飞猪页面、读不到登录后的报价；手机 App 不能像国产手机助手那样直接控制你手机里的其他 App，它只在云端电脑的浏览器里干活（36氪实测，2026-10-13）。
- **应对**：有登录墙的任务（票价、账单、校园内网）你本人先登录或接管那一步；含内网的任务让它做「公开资料部分」，内网部分自己补（03 FAQ Q6）。

### 5.4 共享云电脑 = 共享风险面

- **真实机制**：一个账号下所有 Bot 共用同一台云电脑，一个 Bot 登录过的网站，所有 Bot 都能用（腾讯云教程，2026-10-09）。
- **应对**：① 敏感网站（学校邮箱、网银）先不登录；② 执行型 Bot 和咨询型 Bot 拆开建，互相不污染记忆（腾讯云教程社区实战经验，2026-10）；③ 定期开云桌面看它点了什么（右栏「电脑」标签可实时旁观）。

### 5.5 Grok Bot 频繁需要重置

- **真实案例**：社区多人遇到它时不时不响应、界面卡死，解决办法是重置云电脑——从上一快照重建，最近改动可能丢失（腾讯云教程，2026-10-09）。
- **应对**：重要产出文件及时从「资料库」另存本地；知道 Bot 长期记忆与 Skill 是独立持久化的，重置云电脑不等于清空记忆（03 FAQ Q5）。

### 5.6 账号封禁与地区风险

- Grok Bot 绑定 X 账号存在地区限制，绑定入口灰掉即不可用（腾讯云教程，2026-10-09）。
- Bot 登录用的是你的 X 身份——若该身份被平台判定异常操作，风险落在你账号上（抖音科技评论，2026-09-06）。
- **应对**：不在主 X 账号上做高风险自动化；官方第一版只放开「读」动作期间，不探索越界玩法。

### 5.7 误操作恢复

- Today AI：记忆删错了可以重新告诉它（但不保证立刻改判）；重要死线抄进你手机日历双保险（02 §7.1）。
- Grok Bot：云电脑重置从上一快照重建；本机命令误操作影响你自己电脑——所以本机命令别图省心设「总是允许」（腾讯云教程，2026-10-09）。
- 自建：升级前备份 `~/.hermes` 或 `~/.openclaw` 目录（记忆都在里面）（04 §8 排查表）；Windows 杀软把 Hermes 的 `uv.exe` 误报隔离是已知问题，官方给了 `gh attestation` 校验和加白 `%LOCALAPPDATA%\hermes\bin` 目录的步骤（GitHub README，2026-10-20）。

### 5.8 上下文与额度翻车（Grok Bot 专属）

- **上下文装不下复杂流程**：官方指南自己承认 Bot 上下文有限，长任务要每天提醒自己跟进；「紧急模式」每 5 分钟查一次记录，很烧额度，只真紧急时用（腾讯云教程引官方 guides，2026-10-09）。
- **额度烧完**：免费额度 7 天重置，重度用户实测一周用掉 99%（抖音重度分享，2026-10-10）——学生别在第一周就开多个例行任务，先把免费额度的消耗曲线摸出来再决定充不充。
- **群聊里 Bot 自治翻车**：总管 Bot 改不了面板里的截止时间、书稿日报得手动转进群、Bot 之间吵起来最后还是要人拍板（人人都是产品经理，2026-10-05）——别指望零干预，把群聊当「需要你当产品经理的初级团队」来带。

## 6. 外部风险（产品之外的坑）

### 6.1 第三方模板 / Marketplace 连接器风险

- Grok Bot 模板是「配方」不是克隆：别人拿到的是独立副本，不含你的隐私记忆；但**你发布模板时，系统会带走指令、非个人化记忆、自带 Skill/插件、例行任务、连接器配置**——发布前必须自查（mem0 指南，2026-09-28；腾讯云教程，2026-10）。
- 反过来：你从 Marketplace 一键添加别人的 Bot 模板，等于把别人写的指令和连接器配置装进你的账号——添加前翻一遍它带了哪些连接器。

### 6.2 代充风险

- 官方路径：Today 国内版现阶段免费（齐俊元原话，晚点 LatePost，2026-10-16）；Grok Bot 激活免费试用需绑信用卡（社区实测国内双币卡可用），较新报道称官方已提供人民币结账、可支付宝开通（腾讯云教程，2026-10；36氪实测，2026-10-13）。
- **代充的本质是把账号或支付凭据交给陌生人**——这与本指南「凭证走官方安全输入框、不贴进聊天、不走浏览器托管敏感身份」的全部原则相冲突，且可能导致账号被封、订阅被追回。（风险判断基于上述产品机制，属建议性质，截至 2026-10-20 未检索到针对代充的官方警告原文。）

### 6.3 盗版客户端 / 钓鱼

- Today AI 只认官网下载页 https://todayai.cn/downloads ；App Store 搜索「Today」要核对开发者是 Today AI 官方（02 §4.1）。国内应用商店是否上架截至 2026-10-20 未能确认，以下载页直链为准。
- Grok Bot 下载入口是 **x.ai/bot**（腾讯云教程，2026-10）。
- 该产品太新、第三方安装包满天飞（02 §7：B站/知乎教程生态尚未形成），凡是要你在非官网页面登录或填银行卡的「破解版/汉化版」，一律视为钓鱼。

### 6.4 X 账号被滥用

- Bot 登录用你的 X 身份，@bot 的公开回复是以你的名义发出的（腾讯云教程，2026-10-09）。
- 官方接入第一版动作全是「读」（抖音科技评论，2026-09-06）——未来若放开自动发帖，绑在主号上的风险会放大；做公开传播前先想清楚。

## 8. 上线一个新 agent 前的 15 条安全自查清单

照单全勾再让它上岗：

1. ☐ 客户端来自官方下载页（todayai.cn/downloads 或 x.ai/bot），不是第三方安装包；App Store 已核对开发者。
2. ☐ 邮箱先接的是小号/学习邮箱，主邮箱至少观察一周再决定。
3. ☐ 网银、学校统一身份认证、主支付账号一个都没连。
4. ☐ 没有把身份证号、银行卡号、家庭住址写进给它的「自我介绍」里。
5. ☐ Auto-Review（或等效审批）保持开启，且写了「发信/购买/删除先询问」规则。
6. ☐ 高危审批一律点「只放行这一次」，没开过任何「总是放行」。
7. ☐ 知道无人值守审批约 10 分钟过期、过期要让 Bot 重试。
8. ☐ 知道群聊里看不到审批请求，重要动作都在一对一对话里批。
9. ☐ 密码和验证码走官方安全输入框，从没贴进过聊天框。
10. ☐ 例行任务先手动测跑通过一次，指令里写了「没有就别发」。
11. ☐ 重要文件已从云电脑「资料库」另存本地，知道重置云电脑会丢近期改动。
12. ☐ 每周有一次「记忆审计」安排，说错的地方进记忆 Tab 改掉。
13. ☐ 从 Marketplace 加模板前翻过它带了哪些连接器；自己分享模板前确认不含个人记忆。
14. ☐（自建）Gateway 没裸暴露公网，陌生 DM 配对审批保持开启；API key 设了月度额度上限，没传过公开 GitHub 仓库；workspace 不含浏览器密码库等隐私目录。
15. ☐（自建/VPS）按官方 exposure runbook 配了访问控制；升级前备份了记忆目录。
