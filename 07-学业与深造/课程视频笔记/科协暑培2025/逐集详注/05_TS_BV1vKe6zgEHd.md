## 知识整理

### TS 是什么：在 JS 上加编译期检查

TS = JS 基础上加类型检查，是 JS 的超集，基本类型与 JS 一致。它不能在浏览器控制台直接跑：需装 node.js 与包管理器 npm，把 TS 编译成 JS 再运行。动机很直接——JS 变量类型不明、比 Python 还难读，调试常到出错点才发现类型不是预期；显式类型直接提升可读性与可维护性。

### 标注语法与类型推断

标注方式：形参、返回值、变量名后加冒号+类型，void 表无返回值。与 Python 类型标注的本质区别是 TS 真检查：标 boolean 赋 number 直接报错，Python 的标注只是提示。类型可省略、靠初始值推断；但既无标注又无初始值会推断为 undefined 类型、之后赋任何值都报错——声明时标注与初始值二选一。进阶三件：字面量类型让变量只能取那个值；any 表示任意（全 any 等于退化回 JS，明确不推荐）；type 关键字定义类型别名。

必须记住检查的边界：检查只发生在编译期。用 JS 去调 TS 编译出的库时没有编译过程、不做检查，理论上可以违反其标注——讲师提醒不要这么干；后文的 private、readonly 在运行期同样能被 JS 调用方打破。

### 复合类型：对象、数组、元组与联合

对象类型就是同构的"键: 类型"列表；类型+中括号表示该类型的数组；中括号里列多个类型则固定长度与每一位的元素类型，即元组。联合类型用竖线连接多种类型（string|number 或 string|string[]），使用时需 typeof 判断分支再分别处理，称为类型收窄；字面量联合可当枚举用（如 1|2|4|8|16）。as 是强制断言，不能断言明显冲突的类型；先断言成 unknown 再转目标类型属极端用法、危险不推荐。never 标注"永不终结也不抛异常"的函数（如死循环），不能实例化——好用的地方是 switch 的 default 分支里把收到的值赋给 never 变量做穷尽性检查：联合类型漏了某个情况，编译器立刻报错。

### 函数与面向对象

函数的参数类型必须手标（编译器只推断返回值）；函数类型可整体作变量标注，如 (a:number,b:number)=>number。运行时与 JS 一样不检查参数个数，编译期会查；可选参数 ? 与默认值实现变长参数，且必须排在参数列表末尾。若已看过 JS 讲，箭头函数简写部分完全重复，可略。

类语法同 JS，多出成员类型标注与 private/public 访问修饰；extends 继承、子类构造必须 super 调父类；类名可直接当类型标注用。接口 interface 规定对象"必须有的一部分属性"——多有剩余不限制、少实现报错，讲师类比 C++ 抽象类与纯虚函数；类用 implements 实现接口、必须含全部要求的成员；接口成员可加 ? 可选、readonly 只读。

### 泛型与类型级编程

TS 泛型与 C++ 模板的最大不同：所有类型共用一份代码，编译器只检查各类型是否兼容，不像模板逐类型实例化。函数/类/接口/类型别名均可声明泛型参数（可多个），参数可设默认值、可用 extends 加约束（如必须含 string 的 data 属性）；不显式给 T 时编译器能从实参推断并验证约束。

再往上是"类型级"工具：typeof 作类型标注可提取变量的具体类型；keyof 取"类型的键的类型"，得到键名字面量联合（"foo"|"bar"）——已知缺陷是 for-in 循环变量只会被推断成 string、不会自动推成 keyof。索引访问类型 T["foo"] 取类型的一部分，可层层下钻（接口→对象数组→[0] 取元素类型），像用下标访问数组一样访问类型。条件类型 T extends U ? X : Y 把三目写进类型系统：MessageOf`<T>` 例子中，T 含 any 型 message 属性则取其类型、否则 unknown，传 email 得 string、传 dog 得 unknown。最后是内置工具类型：Partial 全可选、Required 全必选、Readonly 全只读、Pick 挑部分属性等类型映射，用到再查讲义。
