# 寒假前软件与系统能力矩阵

更新日期：2026-09-03。本文用于检查作品和投递准备，不独立生成任务。9 月执行以四周验证计划为准。

## 公共底座

| 能力 | 当前状态 | 9 月验证线 | 寒假前可投线 |
| --- | --- | --- | --- |
| Python | 基础语法 | 能写模块、异常、日志、类型和 `pytest` | 能处理 JSON/文件/数据库，构建可测试服务并定位 traceback |
| Linux/Git | 基本命令 | 能从空目录运行、测试、提交 | 能管理环境、进程和日志，使用 Git 分支/提交说明协作 |
| HTTP/数据 | 未形成系统证据 | 能定义接口、校验输入、处理错误 | 能解释 HTTP、数据库基本设计、幂等/重试和状态流转 |
| 算法 | 尚未系统训练 | 9 月完成 12-16 道复盘题 | 30-40 道基础题，二刷至少 70% 独立完成 |
| 工程表达 | 能描述做过什么 | 每个实验有 README、测试和失败记录 | 能讲清需求、架构、个人贡献、测试、取舍和限制 |

## 后端/系统开发

| 能力 | 只算接触 | 可写进项目 | 可投实习的最低证据 |
| --- | --- | --- | --- |
| 服务接口 | 跑过框架示例 | 有输入校验和错误响应 | 安装、启动、接口测试和异常路径可复现 |
| 数据持久化 | 会 CRUD | 有明确数据模型和重启恢复 | 能解释事务/一致性边界，并有数据迁移或故障处理 |
| 可靠性 | 写过 `try/except` | 有幂等、重试、超时或状态机 | 至少两类失败注入，有日志和恢复结果 |
| 性能 | 跑过一次压测 | 固定环境下有基准 | 能说明瓶颈假设、测量方法和一次优化前后对照 |
| 计算机基础 | 看过八股 | 能结合项目解释 | 数据结构、网络、OS、数据库问题能落到自己的代码 |

“基础架构”是中期深化方向，不是当前简历标签。没有网络、存储、并发、性能或可靠性证据时，不把普通 CRUD 项目包装成基础架构。

## 共同投递门槛

- 至少一个对应岗位的完整项目，而不是课程名、教程复现或计划中的功能。
- 能在 10-15 分钟内讲清架构、关键取舍、个人代码、测试方法和一次失败。
- 陌生人能按 README 复现核心结果；不能公开的条件明确说明。
- AI 辅助、开源代码和自己独立完成部分边界清楚。
- 性能、正确率、用户数、Star 和比赛名次只写可核验证据。
