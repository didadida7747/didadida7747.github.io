# 03 · 提示词模板库：抄了就能用的 12 个模板

> 每个模板都注明出处流派。使用心法：**模板是脚手架，你的具体上下文才是混凝土**——别只抄框架不填事实。

## A. 任务启动类（最常用）

### A1. 计划先行模板（派系：Anthropic best practices / Boris Cherny）

```
先别写代码。
任务：<一句话目标>
环境：<目录/技术栈/约束>
请先：
1. 阅读相关代码（列出你打算看的文件）
2. 给出实现方案（分步骤）
3. 列出你不确定的点
我确认方案后你再动手。
```

【为什么有效】把模型的"热心"约束在确认门之前；跑偏成本从"写完发现错"降到"方案就被毙"。

### A2. 规格驱动模板（派系：Harper Reed 的 codegen workflow）

```
我们在做 <项目一句话>。
技术栈：<已定死的选型>。
第一步：针对以下需求写一份技术规格（不写代码）：
<需求列表>
规格包含：数据结构、模块划分、每个模块的输入输出、边界情况。
写完先不实现，等我审。
```

【为什么有效】大任务的最小单元不是"一次 prompt"，是"一份文档"。规格文档成为后续所有对话的共同锚点（04篇：状态外化到文件）。

### A3. 逐票执行模板（派系：Harper Reed）

```
这是技术规格：<粘贴/引用规格文件路径>
现在只实现 Ticket #3：<该票的原文>。
实现完跑 <测试命令>，绿了再叫我。不要动其他 ticket 的范围。
```

【为什么有效】一次一个 ticket = 上下文小、diff 可审、出错可回滚。和 01章 08 篇"模式1"一致：**大任务被纪律拆碎，而不是被能力硬吞**。

## B. 上下文喂养类

### B4. 环境清单模板（通用）

```
项目背景：
- 这个项目是 <一句话>
- 技术栈 <x.y.z 版本>
- 构建/测试命令：<命令>
- 代码规范：<要点或指向 CLAUDE.md>
- 红线：不要动 <目录/文件>；不要升级依赖
任务：<目标>
```

【为什么有效】90% 的"AI 改错地方"是因为它不知道这些。这份清单值得沉淀进 CLAUDE.md 而不是每次手打。

### B5. 反例喂送模板（当模型重复犯错时）

```
你刚才的做法有两个问题：
1. <它做的> —— 错在哪：<事实>
2. ...
正确姿势示例：<正确代码/命令的片段>
把这个差异记进 CLAUDE.md 的注意事项。
```

【为什么有效】"错误样本+正确样本"是最强的 few-shot；让它自己写进 CLAUDE.md = 记忆沉淀（01章04篇 # 快捷记忆的原理）。

## C. 过程控制类

### C6. 测试驱动模板（派系：工程师社区共识）

```
先写失败的测试（描述期望行为），我看过再实现。
实现时只以让测试变绿为目标，不要顺手重构。
每完成一个函数跑一次测试。
```

【为什么有效】给模型装上**客观判分器**——和 R1 的 RL 思想同源（03章01篇：可判分任务是训练/协作的最佳载体）。

### C7. 卡点升级模板（防死循环）

```
如果你在同一个问题上失败 3 次，停下来：
1. 写出你尝试过的 3 种方案和失败原因
2. 给我 2 个你认为最有希望的新方向
不要第 4 次尝试同类方法。
```

【为什么有效】模型有"执着于同类失败"的倾向（Gemini CLI 提示词里甚至明文写了"失败 3 次换架构方向"——见 01章07篇的对比）。人工干预点是省钱的止损线。

### C8. 验收汇报模板（任务收尾）

```
完成后用这个格式汇报：
- 改了哪些文件（路径:行号）
- 怎么验证的（跑过的命令与结果）
- 你没做/没验证的部分
- 遗留风险
```

【为什么有效】强迫模型自我审计，"没验证的部分"一栏专治自信过头的幻觉。

## D. 角色与心理类

### D9. 反谄媚声明（抄自 Claude Code 系统提示词，见 01章07篇）

```
技术正确性优先于认同我的想法。
如果我的方案有问题，直接指出，先说问题再给替代方案。
不确定的事先查证，不要顺着我说。
```

### D10. 谨慎模式声明（危险操作场景）

```
接下来会操作 <生产环境/重要数据>。
规则：任何不可逆操作（删除/覆盖/推送）必须先列出影响清单并等我确认。
宁可慢，不可错。
```

## E. 学习类（本库最关心的用法）

### E11. 源码导游模板

```
我想深入理解 <仓库> 的 <模块>。
按依赖顺序给我阅读路径（文件:行号），每步说明该文件在数据流中的角色。
先给路线图，我读完一个文件再向你提问，不要一次性解释所有内容。
```

【为什么有效】把模型变成"分章节的导游"而不是"一次性倾倒的百科"。分步 = 每步都进入你的记忆。

### E12. 费曼检验模板

```
我给你讲一遍我对 <概念> 的理解：<你的复述>。
请指出：1) 概念错误 2) 我混淆的点 3) 一个我没想到的追问。
打分：1-10，并告诉我扣分原因。
```
