# 10 · 对照精读：analysis_claude_code 的 17 章 Harness 课程

> 素材：本库 clone 的 `analysis_claude_code`（shareAI-lab，对 Claude Code v1.0.33 的逆向工程课程化拆解）。
> 这个仓库本库引用多次，本篇是它的"导读 + 与本库框架的互证"。**它回答"怎么亲手造"，本库回答"为什么这么造"**——两套材料是互补关系，不是替代。

## 一、它的定位：一份"造载具"的渐进式课程

仓库把 CC 的逆向成果组织成 17 章，每章一个部件、一份可运行代码 + 测试：

```

s02_tool_use          工具调用        ↔ 01 章 02 篇
s03_permission        权限            ↔ 01 章 03 篇
s04_hooks             钩子            ↔ 01 章 06 篇
s05_todo_write        任务清单        ↔ 01 章 04 篇（状态外化）
s06_subagent          子代理          ↔ 01 章 05 篇
s07_skill_loading     技能加载        ↔ 01 章 06 篇（渐进式披露）
s08_context_compact   上下文压缩      ↔ 01 章 04 篇（本篇重点对照）
s09_memory            记忆            ↔ 01 章 04 篇（CLAUDE.md）
s10_task_system       任务系统        ↔ 01 章 05 篇
s11_background_tasks  后台任务        ↔ （本库未展开）
s12_cron_scheduler    定时调度        ↔ （本库未展开）
```

【批注】这个目录本身就是一个行业信号：**逆向工程做到了"可教学"的程度**——每个部件都能从混淆代码里剥出来、用 Python 重写、配测试。s16/s17（工作流运行时、目标循环）是本库没深入的暗线：CC 的 harness 里除了"对话式主循环"还藏着"自治任务运行时"（后台任务、定时任务、目标循环），这是 2026 年"无人值守 Agent"方向的结构基础。

## 二、它的纲领：一段值得逐句读的宣言

README-zh 开篇（原文摘录）：

> **Agency——感知、推理、行动的能力——来自模型训练，不是来自外部代码的编排。** 但一个能干活的 agent 产品，需要模型和 harness 缺一不可。模型是驾驶者，harness 是载具。
>
> 拖拽式工作流构建器……它们做出来的东西是鲁布·戈德堡机械……**提示词水管工式 "Agent" 是不做模型的程序员的意淫。** 你不可能通过工程手段编码出 agency。Agency 是学出来的，不是编出来的。

【批注，三段式解剖】

1. **"Agency 是学出来的，不是编出来的"**——这句话和本库 01 章 08 篇模式 1（"先问能不能用最简单的循环+提示词解决"）是同一个论点的两个语气：它说得激进，Anthropic《Building effective agents》说得克制，内核一致：**工程层不会产生智能，只会放大或浪费智能。**
2. **对"提示词水管工"的嘲讽有点狠，但方向是对的**：把 LLM 用 if-else 串成节点图，本质上是用胶水代码模拟决策——而决策恰恰是模型擅长的。判断某产品是不是"水管工"的试金石：**把里面的 LLM 换成一个更聪明的模型，产品会自动变强吗？** 会 → harness 是放大器；不会 → 胶水锁死了上限。
3. **但也要给它留余地**：工作流编排并非全无价值——它赢在**确定性和成本**（01 章 09 篇 Building effective agents 的 workflow vs agent 之辨）。宣言的价值是纠偏（别用编排冒充智能），不是判死刑（确定性任务用编排更省）。读任何宣言都要做这层祛魅。

## 三、重点对照：s08 的压缩流水线 vs 本库 04 篇

s08 揭示了 CC 压缩机制的**完整工序**（比本库 04 篇的概念描述细一级）：

```
每次调用模型前，固定顺序四段：
① tool_result_budget  超大工具结果 → 落盘存档（.task_outputs/tool-results/）
② snip_compact        旧对话中段 → 归档到 .transcripts/
③ micro_compact       旧工具结果 → 缩短改写
④ compact_history     仍超限 → 整体总结压缩
另外：compact 工具（用户手动）+ reactive_compact（API 报 prompt_too_long 后补救重试一次）
```

【对照批注】四个发现：

1. **"落盘"是第一选择，不是压缩**：超大结果先写成文件、上下文里只留路径引用（需要时再读回）——这正是 04 篇"可再生的信息先丢"的极致形态：**连丢都懒得丢，直接外置**。本库 06 章练习题 3 的实现里没有这一层，做完练习后可以回头加（练习题 3+）。
2. **顺序固定有讲究**：便宜且无损的先跑（落盘、归档），贵的有损的（总结）最后兜底——和 01b 篇循环检测器的"便宜检测高频跑"同一条设计律：**按成本排序的处理流水线**。
3. **reactive_compact 是被 API 逼出来的**：即使预防措施全做了，还是会撞上 "prompt too long"——生产系统必须有"失败后降级重试一次"的最后兜底。这一层最容易被自研 Agent 忘掉。
4. **s08 的实验设计**：每章末尾配"试一下"实验（如"较早的结果被替换""大结果转存"）——学它的做法：**每读完一个机制，立刻构造一个能观察它的最小实验**。这比做笔记有效得多。

## 四、本库与它的分工（怎么搭配用）

| 你的目标 | 用哪套 |
|---|---|
| 建立"为什么这么设计"的判断力 | 本库 01/02/03 章（批注 + 设计动机 + 反事实推理） |
| 亲手把每个部件造一遍 | analysis_claude_code s01-s17（可运行代码 + 测试 + 实验） |
| 学真实产品行为与提示词 | 本库 07/07b 篇（泄露原文批注） |
| 快速见效的用法与模板 | 本库 04 章 |

【建议路径】读完本库 01 章 → 去它那里把 s01-s08 逐章代码跑一遍（它有 tests，改坏了能发现）→ 回本库 06 章做练习题——**读、造、改三层都覆盖了**。

【诚实备注】它逆向的是 CC v1.0.33（2025 年版本），细节与当前版本有出入（如 07 篇讲过 v2.0 的系统提示词删改）；但骨架级结论（主循环、权限、压缩流水线）与 2026 年的泄露源码互相印证，学习价值不受影响。引用它的结论时注明版本即可。
