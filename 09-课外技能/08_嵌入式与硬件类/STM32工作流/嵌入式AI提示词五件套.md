# 嵌入式 AI 提示词五件套

五个覆盖嵌入式开发全流程的 AI 协作提示词：**排查故障 → 学习主题 → 读代码 → 评改动 → 写驱动**。共同设计原则：要求 AI 先复述/总结再动手、给最小验证动作、明确区分"已知正确"和"待验证草稿"、不假装已验证。直接复制对应小节，填好输入区即可使用。

## 一、固件故障排查

请按嵌入式调试方式分析问题，不要直接拍脑袋给结论。

### 输入

- 现象：
- 芯片型号：
- 功能模块：
- 复现步骤：
- 日志或错误信息：
- 已排除项：
- 我怀疑的范围：

### 你的任务

1. 先复述问题，确认理解
2. 给出最可能的 3 到 5 条原因链
3. 每条原因链都给一个最小验证动作
4. 标注优先级最高的排查顺序
5. 如果要改代码，只给草稿和风险提示

### 输出格式

- 问题重述
- 排查树
- 先做什么
- 如果验证失败，下一步是什么

## 二、主题学习

请按下面结构回答，不要跳步骤。

### 输入

- 主题：
- 目标：
- 芯片型号：
- 当前基础：
- 希望输出形式：`入门解释 / 结构化笔记 / 实验步骤 / 常见坑总结`

### 你的任务

1. 先用简洁语言解释这个主题是干什么的
2. 说明它在 STM32 工程里的位置
3. 给出必须理解的 5 个关键点
4. 给出一个最小实验方案
5. 给出常见错误和排查思路
6. 如果涉及代码，请优先用 HAL 风格示例

### 输出要求

- 先讲概念，再讲配置，再讲代码，再讲验证
- 避免只给结论，不解释为什么
- 如果有前置知识，请单独列出

## 三、代码解读

请帮我解释一段 STM32 固件代码。

### 输入

- 文件：
- 函数：
- 芯片型号：
- 使用层级：`裸机 / HAL / LL / FreeRTOS`
- 我最困惑的点：
- 希望解释深度：`快速理解 / 逐行说明 / 架构说明`

### 你的任务

1. 先总结这个函数的职责
2. 说明它依赖哪些初始化条件
3. 标出关键数据流和控制流
4. 提醒可能的时序/中断风险
5. 如果有隐藏假设，请明确说出来

### 输出格式

- 功能概览
- 执行流程
- 关键变量/寄存器/回调
- 风险点
- 如果我要修改，应该先看哪里

## 四、改动评审

请帮我评审 STM32 固件改动，重点找风险，不要只夸代码整洁。

### 输入

- 改动目标：
- 影响模块：
- 芯片型号：
- 关键文件：
- 我担心的点：

### 你的任务

1. 先总结改动意图
2. 检查初始化顺序
3. 检查中断、DMA、缓冲区和并发风险
4. 检查是否可能引入阻塞或时序问题
5. 给出建议补测场景

### 输出格式

- 主要风险
- 可能的行为回归
- 建议补测
- 可以保留的设计

## 五、驱动代码草稿

请帮我生成 STM32 固件代码草稿，但不要假装已经验证过。

### 输入

- 功能目标：
- 芯片型号：
- 外设：
- 使用方式：`HAL / LL`
- 运行模式：`轮询 / 中断 / DMA`
- 约束条件：
- 是否允许伪代码：`是 / 否`

### 你的任务

1. 先给出实现思路
2. 列出需要的初始化前提
3. 输出最小可读代码框架
4. 标注哪些部分需要我按具体芯片修改
5. 单独列出"上板前检查项"

### 输出要求

- 明确区分已知正确模式和待验证草稿
- 优先给出小而完整的结构
- 如果不确定某个 API 或时序，明确说明不确定点
