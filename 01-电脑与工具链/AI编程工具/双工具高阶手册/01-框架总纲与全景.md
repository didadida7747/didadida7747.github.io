# 01 · 框架总纲与全景：把两个工具当成一个物种来学

> 阅读前提：已读 §00 导览。本章是理论总纲，回答"这两个工具本质上是什么、为什么长得越来越像、在 2026 年的 AI 编程版图里各站哪一格"。
> 命令级细节全部在 §02-06，本章不展开。

---

## 1.1 统一解剖模型：8 层逐层看

§00 的解剖图是全书脊柱。这里逐层讲"为什么框架必须长这一层"，你已有的 Harness 源码精读正好可以对上。

### ① 交互层
**解决什么**：人和 Agent 的输入带宽问题——怎么快速引用文件、快速执行命令、快速切换模式，而不是每次都打一大段自然语言。
- Claude Code：`@` 文件引用、`!` bash 直执行、`/` 命令面板、双击 Esc 进检查点、Shift+Tab 循环权限模式。设计取向是**前缀键盘流**。
- Codex：`@`/`/mention` 统一搜索面板（文件、目录、插件、技能、甚至其他任务）、`/vim` 模态编辑、`/tui` 全屏、leader key（Ctrl+X）。设计取向是**面板 + 可配置键位**。

### ② 模型与推理层
**解决什么**：任务难度不同，该用不同模型、不同推理深度——这是成本和质量的旋钮。
- Claude Code：`/model`、`/effort`（low→xhigh/max/auto）、`/fast`、`/advisor`（第二模型当顾问）。
- Codex：`/model`（0.164 起支持内联参数）、config 的 `model_reasoning_effort`、`/personality` 控制回答性格。
- **共同认知**：简单任务降 effort 是最容易被忽略的省钱手段。

### ③ 上下文层
**解决什么**：上下文窗口是稀缺资源，怎么"存（会话）、压（compact）、退（checkpoint/undo）、分（branch/fork）"。
- Claude Code：`/compact`、`/context` 可视化诊断、`/rewind`（代码+对话双向回退）、`/branch`、`/fork`、`/recap`。
- Codex：`/compact`（GPT-5.1-Codex-Max 起 native compaction）、`/fork`、`/undo`（只回退文件改动）、`/resume`。
- 这一域是"上下文工程"显学的主战场，详见 §02。

### ④ 记忆与指令层
**解决什么**：每轮对话都要重复的规则（构建命令、代码风格、禁区）不该由人每次重说。
- Claude Code：CLAUDE.md 三级分层（用户/项目/本地）+ `.claude/rules/` 条件加载 + auto memory 自动沉淀。
- Codex：AGENTS.md 从当前目录向上逐级发现、**就近覆盖**（天然适配 monorepo）。
- 两者哲学差异最小的一层，也是**迁移最容易**的一层。

### ⑤ 权限与安全层
**解决什么**：自主权刻度盘——从"每步都问"到"全自动"，以及出错时的硬护栏。
- Claude Code：7 种 permission mode（default/acceptEdits/plan/auto/dontAsk/bypassPermissions/manual）+ OS 级沙箱 + 33 种 hook 事件的硬保证。
- Codex：`approval_policy × sandbox_mode` 档位矩阵 + `/permissions` 档案（profiles）+ 实验性 hooks。
- 详见 §03。**这是两工具哲学差异最大的一层**：CC 偏"细粒度规则+钩子强制"，Codex 偏"档位矩阵+一键切换"。

### ⑥ 扩展层
**解决什么**：把外部世界（GitHub、数据库、浏览器……）和自己沉淀的流程接进 Agent。
- 两者都收敛到了 **skills + plugins + MCP** 三件套。Codex 还能反过来把自己暴露成 MCP server（`codex mcp-server`），被 Claude Code 调用——这是"有机联动"的实锤，详见 §04。
- 自定义命令层面：CC 的 `.claude/commands/*.md` 已与 skills 等价；Codex 的 `~/.codex/prompts` 已官方弃用、主推 skills。**"自定义命令→技能"是两个框架共同的收敛方向。**

### ⑦ 编排层
**解决什么**：一个会话干不了/不该干的活——并行、隔离、异步、云端。
- Claude Code：subagents（独立上下文的子代理）、`/batch`（拆 5-30 个单元并行跑 worktree）、`-w` worktree、Agent Teams（实验）、`/schedule` 云端定时。
- Codex：spawn_agent（上限 6 个子代理）、`codex agents` 多任务仪表盘、`/worktree`、Codex Cloud 并行容器农场。
- 详见 §05。

### ⑧ 验证与自动化层
**解决什么**：Agent 产出怎么闭环验证？人不在场时怎么安全地跑？
- Claude Code：`/code-review`（多级，ultra 为云端多代理深审）、`/verify`（构建-运行-观察）、`claude -p` 无头 + stream-json + Agent SDK。
- Codex：`/review`（detached 独立面板）、`codex exec`（JSONL 事件流、--output-schema）、官方 codex-action。
- 详见 §06。

## 1.2 正在趋同的范式（学共性，记差异）

把两边放一起看，会发现 2025-2026 两年它们在**互相借鉴、快速趋同**：

| 范式 | Claude Code | Codex | 判断 |
|---|---|---|---|
| 技能（Skills） | `.claude/skills/`（v2.0.20 起） | `.agents/skills/`（prompts 弃用） | **完全趋同**：Markdown+frontmatter，文件名即命令 |
| 生命周期钩子 | hooks（33 事件，成熟） | hooks（0.114.0 实验起步） | CC 领先约一年，方向一致 |
| 工作树隔离 | `--worktree/-w`（v2.1.49） | `/worktree`（0.154.0） | 完全趋同：并行任务的标配 |
| 双向迁移 | `/import codex` | `/import`（0.145.0 迁入 CC/Cursor 设置） | 官方都做了"投奔通道" |
| @ 引用 | `@` 文件/会话引用 | `@`/`/mention`（还能 @ 其他任务） | 趋同且 Codex 略进一步 |
| 压缩 | `/compact` + auto-compact + idle compaction | `/compact` + native compaction | 趋同：压缩已是基础设施 |
| 检查点回退 | `/rewind`（代码+对话） | `/undo`（仅文件）+ thread rollback | CC 更进一步（对话可回退） |

**结论**：核心概念（会话、压缩、技能、钩子、工作树、MCP、子代理）在两边都有对应物，只是命令名和配置语法不同。先学概念，再记名字。

## 1.3 设计哲学对比

| 维度 | Claude Code（Anthropic） | Codex（OpenAI） |
|---|---|---|
| 控制粒度 | 细：120 条斜杠命令、参数级权限规则（`Agent(model:opus)`） | 粗：档位矩阵（approval × sandbox）+ profiles 一键切 |
| 强保证 | hooks 体系成熟，"CLAUDE.md 管建议、hooks 管纪律" | hooks 尚实验，靠沙箱+审批档位兜底 |
| 上下文工程 | 显学级：/context 诊断、auto-compact、idle compaction、1M 上下文模型 | native compaction、/goal 长期目标、/side 侧聊不污染主上下文 |
| 多代理 | subagents + Agent Teams（本地优先） | spawn_agent + Cloud 并行农场（云端优先） |
| 生态开放 | plugins/marketplace + Claude Mods（JS 钩子模块） | plugins 市场 + connectors + apps |
| 人格化 | output styles（Learning/Concise/Proactive…） | /personality（friendly 等） |

**一句话总结**：CC 把"可控性"做到极致（适合精细工作流和强约束场景），Codex 把"省心与规模"做到极致（档位一拨就全自动、云端并行开任务）。这不是优劣，是取舍——所以**双修才是最优解**，也是本手册存在的原因。

## 1.4 2026 年 AI 编程工具全景（三梯队）

| 梯队 | 代表 | 定位 | 与本手册的关系 |
|---|---|---|---|
| **终端 Agent** | Claude Code、Codex CLI、Gemini CLI、ZCode/GLM、Qwen Code、OpenCode、Aider | 驻扎在你的终端/IDE 终端里，读写你的真实仓库，可编排可自动化 | **本手册主角**；解剖模型对全部成员适用 |
| **IDE Agent** | Cursor、Windsurf、GitHub Copilot、Trae | 编辑器内嵌，行级补全+会话，上手门槛最低 | 适合快速补全；编排能力弱于终端 Agent |
| **云端 Agent** | Codex Cloud、Claude Code（web/云会话）、Devin、Jules | 在托管容器里并行开任务，产出 PR/补丁 | 终端 Agent 的"外包车间"，§05 专讲衔接 |

选型共识（中文社区高赞帖口径）：**复杂重构、交互式强约束开发 → Claude Code；长任务、成本敏感、云端并行 → Codex**。但 2026 年的真相是：两者能力带高度重叠，切换成本已被 `/import` 打到接近零，按任务选工具而非站队。

## 1.5 六个正在发生的趋势

1. **长任务化（agentic coding）**：Agent 从"答一题"变成"干一天的活"——CC 的 idle compaction、检查点持久化、Monitor 工具，Codex 的 `/goal`、云任务、`codex queue`，都在为小时级任务铺路。
2. **上下文工程成为显学**：窗口不是越大越好，"什么时候压、什么留给子代理、什么写进记忆文件"成了核心技能（§02 主讲）。
3. **MCP = AI 的 USB-C**：一次接入处处可用，两个框架都是 client；Codex 兼做 server。工具生态正在从"各家私有"走向"统一总线"。
4. **技能/钩子范式固化**：把重复流程写成 SKILL.md、把纪律写成 hook，正在成为和"会写 Makefile"一样的基础工程素养。
5. **多代理与并行农场**：本地子代理 + 云端容器并行，"一个人带一个代理团队"的工作方式已经可用（§05）。
6. **端云互通与遥控**：`/teleport`、`/remote-control`、`codex remote-control`、手机接续——会话跟着人走，不是人围着会话转。

## 1.6 冷思考：边界、风险与不变的东西

**什么不会被替代**（对电子信息专业尤其重要）：
- **硬件世界的最后一公里**：示波器波形、焊接、电磁调试、板子上的玄学问题——Agent 只能陪你推理，不能替你插探头；
- **系统级判断**：架构取舍、需求澄清、"这个方案在生产环境会不会炸"的直觉，来自你踩过的坑；
- **领域知识**：通信原理、信号处理的物理直觉决定了你能否看懂 Agent 给出的仿真结果对不对。

**学生专属风险**：
- **能力错觉**：Agent 写的代码你能跑通 ≠ 你会写。手写能力（数据结构、Verilog、C）是面试和竞赛的硬通货，别让它退化——建议"作业先手写，Agent 只做 review"；
- **依赖退化**：离开 Agent 就不会开工的"拐杖化"；对策是 §10 的练习全部要求先自己试；
- **错觉 bug**：模型会一本正经地编造 API（尤其冷门库），交付前必须 §06 的验证闭环；
- **代码外流**：实验室未公开代码、竞赛方案不要随意发给云端 API（→§09.7 保密意识）。

## 1.7 为什么大二开始积累是复利

时间线直觉：大二练工具力（现在）→ 大二暑假电赛（2027-08 正好撞上全国电赛）→ 大三 数模/集创/大创出成果 → 大三暑假实习（2028）→ 大四保研/秋招面试时，"懂 harness 原理、会 context engineering、有开源技能包作品"是同龄人几乎没有的叙事。工具力的特殊性在于：**它放大你其他所有能力**，早一年开始，后面每个环节都在吃利息。详见 §09.5。
