## 0. 开始之前：ZCode 是什么？

一句话：**ZCode 是一个能直接在你电脑上动手干活的 AI 助手**。

- 普通 AI 聊天机器人像"电话咨询的顾问"——只能给你文字，你得自己复制粘贴。
- ZCode 像"坐你旁边、能操作你电脑的队友"——它能**读写你的文件、运行命令、查网页、生成 Word/PPT/Excel**，并且每一步动手前会向你申请许可。

它在你电脑里长这样（概念图）：

```
你（输入框里打字/拖文件/@文件）
   │
   ▼
ZCode（理解你的意图，规划步骤）
   │
   ├── 文件工具：读/写/改代码和文档
   ├── 终端命令：运行 python、pip install、git …
   ├── 联网能力：搜索资料、打开网页
   ├── 文档技能：生成 .docx / .pptx / .xlsx / .pdf
   └── 你自己加的扩展：斜杠命令 / 技能 / MCP / 插件（第 3 章讲）
```

### 本文档全程贯穿的 3 个原则

1. **在专门的项目文件夹里干活**——不要让 AI 在"下载"或"桌面"里乱翻。
2. **动手操作前，ZCode 会请求确认；看清楚再点允许**。
3. **AI 写的代码你要能看懂、能答辩**——它负责提效，你负责理解（第 5 章细说）。

## 1. 入门篇：第一次上手

### 1.1 安装与启动

1. 到 ZCode 官网下载对应系统的安装包（Windows / macOS / Linux 都支持），按提示安装。
2. 首次启动会引导你登录/配置模型，跟着向导走即可。
3. 建议先做一件事：**在磁盘上建一个专门的工作文件夹**，例如：

```
D:\study\
   ├── 数据结构作业\
   ├── 计算机网络实验\
   └── 大作业-图书管理系统\
```

> **为什么？** ZCode 的很多能力（项目级配置、技能、命令）都以"当前工作文件夹"为基准。文件夹干净、任务明确，AI 的表现会好一大截。

### 1.2 认识工作界面

你需要认识的只有 4 样东西：

| 界面元素 | 在哪 | 干什么用 |
|---|---|---|
| **输入框** | 底部 | 打字对话；`@` 引用文件；输入 `/` 呼出命令/技能菜单 |
| **权限确认** | 弹窗 | ZCode 要写文件、运行命令、联网时弹出，**看清楚再允许** |
| **`/` 菜单** | 输入框里敲 `/` | 查看所有可用的命令（Commands 组）和技能（Skills 组），可搜索 |
| **设置页** | Settings | 管理插件（Plugin Management）、技能（Skills）、子代理（Subagents）、MCP 服务器（MCP） |

### 1.3 实操①：让 ZCode 写出你的第一个程序

**目标**：让它建好文件并跑通一个程序，体验"AI 动手 + 你确认"的完整闭环。

1. 打开 ZCode，把工作目录指向你刚建的文件夹（如 `D:\study\数据结构作业`）。
2. 在输入框输入（可以直接抄）：

   > 帮我创建一个 Python 文件 `hanoi.py`，实现汉诺塔递归解法，函数接收圆盘数量 n，打印每一步移动。写完后运行一次，用 n=3 测试。

3. 观察它的动作：它会**先计划 → 请求写文件（弹出确认）→ 请求运行命令（弹出确认）→ 把运行结果贴给你**。
4. 权限弹窗怎么选：
   - 写/改你自己项目里的文件 → 可以允许；
   - 运行的命令看得懂（如 `python hanoi.py`）→ 可以允许；
   - 看不懂的命令、要删文件、要装一大堆东西 → 先问它"这个命令是干嘛的"再决定。

**检验学习成果**：现在让它加一个功能——

> 给 hanoi.py 加一个计数器，统计总移动步数，验证 n=3 时是 7 步。

如果它顺利改完并跑通，入门第一关通过 ✅

### 1.4 实操②：让它读懂你的文件夹和文件

三种把"上下文"喂给它的方法，按常用程度排序：

1. **`@` 引用文件**：输入框里打 `@`，会弹出文件列表，选中即可。例：
   > @实验数据.csv 帮我分析这组数据，算平均值和标准差，画一张图保存为 PNG。
2. **直接说文件夹**：它默认就在当前工作文件夹里干活，可以直接说"看一下这个项目里有哪些文件，帮我写个 README"。
3. **贴报错/贴代码**：报错信息整段复制进对话框，不要只截一半。

### 1.5 实操③：报错三步修复法

以后所有报错都按这个流程，百试百灵：

```
第 1 步：贴报错     → "这段代码运行报错：[粘贴完整报错信息]，帮我定位原因"
第 2 步：让它修     → "修复它，并解释你改了哪里、为什么"
第 3 步：让它验证   → "改完后重新运行，确认输出正确再告诉我"
```

> **小技巧**：在第 2 步加一句"解释你改了哪里"，是防止"AI 改了但你没学到"的关键。**修 bug 的过程本身就是最好的复习。**

### 1.6 新手六个好习惯

1. **一个任务一个文件夹**：课程作业、大作业、实验分开放。
2. **重要项目先备份**：学会 `git init` + 每天提交一次（可以让 ZCode 教你并代办），AI 改坏代码时能一键回退。
3. **让 AI 先说思路再动手**：复杂任务前加一句"先给我方案，我确认后再写代码"。
4. **拒绝含糊提问**：不说"帮我写个系统"，说"用 Python + SQLite 写一个学生成绩管理，功能包括增删改查和按总分排序"。
5. **让它写注释**：期末要答辩的代码，加上"关键逻辑写中文注释"。
6. **每周清理一次**：删掉试错用的临时文件，保持工作区干净。

### 2.2 写课程作业与算法题（模板 A）

> 帮我做这道题：**[粘贴题目]**
> 要求：
> 1. 先用 5 句话讲清思路和所用数据结构，不要直接写代码，等我确认；
> 2. 确认后用 C++ 实现，关键步骤写中文注释；
> 3. 给出 3 组测试用例（含一个边界情况），运行并展示输出；
> 4. 最后总结这题最容易错的 2 个点。

进阶变体——**让 AI 当陪练而不是枪手**（强烈推荐期中期末前用）：

> 不要直接给答案。我写一版二分查找，你来 review：指出逻辑错误、边界问题，并给我 3 个会让我的代码出错的测试输入，但不告诉我正确答案，让我自己改。

### 2.3 实验报告 / PPT / Excel（模板 B/C/D）

ZCode 内置文档技能，能直接产出文件而不仅是文字。

**模板 B · 实验报告（生成 .docx）**

> @实验数据.csv @程序截图.png
> 帮我生成一份《计算机网络实验报告》Word 文档，包含：一、实验目的；二、实验环境；三、实验步骤（引用我截图）；四、结果与分析（对 csv 数据做统计并插入图表）；五、心得体会。语言风格：学生口吻，客观平实。

**模板 C · 课堂展示 PPT（生成 .pptx）**

> 根据这个主题做一份 10 页左右的课程展示 PPT：《[主题]》。结构：封面 → 背景问题 → 核心原理（配示意图）→ 2 个案例 → 总结。每页要点不超过 5 条，讲稿备注写在我要讲的话。

**模板 D · 数据整理 Excel（生成 .xlsx）**

> 把这个文件夹里 3 次实验的输出结果汇总成一张 Excel 表：第一列实验编号，后面各列是指标值，最后加一行平均值，并生成对比图表。

### 2.4 从零搭课程大作业

大作业不要一上来就"帮我写一个图书管理系统"，按下面的节奏来（这是质量差距最大的一步）：

```
第 1 步  立项："我要做 XX 系统，课程要求是 [粘贴要求]。
         给我 3 个技术方案对比（难度/工作量/亮点），推荐一个。"

第 2 步  设计："确定用方案 X。先输出设计文档保存到 docs/design.md：
         功能清单、数据表结构、模块划分。我确认后再动工。"

第 3 步  骨架："按设计文档搭建项目骨架，能跑起来，
         每个模块先写空实现 + TODO 注释。"

第 4 步  分模块实现：一次只做一块，例如：
         "实现用户注册登录模块，包含输入校验和错误提示，写完后演示运行结果。"

第 5 步  收尾："检查全部代码：补注释、处理异常、写 README（含运行方法）、
         列出我答辩时可能被问到的 10 个技术问题及参考回答。"
```

> 每完成一个模块，如果会 git 就提交一次（对 AI 说"提交当前进度"即可）。

## 3. 进阶篇：定制你自己的 ZCode

这一章教你 5 件武器。先建立一个**贯穿全章的核心概念**：

### 3.0 核心概念：两层配置体系

ZCode 的所有自定义资源都有两个放置层级：

| 层级 | 位置（Windows 示例） | 生效范围 | 适合放什么 |
|---|---|---|---|
| **用户级** | `C:\Users\你的用户名\.zcode\...` | 你电脑上所有项目 | 个人习惯、跨课程通用工具 |
| **项目级（工作区）** | `你的项目\.zcode\...` 或 `你的项目\AGENTS.md` | 仅当前项目 | 课程大作业的专属规则、团队共享配置 |

> 项目级文件夹可随代码一起用 git 分享给队友——队友拉下代码就自动获得同一套配置。

还有一个**总配置文件**要记住：`C:\Users\你的用户名\.zcode\cli\config.json`（存放 MCP 服务器、Hooks、插件的开关状态）。改它之前先复制一份备份，**它对 JSON 格式要求严格，多一个逗号都可能整体失效**。

---

### 3.1 AGENTS.md：给 AI 立规矩

AGENTS.md 是"AI 每次启动都会自动读的说明书"。写一次，以后每个会话都生效，不用反复交代偏好。

- **用户级**：`C:\Users\你的用户名\.zcode\AGENTS.md` → 所有项目通用的个人偏好
- **项目级**：`你的项目\AGENTS.md` → 这个项目的专属规则
- 两者都存在时：**先读用户级，再读项目级**，项目级的更具体的规则会覆盖个人大而化之的偏好。

**实操**：最快的方式是用内置命令。在项目里输入 `/init`，ZCode 会分析你的项目并自动生成/更新项目级 `AGENTS.md`。

也可以手写，示例（`D:\study\大作业-图书管理系统\AGENTS.md`）：

```markdown
# 项目规则
- 技术栈：Python 3.12 + Flask + SQLite，不要引入其他框架
- 数据库操作统一走 db.py，禁止在其他文件里写 SQL
- data/ 目录是原始数据，任何情况下不要修改或删除
- 每次改完代码必须运行 pytest，全绿才算完成

# 风格
- 代码注释用中文；函数必须有 docstring
- 提交信息格式：[模块] 一句话说明
```

个人级示例（`C:\Users\你的用户名\.zcode\AGENTS.md`）：

```markdown
# 个人偏好
- 默认用中文交流
- 解释新概念时，先给一个生活化的类比，再给技术定义
- 给我的代码示例默认用 Python
```

### 3.2 自定义斜杠命令：把重复工作做成 `/快捷键`

发现自己在重复输入同样一段话？把它存成命令。**命令就是一个 `.md` 文件，文件名就是命令名**。

**实操**：新建文件 `C:\Users\你的用户名\.zcode\commands\homework.md`（项目级则放在 `你的项目\.zcode\commands\` 下）：

```markdown
---
description: 按标准流程完成一道编程作业题
argument-hint: 题目描述或题目文件路径
---
请按以下流程完成这道编程题：$ARGUMENTS

1. 先用 5 句话讲思路和数据结构，等我确认再写代码
2. 代码带中文注释
3. 给 3 组测试用例（含边界情况）并运行验证
4. 总结 2 个易错点
```

保存后**重启会话**，在输入框输入 `/homework 二叉树的层序遍历` 即可使用。

**规则速记**（违反任意一条，命令会"无声消失"）：

| 规则 | 说明 |
|---|---|
| 文件名 = 命令名 | 只能**小写字母/数字**开头，可用 `a-z 0-9 _ : -`，≤64 字符；**不要中文、空格、大写** |
| 参数占位符 | `$ARGUMENTS` = 整段参数；`$1` `$2` = 第 1、2 个参数 |
| 子文件夹变冒号 | `review/code.md` 的命令是 `/review:code`（**冒号不是斜杠**） |
| 头部字段 | 常用 `description`、`argument-hint`、`allowed-tools: Read, Bash`（连字符、单行书写） |
| 必须有内容 | description 和正文**至少有一个**非空，否则命令被丢弃 |
| 不能嵌 shell | 正文里不能写 `` !`命令` `` 这种动态执行语法 |
| 查看入口 | 输入 `/` 打开菜单 → Commands 组，可搜索 |

### 3.3 自定义技能 Skill：让 AI 学会新本领

技能和命令的区别：**命令要你手动输入 `/` 触发；技能是 AI 自己看情况决定用的**。你只要把"什么时候该用"写清楚，AI 在合适的对话里会自动启用。

**实操**：新建目录和文件 `C:\Users\你的用户名\.zcode\skills\lab-report\SKILL.md`：

```markdown
---
name: lab-report
description: 生成符合本科课程要求的实验报告 Word 文档。当用户要求写实验报告、上机报告、课程报告，或给出实验数据要求整理成报告时使用。
when_to_use: 用户提到"实验报告""上机报告""课程报告"，或粘贴实验数据并希望生成文档时。
---
# 实验报告生成流程

1. 先向用户确认：课程名、实验名称、是否已有数据文件
2. 报告固定结构：实验目的 / 实验环境 / 实验步骤 / 结果与分析 / 心得体会
3. 有数据文件时：先做统计（均值、误差），生成插图再插入文档
4. 输出为 .docx，文件名格式：课程名-实验名-学号.docx
5. 语言要求：学生口吻、客观平实，不使用夸张形容
```

保存后重启会话，去 **Settings → Skills**（或输入 `/` 看 Skills 组）确认它出现。之后你对 AI 说"帮我写实验报告"，它就会自动套用这套流程。

**规则速记**：

| 规则 | 说明 |
|---|---|
| 目录 + SKILL.md | 技能 = 一个文件夹，里面必须有名为 `SKILL.md` 的文件（大小写敏感） |
| 头部字段 | `name`、`description`、`when_to_use` 必须是**顶格单行**的 `key: value`；长文本用 `description: >` 换行续写 |
| description 是命门 | AI 靠它判断"何时用这个技能"；**前 ~250 字符要把触发场景写明白**；超过 1024 字符整个技能被丢弃 |
| 缺 name/description | 技能加载失败（在 Settings → Skills 里不出现） |
| 触发是 AI 自主决定 | 没有关键词匹配机制——所以描述写得越像"使用说明书"，触发越准 |
| 优先级 | 同名技能只加载扫描顺序里的第一个：用户级 > 项目级 > 插件；项目里**越深的文件夹优先** |

### 3.4 MCP：给 ZCode 接上新工具

MCP（Model Context Protocol）是"AI 工具的 USB 接口"：接入一个 MCP 服务器，ZCode 就多出一类新能力（查数据库、操控浏览器、读写远程文档等）。

**实操**：编辑 `C:\Users\你的用户名\.zcode\cli\config.json`，加入 `mcp.servers`（没有这个文件就新建，保留原有内容）：

```json
{
  "mcp": {
    "servers": {
      "course-db": {
        "type": "stdio",
        "command": "npx",
        "args": ["-y", "@benborla29/mcp-server-mysql"],
        "env": {
          "MYSQL_HOST": "127.0.0.1",
          "MYSQL_PORT": "3306"
        }
      },
      "remote-reader": {
        "type": "http",
        "url": "https://example.com/mcp",
        "headers": {
          "Authorization": "Bearer 你的令牌"
        }
      }
    }
  }
}
```

保存 → **重启会话** → 打开 **Settings → MCP** 查看连接状态（connected = 成功）。之后 AI 对话里就会多出 `mcp__服务器名__工具名` 形式的工具，可以直接说"查一下 course-db 里 scores 表的成绩分布"。

**规则速记**：

| 规则 | 说明 |
|---|---|
| 两种类型 | `stdio`（本地程序，必须有 `command`）和 `http`/`sse`（远程服务，必须有 `url`） |
| 字段严格 | **多写一个未知字段，该服务器会被整体丢弃**；`command` 必须是字符串，参数放 `args` 数组 |
| 环境变量字段 | 本地程序用 `env`（不是 `environment`），请求头用 `headers` |
| 不做模板替换 | 配置文件里 `${...}` 不会被展开——**一律写绝对路径** |
| 默认超时 30 秒 | 启动慢的服务器加 `"timeoutMs": 60000` |
| 自动连接 | 用户级和项目级服务器都会在会话启动时**自动连接**——所以只把项目级 MCP 写进你信任的项目 |
| 项目级位置 | `你的项目\.zcode\config.json`，同样写在 `mcp.servers` 下，可随 git 共享 |
| 依赖 | `npx` 启动的服务器需要先安装 Node.js；Windows 上若报 `ENOENT`，把 `command` 写成 `.cmd`/`.exe` 的完整路径 |

### 3.5 Hooks：在关键动作前后加自动检查

Hook = "挂钩"：在 ZCode 的特定动作节点上，自动执行你的一段脚本。例如"每次要运行 Bash 命令前，先检查有没有危险操作"。

支持的事件**只有 7 种**：`SessionStart`（会话开始）、`UserPromptSubmit`（你提交输入）、`PreToolUse`（调用工具前）、`PermissionRequest`（请求权限时）、`PostToolUse`（工具执行后）、`PostToolUseFailure`（工具失败后）、`Stop`（回答结束）。

**实操**：在 `~/.zcode/cli/config.json` 中加入（注意 **`enabled: true` 必须写，配置文件型 Hook 默认是关闭的**）：

```json
{
  "hooks": {
    "enabled": true,
    "events": {
      "PreToolUse": [
        {
          "matcher": "Bash",
          "hooks": [
            {
              "type": "process",
              "command": "python",
              "args": ["D:/study/hooks/check_cmd.py"]
            }
          ]
        }
      ]
    }
  }
}
```

脚本的约定很简单：**退出码 0 = 放行，退出码 2 = 拦截该操作**。一个最简单的拦截脚本示例（`D:/study/hooks/check_cmd.py`）：

```python
import sys, json

data = json.load(sys.stdin)          # 读取 ZCode 传入的上下文
cmd = json.dumps(data, ensure_ascii=False)
if "rm -rf" in cmd or "rd /s /q" in cmd:
    sys.exit(2)                      # 拦截危险删除命令
sys.exit(0)                          # 其余放行
```

**规则速记**：

| 规则 | 说明 |
|---|---|
| 配置型 Hook 必须手动开启 | `"hooks": { "enabled": true, ... }`，否则永远不会运行 |
| matcher 是**区分大小写**的正则 | 匹配工具名：写 `"Bash"` 不写 `"bash"`；`"Edit|Write"` 表示两者；不写 matcher = 匹配全部 |
| 两种脚本类型 | `type: "process"`（command + args，不走 shell，**跨平台最稳，推荐**）；`type: "command"`（走 shell 的命令字符串） |
| 超时单位别搞混 | `command` 型的 `timeout` 单位是**秒**；`process` 型的 `timeoutMs` 是**毫秒** |
| 事件名必须精确 | 只认上面列出的 7 个，写别的直接失效 |
| 可用变量 | `${ZCODE_PROJECT_DIR}`（项目目录）、`${CLAUDE_SESSION_ID}`（会话 ID）；插件专属的 `${ZCODE_PLUGIN_ROOT}` 在普通配置里不可用 |
| Windows 注意 | `command` 型走 shell，Windows 下 POSIX 语法会失败 → 尽量用 `process` 型 |

### 3.6 插件与市场：一键装别人做好的"全家桶"

插件 = 技能 + 命令 + Hook + MCP 的打包套装。全程图形界面操作，不用改文件：

1. 打开 **Settings → Plugin Management**：
   - **Installed 页**：管理已装插件（开关、详情、卸载）；
   - **Discover 页**：浏览官方市场（`zcode-plugins-official`）并安装。
2. 想装第三方市场：点 Discover 页的 **`+`** 按钮，支持 GitHub 仓库 / Git 链接 / 本地文件夹 / 文件。
3. 装好默认即启用；关掉开关即可整体停用（其所有技能、命令、Hook 立即从会话消失）。
4. 需要填配置的插件：打开插件详情 → 展开 **Advanced** 填写（标记为敏感的字段目前无法在界面保存，用环境变量代替）。

**实用提示**：

- 校园网/代理环境下克隆市场失败（报 `RPC failed`、`timed out`）：设置环境变量 `ZCODE_HTTP_PROXY=http://代理地址:端口` 后重试。
- 内置插件只能停用，不能卸载。

## 4. 排错篇：出了问题当字典查

### 4.0 万能排查三步

1. **先看界面状态**：Settings 里对应页面（MCP / Skills / Plugin Management）会显示状态和错误信息；
2. **检查配置文件**：JSON 语法是否合法（推荐用 ZCode 自己检查：让它"验证这个 JSON 文件"）；
3. **重启会话**：改完配置必须重启会话才生效；界面数据可疑时整个重启 ZCode。

### 4.1 MCP 连不上

| 症状 | 原因 | 解决 |
|---|---|---|
| `failed` + `spawn xxx ENOENT` | 命令不在 PATH 或路径不对 | `command` 写绝对路径；Windows 指向 `.cmd`/`.exe` |
| `failed` + `timed out after 30000ms` | 服务器启动慢 | 给该服务器加 `"timeoutMs": 60000` |
| 只有 `Connection closed` 没有细节 | 错误输出没显示 | 在终端手动运行服务器的 `command` + `args` 看报错 |
| 改了文件没反应 | ① 没重启 ② JSON 语法错 ③ 多了未知字段 ④ 同名服务器被用户级覆盖 | 逐项对照 4.0 与 3.4 的规则表 |
| `${...}` 原样出现在报错里 | 配置文件不做模板替换 | 换成写死的绝对路径 |
| 想用 `.agents/mcp.json` 却不生效 | 同层级 `.zcode` 里已有 MCP 配置时会**整体忽略** `.agents/mcp.json`；且它要求顶层 `mcpServers` 键 | 统一用 `.zcode` 文件里的 `mcp.servers` |

### 4.2 技能不出现 / 不触发

| 症状 | 原因 | 解决 |
|---|---|---|
| Settings → Skills 里根本没有 | 目录不对、文件名不是 `SKILL.md`、或放在 `.` 开头的文件夹里 | 移到 `~/.zcode/skills/技能名/SKILL.md` |
| 出现但 AI 从不主动用 | description 太弱/为空 | 把"什么时候用"写进 description 的前 ~250 字符，并补 `when_to_use` |
| 改了没效果 | 同名技能被更高优先级的副本"遮住" | 按优先级（用户级 > 项目级深层 > 项目根 > 插件）找到先加载的那份，删或改名 |
| 整个技能系统没了 | 配置里技能开关被关 | 检查配置文件中 skills 相关的 `enabled` 是否为 `true` |

### 4.3 `/命令` 找不到

| 症状 | 原因 | 解决 |
|---|---|---|
| 文件存在但 `/` 菜单没有 | 文件名不合法（大写/中文/空格/超长） | 改成小写字母数字命名 |
| 输入 `/review/code` 报不存在 | 子目录名变**冒号** | 正确输入是 `/review:code` |
| 运行的是别的命令 | 同名命令被更高优先级的覆盖（用户级 > 项目级 > 插件） | 找到优先级更高的那份，重命名或删除 |
| `$ARGUMENTS` 原样显示或为空 | 占位符写错（如 `${ARGUMENTS}`） | 只能用 `$ARGUMENTS`、`$1`、`$2` |
| 头部某个字段不生效 | 字段名拼写错或写成了多行 | 用连字符且单行：`allowed-tools: Read, Bash` |
| 命令名与内置命令撞车 | 保留名被过滤 | 换个名字 |

### 4.4 Hook 不生效

按顺序检查：① `"hooks": { "enabled": true }` 写了吗（**配置型 Hook 默认关闭**）→ ② 事件名是 7 个之一吗 → ③ matcher 大小写对吗（`"Bash"` ≠ `"bash"`）→ ④ 脚本手动跑一遍：退出码 0=正常、2=拦截、其他=报错 → ⑤ Windows 下把 `command` 型换成 `process` 型。

### 4.5 插件装不上 / 装了没反应

| 症状 | 解决 |
|---|---|
| 市场克隆失败 | 设置 `ZCODE_HTTP_PROXY` 环境变量后重试 |
| 显示已启用但技能/命令没有 | 确认 Settings → Skills 和 `/` 菜单里真的能看到；看不到则检查插件详情里的组件路径警告 |
| 填不了"敏感"配置 | 该类字段目前无法在界面保存，改用环境变量传入 |

### 4.6 让 ZCode 自己修自己（最省心的一招）

ZCode 内置了 5 个排错技能（`diagnosing-mcp` / `diagnosing-skills` / `diagnosing-commands` / `diagnosing-hooks` / `diagnosing-plugins`），会按"症状 → 原因 → 检查 → 修复"的官方流程定位问题。**直接复制下面的话术**：

> 我自定义的 MCP 服务器连不上，请使用 diagnosing-mcp 技能帮我按官方流程排查，定位到具体配置文件的字段并修复。

> 我新写的技能在 / 菜单里看不到，请使用 diagnosing-skills 技能帮我排查。

> 我的自定义 /命令 没有出现在菜单里，请使用 diagnosing-commands 技能帮我排查。

> 我的 Hook 完全不触发，请使用 diagnosing-hooks 技能帮我排查。

> 插件装不上/装了没反应，请使用 diagnosing-plugins 技能帮我排查。

## 5. 安全与学术诚信

### 5.1 权限确认：看清楚再点

- 写文件、跑命令、联网前 ZCode 都会请求许可。**允许前花 2 秒读懂它要干什么**，这是你对自己电脑的最后一道防线。
- 涉及删除、批量修改、`git push` 的操作，多问一句"具体会改动哪些文件"。

### 5.2 密钥与隐私

- API Key、密码、数据库口令**永远不写进会被 git 提交的文件**；用环境变量传入。
- 项目级配置（`.zcode/config.json`、`AGENTS.md`）会随仓库共享，**别把私密信息写进去**。

### 5.3 只打开你信任的项目

因为项目级 MCP 服务器、Hook 会**随打开项目自动加载运行**，打开来路不明的项目文件夹前要三思——就像不随便插陌生人的 U 盘。

### 5.4 学术诚信边界（务必读）

| 可以 ✅ | 要谨慎/不可以 ❌ |
|---|---|
| 用它理解概念、讲解思路 | 直接提交它生成的代码而不理解一行 |
| 让它帮你 debug 你自己写的代码 | 让它整场替考/代写需独立完成的作业 |
| 允许的工具类作业（先看课程政策） | 在论文里使用 AI 生成内容而不声明（按学校规定） |

原则一句话：**你可以把 ZCode 当助教、陪练、代码审查员，但不能当枪手**。它写的每一段进作业的代码，你都要能在答辩时讲清楚。

## 附录 B：优先级速查（谁覆盖谁）

- **技能**：用户级 > 项目级（越深的文件夹越优先）> 插件；同名只加载第一个

- **MCP**：命令行参数 > 环境变量 > **用户级 > 项目级** > 内置默认
- **AGENTS.md**：用户级先加载，项目级后加载（后者可细化前者）
