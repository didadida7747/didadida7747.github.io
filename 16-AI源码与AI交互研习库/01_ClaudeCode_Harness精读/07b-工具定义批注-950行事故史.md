# 07b · 工具定义批注：那 950 行是一份"事故史"

> 素材：缓存的 CC 2.0 泄露文件第 193–1150 行（`# Tools` 部分，本地 `07_源码仓库/_提示词原文缓存/claude-code-2.0.txt`，已核对 15 个工具及其行号）。

## 1. Bash（195 行起）：一个工具里塞进了一本《Git 安全手册》

原文（节选）：

```text
IMPORTANT: This tool is for terminal operations like git, npm, docker, etc.
DO NOT use it for file operations (reading, writing, editing, searching...)...
  - If the output exceeds 30000 characters, output will be truncated...
  - Avoid using Bash with the find, grep, cat, head, tail, sed, awk, or echo commands...
```

然后是整整一节 "Committing changes with git"：

```text
Git Safety Protocol:
- NEVER update the git config
- NEVER run destructive/irreversible git commands (like push --force, hard reset, etc)
- NEVER skip hooks (--no-verify, --no-gpg-sign, etc) unless the user explicitly requests them
- NEVER run force push to main/master, warn the user if they request it
- NEVER commit changes unless the user explicitly asks you to. It is VERY IMPORTANT...
```

【批注，四层】
1. **"30000 字符截断"写进了工具描述而不是藏进实现**——让模型知道自己看到的是被裁剪的世界，它会主动换策略（翻页/重定向到文件）。诚实标注信息边界，比假装完整更聪明。
2. **一串 NEVER 全是被动语态事故的碑文**：`--no-verify` 跳过钩子、force push main、擅自 commit……每一条都对应一类真实翻车。特别是最后一条重复强调"必须明确被要求才 commit"——它太重要，以至于在系统提示词正文里也出现了一次（07篇讲过"红线说两遍"）。
3. **"NEVER update the git config" 单独成条**很耐人寻味：改 config 影响的是**未来所有会话**（持久性副作用），这是 Agent 的“越权时间轴”——动作本身无害，影响却超出本次任务。你设计工具权限时也该问：这个操作的影响会活多久？
4. **好/坏示例用 `<good-example>` 标签内嵌**（`pytest /foo/bar/tests` vs `cd /foo/bar && pytest tests`）——为什么反对 cd？因为模型对"当前目录"的状态记忆不可靠，绝对路径让每个命令自包含、可独立重放。

## 2. Edit（391 行起）：一行一个防线

原文（节选）：

```text
- You must use your Read tool at least once in the conversation before editing.
  This tool will error if you attempt an edit without reading the file.
- The edit will FAIL if old_string is not unique in the file. Either provide a larger
  string with more surrounding context... or use replace_all...
- ALWAYS prefer editing existing files in the codebase. NEVER write new files unless explicitly required.
```

【批注】
1. 注意措辞的分工：**"will error" 是 harness 的硬实现**（不依赖模型自觉），"must" 是给模型的预告。同一条规则在两层各说一遍——提示词管预期，实现管结果。这就是 01章03篇"软引导+硬护栏"的实物。
2. "old_string 不唯一就失败"的描述里直接给了两条出路（加上下文 / replace_all）——**报错的描述里内置"怎么办"**，模型读到失败信息后能立即自纠，不需要再猜。
3. "NEVER write new files unless explicitly required" 这条系统提示词里也有（`NEVER create files unless absolutely necessary`）——双写。为什么怕建新文件？因为模型有"用新建文件解决问题"的倾向（另起炉灶而不是修旧的），几轮下来目录里全是 `fix.py`、`fix2.py`、`utils_v2.py`。**这是代码库被 AI 污染的头号途径**。
4. 连"别往文件里加 emoji"都写了——没错，这也发生过。

## 3. TodoWrite（804 行起）：把"何时不该用"写成清单

原文（节选）：

```text
#### When to Use This Tool
1. Complex multi-step tasks - When a task requires 3 or more distinct steps...
#### When NOT to Use This Tool
Skip using this tool when:
1. There is only a single, straightforward task
...
NOTE that you should not use this tool if there is only one trivial task to do.
```

【批注】
1. "3 步以上"这种**可数阈值**再次出现（对比 07篇"Tone 4 行以内"）——Anthropic 显然发现模型需要明确边界，否则 TodoWrite 会被滥用成"给加个分号也列个 todo"。
2. 用正反两个清单（When to Use / When NOT to Use）夹击，比单纯说"适度使用"有效得多。**正反例夹逼**是写工具描述的万能公式。
3. 深层设计：TodoWrite 的真正用户其实有两个——模型自己（工作记忆锚点）和人类（进度可见性）。工具描述里"helps the user understand the progress"这句明说了后者。

## 4. Read（640 行起）与 Task（714 行起）：信息形态的两种设计

**Read 的要点**：支持图片和 PDF（多模态直接喂给模型）、`offset/limit` 分页、按行号拼接输出——07b 批注过的"行号即坐标"不重复了。值得补的是：**Read 明确说了 cat/head/tail/sed/awk 都被替代**，这条"工具替代矩阵"（哪些 bash 命令归谁管）在 Bash 描述里也有一份——同一个规则在两个工具的描述里各写一遍，因为模型在用任何一个工具时只会看到那一个的描述。**规则要写在它被需要的地方，而不是写在最合理的地方。**

**Task 的要点**：描述里花大量篇幅教模型"什么时候该派子代理"（探索型任务、代码搜索、多步研究）以及"必须写自包含的任务书"（子代理看不到对话历史，05篇讲过）。最值得学的是这句逻辑：**主 Agent 的上下文是资产，任何能在别处完成的信息处理都不该发生在主线上**。

## 5. 提炼：工具描述的写作公式（从 950 行里蒸馏）

1. **一条职责一句话**，然后立刻写"不做什么"（Bash：terminal operations, NOT file operations）
2. **NEVER 清单来自事故**：每写一条禁令，能说出对应的事故场景才保留，说不出就删掉（别凭空发明规则）
3. **失败信息自带出路**：报错文案里写"两种修复方法"，不写"你做错了"
4. **正反例夹逼**：When to Use + When NOT to Use，各配 3 步以上的具体判据
5. **规则写在被需要的地方**：跨工具的约定（如并行调用）在相关工具里各写一份
6. **好/坏示例用标签内嵌**：`<good-example>` 对比 `<bad-example>`，一屏胜千言
7. **持久性副作用单独立 NEVER**（git config 这种"影响活过本次会话"的操作）

## 思考题

1. Bash 描述说"输出超 30000 字符截断"，Edit 的工具描述却没提失败时返回什么——如果让你给 Edit 补一段"失败时你会看到什么"，你会怎么写？
2. TodoWrite 的"3 步阈值"是写给哪个版本的模型的？模型再进化一版，这个阈值会变大还是变小？（对照 07篇 v1→v2 的"拆脚手架"规律）
3. 去 06 章实验室的 `TOOLS` 字典里，用上面 7 条公式给自己的工具描述做一次体检——哪几条描述"说不出对应事故"却写了禁令？
