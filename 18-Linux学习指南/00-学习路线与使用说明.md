# 00 · 学习路线与使用说明

> 这是整套指南的"地图"。先花 10 分钟读完这一页，再开始第 1 章。

## 一、这份指南为谁准备

这份指南写给**这样的你**：

- 用过 Windows，偶尔见过别人敲黑色终端里的命令，自己也糊里糊涂敲过 `ls`、`cd`，但没有系统学过 Linux；
- 用的是 **Windows 11** 电脑，不打算装双系统、也没有云服务器（可以以后再买）；
- 学 Linux 的目标很实际：**以后做后端开发、服务器运维，能在实习和竞赛里把项目真正跑起来、部署上线**；
- 时间可以持续投入，希望有一条从零到能实战的完整路线，而不是一堆零散的命令。

本指南**不讲**嵌入式 Linux、开发板、驱动开发、内核裁剪和交叉编译——那些是另一条路，等你把本指南学完、确认自己有兴趣再碰也不迟。

## 二、你会得到什么

学完本指南，你将能够：

1. 在 Windows 11 上用 WSL2 拥有一个随时可用的 Ubuntu Linux 环境，并且配得舒舒服服（换源、终端、VS Code、代理都不踩坑）；
2. 熟练使用几十个高频命令，在纯命令行下完成文件、权限、进程、软件、网络的日常管理；
3. 写出能实际用的 Bash 脚本，让重复工作自动化，并能用定时任务自动执行；
4. 从零搭好 Git + Python + Node + 编译工具链的开发环境，和专业开发流程接轨；
5. 用 systemd、Nginx、Docker 把一个 Web 应用部署起来并通过浏览器访问；
6. 遇到报错不慌，按一套方法论自己定位问题——这是新手和熟手最大的差距。

## 四、12 周三阶段路线总览

时间按每天 1.5～2 小时、每周 6 天估算。**这只是参考节奏，慢一点完全没关系**，关键是每章的练习亲手做、每关亲手过。

### 阶段一 · 入门（第 1–4 周）：和终端成为朋友

| 周 | 学什么 | 章节 |
|---|---|---|
| 第 1 周 | 搞懂 Linux 是什么；**亲手把 WSL2 + Ubuntu 装好配好** | 01、02 |
| 第 2 周 | 理解 Linux 怎么组织文件；熟练操作文件和目录 | 03、04 |
| 第 3 周 | 查看/编辑文件、管道重定向、文本搜索、入门编辑器 | 05 |
| 第 4 周 | 复习前三章 + 读 MIT 缺失的一课文字讲义 + 开始打 OverTheWire Bandit | 复盘 |

**阶段验收**：不看任何资料，在终端里独立完成"建一棵项目目录树 → 新建文件 → 按条件查找 → 打包压缩 → 移动到备份目录"的完整流程。

### 阶段二 · 进阶（第 5–8 周）：成为能独立管理系统的用户

| 周 | 学什么 | 章节 |
|---|---|---|
| 第 5 周 | 用户、组、文件权限，彻底搞懂 `chmod 755` | 06 |
| 第 6 周 | 看懂进程、管理任务、前后台；用 apt 管理软件 | 07、08 |
| 第 7 周 | 磁盘与挂载；网络命令、SSH 远程登录（配通 GitHub 免密） | 09、10 |
| 第 8 周 | Bash 脚本编程 + 定时任务；Bandit 通关 | 11 |

**阶段验收**：能独立写出带参数、判断、循环的脚本并用 crontab 定时执行；能配置 SSH 密钥免密登录远程主机，用 `rsync` 同步文件。

### 阶段三 · 实战（第 9–12 周）：开发环境与部署

| 周 | 学什么 | 章节 |
|---|---|---|
| 第 9 周 | 环境变量/PATH；搭好 Git、Python、Node、编译工具链 | 12 |
| 第 10 周 | systemd 服务管理、看日志、Nginx 静态站与反向代理 | 13（前半） |
| 第 11 周 | Docker 容器与 docker compose | 13（后半） |
| 第 12 周 | Vim/tmux 提效；系统排错；**综合项目部署** | 14、15 |

**阶段验收**：用一条 `docker compose up -d` 把一个 Web 应用（含数据库/反代）跑起来并通过浏览器访问；遇到常见故障能按排查手册自己定位。

## 六、怎么学效果最好（请认真对待这一节）

1. **命令必须亲手敲，不能只看。** 看懂和会敲是两回事。每章示例都在你的 WSL 里敲一遍，改改参数看输出有什么变化。
2. **每章练习必须做完再往下走。** 练习是这份指南的"作业"，跳过练习 = 白学。
3. **报错是最好的老师。** 命令跑不通时，先读报错（第 1 章教你怎么读），自己查 2 分钟再翻第 15 章；把踩过的坑记在自己的笔记里。
4. **主线是"读文档"，视频只在卡住时选看。** 如果你也觉得看视频太慢，就按这条纯文档路径走，节奏完全自己掌握：
   - **第一步 读正文**：读当章讲义、在终端敲完所有示例和练习；
   - **第二步 查文档**：概念没吃透、想了解更多，就翻该章"配套资料"里排在前面的文档类资料——官方文档、`man` 手册、MIT 缺失的一课、TLCL、鸟哥、菜鸟、GitHub 高星文字教程；
   - **第三步 动手练**：到 OverTheWire Bandit、Linux Journey、Killercoda 等练习站把命令练成肌肉记忆；
   - **第四步 才看视频（可选）**：只有某一章反复读文档都看不懂、想快速看一眼某个操作的实际演示时，再去"配套资料"末尾的"卡住时再看（可选视频）"或[资料推荐合集](/18-Linux学习指南/资料推荐合集)的"补充 · 卡点时选看"区挑对应那一条，看完立刻回到文档主线，**不必从头刷整套视频课**。
   - 别把"收藏了 20 个视频"当成学过了——文档读通、命令敲熟才算数。
5. **费曼学习法。** 学完一章，试着用大白话给同学（或对着空气）讲一遍"这章解决了什么问题、最常用的 5 个命令是什么"。讲不清楚的地方就是没掌握的地方。
6. **善用三个老师**：`man` 和 `--help`（本地手册）、搜索引擎（把英文报错原文丢进去）、AI（描述清环境和现象，让它解释报错）。
7. **节奏建议**：新命令在当天集中练，第二天先用 10 分钟默写前一天的命令再学新的；每周日做一次本周复盘。

## 七、学完之后往哪走

完成 12 周路线后，你已经具备了后端实习的 Linux 基本功。之后可以按兴趣选择方向：

- **后端开发**：深入一门语言的 Web 框架 → 数据库 → Redis → 消息队列，把项目用 Docker 部署到云服务器；
- **运维 / DevOps / 云原生**：Docker 深化 → 容器编排 Kubernetes（K8s）→ CI/CD（GitHub Actions / Jenkins）→ 云平台与监控（Prometheus、Grafana）；
- **考证（可选，不强求）**：红帽 RHCSA、Linux 基金会 LFCS 对找运维岗有一定帮助；
- **经典书籍进阶**：《鸟哥的 Linux 私房菜·服务器架设篇》、《UNIX/Linux 系统管理技术手册》。
