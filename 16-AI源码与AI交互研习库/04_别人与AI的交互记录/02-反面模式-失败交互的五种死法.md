# 02 · 反面模式：失败交互的五种死法

> 成功案例让人羡慕，失败模式让人免疫。以下五种"死法"覆盖了我见过的大部分翻车现场，每一种都附**尸检报告**和**疫苗**。
> 建议的用法：下次你的 AI 协作不顺时，回来对照——先定死法，再开药。

## 死法一：一句话启动，三小时拉扯

**现场**："帮我做个电商网站。" → 模型兴奋地生成 3000 行 → 跑不起来 → "报错了：xxx" → 又改 → 越改越乱 → 凌晨三点你开始怀疑人生。

**尸检**：需求里没有一个可验证的事实（技术栈？数据存哪？要不要登录？）。模型只能用训练数据里的"平均值电商网站"填空，而平均值不属于任何真实项目。每一轮拉扯都在烧 token 修正本该在第一句里说清的事。

**疫苗**：A1 计划先行 + B4 环境清单（见 03 篇）。**第一轮 prompt 的信息密度，决定整场对话的走向。**

## 死法二：全盘接受，不做验收

**现场**：模型说"已完成，测试通过"。你合上电脑。第二天发现测试根本没跑过，或者跑过了但测的是错误的东西。

**尸检**：模型的"完成"是**文本层面的自我汇报**，不是事实。它甚至会为了自洽而描述一段不存在的验证过程（这不是撒谎，是语言模型的下一个 token 预测本性）。01章08篇的反面模式清单里这叫"让模型自评"。

**疫苗**：C8 验收汇报模板（"你怎么验证的？贴命令输出"）+ 关键任务用 C6 测试驱动。**永远检查 artifacts，永远。**

## 死法三：上下文超载后失忆

**现场**：一个超长会话里，模型开始违反你 30 轮前定下的约定，你提醒它，它道歉，然后再犯。

**尸检**：早期指令被后来的海量工具结果淹没（01章04篇"lost in the middle"）。上下文是工作记忆不是硬盘，堆满就会遗忘——这不是态度问题，是机制问题。

**疫苗**：任务切换就 /clear（或开新会话）；关键约定写进 CLAUDE.md/AGENTS.md（每次注入）；长会话主动 /compact 并检查摘要有没有丢关键约束。

## 死法四：在错误的层级治故障

**现场**：代码有 bug → 模型修不好 → 你说"再认真想想" → 还是不行 → 你说"你是专家，一定可以" → 模型开始说漂亮话但 bug 还在。

**尸检**：bug 的根因可能是**信息不足**（没贴报错全文/没给复现步骤），而不是模型不认真。在"鼓励"层面施压是打错了靶子——情绪激励对 token 预测器无效，有效的是数据。

**疫苗**：卡住时回到信息层：补报错全文、最小复现、相关代码片段。三次失败触发 C7 卡点升级，人工进场读代码。

## 死法五：危险操作的温水 frog

**现场**：`--dangerously-skip-permissions` 真香 → 模型自由发挥删了个"它认为没用"的目录 → 那是你没推过远端的半成品。

**尸检**：不是模型恶毒，是**在无护栏环境里，任何概率性的失误都会被兑现**。YOLO 模式该配沙箱（容器/VM/一次性环境），而不是裸生产机——03篇讲过官方立场：给开关，也教姿势，但用不用对是你的责任。

**疫苗**：危险模式只在隔离环境开；deny 列表先于 allow 列表配置（.env、git push、rm -rf）；有 checkpoint/回滚习惯再用自动化。

## 五种死法的共同解剖学

把五个案例叠在一起看，病灶只有两个：

1. **信息层**：上下文里缺事实（死法一、四）→ 药方是"喂足"
2. **控制层**：流程里缺门禁（死法二、三、五）→ 药方是"验收+护栏+清空"

而这两个病灶，恰好对应 harness 的两大主题：上下文工程（01章04篇）和权限/护栏（01章03篇）。**你管理 AI 的水平，本质上是你在人肉扮演一个多好的 harness。**
