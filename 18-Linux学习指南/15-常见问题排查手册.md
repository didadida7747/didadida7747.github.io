# 第 15 章 常见问题排查手册

> 学完前 14 章你已经能独立在 Linux 上干活了，但真实世界不会顺——"为什么命令找不到？""为什么磁盘满了？""为什么网站打不开？"这一章就是你的急救包：按现象查、按命令定位、按套路解决。

## 本章你将学会

- 建立一套通用排错思路（不是瞎试，是有方法的）
- 快速定位 8 大类常见故障：命令找不到、权限不对、磁盘满、端口被占、CPU/内存爆、网络不通、apt 出错、WSL 特有问题
- 知道各类日志都在哪
- 学会高效提问（怎么向 AI/Stack Overflow 描述问题）
- 拿到一张 50 条高频命令速查表

## 15.1 排错方法论：先冷静，按套路来

新手排错最常见的反应是：**报错一出来就慌了，开始瞎改，越改越坏。** 正确的步骤是固定的五步：

1. **完整读报错原文。** 报错信息里 80% 已经告诉你哪错了、哪个文件、哪一行。别只看最后一行，往上翻几行。
2. **看日志。** 命令行报错只是冰山一角，详细信息在日志里（`journalctl`、`/var/log/`、程序自己的日志）。
3. **最小复现。** 用最短的命令复现这个问题（比如 "我一进这个目录 ls 就报错"），把环境变量、复杂操作都排除掉。
4. **二分定位。** 把范围砍半：是代码问题？还是环境问题？把最近改过的文件临时还原，看问题在不在。
5. **记录。** 修好之后把这个坑记下来（你以后还会遇到）。

> 💡 **小技巧：** 报错里出现 `No such file or directory`、`Permission denied`、`Address already in use`、`command not found` 这几个关键词，直接跳到下面对应的小节。

## 15.2 故障一：`command not found`（命令找不到）

**现象：** 你输了个命令，bash 回你 `xxx: command not found`。

**三种原因，挨个排查：**

| 原因 | 怎么判断 | 解决 |
|---|---|---|
| ① 命令真没装 | `which xxx` 空，`apt search xxx` 能找到 | `sudo apt install xxx` |
| ② 命令装了但**不在 PATH** | `whereis xxx` 能找到路径 | 用绝对路径跑，或把它的目录 `export PATH=` 加进去（12 章） |
| ③ 拼写错了 / 漏了别名 | 少个字母、大小写错 | 用 `Tab` 补全，别手打 |

典型例子：

```bash
$ python --version
Command 'python' not found, did you mean: ...
# Ubuntu 只有 python3，没有 python。解决：
$ python3 --version
Python 3.12.x
# 或者建个别名：echo "alias python=python3" >> ~/.bashrc

$ ifconfig
Command 'ifconfig' not found
# ifconfig 是老命令，新系统推荐用 ip addr。要装：
$ sudo apt install net-tools
```

## 15.3 故障二：`Permission denied`（权限不够）

**现象：** `bash: ./xxx.sh: Permission denied`、`cat: /etc/shadow: Permission denied`、`mv: cannot move ... Permission denied`。

**三种常见情况：**

| 现象 | 原因 | 解决 |
|---|---|---|
| 跑脚本报这个 | 脚本没有执行权限 | `chmod +x 脚本.sh`（第 6 章） |
| 读/改某文件报这个 | 你不是文件主人，也没权限 | `sudo` 读（读一次加 sudo），或 `sudo chown 你的用户 文件`（文件本来就该你管） |
| 往某目录写东西报这个 | 目录权限不够 | `sudo chmod` 或 `chown` 整个目录 |

> ⚠️ **警告：** 新手第一反应是 `sudo chmod -R 777 /` 把所有东西全开放——**千万不要**。777 是把文件对任何人都可写，安全黑洞。正确做法是：搞清楚这个文件的主人应该是谁，用 `chown` 改属主，而不是开放权限。

## 15.4 故障三：磁盘满了

**现象：** `No space left on device`、写文件失败、apt 装不动。

**第一步：看哪个分区满了**

```bash
$ df -h
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda5        60G   55G  2.2G  97% /
tmpfs           3.9G     0  3.9G   0% /tmp
```

看 `Use%` 那列，超过 90% 就是它。

**第二步：找出哪个目录吃空间**

```bash
# 看当前目录下每个子目录多大（-h 人性化，-s 汇总）
$ du -sh /* 2>/dev/null
# 或者聚焦到某个可疑目录
$ du -sh /var/* 2>/dev/null | sort -rh | head
```

> 📌 **注意：** `2>/dev/null` 是把"权限不够"的报错扔掉，不然满屏 Permission denied 看花眼。

**WSL 特有：`/` 满了但 du 看不出啥**

WSL2 的磁盘是个虚拟文件 `ext4.vhdx`，你在 Linux 里删文件，**Windows 那边的 vhdx 文件不会自动缩小**（只会不增大）。跑了半年发现 C 盘被它吃了 100G，用第 9 章讲的方法：在 PowerShell 里 `wsl --shutdown`，然后 `diskpart` 压缩 vhdx。

**inode 满（少见但阴险）：**

```bash
$ df -i
# 如果某个分区的 Inodes IUse% 是 100%，说明你不是"空间满"，是"小文件数量爆了"
# 常见场景：/var/log 里几百万个小日志、npm 缓存里几十万个包
# 找哪个目录小文件最多：
$ find /path -xdev -printf '%h\n' | sort | uniq -c | sort -rn | head
```

**清理建议：**

```bash
$ sudo apt clean                    # 清 apt 缓存
$ sudo journalctl --vacuum-size=200M  # 把 systemd 日志压到 200M
$ npm cache clean --force           # 清 npm 缓存
```

## 15.5 故障四：端口被占

**现象：** 你启动 Flask，报错 `OSError: [Errno 98] Address already in use`。

**第一步：看谁占了这个端口**

```bash
# 现代命令（推荐）
$ ss -lntp | grep 5000
LISTEN 0  511  127.0.0.1:5000  0.0.0.0:*  users:(("python",pid=12345,fd=3))

# 老命令（也行）
$ sudo lsof -i:5000
```

输出里的 `pid=12345` 就是占用进程。

**第二步：干掉它**

```bash
$ kill 12345            # 温柔地让它退出
# 不听话再上：
$ kill -9 12345         # 强制杀
```

> ⚠️ **警告：** `kill -9` 是直接拔电源，不给程序收拾的机会（比如写一半的数据库文件会坏）。先 `kill`，不行再 `-9`。

**如果你想换个端口（更安全）：** 改你的 Flask 代码 `app.run(port=5001)`，或者 Nginx 配置里 `proxy_pass` 改成 5001。

## 15.6 故障五：CPU / 内存爆了

**现象：** 机器卡、负载高、程序被莫名其妙杀掉。

**第一步：看谁在吃资源**

```bash
$ top
# 或者装更好用的 htop
$ sudo apt install -y htop
$ htop
```

htop 界面从上到下：CPU 占用、内存占用、进程列表（按 CPU 或内存排序）。按 `F6` 选排序字段，`q` 退出。

**OOM（内存不够被内核杀）：**

程序突然没了，日志里没报错？那是被 **OOM Killer**（内存不足时内核自动杀进程）干掉的。查：

```bash
$ dmesg | grep -i "killed process"
[12345] Out of memory: Killed process 6789 (python)
```

意思是你内存不够，内核把 Python 杀了。解决：加 swap（第 9 章）、或者优化你的程序别吃那么多内存。

## 15.7 故障六：网络不通

**现象：** `ping` 不通、`curl` 拿不到东西、`git clone` 卡住。

**按链路从下往上查：**

### 第 1 步：能 ping 通 IP 吗？

```bash
$ ping -c 4 8.8.8.8
# 有返回 = 网络通；不通 = 你机器网络就有问题（WSL 配置、路由器、代理）
```

### 第 2 步：能解析域名吗？

```bash
$ ping -c 4 github.com
# 报 "Temporary failure in name resolution" = DNS 解析挂了
$ dig github.com           # 看 DNS 详细
$ nslookup github.com
```

DNS 挂了怎么修？看你用的 DNS 服务器：

```bash
$ cat /etc/resolv.conf
nameserver 8.8.8.8
```

WSL 经常 DNS 抽风，可以手动指定一个：

```bash
$ echo "nameserver 223.5.5.5" | sudo tee /etc/resolv.conf    # 阿里 DNS
```

但这个文件重启会被 WSL 覆盖。要永久生效得改 `/etc/wsl.conf`（第 2 章）。

**WSL 时间不同步（TLS 握手失败的隐藏原因）：**

有时候你 `curl https://github.com` 报 `SSL certificate problem`，不是网络问题——是 **WSL 内部时间比真实时间慢了几个小时**，TLS 证书有效期一过就报错。修复：

```bash
$ sudo hwclock -s          # 从 Windows 硬件时钟同步过来
$ date                     # 验证一下时间对不对
```

如果 WSL 频繁时间漂移，关掉 Windows 那边的快速启动（Fast Startup），或者在 `/etc/wsl.conf` 里开启时钟同步配置（第 2 章讲过）。

### 第 3 步：能 curl 通吗？

```bash
$ curl -v https://github.com
# -v 是 verbose，把每一步（DNS 解析、TCP 连接、TLS 握手、HTTP 请求响应）全打出来
```

卡在哪一步，问题就在哪：

- DNS 那步卡 → 域名解析问题（第 2 步）
- TCP 连接超时 → 网络/防火墙问题
- TLS 握手失败 → 时间不对（WSL 时间不同步）
- 403/404 → 服务本身的问题，不是你网络

### 代理问题（校园网/公司网）

```bash
$ echo $http_proxy
$ echo $https_proxy
# 如果你需要代理才能上网，但这些变量没设，git/curl 就会卡住
# 临时设：
$ export https_proxy=http://127.0.0.1:7890    # 你代理软件的端口
```

## 15.8 故障七：apt 出错

### 锁：`Could not get lock /var/lib/dpkg/lock`

**现象：** `E: Could not get lock /var/lib/dpkg/lock-frontend`。

**原因：** 另一个 apt 进程在跑（可能是系统自动更新在后台）。

**解决：**

```bash
# 先等等，看是不是有自动更新在跑
$ ps aux | grep apt
# 真有就等它完。万一是卡死的（不推荐强杀，但新手常遇到）：
$ sudo rm /var/lib/dpkg/lock-frontend /var/lib/dpkg/lock /var/cache/apt/archives/lock
$ sudo dpkg --configure -a
```

> ⚠️ **警告：** 手动删锁文件是下策，正常情况等就行。删错了 apt 数据库就坏了。

### 依赖损坏：`dpkg was interrupted`

```bash
$ sudo dpkg --configure -a       # 修复中断的包
$ sudo apt install -f            # 修复依赖（-f = fix broken）
```

### 源 404 / 拿不到包

```bash
$ sudo apt update
# 看报错：某个仓库 404 Not Found
# 原因：你加的第三方源已经不支持你这个 Ubuntu 版本了
# 解决：去 /etc/apt/sources.list.d/ 把那个 .list 文件删掉（或注释掉）
```

## 15.9 故障八：WSL 特有问题

| 现象 | 原因 | 解决 |
|---|---|---|
| `wsl --install` 报 `0x800701bc` | 没装 WSL2 内核 | `wsl --update`，或者去微软官网下内核更新包 |
| systemctl 报 `System has not been booted with systemd` | WSL 没开 systemd | 在 `/etc/wsl.conf` 里加 `[boot] systemd=true`，然后 `wsl --shutdown` 重开 |
| `/mnt/c/...` 下文件权限全是 777 | Windows 文件系统权限模型不同 | 正常现象，**别把代码放 /mnt/c**，放 Linux 家目录 |
| 代理在 Windows 设了但 WSL 不生效 | WSL 没走 Windows 代理 | 在 WSL 里 `export https_proxy=http://Windows主机IP:端口` |
| WSL 时间比 Windows 慢 1 小时 | WSL2 时钟漂移 | `sudo hwclock -s`（同步硬件时钟）；或开 `wsl.conf` 里的时钟同步 |
| WSL 启动失败 | 上次强制关机搞坏了 | PowerShell `wsl --shutdown` 再 `wsl` |
| Windows 改了 `~/.bashrc` 但 WSL 读不到 | 你改错地方了 | 必须在 WSL 内部改 `\\wsl.localhost\...` 那个路径下的文件，不是 Windows 那边的文件 |

## 15.10 日志位置速查表

出事先想"日志在哪"：

| 你要看什么 | 路径/命令 |
|---|---|
| 系统通用日志 | `/var/log/syslog` |
| 登录、sudo 记录 | `/var/log/auth.log` |
| apt 装包 | `/var/log/dpkg.log` |
| systemd 服务日志 | `journalctl -u 服务名` |
| Nginx 访问/错误 | `/var/log/nginx/access.log`、`/var/log/nginx/error.log` |
| MySQL | `/var/log/mysql/error.log` |
| 程序自己的日志 | 你项目目录下的 `logs/`、或者代码里写死的路径 |
| 内核报错（OOM、硬件） | `dmesg` |

实时跟踪日志：

```bash
$ tail -f /var/log/nginx/access.log      # 滚动看
$ tail -n 100 /var/log/syslog            # 最后 100 行
```

## 15.11 如何高效提问（对 AI / Stack Overflow）

学了这么多，你迟早要去网上问问题。问得好，10 分钟得到答案；问得烂，三天没人理。一个好问题模板：

1. **环境**：Ubuntu 24.04 / WSL2 / Python 3.12 / 什么版本的软件
2. **我想干嘛**：一句话说目标（不是说 "help me"）
3. **我做了什么**：贴关键命令
4. **预期结果**：我以为会怎样
5. **实际结果**：完整报错（**贴原文，不要截图打字**）
6. **已经试过什么**：让回答者别让你重做

**反例：** "我 git push 报错了怎么办？"——没人能帮你。

**正例：** "Ubuntu 24.04 WSL2，git 2.43。我在项目里跑 `git push -u origin main`，预期是把代码推到 GitHub，实际报错：

```text
ERROR: Permission to xxx/xxx.git denied to yourname.
fatal: Could not read from remote repository.
```

我已经跑过 `ssh -T git@github.com` 返回 successfully。请问怎么回事？"

> 💡 **小技巧：** 用 AI 工具问问题时，**把完整报错、完整命令、环境信息一起贴**，它立刻能定位。只说"报错了"它只能猜。

## 15.12 常见报错速查表（一行对照）

把上面分散的故障再浓缩成一张"报错原文 → 定位命令 → 解决"的对照表，你遇到任何报错先在这张表里扫一眼：

| 报错原文关键词 | 大概率原因 | 定位命令 | 解决 |
|---|---|---|---|
| `command not found` | 没装 / PATH 不对 / 拼错 | `which xxx`、`whereis xxx` | `sudo apt install xxx` 或加 PATH |
| `Permission denied` | 没执行权限 / 属主不对 | `ls -l 文件`、`id` | `chmod +x` / `chown` / `sudo` |
| `No such file or directory` | 路径写错 / 文件被删 | `ls 那个路径`、`pwd` | 核对绝对路径 |
| `Address already in use` | 端口被占 | `ss -lntp \| grep 端口` | `kill PID` 或换端口 |
| `No space left on device` | 磁盘满 / inode 满 | `df -h`、`df -i` | 清大文件、清日志 |
| `Temporary failure in name resolution` | DNS 挂了 | `dig 域名`、`cat /etc/resolv.conf` | 改 nameserver |
| `Connection refused` | 目标服务没跑 | `ss -lntp`、`systemctl status 服务` | 启动服务 |
| `Connection timed out` | 防火墙 / 安全组 / 网络 | `ping IP`、`curl -v` | 放行端口、查代理 |
| `502 Bad Gateway`（Nginx） | 后端挂了 | `systemctl status 后端`、`journalctl` | 启动后端、查 proxy_pass |
| `403 Forbidden`（Nginx） | 静态目录权限 | `ls -ld 目录` | `chmod o+x`、放 `/var/www/` |
| `Could not get lock` | apt 正在跑 | `ps aux \| grep apt` | 等 / 删锁（下策） |
| `fatal: not a git repository` | 当前目录不是仓库 | `git rev-parse --show-toplevel` | `cd` 到仓库根 / `git init` |
| `Permission denied (publickey)`（git ssh） | SSH key 没配好 | `ssh -T git@github.com` | 重贴公钥到 GitHub |
| `Out of memory: Killed process` | 内存被 OOM | `dmesg \| grep -i oom` | 加 swap / 优化程序 |

> 📌 **注意：** 报错信息的**前几行**最重要，最后一行往往是概括。读报错要从后往前读，找到第一个 "error"、"failed"、"No such"。

### 什么时候该自己查、什么时候该问

给你一个判断标准：

- **命令行直接报错**（`command not found`、`Permission denied`）：自己查，本章就是答案，5 分钟能搞定。
- **服务起不来 / 网站打不开**：先 `journalctl -u` 和 `tail -f` 看日志，日志里 80% 直接写了原因。
- **折腾 1 小时还没头绪**：停下来，把问题按 15.11 的模板整理好，去问 AI / 搜 Stack Overflow。硬扛只会浪费时间。
- **涉及 rm / sudo / 改 fstab / 删数据库**：停下来，先备份，再操作。

> 💡 **小技巧：** 排错时最忌讳"试一下不行、再试一下不行"——没有记录。**在纸上/笔记里写下你已经试过什么、每条命令的输出**，下次问别人或者自己回头看都有依据。

## 动手练习

1. 故意跑 `cd /notexist`，读完整报错，用 `ls` 验证路径不存在。
2. 跑 `sudo apt install sl`（一个小玩具），然后敲 `sl`，观察动画（这是命令拼错的经典彩蛋）。
3. 用 `ss -lntp` 看你现在 WSL 里开了哪些端口，猜每个是什么程序。
4. 跑 `df -h` 和 `df -i`，看看你 Linux 侧磁盘使用率和 inode 使用率。
5. 写一个"模拟故障排查"笔记：把你今天遇到的一个报错、定位过程、解决方法记下来，以后就是你的私人排错手册。
6. 用 `journalctl --since "10 minutes ago"` 看你最近 10 分钟的系统日志。
7. 故意输一个不存在的命令（比如 `sl`），看 bash 给你的提示——它经常会告诉你"did you mean" 哪个包。
8. 打开本章末尾的 50 条速查表，遮住一列，看自己能回忆起多少条。

## 15.13 50 条高频命令速查表

最后，把整本指南最常用的命令浓缩成这张表。**打印出来贴墙上。**

### 导航与文件

| 命令 | 作用 |
|---|---|
| `pwd` | 当前在哪 |
| `cd 路径` / `cd -` | 切换目录 / 回上次 |
| `ls -lah` | 长格式看文件 |
| `mkdir -p a/b/c` | 递归建目录 |

## 路线终点与进阶方向

恭喜你走到这。前面 14 章已经让你从"见过终端"到"能独立在 Linux 上跑后端项目、部署网站、排查问题"。接下来想继续深入，给你几个方向：

1. **网络与安全**：学 iptables/ufw 防火墙、SSH 加固、fail2ban、HTTPS 证书自动化。
2. **容器编排**：Docker 熟练后学 Docker Compose 多服务项目，再进阶到 Kubernetes（K8s）——大厂后端/运维面试必考。
3. **云原生**：阿里云/腾讯云的 ECS、OSS、RDS 怎么配合，学 Terraform 写基础设施即代码。
4. **Python/Go 后端**：Flask/FastAPI/Gin 写一个真实小项目，然后用 Nginx + systemd + Docker 部署到云学生机。
5. **闯关巩固**：OverTheWire Bandit 34 关、HackerRank Shell 题——把前面学的全用一遍。

你的 Linux 之路才刚开始，但这条路你已经走通了最难的第一步。加油。
