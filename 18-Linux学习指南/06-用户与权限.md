# 第6章 用户与权限

> 学完这章，你能看懂 `ls -l` 那一堆 `-rwxr-xr-x` 到底在说什么，能自己加用户、改文件权限，并且再也不会把 `777` 当成"万能修复按钮"。

## 本章你将学会

- 理解 Linux 多用户模型、root 是谁、`sudo` 在干嘛
- 用 `whoami` / `id` / `who` 看清"我是谁"
- 分清 `su` 和 `sudo -i` 的区别，知道 WSL 下 root 密码怎么回事
- 用 `useradd` / `usermod` / `userdel` / `groupadd` / `passwd` 管理账号
- 逐字段读懂 `/etc/passwd`、`/etc/shadow`、`/etc/group`
- 用 `chmod` 符号法和数字法改权限，说清 `755` / `644` / `700` / `777` 的含义
- 用 `chown` / `chgrp`（带 `-R`）改属主
- 理解 `umask`、SUID、sticky bit 是怎么回事
- 亲手给一个脚本加上"能双击运行"的执行权限

## 为什么需要它

你前面一直在自己的账号下敲命令，看起来系统里就你一个人。但 Linux 从娘胎里就是个多用户系统——一台服务器上可能跑着几十个账号，Web 服务用 `www-data` 身份跑，数据库用 `mysql` 身份跑，每个人只能看自己的文件。权限这东西，本质就是回答两个问题：**"这个文件是谁的？"** 和 **"你能对它做什么？"**

你以后一定会遇到两种报错：`Permission denied`（权限不够）和 `Operation not permitted`（你不是 root）。这一章就是让你看到这两行字时不再慌，而是知道该查谁、改哪里。

## 6.1 多用户模型与 root

Linux 里每个用户都有一个数字编号，叫 **UID**。普通用户的 UID 一般从 1000 开始（你 WSL 装完系统时建的那个账号就是 1000）。而 **root**（也叫超级用户）的 UID 永远是 0，它是系统的"上帝账号"——想删什么删什么，想改什么改什么。

> ⚠️ **警告：root 没有"回收站"。** root 权限下 `rm` 删掉的文件不会进任何垃圾箱，立刻没了。而且 root 能改 `/etc`、`/bin` 这种系统目录，手一抖可能把系统搞崩。所以日常你应该用普通用户干活，只在需要的时候临时"借"root 权限。

### `whoami` / `id` / `who`：我是谁

先确认你现在是以谁的身份在敲命令。三个小命令：

```bash
$ whoami
yourname
```

`whoami` 就回答一件事：当前登录用户是谁。

```bash
$ id
uid=1000(yourname) gid=1000(yourname) groups=1000(yourname),27(sudo),998(docker)
```

`id` 输出更全：`uid` 是你的用户编号，`gid` 是你的主组编号，后面 `groups=` 列出你加入的所有附加组。上面这台机器里，这个用户除了自己的主组，还在 `sudo` 组（可以用 sudo）和 `docker` 组里。

```bash
$ who
yourname  pts/0        2026-10-13 10:20 (127.0.0.1:0)
```

`who` 看的是"当前这台机器上都有谁登录着"。在 WSL 里你通常只看到自己一个；以后连到云服务器时，能看到别的运维同学也在线。

### `su` vs `sudo`：两种"变成 root"的方式

新手最容易混的就是这俩。我给你讲透：

| | `su` | `sudo` |
|---|---|---|
| 本质 | 切换成另一个用户（默认是 root） | 以 root 身份"临时执行一条命令" |
| 需要知道谁的密码 | **目标用户的密码**（也就是 root 密码） | **你自己的密码** |
| 适合场景 | 长时间在 root 下干活 | 偶尔执行一条管理员命令 |
| 危险程度 | 高——切进去之后你所有操作都是 root | 低——用完就回来 |

最常用的写法是 `sudo 命令`：

```bash
$ sudo apt update
```

系统会提示你输密码——注意，**输密码时屏幕上什么都不显示**，连星号都没有，这是 Unix 的设计，不是卡了。输完回车就行。

如果你想一次性进入"root shell"，所有命令都以 root 身份跑，用：

```bash
$ sudo -i
```

提示符会从 `$` 变成 `#`，这就告诉你：现在你是 root 了。干完活用 `exit` 退回到普通用户。

> 📌 **注意：Ubuntu 默认不设 root 密码，也不允许 root 直接登录。** 这是 Ubuntu 故意的安全设计——它鼓励你用 `sudo` 而不是裸奔 root。所以你直接敲 `su -` 会失败，因为根本没有 root 密码可用。

> 💡 **小技巧：** 刚输完一次 sudo 密码，接下来 15 分钟内再用 sudo 不会再问你。别以为"我刚才输过密码了怎么又问"——那是过了时间窗口了。

## 6.2 在 WSL 下建一个新用户练手

你说：我就一个账号，练什么多用户？来，我们建一个。这些命令都需要 root 权限，所以前面要加 `sudo`：

```bash
# 建一个名叫 alice 的用户，同时创建家目录（-m），指定 shell 为 bash（-s）
$ sudo useradd -m -s /bin/bash alice

# 给她设密码
$ sudo passwd alice
New password:
Retype new password:
passwd: password updated successfully
```

常用用户管理命令我列成表，不用背，查得到就行：

| 命令 | 作用 |
|---|---|
| `sudo useradd -m 名字` | 建用户，`-m` 表示同时建 `/home/名字` 家目录 |
| `sudo passwd 名字` | 给某用户设置/改密码 |
| `sudo usermod -aG 组名 名字` | 把用户**追加**到附加组（`-a` 是 append，千万别漏，漏了会把她踢出原来所有组） |
| `sudo userdel 名字` | 删用户（**家目录不会自动删**） |
| `sudo userdel -r 名字` | 删用户**并**删家目录 |
| `sudo groupadd 组名` | 建一个新组 |

> ⚠️ **警告：`usermod -G` 不加 `-a` 是事故高发点。** `-G` 是"设置附加组列表为这些"，会把用户原来加入的组全部清掉。比如你写 `sudo usermod -G docker alice`，她原来在 `sudo` 组里的权限就没了。永远用 `-aG`（append）。

建完验证一下：

```bash
$ id alice
uid=1001(alice) gid=1001(alice) groups=1001(alice)
```

看到 UID 从 1000 涨到 1001 了吧，系统自动分配的。

现在切到她的身份体验一下：

```bash
$ sudo -u alice bash
$ whoami
alice
$ exit
```

`sudo -u 用户名 命令` 是以别人的身份执行命令，不用知道她的密码，因为你本来就是 root。这招在以后调试"为什么这个网站以 www-data 身份跑不起来"时特别有用。

## 6.3 三个配置文件逐字段解读

用户和组的信息不是存在什么神秘数据库里，就是三个纯文本文件。你直接 `cat` 就能看。

### `/etc/passwd` —— 用户账户信息

```bash
$ head -3 /etc/passwd
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
yourname:x:1000:1000:,,,:/home/yourname:/bin/bash
```

一行一个用户，用冒号分成 7 段：

| 字段 | 示例 | 含义 |
|---|---|---|
| 1 用户名 | `yourname` | 登录名 |
| 2 密码占位 | `x` | 真正的密码哈希存在 `/etc/shadow` 里，这里只是占位 |
| 3 UID | `1000` | 用户编号 |
| 4 GID | `1000` | 主组编号 |
| 5 备注 | `,,,` | 全名/电话之类，通常空着 |
| 6 家目录 | `/home/yourname` | 登录后默认所在目录 |
| 7 登录 Shell | `/bin/bash` | 登录后用哪个 shell；`nologin` 表示这个账号不能登录（给系统服务用的） |

> 📌 **注意：`/etc/passwd` 所有人都能读。** 这就是为什么密码哈希不放在这儿——放在 `shadow` 里，只有 root 能看。

### `/etc/shadow` —— 密码哈希

```bash
$ sudo head -3 /etc/shadow
root:*:19725:0:99999:7:::
daemon:*:19725:0:99999:7:::
yourname:$y$j9T$xxxxxxxxxxxx:19988:0:99999:7:::
```

这里要 sudo 才能看。挑你自己那行讲：第一段是用户名，第二段是密码哈希（`$y$...` 这种），后面还有密码改了多少天、过期策略之类。你不需要背这些字段，只要知道：**这文件里是加密后的密码，泄露出去等于所有人的密码都裸奔了**，权限必须是 600、属主 root。

### `/etc/group` —— 组信息

```bash
$ grep sudo /etc/group
sudo:x:27:yourname
```

四段：组名、密码占位（基本不用）、GID、组里有哪些用户（逗号分隔）。上面这行的意思是：`sudo` 组（GID 27）里有成员 `yourname`——这就是你能用 `sudo` 的原因。

## 6.4 rwx：权限的三层九位

现在回头看第 3 章那个 `ls -l` 输出：

```text
-rw-r--r-- 1 yourname yourname  892 Oct 13 09:05 notes.txt
```

最开头的 `-rw-r--r--` 一共 10 个字符。拆开看：

```
类型   属主      属组      其他人
-      rw-       r--       r--
```

- 第 1 位：文件类型（`-` 普通文件，`d` 目录，`l` 软链接）
- 第 2-4 位：**属主（user）** 权限
- 第 5-7 位：**属组（group）** 权限
- 第 8-10 位：**其他人（other）** 权限

每一组三位是 `rwx`，含义如下表：

| 字母 | 对文件的含义 | 对目录的含义 |
|---|---|---|
| `r` | 能读内容（cat/less） | 能列出目录里有什么（ls） |
| `w` | 能改内容（写入、保存） | 能在目录里增删文件 |
| `x` | 能作为程序执行 | 能进入这个目录（cd 进去） |

> 📌 **注意：目录的 `x` 特别容易误解。** 目录没有"执行"这回事，这里的 `x` 意思是"能不能 `cd` 进去、能不能访问目录里文件的元信息"。一个目录权限 `r--` 看起来你能 `ls`，但其实你连进去都进不去，也读不了里面的文件名。

回到那个例子 `-rw-r--r--`：属主能读写，属组和其他人都只能读。这是普通文本文件最常见的权限。

### `chmod` 符号法

`chmod`（change mode）就是改权限的命令。符号法比较好记：`谁 +/-/= 权限`。

```bash
# 给 notes.txt 加"属主可执行"
$ chmod u+x notes.txt

# 把属组的写权限去掉
$ chmod g-w notes.txt

# 把"其他人"权限设成只能读（= 表示直接覆盖成这个值）
$ chmod o=r notes.txt

# 可以一次写多个，逗号分隔：属主=rwx，属组=r-x，其他=---
$ chmod u=rwx,g=rx,o=--- notes.txt
```

`u/g/o/a` 分别代表 user / group / other / all（所有人）。`+` 是加、`-` 是减、`=` 是直接设定。

### `chmod` 数字法

数字法把 `rwx` 翻译成三个八进制位：`r=4`、`w=2`、`x=1`，加起来就是这一组的数字。

| 三组权限 | 数字 | 常见场景 |
|---|---|---|
| `rwx rwx rwx` | 777 | 所有人都能读写执行——**危险，别用** |
| `rwx r-x r-x` | 755 | 可执行文件/目录：主人全权，其他人只读可进入 |
| `rw- r-- r--` | 644 | 普通文件：主人读写，其他人只读 |
| `rw- --- ---` | 600 | 私密文件（比如私钥）：只有主人能读写 |
| `rwx --- ---` | 700 | 私密目录：只有主人能进 |

```bash
$ chmod 755 script.sh     # 脚本：主人可读写执行，其他人可读可执行
$ chmod 644 notes.txt     # 文档：主人读写，其他人只读
$ chmod 600 ~/.ssh/id_ed25519   # SSH 私钥必须 600，ssh 命令会拒绝用更松的
```

> ⚠️ **警告：千万别把 `chmod -R 777 /` 当"包治百病"。** 新手一旦遇到 `Permission denied`，第一反应就是 `sudo chmod -R 777 某个目录`——这等于把家门钥匙塞门缝里，谁都能进能改。正确思路是先搞清楚：这个文件该属主是谁？服务进程用什么身份跑？是应该 `chown` 而不是 `chmod 777`。

## 6.5 `chown`：改属主

权限不对，很多时候不是权限位不对，而是**属主不对**。比如你用 sudo 跑了个程序，它生成的文件属主变成 root 了，你自己再去改就 `Permission denied`。

```bash
# 把文件属主改成 alice
$ sudo chown alice notes.txt

# 同时改属主和属组：  属主:属组
$ sudo chown alice:alice notes.txt

# -R 递归：把整个目录里的东西都改了
$ sudo chown -R alice:alice myproject/
```

| 命令 | 作用 |
|---|---|
| `chown 用户 文件` | 只改属主 |
| `chown 用户:组 文件` | 属主属组一起改 |
| `chown :组 文件` | 只改属组（等价于 `chgrp`） |
| `chown -R ... 目录/` | 递归改整个目录树 |

> ⚠️ **警告：`chown -R` 和 `chmod -R` 都是递归操作。** 跑之前先想想目录里有多大、你是不是真的要改全部。对系统目录 `/`、`/etc` 跑递归 chown 等于给自己挖坑。

## 6.6 `umask`：新建文件默认权限

你有没有好奇过：为什么我 `touch` 一个新文件，它自动就是 `644`，而不是 `666`？这是 **umask** 在起作用。

Linux 约定：新建目录默认想给 `777`，新建文件默认想给 `666`（文件不默认带执行位，更安全）。然后用 umask **减去**一部分权限。

```bash
$ umask
0022
```

默认 umask 是 `022`：
- 新文件：`666 - 022 = 644`（rw-r--r--）
- 新目录：`777 - 022 = 755`（rwxr-xr-x）

你不需要现在改它，只要知道有这回事。以后想让"我新建的文件默认只有我自己能看"，可以在 `~/.bashrc` 里加一行 `umask 077`，那时候新文件就是 `600` 了。

## 6.7 SUID 与 sticky bit（概念扫盲）

这两个东西你以后会撞见，先混个脸熟，不要求现在就用。

**SUID**：正常情况下，一个程序是谁跑的，它就有谁的权限。但有些程序必须临时"借"文件属主的身份运行——最典型的是 `passwd` 命令。普通用户改自己密码要写 `/etc/shadow`，但那个文件只有 root 能写。怎么破？`passwd` 这个可执行文件被设了 SUID 位，属主是 root，所以**任何人运行它时，它都以 root 身份短暂运行**，改完密码就退出来。

看一眼：

```bash
$ ls -l /usr/bin/passwd
-rwsr-xr-x 1 root root  ... /usr/bin/passwd
```

注意属主那三位里的 `x` 变成了 `s`——这就是 SUID。

**sticky bit**：看 `/tmp` 目录：

```bash
$ ls -ld /tmp
drwxrwxrwt  ... /tmp
```

其他人那三位最后一位是 `t` 而不是 `x`。这是什么意思？`/tmp` 是全世界都能写的临时目录，要是没有 sticky bit，任何用户都能删别人的临时文件。加了 sticky bit 之后，**即使目录可写，也只有文件属主自己（或 root）能删它**。

> 📌 **注意：这两个机制是系统安全的重要部分，但也是提权攻击的常见入口。** 你现在不需要自己去设 SUID，但如果哪天在自己家目录里莫名其妙看到个 `-rwsr-xr-x` 的程序，那是个红旗，得查查它哪来的。

## 6.8 WSL 下的 root 与忘记密码

WSL 有个特殊情况你必须知道：

1. **WSL 装完系统时让你建的那个账号，就是默认登录用户，UID 1000，已经在 sudo 组里。**
2. **Ubuntu 默认没有 root 密码**，所以你 `su -` 切 root 会要密码但你根本不知道是啥。
3. 想当 root，直接 `sudo -i` 就行，不用管 root 密码。

万一你真把自己密码忘了（比如 WSL 里那个账号的 sudo 密码），怎么救？思路是：**从 Windows 侧直接以 root 身份进入 WSL，然后重置密码。**

在 **Windows PowerShell**（不是 WSL 里）执行：

```powershell
# 查看装了哪个发行版
wsl --list -v

# 以 root 身份进入这个发行版
wsl -d Ubuntu-24.04 -u root
```

进去之后你就是 root 了，直接 `passwd yourname` 重置你自己的密码即可。

> ⚠️ **警告：`wsl --unregister Ubuntu-24.04` 会把整个发行版连同里面所有文件一起删掉。** 这是终极手段，不到万不得已不要用，用之前一定先 `wsl --export` 备份。

## 6.9 实操：给脚本加执行权限

学了半天权限，现在真刀真枪用一次。我们写个最简单的脚本：

```bash
$ cd ~
$ cat > hello.sh << 'EOF'
#!/bin/bash
echo "你好，$(whoami)！现在是 $(date)"
EOF
```

先看看它现在的权限：

```bash
$ ls -l hello.sh
-rw-r--r-- 1 yourname yourname  42 Oct 13 10:30 hello.sh
```

试着直接运行：

```bash
$ ./hello.sh
bash: ./hello.sh: Permission denied
```

看到了吧——这就是本章开头说的那个 `Permission denied`。因为它没有执行位。加上：

```bash
$ chmod +x hello.sh
$ ls -l hello.sh
-rwxr-xr-x 1 yourname yourname  42 Oct 13 10:30 hello.sh
$ ./hello.sh
你好，yourname！现在是 Tue Oct 13 10:31:02 CST 2026
```

> 💡 **小技巧：`chmod +x 脚本名` 等价于 `chmod a+x`，给所有人加执行位。** 如果你只想自己能跑、别人不能，用 `chmod 700 hello.sh`。

记住这个流程：写完脚本 → `chmod +x` → `./脚本名`。这是后端开发日常。

---

## ⚠️ 危险操作与安全红线

- **`chmod -R 777` 不要随便用。** 遇到 Permission denied 先想属主，再想权限位。
- **`usermod -G` 不加 `-a` 会把用户从所有附加组踢出去。** 永远用 `-aG`。
- **`userdel -r` 会连家目录一起删。** 删之前确认 `/home/名字` 里没有别人要的东西。
- **`chown -R` 对系统目录是自杀行为。** 只对你自己的项目目录用。
- **root 下 `rm` 没有后悔药。** 删之前先 `ls` 一遍看看要删的到底是什么。
- **SSH 私钥 `~/.ssh/id_ed25519` 权限必须是 600。** 权限松了 ssh 命令会直接拒绝使用它，这是第 10 章的坑，提前记住。

## 常见报错与排查

| 现象 | 原因 | 解决 |
|---|---|---|
| `Permission denied` 运行脚本 | 脚本没有执行位 | `chmod +x 脚本名` |
| `Permission denied` 写文件 | 你不是属主，也没有写权限 | `ls -l 文件` 看属主；`sudo chown 你:你 文件` |
| `sudo: xxx is not in the sudoers file` | 当前用户不在 sudo 组 | 需要一个已经在 sudo 组的人执行 `sudo usermod -aG sudo 你` |
| `su: Authentication failure` | WSL 默认没 root 密码 | 别用 `su -`，用 `sudo -i` |
| 输 sudo 密码时屏幕没反应 | Unix 设计，密码不回显 | 盲打就行，打完回车 |
| `chmod: changing permissions of '...': Operation not permitted` | 文件属于 root，你是普通用户 | 前面加 `sudo` |

## 动手练习

1. 用 `useradd -m` 建两个用户 `bob` 和 `carol`，分别设密码，用 `id` 确认他们 UID 是 1001、1002。
2. 建一个组 `devteam`，把 bob 加进去（用 `-aG`），然后 `grep devteam /etc/group` 验证。
3. 在你家目录建一个文件 `secret.txt`，写点东西，用 `chmod 600` 把它变成只有你自己能读写。然后 `sudo -u bob cat secret.txt`，观察报什么错。
4. 写一个脚本 `backup.sh`，内容是把 `~` 下的 `notes.txt` 复制到 `/tmp/`，给它加执行权限，跑通它。
5. 用 `chmod 700` 把 `backup.sh` 改成只有你能执行，然后再 `sudo -u bob ./backup.sh`，看报什么错。
6. （清理）练完了用 `sudo userdel -r bob` 和 `carol` 删掉测试用户，别让垃圾账号留着。

## 本章小结

| 命令/概念 | 一句话作用 |
|---|---|
| `whoami` / `id` / `who` | 看我是谁 / 我的 UID 和组 / 当前谁在线 |
| `sudo 命令` | 以 root 身份跑一条命令 |
| `sudo -i` | 进入 root shell（提示符变成 `#`） |
| `useradd -m` / `userdel -r` | 建用户（带家目录）/ 删用户（连家目录） |
| `usermod -aG 组 用户` | 把用户追加进组（别漏 `-a`） |
| `passwd 用户` | 改密码 |
| `/etc/passwd` `/etc/shadow` `/etc/group` | 用户信息 / 密码哈希 / 组信息 |
| `chmod u+x` / `chmod 755` | 符号法 / 数字法改权限 |
| `chown 用户:组 文件` | 改属主（`-R` 递归） |
| `umask` | 决定新文件默认权限 |
