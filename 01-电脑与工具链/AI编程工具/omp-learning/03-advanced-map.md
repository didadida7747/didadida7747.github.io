# 03 - OMP 进阶能力地图

进阶功能的价值在于解决明确问题，不是堆功能。下面按“什么时候值得学”组织。

| 能力 | 适合的触发条件 | 先做的最小实验 | 风险与边界 |
|---|---|---|---|
| 多模型/多供应商 | 单一模型经常限流，或需要公平比较模型 | 同一个小 bug、同一提示词、同一测试命令跑两次 | API 费用、数据发送、模型版本差异；不要把一次结果当结论 |
| 回退链 | 主模型偶发 429/配额不足且任务必须连续 | 仅为一个低风险项目配置两个已授权模型 | 回退会改变成本和输出风格，记录实际用了哪个模型 |
| LSP | 重命名、查引用、跨文件修改需要语义信息 | 在测试分支重命名一个私有符号，再构建 | LSP 配置或项目索引不正确时，不要相信“零引用” |
| DAP 调试 | 仅靠日志无法定位崩溃、死锁或变量异常 | 对本地最小复现做一次断点和变量检查 | 进程、端口、源码映射和敏感运行数据需要控制 |
| 子代理 | 任务可拆为独立研究、实现、测试或审查子任务 | 一主一审：主代理只读分析，子代理独立列风险 | 并行会增加费用和改动冲突；不要让多个代理无边界写同一目录 |
| MCP/插件 | 已有稳定的外部工具接口，且手工步骤重复 | 先只读连接并验证权限与日志 | 第三方 MCP 可能读取文件/联网/写外部系统，先审查来源与权限 |
| 项目记忆/规则导入 | 同一项目反复出现稳定约束 | 写入一条可验证规则，例如测试命令或目录禁区 | 过时规则会误导后续任务；定期删改并避免保存凭据 |

## 推荐进阶顺序

1. 先稳定完成“读项目、最小修改、看 diff、跑测试”。
2. 给一个练习仓库试用项目规则和已有 `AGENTS.md`。
3. 再试一种额外模型，记录费用、速度、测试结果和失败方式。
4. 需要语义重构时再配 LSP；有可复现运行错误才试 DAP。
5. 最后才启用子代理、MCP、扩展、远程协作或自动提交。

## 适合你的项目边界

对于 STM32/嵌入式项目，OMP 可以辅助阅读 HAL、找调用链、整理构建错误、解释中断流程和生成测试清单。但它无法替代板子上的实际下载、示波器/串口观察、按键次数、接线电平和重复实验记录。建议让代理输出“待实测清单”，而不是声称硬件功能已经完成。
