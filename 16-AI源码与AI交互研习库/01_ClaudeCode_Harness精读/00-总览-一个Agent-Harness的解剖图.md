# 00 · 总览：一个 Agent Harness 的解剖图

> Claude Code 是 Anthropic 官方的命令行编程 Agent，也是 2025-2026 年公认的 harness 设计标杆。
> 关于源码可读性的重要更新：**2026 年 3 月，Claude Code 因 npm 包里残留的 source map 文件意外泄露了完整 TypeScript 源码（约 51 万行）**，社区随后出现了大量逐层拆解文章（知乎《薄模型，厚控制：Claude Code 与当下 AI 工程的真相》、CSDN《一场因 .map 引发的史诗级"开源"》等，GitHub 有多个归档镜像，搜索 "claude code source map leak" 自行甄别）。本库的解剖图基于泄露提示词、逆向工程、开源同构实现（Gemini CLI/OpenCode 等）与官方博客四类来源，骨架结论与泄露源码互相印证；想读原始代码，去 07_源码仓库 找归档。
> 本篇先给你整张解剖图，后面 8 篇逐个器官拆。

## 一、一句话说透 Agent 编程

```
Agent = LLM + 工具 + 循环 + 上下文管理
```

拆开就是：

```
┌─────────────────────────────────────────────────────┐
│                    Claude Code (harness)             │
│                                                      │
│   用户输入 ──► 上下文组装器 ──► ┌────────┐            │
│   (CLI/IDE)    (系统提示词 +    │  API   │            │
│                 历史 + 环境 +   │ 调用    │            │
│                 工具定义)  │    └───┬────┘            │
│                            ▲         │ 流式响应         │
│                            │         ▼                 │
│                       历史记录    有 tool_use 吗？       │
│                            │      │yes      │no       │
│                            │      ▼         ▼         │
│                       结果回填 ◄── 权限门 ◄  收尾：      │
│                            │   (允许?)    检查 Stop    │
│                            │      │      Hook、输出    │
│                            │      ▼      统计          │
│                       工具执行器 ◄──┘                   │
│                       (Bash/Read/                      │
│                        Edit/搜索/                       │
│                        Task子代理/MCP)                  │
└─────────────────────────────────────────────────────┘
```

【为什么这样设计】注意一个反直觉的事实：**模型从头到尾只做一件事——生成文本（结构化的 tool_use 也是文本）**。所有"干活"的部分——读文件、跑命令、改代码——都是 harness 用普通代码做的。这个分工是刻意的：

1. **安全边界**：模型只拥有"提议权"，执行权在 harness 手里。所以才有权限门、沙箱、Hook 这些拦截点。如果模型直接执行，一切护栏都不存在。
2. **可观测**：每一步都经过 harness，才能留下 trace、做计费、做取消、做回滚（2.0 的 checkpoint/rewind 就建立在这上面）。
3. **模型无关**：这套循环对模型黑盒，所以同一套 harness 能换模型、能做 Agent SDK 开放出去。

## 三、先建立三个"设计世界观"

在读任何细节之前，先记住这三条贯穿全部代码的理念。后面每一篇都会反复见到它们。

### 世界观 1：一切皆文本，文本即接口

Claude Code 里几乎没有隐藏的 API。工具的输入输出是文本，子代理的返回是文本，CLAUDE.md 是文本，连 TODO 列表都是一个工具（TodoWrite）管理的文本。

【为什么】文本是模型最擅长的表示形式。一个"万能文本接口"意味着任何新能力（MCP 工具、自定义命令、技能）都不需要改协议——接进来就能用。这是 Unix "一切皆文件"哲学的 AI 版。

### 世界观 2：harness 是护栏堆，不是功能堆

去数 Claude Code 系统提示词里的措辞分布：大量篇幅不是在讲"你要做什么"，而是在讲"你不许做什么"——不要用 sed 读文件、不要 git commit --no-verify、改完代码不要主动提交（除非被要求）……

【为什么】模型的默认行为是"热心过头"（over-eager）和"自信过头"（hallucination）。harness 的价值一半在于把模型的野性约束到工程可接受的范围内。这个比例你写自己的提示词时也该参考。

### 世界观 3：省 token 是第一性原理

上下文窗口是 Agent 最稀缺的资源。看这些设计的共同点：
- 子代理只把结论带回主线（几百 token），不带回过程（几十万 token）
- Skill 渐进式披露：先只加载名字+描述
- Read 工具分页、单次读取有行数上限
- 旧工具结果会被压缩（microcompaction）
- /clear 被官方文档反复强调

【为什么】token 就是钱、就是延迟、就是注意力质量。上下文越长，模型对早期内容的关注度越低（"lost in the middle"）。**上下文管理能力 = Agent 使用能力的核心差距。**

## 四、Claude Code 的大事记（帮你定位资料的新旧）

- 2024.10 内部工具诞生（代号 claude-cli），2025.2 随 Claude 3.7 Sonnet 公开发布
- 2025.5 GA + Claude 4 系列；MCP 生态铺开
- 2025 下半年：Hooks、Subagents（`.claude/agents/`）、Plan Mode、Skills、Settings 分层逐步完善
- 2025.9：2.0 版本——Checkpoints（/rewind 时光回溯）、Claude Agent SDK（把 Claude Code 的 harness 开放成库）
- 2026.3：完整源码经 npm source map 意外泄露（约 51 万行 TypeScript），社区拆解热潮（记忆架构、上下文压缩算法等细节被逐一分析）
- 2026：2.x 持续迭代（具体版本号以官方 changelog 为准，随时会变）

【你怎么用这条时间线】看到任何旧教程，先对照它讲的是哪个时期的设计。比如 2025 年初的教程没有 Skills 和 Subagents，2025 年中的没有 Checkpoints。
