# 实战工作流与玩法案例（个人智能体系列 · 05）

> 本篇不是分册内容的复制，而是跨产品整合的「工作流合集」：同一个需求，今天可以用 Today AI 跑、明天可以用 Grok Bot 跑、动手能力强的可以自建 OpenClaw/Hermes 跑。
> 每个工作流都标了「适用产品 + 选择理由」，指令原文全部来自 02/03/04 分册已验证的场景，可直接照抄。
> 信息基准日期：2026-10-20。

---

## 0. 怎么用这一章

- **先用对工具**：盯国内的事（飞书/教务网/微信）→ Today AI；盯 X、跑代码、拉团队 → Grok Bot；想练架构 → 自建。
- **所有指令里的括号内容**（URL、公司名、死线日期）按你自己情况替换。
- **通用铁律**（来自 02/03 分册安全章节）：①密码/验证码永远不要贴进聊天框；②发消息、付款、删文件这类动作一律开「先询问」；③先用小号邮箱练手一周再接主账号。

## 一、学习类工作流（3 个）

### 工作流 1：论文/英文长文 → 结构化中文学习笔记

- **适用产品**：首选 Grok Bot（云电脑能打开网页通读长文）；Today AI 也能跑（把 PDF 直接喂给它）。
- **选择理由**：这个需求的关键是「长文档通读 + 生成 Markdown 进资料库」，Grok Bot 的「资料库」标签天然是文件仓库；Today AI 则胜在它会**记住你这门课的上下文**，下次喂第二篇不用重讲。
- **操作步骤**：
  1. 建一个「学习助教」Bot（Grok Bot）或直接在 Today 主对话里发（Today）。
  2. 粘贴下面的指令 + 文章链接/PDF。
  3. 要求它「知识点清单等我确认后再继续」——先审一遍笔记结构再让它展开。
- **指令原文**：
  ```
  你是我的学习助教。任务：这是一篇英文长文链接 [粘贴 URL]。要求：
  1. 通读后产出一份结构化中文学习笔记（Markdown，存进资料库）：按概念分节，
     关键术语中英对照；
  2. 提炼 10 个关键知识点，每个写 3 句「讲给完全没基础的同学听」的口播稿；
  3. 列出可以配画面的时间点建议。
  做完把笔记链接发我，知识点清单等我确认后再继续。
  ```
- **预期产出**：一份分节、术语中英对照的 Markdown 笔记 + 10 条口播稿。社区作者正是用这套流程把官方 8 小时 Grok 教程摘出 1 小时精华，生成音画对齐的 HTML 学习网页（人人都是产品经理·老章，2026-10-17）。
- **注意事项**：Today 跑这个时，把论文 PDF 直接拖进对话框；Grok Bot 跑时，它可能要登录墙才能看到的内容（如付费论文）会停下来问你，接管那一步即可。

### 工作流 2：课程资料累积 → 复习笔记 + 断更提醒

- **适用产品**：首选 Today AI（长期记忆 + 定时任务是它的主场）；Grok Bot 也能（挂例行任务），但「断更提醒」这种跨会话判断是 Today 的记忆强项。
- **操作步骤**：
  1. 在 Today 对话里发一次你的课程清单（它会记住）。
  2. 之后每周把课件 PDF / 课堂截图陆续丢给它，不用重讲背景。
  3. 周日晚上等它的汇总清单。
- **指令原文**：
  ```
  这学期我在学《信号与系统》和《数据结构》。我会陆续把课件 PDF 和课堂笔记截图发给你。
  请你：1）每收到一批就整理成一份带小节标题的复习笔记，标注重点公式和易错点；
  2）每周日晚上汇总一次「本周没搞懂的知识点」清单给我；
  3）如果我连续两周没发这门课的资料，主动提醒我是不是落下了。
  ```
- **预期产出**：两门课各一条不断累积的复习线；周日自动出薄弱点清单；断更自动喊你（依据：记忆累积 + 定时任务 + 变化提醒，02 分册 §5 场景 1）。
- **注意事项**：Grok Bot 复刻这个玩法时，把第 2 条挂成例行任务（右栏→详情→例行任务）；社区记录单 Bot 最多挂 50 个例行任务、两次运行间隔至少 5 分钟（腾讯云教程，2026-10，社区经验）。

### 工作流 3：期末/课程调研包 → 多 Bot 流水线出报告

- **适用产品**：Grok Bot 群聊（唯一原生支持多 Bot @交接的产品）；Today 只能单线程跑。
- **操作步骤**：建群 → 按群公告规则跑 → 等 @你 终稿确认。
- **指令原文（群公告）**：
  ```
  建群：你 + 资料收集Bot + 数据整理Bot + 报告撰写Bot + 审稿Bot。
  群公告规则：
  1. 资料收集Bot：去 GitHub 搜 [STM32 PID 开源项目]，按 star 排序挑 5 个，
     记录 README 要点，@数据整理Bot；
  2. 数据整理Bot：把 5 个项目整理成对比表（语言/协议/star数/最近更新/适合新手程度），
     @报告撰写Bot；
  3. 报告撰写Bot：写成 800 字推荐报告，@审稿Bot；
  4. 审稿Bot：按「事实、来源链接、时效」三项审，不过就打回写修改意见；
  全部完成后 @我 终稿确认。
  ```
- **预期产出**：全自动跑完整条流水线；审稿 Bot 会真的打回初稿要求补事实清单（腾讯云教程实测，2026-10-09）。
- **注意事项**：**群聊盲区**——审批请求、登录、密钥请求不进群聊，涉及这些的事必须回一对一对话处理（腾讯云教程，2026-10-09）。跑完第一遍别急着交，人要当「产品经理」把审稿意见再过一遍。

## 二、信息盯梢类工作流（4 个）

### 工作流 4：官网/官宣/教务通知 → 每日巡检，有更新才喊你

- **适用产品**：两个都行。盯海外（xAI 博客/OpenAI 博客）→ Grok Bot（原生读网页无登录墙问题）；盯国内（教务网通知栏）→ Today AI（网络环境直连）。
- **指令原文**：
  ```
  你是我的技术情报员。例行任务：每天早 8 点（北京时间）和晚 8 点各跑一次——
  打开浏览器检查 [xAI 官网博客]、[OpenAI 博客]、[你学校教务网通知栏] 这三个页面，
  对比上次记录，发现新发布的内容就：摘要成 3 条中文要点 + 原文链接，发到这个对话；
  没有新内容就只回一句「今日无更新」。把这三个页面的旧记录存进你的资料库。
  ```
- **预期产出**：每天两轮自动巡检；有更新才打扰你。关键设计是「没有就回一句今日无更新」——反过来说，你也教会它「没有就别刷屏」（03 分册 §11 场景 1）。
- **注意事项**：国内版 Today 跑同类任务时（02 分册场景 2），实测用户第二天只发一句修正标准，它后续就按新标准判断——**标准写一次，以后只改增量**。国内教务网若要登录，Grok Bot 云电脑访问不了校园内网（FAQ Q6），那部分自己补。

### 工作流 5：定时日报（资金/学习/竞赛三合一）

- **适用产品**：Grok Bot（定时推送机制成熟）；Today AI 天然就是早晚报，但它是基于你的日程主动归纳，格式你控制不了——想要「固定三块、200 字以内」这种定制日报，用 Grok Bot。
- **指令原文**：
  ```
  你是我的日报秘书。每个工作日晚 10 点生成今日日报，固定三块：
  ① 今天 X 上 AI agent 领域最值得看的 5 条动态（原生读 X，每条一句话点评）；
  ② 提醒我明天截止的待办；
  ③ 用一句话总结我今天存进资料库的文件。
  输出 200 字以内，发进我们的一对一对话，不要发群里。
  ```
- **预期产出**：晚 10 点固定推送；对应社区「早 8 推选题、晚 8 汇报成果」的总管 Bot 玩法（抖音创作者实战，2026-10-13）。
- **注意事项**：无人值守触发的审批约 10 分钟过期，过期要让 Bot 重试（腾讯云教程，2026-10-09）。日报里涉及 X 的部分依赖官方 2026-10-08 起原生支持的 X 读取能力；它**还不会自动发推**（接入第一版官方动作全是「读」，抖音科技评论，2026-09-06）。

### 工作流 6：竞赛/实习/秋招信息追踪 + 面试突击包

- **适用产品**：首选 Today AI（它会把你的简历、目标公司、偏好全记住，下次说「明天面试」不用重讲）。
- **指令原文**：
  ```
  我目标是明年找嵌入式 / 后端开发实习，目标公司是华为、大疆、小米、中科创达。
  请你：1）盯这几家的校招官网和牛客/github 上的面经更新，每周三早上发一次简报；
  2）我每次说「明天面试 XX 公司」，你就在当晚按这个岗位方向给我出一份
     10 个高频技术问题 + 参考答案要点；
  3）我的简历在附件里，以后所有内容都以我简历上写的项目经历为准来包装。
  ```
- **预期产出**：每周三简报 + 面试当晚 10 问速查包。齐俊元本人的高频用法就是面试、见投资人前让它做准备，沟通质量明显提升（晚点 LatePost，2026-10-16）。
- **注意事项**：简历喂进去后它会长期记住——这是双刃剑，简历更新了要主动告诉它「我简历改了」。牛客/GitHub 若要登录才能看的内容，Grok Bot 路线会卡在登录墙。

### 工作流 7：账单/订阅/敏感邮件异常监控

- **适用产品**：两个都行。Today AI 实测最稳（阑夕长期监管 Cloudflare 账单和车险，2026-09-24）；Grok Bot 走 Gmail 连接器的「收件箱分诊」模板。
- **指令原文（Today 版）**：
  ```
  把我两个邮箱都接上，只做一件事：长期盯「付款、账单、续订、发票」类邮件。
  出现新的扣费或续订提醒时第一时间告诉我金额和去向；
  如果是我不认识的服务扣费，直接标「可疑」。每周日汇总一次本周所有支出类邮件。
  ```
- **指令原文（Grok Bot 版）**：
  ```
  你是我的收件箱分诊员。已连接我的 Gmail。
  规则：邮件只做三件事——①垃圾/广告直接归档；②学校、老师、竞赛组委会的邮件
  星标并摘要给我；③需要我回复的，先起草好草稿存在草稿箱，告诉我「有 X 封待批，
  回复内容如下」，等我审批后再发。永远不要未经审批直接发信。
  ```
- **预期产出**：漏交/异常续订第一时间通知；Grok 版发信必走审批卡，你点 Send 才真发（mem0 官方模板，2026-09-28）。
- **注意事项**：Today 的邮箱整理任务**全程只读**，不删不改不回（实测截图）；先用学习邮箱/小号练手一周再接主邮箱（02 分册 §7.1 避坑表）。

## 三、创作类工作流（2 个）

### 工作流 8：写作辅助 + 文风记忆（周报/推文/答辩稿）

- **适用产品**：首选 Today AI（记住文风是它的记忆强项）。
- **指令原文**：
  ```
  以后我让你写的东西都遵守这个标准：技术向、写给大学生看；先一句话结论，
  再分点；每点不超过三行；术语第一次出现要解释一句。风格参考我发你的这篇
  范文（附上范文链接/文件）。写好后自己检查一遍有没有违反上面的标准再发我。
  ```
- **预期产出**：实测——用户第二次让它写同类内容，它沿用了上一轮的受众和标准，不用重新交代（抖音技术拆解，2026-10-10）。
- **注意事项**：它会「很笃定地写错」事实（汉化 mod 时自信给错目录结构，害作者重启测试一小时，极客公园十天实测）——**写好的引用、数据、路径必须自己复核一遍**。

### 工作流 9：内容流水线（选题→写稿→审稿→二稿）

- **适用产品**：Grok Bot 群聊（范式 A 是社区跑通的标杆）。
- **操作步骤**：
  1. 建群：你 + X监控Bot + 选题分析Bot + 写稿Bot + 审稿Bot。
  2. 一句话规则：每个环节做完，@下一个人交活。
  3. 你只在选题那步拍板，其余让它们自己转。
- **指令原文（拍板后的衔接）**：
  ```
  规则一句话：每个环节做完，@下一个人交活。
  审稿标准：事实、立场、来源、时效四项；不过就打回，修改意见写清楚要补什么；
  二稿必须附事实清单——每条事实挂来源链接，挂不上的标「未核实」。
  ```
- **预期产出**：实测全自动跑通——X 监控每小时抓 6 条简报 → 选题 Bot 挑 3 个 @你 → 你选定后它整理时间线/正反方观点 → 写稿 → 审稿打回 → 二稿附事实清单（腾讯云教程作者亲测，2026-10-09）。
- **注意事项**：社区吐槽总管 Bot 改不了面板里的截止时间、Bot 之间吵起来最后还是要人拍板——**把群聊当「需要你当产品经理的初级团队」来带**（人人都是产品经理转载，2026-10-05）。

## 四、开发类工作流（2 个）

### 工作流 10：手机遥控云电脑跑代码（clone→装依赖→跑通→日志回传）

- **适用产品**：Grok Bot（重度用户的主流玩法）；Today AI 云电脑也能做代码汉化/构建类任务。
- **操作步骤**：教室/路上掏出手机发指令 → Bot 在云电脑终端开工 → 日志贴回对话。
- **指令原文**：
  ```
  你是我的实验助手。任务：在你的云电脑终端里——
  1. 用 git clone 把 [https://github.com/xxx/repo.git] 克隆下来；
  2. 读 README，建 venv、装依赖；
  3. 跑通 main 入口，把运行日志贴给我；
  4. 如果依赖装不上，先试换国内镜像源，仍失败才停下来问我。
  每一步开始前先在群里说一声你在做什么。
  ```
- **预期产出**：重度用户实测一周额度用掉 99% 的主流玩法就是「手机派活 → 云电脑跑代码 → 日志回传」；Bot 内置 bash/read/write/edit/glob/grep 工具（抖音重度用户，2026-10-10）。
- **注意事项**：①这是最烧额度的玩法，免费套餐 7 天重置撑不住，重度用必须付费；②计算机方向可叠加 Herdr，让 Bot 远程指挥 Codex CLI 在常驻终端里改 PR（herdr.dev，2026-10）；③云电脑时不时卡死，解决办法是重置云电脑（从上一快照重建，**最近改动会丢**）。

### 工作流 11：批量文件处理（仓库汉化/注释翻译/打包交付）

- **适用产品**：Today AI（实测案例就是发 zip 给它做游戏 mod 汉化）。
- **指令原文**：
  ```
  这个仓库（发 zip 或 GitHub 链接）里有一份 STM32 寄存器级驱动代码，注释全是英文。
  请你：在你的云端环境里跑一遍构建，把关键函数注释翻译成中文、生成一份中文 README，
  完成后把整个改好的项目打包给我。过程中如果构建报错，把报错和你的修复过程记录下来。
  ```
- **预期产出**：实测同类型——发 zip 给它，它自行拆包、调前沿模型（实测调 Claude Opus 5）完成代码级任务，15 分钟出活，过程在侧边栏可见（极客公园十天实测，2026-10-08）。
- **注意事项**：踩过的坑——它自信给错目录结构指令，直到被命令「去官方文档查」才解决。**涉及配置、路径、命令这类硬知识，追加一句「先查官方文档再回答」，关键步骤自己复核**（02 分册 §7）。

## 五·补 三个追加工作流（学习陪练 / 团队盯稿 / 自建派）

### 工作流 13：英语听力口语定时陪练（长期项）

- **适用产品**：首选 Today AI（定时任务 + 长期记忆犯过的错）。
- **选择理由**：官网定时任务示例本身就有「西班牙语练习周二/周四 20:30」，这是 Today 官方背书的玩法；关键是它记得你上周犯过的语法错误，不用每周重讲。
- **指令原文**：
  ```
  我在练英语听力和口语，目标是能去外企工作。请你每周二、周四晚上 8:30
  给我发一段 3 分钟的对话练习：主题轮流来（校园、技术面试、日常生活），
  我回复后你纠正我的语法和用词，并给一个更地道的说法；
  每两周做一次小结，告诉我哪类错误犯得最多。
  ```
- **预期产出**：每周两次定时推送 + 错因小结（官网示例机制，2026-10）。
- **注意事项**：它推练习的时间撞上你的晚自习？直接说「改到晚上 9 点半」——它会记住。

### 工作流 14：创业团队盯飞书 + 会议纪要流水线

- **适用产品**：首选 Today AI（国内版已接飞书，实测读完文档后每天主动问进度）。
- **指令原文**：
  ```
  我接上了咱们团队的飞书。请你读一遍我近一周的飞书文档，搞清楚我们创业项目
  现在卡在哪；以后每次团队会议结束，把纪要整理成：决策 / 待办（负责人+死线）/
  风险 三部分，发到对话里；有超过 3 天没动的待办，标红提醒。
  ```
- **预期产出**：实测同类——接飞书后它自动读出在写的两篇稿子和日更栏目，之后每天早 9 点自动推选题并追问进度（极客公园十天实测，2026-10-08）；社区还有现成的「会议纪要」Skill 可装。
- **注意事项**：团队成员的飞书权限你要先想清楚——它读的是**你的**飞书账号能看到的文档，不是全公司的。

### 工作流 15（自建派专属）：Hermes 每日早起简报 + 每周代码复盘

- **适用产品**：Hermes Agent / OpenClaw（已自建的同学）。
- **选择理由**：内置 cron 是自建派的杀手级功能，unattended 运行，不依赖任何商业 App。
- **指令原文**：
  ```
  （每日简报）每天早上 7:30 给我推送：西安今天天气、今日课程表、一条技术新闻。
  天气查准确的实时数据，不要猜。

  （每周复盘）每周日晚上 9 点，扫一遍我本周 git commit 记录，按项目总结我写了什么、
  哪里改了三次以上（说明没写好），发给我。
  ```
- **预期产出**：到点自动推送到你的 Telegram/聊天窗口；代码复盘是自动化审计，不用自己回忆（04 分册 §4.8 场景 A/C）。
- **注意事项**：Gateway 跑在本机，**笔记本关机即停**；长期挂着用就租 $5/月 VPS 跑 Linux 版（04 分册 §8 排查表）。凡是要付款、发消息、删文件的操作，先加审批指令：「先停下来问我确认，我同意了再执行」。

## 六、数字员工团队类工作流（1 个，复合范式）

### 工作流 12：「个人公司制」——你当老板，Bot 当员工

- **适用产品**：Grok Bot（唯一支持多 Bot 组队的产品）。
- **操作步骤**：按抖音创作者实战的分工范式搭团队，人只做三件事：定方向、批选题、最后拍板。
- **指令原文（建群分工）**：
  ```
  AI线：AI运营Bot + 视频Bot
  占星线（换成你的领域线）：运营Bot + 内容Bot
  共用：写作Bot、图片Bot、成果管理Bot
  财政大臣：专管额度与预算
  总管Bot：中国时间早8点推候选选题，晚8点汇报成果
  人只做三件事：定方向、批选题、最后拍板
  ```
- **预期产出**：实测跑通——两个业务线 + 共用中台 + 财政大臣控额度，总管 Bot 每天早 8 推选题、晚 8 汇报（抖音创作者实战，2026-10-13）。进阶玩法：再拉一个「经理 Bot」主动向你提问、梳理任务依赖、编排定时 Routine（人人都是产品经理，2026-10-17）。
- **注意事项**：①别一次建十个 Bot，按 30 天养成路线走（第 1 周只养 1 个，03 分册附录 A）；②分享 Bot 模板前自查——发布模板会带走指令、Skill、例行任务、连接器配置，确认不含个人化记忆再发（03 分册 §14）。

## 七、三个通用提示词模板（直接套用）

### 模板 A：数字员工角色设定模板（建 Bot 时用）

> Grok Bot 官方建议：描述写成「岗位契约」，而不是操作手册；步骤类流程要用 Teach a Task 演示教（continuumcode.ai，2026-08）。

```
【名称】______（带角色感，如：盯梢老王、课代表小郭）
【岗位名】______（一句话职位，如：课程资料研究员）
【描述】你是我的______。你负责______（长期职责），对我负责，
       产出______（你定期交付什么文件/消息）。
       铁律：①遇到发消息、付款、删文件的动作，先停下来问我；
       ②读不到原文的内容标「未核实」，不许编；
       ③没有值得说的更新时，只回一句「今日无更新」，不要刷屏。
```

### 模板 B：信息盯梢任务模板（挂例行任务时用）

```
你是我的______情报员。例行任务：每天早 8 点和晚 8 点各跑一次——
打开浏览器检查 [目标页面1]、[目标页面2]、[目标页面3]，对比上次记录：
发现新发布内容就：摘要成 3 条中文要点 + 原文链接，发到这个对话；
没有新内容就只回一句「今日无更新」。
筛选标准（只推符合的）：(a) ______；(b) ______；(c) 纯八卦/融资新闻不要。
旧记录存进你的资料库，下次对比用。
```

> 变体（Today 版）：把「例行任务」换成「每周一早上 8 点给我一份简报……其他时间不要打扰我」（02 分册 §2 第一个长期任务的原话）。

### 模板 C：学习笔记模板（喂资料时用）

```
这是我______课程/方向的资料（PDF/链接/截图）。请你：
1）整理成带小节标题的复习笔记，标注重点公式/概念和易错点，术语中英对照；
2）提炼 10 个关键知识点，每个写 3 句「讲给完全没基础的同学听」的解释；
3）列出我可能没搞懂的 3 个问题。
以后我再发这门课的资料，沿用同一套格式，不用重问背景。
```

## 九、第一周跑起来的节奏（别一次上十个工作流）

工作流再多，第一周只跑三个，多了顾不过来：

- **Day 1**：装 Today AI（或 Grok Bot），完成自我介绍（模板 C 的思路），只接**一个**邮箱。派第一个长期盯梢任务（工作流 4 或 6）。
- **Day 2**：等它的第一次推送/早报。挑出 1 条它说对的、1 条说错的——说错的地方立刻进「记忆」Tab 纠正（Today）或直接说「这条以后别提醒」。
- **Day 3**：喂第一批课程资料（工作流 2），跑通「资料→笔记」链路。
- **Day 4~5**：派第一个重活——一篇英文长文（工作流 1）或一次云电脑跑代码（工作流 10，Grok Bot）。
- **Day 6~7**：做一次「记忆审计 + 推送规则收紧」。判断标准（抖音测评博主建议，2026-10-02）：一周后回看，有几条提醒真帮你提前处理了问题？有几条只是打扰？**前者多就继续加工作流，后者多就收紧连接和推送规则。**

> 教训沿用分册：①别一上来接主邮箱/飞书全量权限，先用小号练手；②它推错一次就明确说「这条以后不用提醒我」，追踪类任务写死「没有就别发」；③复杂任务让它自动拆到「任务」栏，别都堆主对话（02 分册 §7 避坑表）。
