# 05 · 常见问题与坑

> 每个坑：症状 → 原因 → 解法 → 来源。按类别组织。
> 标注【官方】/【社区】。调研截止 2026-10-20。

---

## A. 安装类

### A1. 装完敲 `hermes` 报 command not found

- **症状**：install 脚本没报错，重启/重开终端后 `hermes` 命令不存在。
- **原因**：启动器路径（`~/.local/bin/hermes`）还没加载进当前 shell。
- **解法**：

```bash
source ~/.bashrc
```

- **来源**：【社区】BetterClaw 作者自述折腾 3 小时的真实案例 \<https://www.betterclaw.io/blog/hermes-agent-not-working>

### A2. WSL2 里 git clone 报 `GnuTLS recv error`

- **症状**：安装或克隆仓库时 TLS 报错中断。
- **原因**：WSL2 网络 / TLS 偶发问题。
- **解法**：重试；有中文教程建议换国内镜像源提速。
- **来源**：【社区】掘金实战 \<https://juejin.cn/post/7628894338689024015>

### A3. Python 依赖大包下载超时

- **症状**：安装中途依赖下载卡住/超时。
- **原因**：默认 HTTP 超时太短。
- **解法**：

```bash
export UV_HTTP_TIMEOUT=300
```

- **来源**：【社区】同上掘金。

### A4. Windows Defender 把 `uv.exe` 报成木马

- **症状**：Windows 原生安装时杀软拦截捆绑的 uv。
- **原因**：误报（已知问题）。
- **解法**：按 README 的 gh attestation 核验脚本真实性，然后加白名单。
- **来源**：【官方】README / Installation 页 \<https://hermes-agent.nousresearch.com/docs/getting-started/installation>

### A5. 用 `pip install hermes-agent` 安装失败/不对

- **症状**：pip 装出来的不能用。
- **原因**：官方明确告诫不要这么装——受管安装要 bootstrap uv、准备固定版本运行时。
- **解法**：用官方一键命令（见 02 文件）。
- **来源**：【官方】Installation 页。

## B. 配置类

### B1. 装好了但 agent "不会自我进化"

- **症状**：没有自动沉淀 skill / 记忆。
- **原因**：**自学习默认关闭**。
- **解法**：

```bash
hermes config set memory.persistent true
hermes config set skills.autogen true
```

- **来源**：【社区】dplooy（首次使用最常见的"惊喜"）\<https://www.dplooy.com/blog/hermes-agent-nous-researchs-self-learning-ai-runtime>

### B2. 工具调用静默失败

- **症状**：agent 起来了、模型连上了，但 web 搜索/浏览什么都不发生，无报错。
- **原因**：本地模型过不了 web backend 检查；或 provider 配置问题。
- **解法**：留一个云模型做 "web access provider"；`hermes tools` 检查逐工具配置。
- **来源**：【社区】BetterClaw（"最耗时间的一层"）\<https://www.betterclaw.io/blog/hermes-agent-not-working>；官方 Ollama 文档互证。

### B3. provider 限流后切换模型，上下文被静默截断

- **症状**：中途从 gpt-5 切到免费 OpenRouter 模型后，长对话表现异常。
- **原因**：切换后上下文窗口/行为不兼容，静默截断。
- **解法**：切模型时同步评估上下文窗口；长会话用 `/compress`。
- **来源**：【社区】andrew.ooo \<https://andrew.ooo/posts/hermes-agent-nous-research-self-improving-review/>

## C. 模型与成本类

### C1. 模型 <64K 上下文，启动直接被拒

- **症状**：启动报错要求更大上下文。
- **原因**：【官方】硬性要求至少 64,000 token 上下文窗口。
- **解法**：换 ≥64K 的模型；Ollama 启动时显式指定：

```bash
ollama run <model> -c 65536
```

- **反面教材**：有人 sed 改 `context_length: 65536` "骗过检查"，实际模型仍 32K，长对话会遗忘——不推荐。
- **来源**：【官方】快速入门；【社区】掘金 \<https://juejin.cn/post/7628894338689024015>

### C2. Ollama 默认 context 仅 2048

- **症状**：本地模型一接长对话就忘。
- **原因**：Ollama 默认 context 太小。
- **解法**：同 C1 显式 `-c 65536`。
- **来源**：【社区】第三方教程站 \<https://hermes-agent.wulu.ai/>【仅摘要】

### C3. token 消耗比预期高

- **症状**：同样的对话，API 账单超预期。
- **原因**：工具定义本身占 ~50% 输入 token；内置工具太多用不到又没方便开关（约 15% token）；每次调用约 73% 是固定开销（~13.9K tokens 加载上下文+skill 库，Reddit 实测口径）。
- **解法**：① 保持 system prompt 稳定吃满 prompt cache；② 长会话 `/compress`；③ `/usage`、`/insights` 查消耗；④ `hermes prompt-size` 离线算固定开销；⑤ 复杂任务用 `delegate_task` 并行子智能体（各自独立上下文，只回汇总）；⑥ 把后台 review 路由到便宜模型（官方称成本低 3–5×）。
- **来源**：【官方】Tips；【社区】dplooy、腾讯云 \<https://cloud.tencent.com/developer/article/2702804>、博客园转述 Reddit \<https://www.cnblogs.com/haibindev/p/19881562>

### C4. 记忆库越用越大

- **症状**：~200 次对话后 SQLite 库达 280MB。
- **原因**：无自动压缩。
- **解法**：用 `/compress`；定期 `/journey` 剪枝。
- **来源**：【社区】andrew.ooo。

## D. WSL2 / Windows 类

### D1. WSL2 里访问 Windows 端 Ollama 怎么都不通

- **症状**：WSL2 内 Hermes 连 Windows 的 Ollama 连接失败。
- **原因**：① Ollama 只监听 127.0.0.1；② **Windows 防火墙自动创建了 ollama.exe 的 Block 规则**。
- **解法**：Windows 端设置 `OLLAMA_HOST=0.0.0.0`；进 Windows 防火墙**手动删掉 ollama.exe 的 Block 规则**再放行。
- **来源**：【社区】掘金实战（高价值）\<https://juejin.cn/post/7628894338689024015>

### D2. Windows 原生到底支不支持？

- **症状**：看到中文文档写"早期测试版"，英文写"fully supported"，不知道听谁的。
- **解法**：以英文页为准（官方一手）；但遇到问题优先回退 WSL2——社区长期主路径。
- **来源**：【官方】英文 README vs 中文首页口径矛盾，详见 02 文件第 2 节。

### D3. Windows 写文件乱码

- **症状**：agent 写出的文件中文乱码。
- **原因**：默认 cp125x 编码。
- **解法**：显式 UTF-8 编码。
- **来源**：【官方】Tips \<https://hermes-agent.nousresearch.com/docs/guides/tips>

## E. 消息网关 / 风控类

### E1. Telegram bot `409 Conflict`

- **症状**：gateway 起来后 Telegram 报错。
- **原因**：同一个 bot token 多端同时 getUpdates，互相冲突。
- **解法**：只保留一个 gateway 实例；关掉别处的 webhook/轮询。
- **来源**：【社区】BetterClaw \<https://www.betterclaw.io/blog/hermes-agent-not-working>

### E2. gateway 连 Telegram 超时

- **症状**：国内网络直连 Telegram 不通。
- **解法**：配置 `HTTPS_PROXY`。
- **来源**：【社区】CSDN 一粒黑子（软文口径但与他源吻合）\<https://blog.csdn.net/u014354882/article/details/160173016>

### E3. 个人微信 / WhatsApp 接入后封号

- **症状**：扫码接入个人微信，号被风控/封禁。
- **原因**：走第三方桥接违反平台条款。
- **解法**：① 优先 Telegram / Discord / 飞书（正式 bot API）；② 微信/WhatsApp 用小号、专用号码，不群发、不主动 outbound；③ 抖音教程建议"私信审批、禁群聊、设主管频道"。
- **来源**：【社区】抖音封号叙事（注：该分享页 2026-10-20 抽查返回 404，视频可能已下架，观点来自调研原始记录）\<https://www.iesdouyin.com/share/video/7695121437635513650>；官方 whatsapp 文档口径（中文镜像站）；51CTO \<https://www.51cto.com/article/856449.html>

### E4. 陌生人能触发 bot

- **症状**：bot 在群里被陌生人乱用。
- **原因**：网关默认拒绝名单外用户，但配置不当会放开。
- **解法**：**绝不要开 `GATEWAY_ALLOW_ALL_USERS=true`**；用 DM 配对码（一次性、1 小时过期）；admin/普通用户分级。
- **来源**：【官方】Messaging 页 \<https://hermes-agent.nousresearch.com/docs/user-guide/messaging>

## F. 记忆 / 技能误操作类

### F1. agent 说记住了但没记住

- **症状**：小模型嘴上说"记住了"，文件里没有。
- **原因**：小模型（<30B）常不调 memory 工具。
- **解法**：核对

```bash
cat ~/.hermes/memories/MEMORY.md
```

- **来源**：【官方】Memory 页。

### F2. 当次会话说的"记住这个"没生效

- **症状**：刚说的事下一句就忘了。
- **原因**：会话中途写入的记忆是冻结快照，**下一会话才生效**。
- **解法**：理解机制；要立即生效的事直接写进 prompt / AGENTS.md。
- **来源**：【官方】Memory 页。

### F3. 自进化 skill 把错误流程固化（最大坑）

- **症状**：你手动改好一个 bug，下次 agent 又按旧 skill 把错误改回去；skill 库越来越乱。
- **原因**：agent 几乎总认为自己做对了，错误经验也会沉淀成 skill（三方互证）。
- **解法**：① 定期审查 `~/.hermes/skills/` 手动修剪；② `/journey` 剪枝；③ 关闭自动 review 改人工 `/learn`；④ 多项目用 profile 隔离。
- **来源**：【社区】博客园转述 Reddit \<https://www.cnblogs.com/haibindev/p/19881562>；腾讯云 \<https://cloud.tencent.com/developer/article/2702804>；andrew.ooo。

## G. 安全隐私类

### G1. 想让 agent 自动批准危险命令

- **症状**：YOLO / `approvals.mode: off` 图省事。
- **解法**：保持默认 `smart`；第一次选「session」不要「always」；cron 下 YOLO 也不生效（硬线黑名单拦 `rm -rf /` 等）。
- **来源**：【官方】Security 页 \<https://hermes-agent.nousresearch.com/docs/user-guide/security>

### G2. 不想让对话内容出本机

- **症状**：隐私敏感（课程代码、个人笔记）。
- **解法**：全 BYOK + 本地 Ollama 模型，不开 Portal / Tool Gateway，对话与记忆可完全不出本机【编者推断】；网关开 `privacy.redact_pii: true`。
- **来源**：【官方】Security / Messaging 页机制；推断部分已标注。

## H. 更新 / 工程化债类

### H1. `hermes update` 后版本行为突变

- **症状**：点了更新，被切到 main 分支开发版，bug 频出，甚至 502。
- **原因**：update 曾默认拉 main（每日未发布改动）。
- **解法**：常驻环境钉 release tag；更新前看 changelog；API 约每两周 breaking change，生产 pin 版本。
- **来源**：【官方 issue #58746】\<https://github.com/NousResearch/hermes-agent/issues/58746>

### H2. 安装体积大、npm audit 一堆漏洞

- **症状**：fresh 沙箱实测拉 1209 个 npm 包、占 1452MB，audit 报 15 个漏洞（11 high / 3 moderate / 1 low）；仓库 ~311 万行代码。
- **解法**：知道即可；无 root build/test script，供应链风险存在；企业环境需自行评估。
- **来源**：【社区】mrkeyoor 沙箱实测 \<https://mrkeyoor.com/repos/hermes-agent/>

### H3. open issues 积压

- **症状**：报的 bug 石沉大海。
- **原因**：open 16,267（2026-10-20），增长比关闭快；v0.21.5 时 open 队列 45,710。
- **解法**：遇问题先搜 issue 是否已有 workaround；别指望官方快速修。
- **来源**：【官方】issues 页；【社区】mrkeyoor。

### H4. MCP allowlist 意外失效

- **症状**：用 `mcp-<server>` 规范名配一个 MCP server，结果启用了所有已配置 server。
- **解法**：已知 open bug #128017；配置 MCP 前注意命名规范带来的副作用。
- **来源**：【社区】mrkeyoor 引用 open issue \<https://mrkeyoor.com/repos/hermes-agent/>
