# 08 · 从 Claude Code 学到的 10 个工程模式

> 把前几篇的批注收拢成一张"模式清单"。每条模式都是可以直接搬去你自己的项目/产品/工作流的。编号持续可加。

## 模式 1：单循环 + 工具，而不是多阶段流水线

Agent 的第一版永远是：`while True: 调模型 → 执行工具`。不要一上来就编排 DAG。Anthropic《Building effective agents》的核心论点：**先问能不能用最简单的循环+提示词解决，不能才加工作流，再不能才上多代理。** 复杂度是负债，每层编排都会让调试难度翻倍。

## 模式 2：模型只有提议权，执行权在 harness

所有副作用（读文件、跑命令、发请求）都由 harness 代为执行，模型只输出结构化"意图"。由此免费获得：权限门、审计日志、结果裁剪、打断处理。**架构上最值钱的一刀，就是切在"意图"和"执行"之间。**

## 模式 3：错误是信息，不是异常

工具失败 → 错误文本回填上下文 → 模型自纠。给模型的第一手错误信息要"可行动"（not found → 说明找过哪些路径）。你的 Agent 自愈能力 = 错误信息的质量。

## 模式 4：用协议防幻觉（Edit 的 old_string）

"改文件"不是让模型输出新文件全文，而是"原文片段+新文片段"，原文片段本身就是校验锚点。**把校验内置到交互协议里，比事后检查便宜一个数量级。**

## 模式 5：上下文是预算，一切按预算管理

固定开销（系统提示词/工具定义/CLAUDE.md）要薄；动态内容（工具结果）要裁剪；历史要压缩或清空；脏活外包给子代理。给每个信息源标"信息密度"，低密度的先扔。

## 模式 6：渐进式披露

Skills 的三层加载（目录常驻、正文按需、附件更次）是通用模式。任何"知识库/插件/文档"系统都该问：能不能只常驻一行摘要？**为注意力付费的不该是目录，而该是正文。**

## 模式 7：状态外化到文件

TODO 用 TodoWrite 落到界面、计划落成 plan 文件、记忆落成 CLAUDE.md。**凡是需要跨轮次、跨会话存活的东西，都写到上下文之外**——文件是比对话历史可靠得多的存储介质。

## 模式 8：软引导为主，硬护栏为辅，事后可撤销兜底

三层安全（03 篇的"三明治"）：配置规则（可审计）→ 沙箱（物理隔离）→ checkpoint/rewind（可撤销）。单独任何一层都不够，叠加后单次犯错成本趋近于零。**安全设计的目标是降低事故成本，不是消灭事故。**

## 模式 9：扩展点按信任分级

命令（信模型执行）→ 技能（信模型判断时机）→ Hook（不信模型，代码说了算）。设计任何可扩展系统时先画这张信任谱，再决定每个功能落在哪个级别。

## 模式 10：文本即通用接口

工具进出是文本、子代理返回是文本、配置是文本（YAML/Markdown）。文本让生态可以野蛮生长（MCP server 爆发就是因为接口足够"笨"）。**接口越通用，生态越繁荣；接口越聪明，生态越狭窄。**

---

## 附：反面模式（从失败 Agent 产品里总结的）

- **多阶段编排起步**：Plan→Search→Write→Review 四阶段流水线，任何一步卡死全链瘫。第一版就该是单循环。
- **工具结果直塞上下文**：网页全文、整库日志。三轮就爆窗口。
- **让模型自评权限**：模型说"这个操作很安全"就算安全。权限必须语法化。
- **记忆=往数据库塞聊天记录**：检索回来一堆旧对话，没有"信息寿命"概念。
- **提示词里写礼貌不写规则**："请小心不要犯错"是无效指令；"不要用 rm -rf，删除前列出文件清单"才是指令。
