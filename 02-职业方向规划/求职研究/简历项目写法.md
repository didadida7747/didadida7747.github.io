# 简历与作品写法

更新时间：2026-09-03。

## 项目条目模板

```text
项目名称｜时间｜个人项目/实验室项目
背景：系统要解决什么问题。
职责：你独立完成的模块，不写团队整体成果。
技术：只列自己实际使用并能解释的技术；可为 Python/FastAPI/HTTP/SQLite/测试、FFmpeg/C++/媒体管线，或 AI 检索/评测/接口。
结果：用实测数据写正确率、拒答、延迟、异常覆盖、处理耗时、输出体积、吞吐或恢复时间等；没有测量就不写数字。
证据：仓库、README、架构图、实验报告、演示视频。
```

## 弱表达与强表达

| 弱表达 | 强表达方向 |
|---|---|
| 学习了 STM32 外设 | 实现 DMA 采集、周期调度和异常恢复，并完成测试 |
| 熟悉 C 语言 | 独立封装驱动接口，处理缓冲区、状态机和错误码 |
| 了解 ROS2 | 编写节点与 Launch，将 STM32 数据发布为话题并记录 rosbag |
| 学过强化学习 | 复现 baseline，改变一个变量并报告训练曲线与指标 |
| 调用了大模型 API | 构建带固定评测集的日志诊断服务，记录命中、误判、拒答、延迟和异常处理 |
| 做了一个 RAG | 说明数据来源、切分/检索基线、评测方法和失败样例，不只展示聊天截图 |
| 做了一个后端项目 | 说明接口、数据模型、幂等/重试、日志、测试和一次故障定位，不把 CRUD 包装成基础架构 |
| 参加了黑客松 | 写清是否入选/获奖、成品链接、个人负责模块和评审结果；单纯参与不单列 |

## 作品仓库最低标准

- README 能让陌生人从零安装、编译/启动并运行核心流程。
- 有架构图；硬件项目补接线和协议，AI 应用补数据流、接口和评测集说明。
- 有失败记录和测试数据，不只展示成功截图。
- 代码能指出哪些部分是自己写的、哪些来自库或参考资料。
