# 常用提示词模板

复制后把方括号替换成你的具体信息。

## 只读项目

```text
请先不要修改任何文件。

请阅读当前项目并输出项目理解报告：
1. 项目用途
2. 技术栈
3. 关键目录和文件
4. 启动、测试、构建命令
5. 不应随便修改的文件
6. 对新手最友好的第一个练习任务
```

## 修 bug

```text
我遇到一个 bug：
【现象】

复现步骤：
1. 【步骤 1】
2. 【步骤 2】

期望结果：
【期望】

实际结果：
【实际】

请先定位原因，不要直接修改。请输出：
1. 可能相关文件
2. 推理链路
3. 最小修复方案
4. 需要我确认的信息
```

## 小步实现

```text
请做一个小步实现。

目标：
【目标】

范围：
只允许修改【文件/目录】

要求：
1. 保持现有功能不变
2. 不新增依赖
3. 不改公共接口
4. 修改后运行/说明验证方式
5. 最后总结 diff 和风险
```

## 前端页面优化

```text
请优化【页面/组件】。

目标用户：
【用户】

风格要求：
【例如：克制、清晰、工具型、不要营销页感】

边界：
1. 只改【文件】
2. 不改变路由和接口
3. 移动端必须可用
4. 文案不要解释功能本身
5. 修改后检查是否有文字重叠
```

## 写测试

```text
请为【模块/函数】补测试。

要求：
1. 先阅读现有测试风格
2. 沿用当前测试框架
3. 覆盖正常路径、异常路径、边界条件
4. 不改业务逻辑，除非测试暴露真实 bug 并先说明
5. 运行相关测试并报告结果
```

## 代码审查

```text
请对当前改动做代码审查，不要修改文件。

请重点检查：
1. 是否有 bug 或回归风险
2. 是否改了无关文件
3. 是否有安全问题
4. 是否缺测试
5. 是否有更简单的实现

请按严重程度排序，只列真实问题，不要泛泛建议。
```

## 交付总结

```text
请进入交付总结阶段，不要继续新增功能。

请输出：
1. 本次修改摘要
2. 涉及文件
3. 已运行验证命令和结果
4. 未验证部分
5. 风险
6. 建议 commit message
7. 后续最小下一步
```
