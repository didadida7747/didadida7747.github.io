# 09 · 官方工程博客导读：Anthropic 亲口讲的设计理念

> 源码告诉你"是什么"，官方博客告诉你"为什么"。Anthropic 工程博客（anthropic.com/engineering）的这几篇是 Agent 设计的一手文献，本篇给每篇划重点 + 我的批注，省你通读时间。原文链接可搜索标题获得（标题原样给出，方便检索）。

## 1.《Building effective agents》（2024.12）

**一句话**：别急着上框架。先分清 workflow（代码编排 LLM）和 agent（LLM 自主循环），能简单就别复杂。

**核心内容**：五种由简到繁的模式——
1. **Prompt chaining**（提示词链）：任务拆步，前一步输出是后一步输入，中间可加程序化检查点。
2. **Routing**（路由）：先分类再分发，每类用专属提示词/工具。
3. **Parallelization**（并行）：切片并行 + 投票并行。
4. **Orchestrator-workers**（指挥-工人）：一个 LLM 动态拆任务派发。
5. **Evaluator-optimizer**（评估-优化循环）：一个生成一个挑刺，循环到达标。

**我的批注**：这篇的"五模式"已经成为行业通用词汇表，读懂它 = 有了给一切 Agent 产品定位的坐标系。文中反复强调"何时不用 agent"（定义清晰、不需要灵活判断的任务用 workflow 更省钱可靠）——这种"反卖货"的诚实是它含金量高的原因。

## 2.《Claude Code: best practices》（2025，作者含 Boris Cherny）

**一句话**：Claude Code 作者本用法说明书，重点在"探索→计划→写码→提交"的节奏控制。

**核心要点**：
- CLAUDE.md 写构建命令、代码风格、测试习惯；
- **给权限、给引导**：先让它读代码再动手，"wait, don't code yet"是名场面话术；
- **多用 /clear**：任务切换就清上下文；
- 多 CC 并行：多个终端各干一件事，或 headless 模式自动化；
- 用截图/链接喂上下文，用 `#` 快捷沉淀记忆；
- checklist 驱动：让它先产出计划清单，再逐项执行。

**我的批注**：这篇是"交互记录"类教材的官方样本（04 章会拆它的完整用法）。注意一个隐藏主线：**用户的工作不是写代码，是管理上下文和验收产出**——工具越强，人的角色越像 tech lead 而不是打字员。

## 3.《How we built our multi-agent research system》（2025.6）

**一句话**：Anthropic 自家 Research 功能的复盘：orchestrator-worker 多代理架构的工程细节与血泪教训。

**核心要点**：
- Lead agent 负责拆解规划，子代理并行搜索，各自独立上下文；
- Token 消耗约为单代理聊天 **15 倍**——多代理要用在值得的任务上；
- 给 lead 的努力分级规则（简单事实 1 代理，中等 2-4，深入 10+）写进了提示词；
- 子代理的返回质量取决于任务书质量：必须写明目标、输出格式、工具偏好；
- 教训：多代理的可靠性瓶颈在"协调"不在"单兵"。

**我的批注**：这是 05 篇（子代理）的一手出处。最有价值的是"努力分级规则"——把"何时扩军"写成规则注入提示词，而不是靠模型自觉。这种**把管理经验写进 harness**的思路非常值得偷。

## 4.《Writing effective tools for agents — with AI agents》（2025.9）

**一句话**：工具设计的实战手册：写工具提示词、选响应格式、控制 token 成本。

**核心要点**：
- 工具响应是主要 token 消耗源：选**高信号格式**（如简洁的搜索结果优于原始网页）；
- 一次工具响应控制在 token 预算内（如 25k），超长内容**外置成文件路径**让 Agent 按需再取；
- 命名空间/参数名要无歧义；响应要可高效索引（行号、稳定格式）；
- 他们的方法论：**用 Claude 帮 Claude 优化工具**（让 agent 实测工具并提出改进）。

**我的批注**："超长结果外置成文件"这个技巧直接回应了 04 篇的上下文经济学。另外"让 Agent 评测 Agent 的工具"是个方法论彩蛋——你现在就可以用在优化自己的提示词上。

## 5.《Effective context engineering for AI agents》（2025.9）

**一句话**：从 prompt engineering 进化到 context engineering：找"最小充分信息集"。

**核心要点**：
- 注意力是稀缺资源（"lost in the middle"），上下文不是越多越好；
- 三大技术：**压缩**（compaction）、**结构化笔记**（agentic memory，写 todo/notes 文件）、**子代理架构**（隔离上下文）；
- 系统/工具/示例都要"刚好够用"（just enough）；
- 用 CLAUDE.md/AGENTS.md 沉淀经验。

**我的批注**：04 篇的一手出处。"最小充分集"这个提法值得刻在脑子里：所有上下文优化的终点都是它。

## 6.《Anthropic's internal Claude Code talk》（团队内部分享，2025）

**一句话**：造 Claude Code 的团队讲自己怎么用 Claude Code，/clear 高频出现。

**核心要点**：内部工程师日常 = 多窗口并行 + 勤 clear + CLAUDE.md 持续沉淀 + "和它结对而不是下订单"的心态。

**我的批注**：当你怀疑"这些最佳实践是不是营销话术"时，看造工具的人自己怎么用最有说服力。他们和你的差别只有一点：纪律性（clear 得更勤、计划先行做得更彻底）。
