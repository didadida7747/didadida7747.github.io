# 04 · 数据备份 3-2-1 方案

> 你最不可再生的数字资产：课程论文、实验数据、竞赛代码、GitHub 仓库、照片、笔记。硬盘损坏/误删/勒索病毒/笔记本被偷，任何一样都可能一次清空。**3-2-1 是业界通行标准：3 份副本、2 种介质、1 份异地。**

---

## 一、个人版 3-2-1 落地方案

```
副本1（本地工作区）：拯救者本地文件
副本2（近线备份）  ：移动硬盘（每周插一次全量同步）
副本3（异地容灾）  ：网盘自动同步 + GitHub 私有仓库（代码/笔记）
```

| 资产类型 | 副本2（硬盘） | 副本3（异地） | 频率 |
|---|---|---|---|
| 课程论文 / 实验报告 | 复制整目录 | 网盘同步目录 | 每周 + 交稿前 |
| 代码 / 大模型项目 | Git 仓库目录 | **GitHub 私有仓库**（push 即异地） | 每次提交 |
| 笔记（Obsidian 等） | 仓库目录 | GitHub 私有仓库 / 网盘 | 每周 |
| 照片 / 视频 | 照片库 | 网盘（或 ente 加密相册） | 每月 |

> GitHub 学生包里有免费私有仓库额度（其实个人无限免费），代码类资产的异地备份**零成本**——这也顺便养成了"天天 commit"的工程习惯。

## 二、加密上传（敏感文件进云前的最后一步）

| 工具 | 链接 | 定位 | 核验状态 |
|---|---|---|---|
| Cryptomator | [cryptomator/cryptomator](https://github.com/cryptomator/cryptomator) | 上传网盘前客户端加密：建"保险库"拖入网盘同步目录，云端只见密文 | 已核验 16,235★ |

> 适用：奖学金材料、身份证照片、家庭信息等不想交给云厂商明文保存的目录。代码与普通课件可不做。

## 三、自动备份工具（进阶，Windows 可用）

| 工具 | 链接 | 定位 | 核验状态 |
|---|---|---|---|
| restic | [restic/restic](https://github.com/restic/restic) | 快速、加密、增量备份 CLI：`restic backup 目录` 一条命令，支持定时任务到硬盘/网盘 | 已核验 36,391★ |
| rclone | [rclone/rclone](https://github.com/rclone/rclone) | 网盘命令行瑞士军刀（"rsync for cloud"），脚本化同步几十种云存储 | 已核验 60,082★ |
| Syncthing | [syncthing/syncthing](https://github.com/syncthing/syncthing) | 设备间 P2P 持续同步（不经第三方云）：笔记本 ↔ iPad/其他电脑互为备份 | 已核验 89,111★ |

> 学生阶段建议：**先用"手动拷硬盘 + 网盘客户端自动同步"跑通**，等脚本需求真出现了再上 restic/rclone——工具是为备份习惯服务的，不要倒过来。

## 四、防勒索与误删的两条附加原则

1. **副本 ≠ 同步**：网盘同步会把你的"误删"也同步掉。所以必须有一份**离线副本**（移动硬盘拷完就拔）——这是 3-2-1 里"2 种介质"的真正含义。
2. **定期演练恢复**：每学期从备份里随机恢复一个文件试试。没验证过的备份等于没有备份。

## 五、最小可行版（今天就做，10 分钟）

1. 网盘客户端装好，把「课程」「项目」「照片」三个目录设为自动同步；
2. 移动硬盘建 `备份/YYYY-MM-DD` 目录，今晚全量拷一次；
3. 代码目录 `git init` + 建 GitHub 私有仓库，以后写完就 push；
4. 在日历里加一个**每周五 17:00** 的重复提醒："插硬盘，跑备份"。
