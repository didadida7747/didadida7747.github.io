# 第 12 章 环境变量与开发环境

> 学完这章，你能把一台刚装好的 Ubuntu 从"裸系统"配成"能 Git 拉代码、Python 跑 Flask、Node 跑前端"的正经开发机——而且知道每一步为什么这么配。

## 本章你将学会

- 搞懂环境变量和 `PATH`，能自己写持久化配置并解决"为什么我配的变量不生效"
- 用 `alias` 配出 `ll`、`gs` 这种偷懒快捷键
- 装好 Git、配置好 GitHub 免密推送
- 用 `venv` 给 Python 项目建独立环境、给 pip 换国内源
- 用 `nvm` 装 Node.js（而不是傻乎乎用 apt 装）
- 装 `build-essential` 编译工具链（配合你 C/C++ 课程）
- 在 WSL 里用 VS Code Remote 打开项目

## 12.1 环境变量与 PATH：命令到底是怎么找到的

### 什么是环境变量

环境变量就是一组"系统全局的键值对"，所有程序启动时都能读到。你前面已经见过几个了：

```bash
$ echo $HOME
/home/yourname
$ echo $USER
yourname
$ echo $SHELL
/bin/bash
```

`HOME` 是你家目录、`USER` 是用户名、`SHELL` 是你用的 shell。这些是系统启动时就设好的。你也可以自己加。

### PATH：为什么输 `ls` 能找到 `/bin/ls`

你输 `ls` 的时候，bash 怎么知道 `ls` 这个程序在哪？答案在 `PATH` 这个变量里：

```bash
$ echo $PATH
/home/yourname/.local/bin:/usr/local/bin:/usr/bin:/bin:/usr/local/games:/usr/games
```

冒号分隔的一串目录。bash 的逻辑是：**你输一个命令，它就按顺序去这些目录里找有没有这个名字的可执行文件，找到第一个就执行。**

- `/usr/bin/ls`：`ls` 在这
- `/usr/bin/python3`：Python 在这

> 📌 **注意：** 当你自己装了个软件（比如 `~/go/bin/myapp`），敲 `myapp` 提示"command not found"，十有八九是它的目录**不在 PATH 里**。解决办法：要么用绝对路径 `~/go/bin/myapp`，要么把它加进 PATH（下面讲）。

### 找一个命令在哪：`which` / `whereis`

```bash
$ which python3
/usr/bin/python3

$ which ls
/usr/bin/ls

$ whereis git
git: /usr/bin/git /usr/share/man/man1/git.1.gz
```

| 命令 | 给什么 |
|---|---|
| `which 命令` | 只给**第一个**可执行文件路径（实际会跑哪个） |
| `whereis 命令` | 可执行文件 + 源码 + man 手册位置，全列出来 |

当你发现"我装了两个 python，为什么跑的是旧的"，用 `which -a python3` 把所有位置列出来。

### 临时加 PATH vs 永久加 PATH

**临时（只在当前终端有效）：**

```bash
$ export PATH="$HOME/mytools/bin:$PATH"
```

意思是：把 `~/mytools/bin` 塞到 PATH **最前面**（`$PATH` 是原来的值）。当前终端立刻生效，关掉就没了。

> 📌 **注意：** 放**前面**还是**后面**有讲究。放前面 = "我这个版本优先用"，能盖过系统自带的同名命令（nvm 装 Node 就是这么干的）。放后面 = 系统有同名命令时还是用系统的。

**永久（写到配置文件里）：**

```bash
$ echo 'export PATH="$HOME/mytools/bin:$PATH"' >> ~/.bashrc
$ source ~/.bashrc
```

### `.bashrc`、`.profile`、`source`——为什么配置不生效

新手 90% 的困惑是："我明明写进 `.bashrc` 了，怎么新开终端还是没生效？" 我们一次讲清。

| 文件 | 什么时候读 | 放什么 |
|---|---|---|
| `~/.bashrc` | 每次开**新的 bash 终端**（交互式 shell）时 | alias、PATH、环境变量——**你的配置基本都写这儿** |
| `~/.profile` | 登录时（比如 SSH 登录、首次开终端） | 登录级别的配置 |
| `~/.bash_profile` | 如果存在，会**优先于** `.profile` 被读 | Ubuntu 默认没有，很多教程让你建这个 |

> 📌 **注意：** Ubuntu 默认情况是 `.profile` 里会自动去读 `.bashrc`（你打开它能看到最后几行）。所以**日常配置就写 `~/.bashrc`**，不用纠结其他文件。

**写完配置不生效怎么办？** 两种情况：

1. **当前终端不生效** —— 配置文件是"启动时读一次"，你改完之后当前终端不会自动重读。手动 `source ~/.bashrc` 一下。
2. **新开终端也不生效** —— 检查：
   - 你是不是写到 `~/.bash_profile` 去了，而你这台机器读的是 `.bashrc`？
   - 是不是语法写错了（少引号、少 `export`）？下次开终端会在最上面报错。
   - 是不是写到 `/etc/environment` 这种系统级文件去了，语法不对？

> 💡 **小技巧：** 改完 `.bashrc` 想知道写没写错，新开一个终端看第一行——如果有 `-bash: xxx: command not found` 这种报错，就是你写错了，赶紧回去修。

## 12.2 alias：给自己配偷懒快捷键

`alias` = 给长命令起个短名字。

```bash
# 临时用
$ alias ll='ls -alF'
$ ll                 # 等价于 ls -alF

$ alias gs='git status'
$ alias update='sudo apt update && sudo apt upgrade'
```

写成永久配置就追加到 `~/.bashrc`：

```bash
$ echo "alias ll='ls -alF'" >> ~/.bashrc
$ echo "alias gs='git status'" >> ~/.bashrc
$ echo "alias ..='cd ..'" >> ~/.bashrc
$ source ~/.bashrc
```

常用别名推荐表：

| 别名 | 实际命令 | 作用 |
|---|---|---|
| `ll` | `ls -alF` | 长格式看文件 |
| `..` | `cd ..` | 回上一级 |
| `...` | `cd ../..` | 回上两级 |
| `gs` | `git status` | 看 git 状态 |
| `gp` | `git push` | 推送 |
| `update` | `sudo apt update && sudo apt upgrade` | 一键更新系统 |

查看你现在有哪些别名：`alias`。取消一个：`unalias ll`。

### PS1：你的命令行长啥样（简介）

你终端前面那串 `yourname@machine:~$` 是 `PS1` 变量控制的。一般不用动，但如果你想显示 git 分支（很有用），Ubuntu 默认的 bash-git-prompt 已经帮你弄好了——装完 git 进一个仓库，命令行就会自动显示 `(master)`。

真要改 PS1 也只是一行 `export PS1=...` 的事，网上模板很多，这里不展开，免得你配乱了。

## 12.3 Git：版本控制与 GitHub 协作

Git 是程序员的"时间机器"——你写完一段代码、把它"存档"一次，以后随时能回到任何一次存档。**这是后端/算法/竞赛必备技能，学不会 Git 等于没法在团队干活。**

### 安装与首次配置

```bash
$ sudo apt update
$ sudo apt install -y git
$ git --version
git version 2.43.0
```

装完第一件事：告诉 Git 你是谁（每次存档都会记录这个）：

```bash
$ git config --global user.name "你的名字"
$ git config --global user.email "你的GitHub邮箱@example.com"

# 顺便设个默认分支名和默认编辑器
$ git config --global init.defaultBranch main
$ git config --global core.editor nano
```

`--global` 的意思是"全局，所有仓库都用这个"。这些配置写在 `~/.gitconfig` 里，你可以随时 `git config --list` 看一眼。

### SSH key：让 GitHub 不用每次输密码

HTTPS 方式推代码每次都要输 token，麻烦。配一次 SSH key 终身免密：

```bash
$ ssh-keygen -t ed25519 -C "你的GitHub邮箱@example.com"
```

一路回车（passphrase 直接回车留空）。它会生成两个文件：

- `~/.ssh/id_ed25519`：**私钥**（永远不告诉任何人，就像密码）
- `~/.ssh/id_ed25519.pub`：**公钥**（给别人看的，贴到 GitHub）

把公钥内容贴到 GitHub：

```bash
$ cat ~/.ssh/id_ed25519.pub
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIxxxxxxxx 你的邮箱
```

复制这一整行，去 GitHub 网页：右上角头像 → `Settings` → `SSH and GPG keys` → `New SSH key`，粘进去保存。

测试通不通：

```bash
$ ssh -T git@github.com
Hi yourname! You've successfully authenticated, but GitHub does not provide shell access.
```

看到这句话就通了（"does not provide shell access"是正常的，不是报错）。

> 📌 **注意：** `~/.ssh` 目录权限必须是 700，私钥必须是 600，否则 ssh 拒绝用。WSL 里一般默认就对了，真出问题：
> ```bash
> chmod 700 ~/.ssh
> chmod 600 ~/.ssh/id_ed25519
> ```

### 基本工作流（记住这 6 个命令）

假设你有个项目目录 `myproject`：

```bash
# 1. 把它变成 git 仓库（只在第一次）
$ cd myproject
$ git init
Initialized empty Git repository in /home/yourname/myproject/.git/

# 2. 看现在有什么改动
$ git status
On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        main.py

# 3. 把文件加到"暂存区"（准备存档）
$ git add main.py
# 或者全部加：git add .

# 4. 存档（commit），写一句这次改了啥
$ git commit -m "第一次提交：写了 main.py"
[main (root-commit) a1b2c3d] 第一次提交：写了 main.py
 1 file changed, 5 insertions(+)

# 5. 看历史
$ git log
commit a1b2c3d...
Author: yourname <邮箱>
Date:   ...

    第一次提交：写了 main.py
```

**从 GitHub 拉现成的项目（clone）：**

```bash
# 找 GitHub 上任何项目，点绿色 "Code" 按钮，复制 SSH 地址
$ git clone git@github.com:用户名/项目名.git
$ cd 项目名
# 改代码...
$ git add .
$ git commit -m "改了 xx"
$ git push          # 推回 GitHub（第一次要 git push -u origin main）
```

**远程同步：**

| 命令 | 作用 |
|---|---|
| `git clone 地址` | 把远程仓库整个下载到本地 |
| `git add 文件 / git add .` | 把改动放进暂存区 |
| `git commit -m "说明"` | 存档 |
| `git status` | 看现在改了啥 |
| `git log` | 看历史存档 |
| `git push` | 把本地存档推到 GitHub |
| `git pull` | 把 GitHub 上的最新改动拉到本地 |

> 💡 **小技巧：** 经典循环 = 改代码 → `git add .` → `git commit -m "xxx"` → `git push`。每天重复几百遍，肌肉记忆。

### `.gitignore`：哪些东西不让 Git 管

Python 项目会生成 `__pycache__/`、`.env`、虚拟环境 `venv/`，这些不该传到 GitHub。在项目根目录建个 `.gitignore`：

```bash
$ nano .gitignore
```

写入：

```text
# Python
__pycache__/
*.pyc
.venv/
venv/

# 环境变量（密钥别传上去！）
.env

# 编辑器
.vscode/
.idea/

# 系统
.DS_Store
```

> ⚠️ **警告：** 永远不要把 `.env`（里面有数据库密码、API key）传到 GitHub。全世界的机器人天天在 GitHub 扫这种文件偷密钥。`.gitignore` 第一件事就是把 `.env` 加上。

## 12.4 Python：venv 与 pip 换源

Ubuntu 24.04 自带 Python 3（`python3`），但**系统那个 Python 别动**（apt 包依赖它），每个项目用独立的虚拟环境。

### 创建虚拟环境

```bash
# 先确保装了 venv 模块（24.04 可能要手动装）
$ sudo apt install -y python3-venv python3-pip

$ mkdir myproject && cd myproject

# 在项目目录里建一个叫 .venv 的虚拟环境
$ python3 -m venv .venv

# 激活它（命令行前面会出现 (.venv)）
$ source .venv/bin/activate
(.venv) $

# 退出虚拟环境
(.venv) $ deactivate
```

> 📌 **注意：** 激活后 `python` 和 `pip` 就指向这个项目专属的环境，你装的东西只在这个项目里，不污染系统。这就是为什么每个项目都要建 venv——不然 A 项目要 Django 3、B 项目要 Django 4，打架。

### pip 换国内源（不换下载慢到哭）

```bash
# 一次性配置清华源
$ pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

现在装东西：

```bash
(.venv) $ pip install flask
(.venv) $ pip install requests
```

### requirements.txt：导出依赖

项目要给别人跑，得告诉他"我用了哪些库"：

```bash
# 导出当前环境的所有依赖
(.venv) $ pip freeze > requirements.txt

# 别人拿到这个项目，一行装齐：
(.venv) $ pip install -r requirements.txt
```

### pyenv（简介，进阶用）

有时候你需要"系统 Python 是 3.12，但这个项目要 3.10"。这时候用 `pyenv`——一个能在同一台机器上装多个 Python 版本的工具。初学先不用管，真遇到"这个项目只支持旧版 Python"再查。

## 12.5 Node.js：用 nvm，别用 apt 装

### 为什么别用 apt 装 node

```bash
$ sudo apt install node    # ❌ 别这么干
```

Ubuntu 仓库里的 Node 版本非常旧（24.04 里是 Node 18，但前端现在都要 20/22）。而且 apt 装的版本你将来升级、换大版本都很麻烦。**正确做法是用 `nvm`（Node Version Manager）**——像 Python 的 pyenv 一样，专门管 Node 版本。

### 装 nvm 然后装 Node

```bash
# 1. 装 nvm（一行命令，从 GitHub 官方脚本）
$ curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash

# 2. 让 nvm 在当前终端生效（它自动写了 .bashrc，但当前终端要手动 source）
$ source ~/.bashrc

# 3. 验证
$ nvm --version
0.39.7

# 4. 装最新 LTS（长期支持版）
$ nvm install --lts
# 自动切换到刚装的版本
$ nvm use --lts

# 5. 验证
$ node -v
v22.x.x
$ npm -v
10.x.x
```

### nvm 常用命令

```bash
$ nvm ls                  # 看你装了哪些 node
$ nvm install 20          # 装 20 版本
$ nvm use 20              # 切到 20
$ nvm alias default 22    # 把 22 设成默认版本（新开终端自动用它）
```

### npm 换源

```bash
$ npm config set registry https://registry.npmmirror.com
```

装包：

```bash
$ npm install react
$ npm install -g yarn      # -g 是全局装（命令行工具）
```

> 📌 **注意：** nvm 装的所有东西都在 `~/.nvm/` 下，**不碰系统目录，所以不需要 sudo**。全局装 npm 工具（`npm i -g xxx`）也不用 sudo。如果你用 apt 装的 node，全局装就要 sudo——这也是别用 apt 的原因之一。

## 12.6 编译工具链：`build-essential`

你是电子信息/计算机专业的，早晚要在 Linux 下编 C/C++ 程序（课程实验、开源项目编译都要）。

```bash
$ sudo apt install -y build-essential
```

这一包会拉下来：

| 工具 | 作用 |
|---|---|
| `gcc` | C 编译器 |
| `g++` | C++ 编译器 |
| `make` | 根据 Makefile 自动化编译 |
| `libc6-dev` | C 标准库头文件 |

验证：

```bash
$ gcc --version
gcc (Ubuntu 13.x) 13.x.x

$ g++ --version
```

写个 C 程序试试：

```bash
$ nano hello.c
```

```c
#include <stdio.h>
int main() {
    printf("Hello from Linux!\n");
    return 0;
}
```

```bash
$ gcc hello.c -o hello
$ ./hello
Hello from Linux!
```

**CMake（进阶，写大型 C++ 项目用）：**

```bash
$ sudo apt install -y cmake
$ cmake --version
```

很多开源项目（比如 Redis、各类机器学习 C++ 库）都是 `cmake .. && make` 这种流程，先知道有这个东西。

### OpenJDK（可选，Java 方向再装）

如果你学 Java / 后端要跑 Spring：

```bash
$ sudo apt install -y openjdk-21-jdk
$ java -version
```

不写 Java 就别装，省空间。

## 12.7 WSL 开发最佳实践

### 代码放哪：**放 Linux 文件系统里**

这是新手最大的坑。你可能会想："我 Windows 下有 D 盘，直接把项目放 `/mnt/d/projects/` 不就行了？"

**不行。** WSL 访问 `/mnt/c`、`/mnt/d` 是通过一个特殊的桥接层，**IO 速度慢 10 倍以上**，而且权限全是 777（git 会烦）。正确做法：

| 代码放哪 | 速度 | 权限 | 建议 |
|---|---|---|---|
| `~/projects/`（Linux 家目录） | 快 | 正常 | ✅ 放这儿 |
| `/mnt/c/Users/你/...` | 慢 | 777 | ❌ 别放 |
| `/mnt/d/...` | 慢 | 777 | ❌ 别放 |

那我 Windows 下怎么看到这些代码？用 `\\wsl.localhost\Ubuntu\home\yourname\projects` 在文件管理器里访问就行（第 2 章讲过）。

### VS Code Remote

在项目目录里直接：

```bash
$ cd ~/projects/myproject
$ code .
```

第一次会自动装 VS Code Server，然后你就能在 Windows 的 VS Code 窗口里编辑 Linux 下的代码，终端、调试全在 WSL 里跑。这是目前 WSL 开发最丝滑的方式。

### 终端字体

Windows Terminal 默认字体对程序员不太友好（连字、特殊符号显示不全）。推荐在设置里把字体改成 `CaskaydiaCove Nerd Font` 或 `FiraCode Nerd Font`——不然后面装 tmux、zsh 插件时那些图标会显示成方块。

## 12.8 综合练习：从零跑通一个 Hello World 项目

把本章所有东西串一遍。假设你要写一个 Flask 小网站：

```bash
# 1. 建项目目录（放 Linux 家目录！）
$ mkdir -p ~/projects/hello-flask
$ cd ~/projects/hello-flask

# 2. 建 Python 虚拟环境
$ python3 -m venv .venv
$ source .venv/bin/activate
(.venv) $

# 3. 装 flask（已经换过清华源的话很快）
(.venv) $ pip install flask

# 4. 写代码
(.venv) $ nano app.py
```

```python
from flask import Flask
app = Flask(__name__)

@app.route('/')
def hello():
    return "<h1>Hello from WSL + Flask!</h1>"

if __name__ == '__main__':
    app.run(host='0.0.0.0', port=5000)
```

```bash
# 5. 跑起来
(.venv) $ python app.py
 * Running on http://0.0.0.0:5000

# 6. 浏览器（Windows 那边）打开 http://localhost:5000
#    WSL2 的 localhost 会自动转发到 Windows

# 7. 导出依赖
(.venv) $ pip freeze > requirements.txt

# 8. 建 git 仓库，传到 GitHub
(.venv) $ git init
(.venv) $ nano .gitignore       # 把 .venv/、__pycache__/ 写进去
(.venv) $ git add .
(.venv) $ git commit -m "first flask app"

# 去 GitHub 建空仓库 hello-flask，然后：
(.venv) $ git remote add origin git@github.com:你的用户名/hello-flask.git
(.venv) $ git push -u origin main

# 9. 试试 Node 这边：nvm 装个 node，npm 跑个前端框架也行
```

做完这一遍，你的开发机就齐了。

## ⚠️ 危险操作与安全红线

> ⚠️ **警告：** 永远不要 `sudo pip install xxx`。一旦你用 sudo 往系统 Python 里装东西，可能把 apt 依赖的库搞崩，系统直接报错。Python 包一律在虚拟环境里装。

> ⚠️ **警告：** 改 `~/.bashrc` 之前先备份：`cp ~/.bashrc ~/.bashrc.bak`。写乱了直接 `cp ~/.bashrc.bak ~/.bashrc` 还原。

> ⚠️ **警告：** GitHub 上误传密钥（`.env`、私钥、密码）是高危事件。一旦传上去，**立刻去 GitHub 删除并重置那个密钥**，光删 git 历史没用——别人可能已经 clone 走了。

> ⚠️ **警告：** `npm install -g` 和 `pip install` 在虚拟环境里不需要 sudo。如果你习惯性加了 sudo，nvm/pip 环境反而被污染。

## 常见报错与排查

| 现象 | 原因 | 解决 |
|---|---|---|
| `command not found: node` | nvm 没在当前终端生效 | `source ~/.bashrc`，或检查 `~/.bashrc` 里有没有 nvm 那段 |
| `command not found: python` | Ubuntu 只有 `python3` | 用 `python3`，或者建个别名 `alias python=python3` |
| `pip: command not found` | 没装 pip 或没激活 venv | `sudo apt install python3-pip`，或 `source .venv/bin/activate` |
| git push 报 `Permission denied (publickey)` | SSH key 没配好 | 重跑 `ssh -T git@github.com`，看 key 有没有贴到 GitHub |
| `fatal: not a git repository` | 当前目录不是 git 仓库 | `cd` 到项目根，或先 `git init` |
| `git pull` 报冲突 | 本地和远程改了同一处 | 打开冲突文件手动解决，再 `git add . && git commit` |
| pip install 慢到卡死 | 没换源 | `pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple` |
| VS Code 打不开 `code .` | 没装 "WSL" 扩展 | 在 Windows 那边 VS Code 装 "WSL" 扩展 |

## 动手练习

1. 给 `~/.bashrc` 加 3 个你自己的 alias（比如 `gs='git status'`、`j='jobs'`），`source` 后试用。
