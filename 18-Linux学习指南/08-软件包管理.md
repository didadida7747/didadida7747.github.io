# 第8章 软件包管理

> 学完这章，你能清楚说出 `apt update` 和 `apt upgrade` 的区别，不会再把"装软件"和"更新系统"混为一谈，也能看懂报错里说的"依赖"到底是个啥。

## 本章你将学会

- 理解什么是包管理、仓库、依赖
- 熟练用 `apt install` / `remove` / `purge` / `autoremove` / `search` / `show` / `list`
- 搞清楚 `apt update` 和 `apt upgrade` 最容易混淆的区别
- 用 `dpkg -i` 装本地 `.deb` 包并修依赖
- 知道 PPA、snap、tar.gz 二进制、AppImage、源码编译分别是什么、什么时候用
- 养成健康的系统更新习惯

## 为什么需要它

Windows 下装软件你会去官网下一个 `.exe`，下一步下一步。Linux 不是这么玩的——你系统里装的几乎所有软件，都是通过一个叫**包管理器**的东西统一管理。它的好处是：装一个命令搞定、卸载干净、自动解决依赖、系统升级时一起升级。坏处是：你得搞懂几个概念，不然会踩坑。

---

## 8.1 三个基本概念：包、仓库、依赖

**包（package）**：一个预编译好的软件 + 配置文件 + 元信息（版本、依赖谁）打包成的文件。Ubuntu/Debian 用的包格式叫 `.deb`。

**仓库（repository，简称 repo）**：一堆包放在服务器上，你本地通过网络去拿。Ubuntu 默认给你配好了官方仓库（在 `/etc/apt/sources.list` 或新格式 `/etc/apt/sources.list.d/` 下）。你之前换国内源就是换这个"去哪拿"的地址。

**依赖（dependency）**：A 软件跑起来需要 B 库先存在。比如你装 `nginx`，它依赖 `libc6`、`openssl` 这些库。包管理器会自动帮你把这些依赖一起装上。

> 📌 **注意：你用的是 apt（Advanced Package Tool），底层调用 dpkg。** apt 聪明在会自动解决依赖、去仓库下载；dpkg 是底层工具，只管"把这个 deb 解开装上"，不管依赖。日常你 99% 时间用 apt。

> 📌 **注意：CentOS/RHEL 系用的是 `yum` / `dnf`（包格式 `.rpm`）。** 你以后可能会在工作中碰到，但本教程一律以 Ubuntu 的 apt 为准。看到别的教程写 `yum install`，脑子里自动翻译成 `apt install` 就行。

---

## 8.2 `apt update` 和 `apt upgrade`——新手最容易混的两个

这两个命令必须分开讲透，因为 90% 的新手第一次用都会搞错：

| 命令 | 干什么 | 类比 |
|---|---|---|
| `sudo apt update` | **只更新"包清单"**——从仓库服务器拉一份最新的"哪些包出了新版本"的目录，**不装任何东西** | 相当于刷新一下应用商店首页 |
| `sudo apt upgrade` | **真正升级软件**——根据刚才那份清单，把你系统里能升级的包全部升级 | 相当于点"全部更新" |

```bash
$ sudo apt update
$ sudo apt upgrade
```

> ⚠️ **警告：顺序永远是先 update 再 upgrade。** 如果你只跑 `upgrade` 不先 `update`，apt 用的还是几天前的旧清单，可能会说"所有包都是最新的"——但其实仓库里早有新版了。这是新手最常见的"我 apt upgrade 了怎么还是老版本"的根因。

> 💡 **小技巧：Ubuntu 22.04 之后推荐用 `sudo apt update && sudo apt upgrade -y` 一条龙。** `-y` 表示自动回答 yes，不用你盯着中间的确认。

## 8.3 日常装/卸/查命令

| 命令 | 作用 |
|---|---|
| `sudo apt install 包名` | 安装软件 |
| `sudo apt remove 包名` | 卸载软件，但**保留配置文件** |
| `sudo apt purge 包名` | 卸载软件并**删掉配置文件**（想彻底重来用这个） |
| `sudo apt autoremove` | 清理因为装别的软件而被自动带进来、现在没人用了的依赖 |
| `apt search 关键词` | 在仓库里搜软件（不用 sudo） |
| `apt show 包名` | 看某个包的详细信息（版本、大小、依赖） |
| `apt list --installed` | 列出你系统里已经装了哪些包 |

举个例子，装 git：

```bash
$ sudo apt install git
```

你会看到一堆输出：apt 先告诉你它要装哪些包（包括依赖）、总共多大空间、问你 `[Y/n]`，回车继续。

> ⚠️ **警告：`apt` 的绝大多数写操作（install/remove/upgrade）都需要 root 权限，所以前面必须加 `sudo`。** 不叫 sudo 会报 `Permission denied` 或 `/var/lib/dpkg/lock-frontend` 打不开。而 `search`、`show`、`list` 这些只读操作不需要 sudo。

> 💡 **小技巧：apt 一次能装多个包：**
> ```bash
> $ sudo apt install git curl wget htop tree net-tools
> ```
> 这就是本章末尾让你练的那一组。

## 8.4 装本地 `.deb` 包：`dpkg -i` 与依赖修复

有时候你要装的软件不在官方仓库里，作者直接在官网给了个 `.deb` 文件（比如 VS Code、Docker）。这种时候用 `dpkg -i`：

```bash
$ sudo dpkg -i ./code_1.95_amd64.deb
```

注意——`dpkg` 不懂依赖。如果这个包依赖别的库还没装，它会报错退出。这时候跑一句：

```bash
$ sudo apt --fix-broken install
```

apt 会自动把缺的依赖从仓库里补上。补完之后你再 `dpkg -i` 一次就成功了。

> 💡 **小技巧：现在 Ubuntu 其实支持直接 `sudo apt install ./xxx.deb`，apt 会自动处理依赖。** 等价于 dpkg -i + fix-broken 一条龙。

---

## 8.5 PPA：第三方软件源

官方仓库里有些软件版本偏旧（稳定优先）。如果想要新版，Ubuntu 生态有个东西叫 **PPA**（Personal Package Archive）——第三方维护者自己托管的软件仓库。

用法：

```bash
$ sudo add-apt-repository ppa:deadsnakes/ppa
$ sudo apt update
$ sudo apt install python3.12
```

> ⚠️ **警告：PPA 是第三方的，质量参差不齐。** 加之前想清楚这个 PPA 是谁维护的、靠不靠谱。乱加 PPA 是搞坏 apt 源的常见原因。而且 WSL2 环境里能不加就不加，官方源够用就官方源。

## 8.6 snap：Ubuntu 自家的新包格式

snap 是 Canonical（Ubuntu 公司）搞的新打包格式，一个包把依赖全塞进去，号称"一次打包到处跑"。Ubuntu 桌面版默认装了很多 snap 软件（比如 Firefox）。

```bash
$ snap list
$ sudo snap install code
```

客观说一下优缺点，不站队：

| 优点 | 缺点 |
|---|---|
| 依赖全打包，不污染系统 | 启动慢（首次解压慢） |
| 自动后台更新 | 占用磁盘大 |
| 软件版本新 | 后端服务器上一般不用，争议不小 |

**后端服务器 / WSL 开发环境里，优先用 apt。** snap 你知道有这东西就行，不用主动用。

## 8.7 其他安装方式（知道原理就行）

以后你会碰到下面几种"不是 apt 装的"软件，混个脸熟：

### tar.gz 二进制包

作者给你一个压缩包，里面是编译好的可执行文件。解压出来就能用：

```bash
$ tar -xzf xxx.tar.gz
$ cd xxx/
$ ./xxx --version
```

通常你会把它放在 `/opt/` 下，然后手动在 `~/.bashrc` 里把它的 `bin` 目录加进 PATH（第 12 章讲 PATH）。

### AppImage

单文件可执行，给它加执行权限就能跑：

```bash
$ chmod +x Some.AppImage
$ ./Some.AppImage
```

服务器上基本不用，桌面 Linux 多见。

### 源码编译：`./configure && make && make install`

有些软件官方只给源代码，要你自己编译：

```bash
$ tar -xzf xxx.tar.gz
$ cd xxx/
$ ./configure     # 检测系统环境，生成 Makefile
$ make            # 编译
$ sudo make install   # 安装到系统
```

这三步曲你现在不要求精通，知道大概流程就行。真到要编译的时候（比如装某个特定版本的 Python），我们在第 12 章开发环境那章细讲。需要先装编译工具链：`sudo apt install build-essential`。

## 8.8 养成健康的更新习惯

后端运维有一条不成文规矩：**装软件前先 `sudo apt update`，定期（比如一两周一次）`sudo apt upgrade`。** 安全补丁都是通过 apt 推过来的。

但有个坑：升级过程中可能会弹一个紫色的全屏界面，问你"要不要保留现有的配置文件"。新手经常慌。正确做法是：**大多数情况选保留现有配置（`keep the local version`）**，除非你明确知道自己想升级配置。

> ⚠️ **警告：升级到一半（尤其是内核、systemd 这种关键包）千万别断电、别强制关 WSL。** 在 WSL2 里相对安全（大不了 `wsl --shutdown` 重来），但在真正的云服务器上，升级中途断机会直接起不来。

## 动手练习

1. 跑一遍 `sudo apt update` 和 `sudo apt upgrade -y`，观察两个命令输出有什么不同。
2. 一次性装齐这组工具：`sudo apt install git curl wget htop tree net-tools`。
3. 装完跑一下 `tree ~` 看看你家目录长什么样；跑 `netstat -tunlp`（第 10 章会讲它和 `ss` 的关系）。
4. `apt search htop` 看看搜索结果长什么样；再 `apt show htop` 看详细信息。
5. `apt list --installed | wc -l` 数一下你系统里现在装了多少个包。
6. 用 `sudo apt autoremove` 清理一下没人要的依赖，看它输出说删了什么。

## ⚠️ 危险操作与安全红线

- **`apt upgrade` 中途别中断。** 尤其是涉及 systemd、内核时。
- **不要随便加陌生 PPA。** 加错了源，整个 apt 可能坏掉。
- **`sudo make install` 装的软件 apt 管不着。** 以后想卸载你得自己记得装到哪了——优先用 apt。
- **`dpkg -i` 失败后一定要跑 `sudo apt --fix-broken install`，** 不然 apt 会一直锁着，你后面装啥都报"无法纠正问题，您有损坏的软件包"。
- **WSL2 里不要 `apt dist-upgrade` 大版本升级**（比如从 24.04 升到 24.10），容易把 WSL 搞挂。要大升级就重装一个新发行版。

## 常见报错与排查

| 现象 | 原因 | 解决 |
|---|---|---|
| `Could not get lock /var/lib/dpkg/lock` | 另一个 apt 进程在跑（或上次没退干净） | 等它跑完；真卡死了再考虑删锁文件（新手别乱动） |
| `Unable to correct problems, you have held broken packages` | 依赖坏了 | `sudo apt --fix-broken install` |
| `E: Package 'xxx' has no installation candidate` | 包名拼错了，或源没更新 | 先 `apt update`；再 `apt search xxx` 找正确名字 |
| `Permission denied` 跑 apt | 忘了加 sudo | 前面加 `sudo` |
| 装的软件运行时说 `command not found` | 装了但 PATH 没刷新，或根本没装成功 | 先 `which 命令`；新装的有时新开终端就行 |
| snap 软件启动特别慢 | snap 首次要解压 | 正常现象，第二次会快；着急就用 apt 版 |

## 本章小结

| 命令 | 作用 |
|---|---|
| `sudo apt update` | 刷新包清单（不装东西） |
| `sudo apt upgrade` | 真正升级软件 |
| `sudo apt install 包` | 装软件 |
| `sudo apt remove / purge 包` | 卸载（保留/删除配置） |
| `sudo apt autoremove` | 清理没用的依赖 |
| `apt search / show / list` | 查软件信息 |
| `sudo dpkg -i xxx.deb` | 装本地 deb |
| `sudo apt --fix-broken install` | 修依赖 |
