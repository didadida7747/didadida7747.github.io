# 证据规范

结论必须由“断言 + 证据”组成；没有证据就标记为“待核实”。

## 合格证据

| 类型 | 形式 |
|---|---|
| 代码位置 | `path/to/file:line` |
| 搜索结果 | 搜索命令/关键词、范围、命中数和关键位置 |
| 命令输出 | 执行命令、退出状态与关键结果 |
| 产物检查 | 文件路径、数量、字段、页面或运行行为 |
| 用户确认 | 用户原话与确认时间/上下文 |

## 否定结论

“不存在 / 没有 / 无可复用”必须同时包含：

1. 至少两个关键词或同义词。
2. 搜索范围和文件类型。
3. 0 命中结果。

示例：

```text
搜索词：export|导出|download|excel
范围：src/**/*.{ts,tsx,java}
结果：0 命中，因此当前搜索范围内未发现导出能力。
```

不要把“当前范围内未发现”扩大成对整个系统的断言。

## 验收证据

避免：`测试通过了`、`功能正常`、`应该没问题`。

使用：

```text
npm test -> exit 0；42 passed，0 failed。
dist/ -> 12 个文件；入口文件存在；目标链接可解析。
GET /orders?page=2 -> HTTP 200；返回 10 条；页码字段为 2。
```

代码或配置修改后，相关旧证据失效，必须重新验证。引用其他 agent 的结论时标注来源，并在高风险结论上重新核对原始证据。
