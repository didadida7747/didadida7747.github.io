# 寒假前双入口能力矩阵


本矩阵用于检查作品和投递准备，不独立生成学习任务；阶段安排冲突时遵循[规划优先级与冲突处理](./规划优先级与冲突处理.md)。

## 公共底座

| 能力 | 当前入门线 | 寒假前可投线 |
|---|---|---|
| Python | 会基础语法 | 能处理 JSON/CSV/日志、写函数和异常处理、管理环境并调试 traceback |
| C/C++ | 会基础语法 | C 能解释指针/内存/中断数据流；C++ 能写小模块并使用 STL、CMake、GDB |
| Linux/Git | 会基本命令 | 能从空目录构建、运行、定位错误，提交清楚的 Git 历史 |
| 数据结构与算法 | 尚未系统训练 | 掌握数组、字符串、哈希、链表、栈队列、树和复杂度；基础题二刷可独立完成 |
| 工程表达 | 能描述做过什么 | 能说明需求、架构、个人贡献、测试、失败和限制，并给出可复现入口 |

## AI 应用入口

| 能力 | 只算接触 | 可写进项目 | 可投实习的最低证据 |
|---|---|---|---|
| 数据处理 | 跑过示例 | 能清洗、切分和版本化数据 | 数据来源、规模、异常样本和处理脚本可说明 |
| 模型/检索调用 | 调过 pipeline/API | 有检索基线或模型调用 | 能解释输入输出、失败边界、成本/延迟和为什么选它 |
| 服务接口 | 看过 FastAPI | 有 JSON 接口和异常处理 | 安装、启动、接口测试和错误响应可复现 |
| 评测 | 展示成功对话 | 有至少 20 条固定样例 | 记录命中、误判、拒答、延迟和一次受控变量对比 |
| 质量边界 | 会写提示词 | 能识别无证据回答 | 不把纯提示词、标注或低代码截图包装成工程项目 |

## Agent 应用工程入口

| 能力 | 只算接触 | 可写进项目 | 可投实习的最低证据 |
|---|---|---|---|
| 模型与结构化输出 | 能完成一次对话 | 能验证 JSON、处理无效响应和保留上下文 | 能解释输入输出约束、错误处理、成本或延迟边界 |
| 工具调用 | 让模型调用过函数 | 工具参数可校验，有明确状态流转 | 工具白名单、目录限制、超时和失败返回均可复现 |
| 资料检索与引用 | 能搜到片段 | 答案附可定位引用并能正确拒答 | 固定样例记录正确性、引用有效性、拒答与失败分类 |
| 评测与测试 | 展示成功对话 | 有至少 25 条固定样例和回归记录 | 有指标、失败修复和接口/单元测试，不靠手工演示 |
| 安全边界 | 知道风险 | 默认只读，危险动作需确认 | README 可说明允许范围、拒绝范围和人工确认策略 |

## 嵌入式/Linux 入口

| 能力 | 只算接触 | 可写进项目 | 可投实习的最低证据 |
|---|---|---|---|
| STM32/外设 | 会调用 HAL | 能完成中断、定时、UART 和状态机 | 构建、下载、接线、物理现象和重复测试均有证据 |
| 协议与可靠性 | 能收发一次 | 有超时、校验、重同步或错误码 | 能解释失败路径，并有故障注入或统计结果 |
| RTOS | 看过概念 | 能划分任务和同步 | 只有项目确实需要时再加入，并测周期、负载或队列行为 |
| Linux/C++ 工具 | 会安装软件 | 能写解析/测试小工具 | CMake 构建、GDB 定位和测试结果可复现 |
| ROS2 | 看过教程 | 条件式扩展 | 只有岗位样本支持且主项目过闸门，才要求节点、QoS、rosbag 等证据 |

## 达到投递线的共同判断

- 至少一个对应岗位的完整项目，而不是课程名称或零散 demo。
- 能在十分钟内讲清架构、关键取舍、个人代码、测试方法和一次失败。
- 陌生人能按 README 复现核心结果；不能复现的硬件/服务条件明确写出。
- AI 辅助生成、开源代码和本人独立完成部分边界清楚。
