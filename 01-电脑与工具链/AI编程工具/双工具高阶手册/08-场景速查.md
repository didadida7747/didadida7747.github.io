# 08 · 场景速查：我想做 X，用什么命令组合

> 用法：按场景查 → 拿组合 → 命令细节跳 §07/对应章。每个场景给**双工具组合**，能对照着学。

## 8.1 通用高频场景

| # | 场景 | Claude Code 组合 | Codex 组合 | 心法 |
|---|---|---|---|---|
| 1 | 上下文快满了 | `/context` 体检 → 关键结论先写进文件 → `/compact 保留xxx` | `/status` 看额度 → `/compact` | 60-70% 主动压，别等爆（§02） |
| 2 | 改砸了想回退 | `/rewind`（选"仅代码/代码+对话"） | `/undo`（文件回滚，对话保留换说法重做） | rewind 退对话+代码；undo 只退文件（§02） |
| 3 | 接手陌生项目 | `/init` → plan mode 读结构出报告 → 满意后再动手 | `/init` → `/plans` → 确认后执行 | 先读后写，plan 永远在改之前（§03） |
| 4 | 切到无关新任务 | `/clear 新任务名` | `/new 新任务名` | 一任务一会话，命名防串台（§02） |
| 5 | 想试激进方案 | `/branch 尝试-xxx` | `/fork` | 试错走分支，主线保平安（§02） |
| 6 | 干活中冒出小疑问 | `/btw 这个报错啥意思` | `/side ...` | 旁支提问不污染主上下文（§02） |
| 7 | 提交/交付前审查 | `/code-review --max-findings 5` → `/verify` | `/review` 选 base branch → 回主会话修复 | 审查+真跑才算完（§06） |
| 8 | 代码要上公开仓库 | `/security-review` | AGENTS.md 审查规则 + 人工扫密钥 | 先扫密钥再 push（§06） |
| 9 | 多任务并行 | `claude -w 任务A` × 3 + `--tmux` | `/worktree` + `codex agents` 仪表盘 | 独立子任务才并行（§05） |
| 10 | 批量重复操作 | `/batch 给这20个文件各做X` | `codex exec --json "对每个文件..."` 循环 | 单元独立才批；有依赖就串行（§05/§06） |
| 11 | 长任务防跑偏 | `/goal 全部测试通过且覆盖率≥80%` | `/goal 本周完成xxx` | 目标写验收标准不写愿望（§02） |
| 12 | 隔几天回会话 | `/resume 任务名` → `/recap` | `/resume` → 看自动 recap | 落盘过的结论比记忆可靠（§02） |
| 13 | 它反复犯同一个错 | `/memory` 写进 CLAUDE.md / `.claude/rules/` | 写进 AGENTS.md（就近覆盖） | 反复>2 次的纠正必入记忆文件（§02） |
| 14 | 防误删/防危险命令 | PreToolUse hook + `Bash(rm *)` deny | read-only 档位 + deny 习惯 | CLAUDE.md 管建议，hook 管纪律（§03） |
| 15 | 无人值守跑批 | `claude -p "..." --permission-mode auto --permission-prompts none --max-budget-usd 2` | `codex exec --sandbox workspace-write -a never ...` | 必配预算/轮数上限（§06） |
| 16 | 省钱 | `/model sonnet` + `/effort low`（杂活）+ `/usage` | `/model` 降档 + `Alt+,` 降力度 + `/usage` | 模型和力度是两大省钱旋钮（§02） |
| 17 | 多方案择优 | worktree 各开一个变体或 `--cloud` | Codex Cloud 并行 3 个变体 → `cloud apply` | 让并行替你做实验（§05） |
| 18 | "它怎么不听话了" | `/doctor`（`prompt-audit`）→ `--safe-mode` 排插件/hook | `/debug-config` → `codex doctor` | 先体检再怀疑人生（§03/§11） |
| 19 | 把项目推上 GitHub 做作品集 | GitHub MCP + `/security-review` + `/code-review --comment` | GitHub 集成 + @codex | 公开前安全审查是底线（§04/§06） |

## 8.2 双工具联动专项

| 场景 | 做法 |
|---|---|
| **同居不内耗** | 项目里只写一份 `AGENTS.md`（CC 回退可读）；技能放共享目录，去 CC 专有字段后两边复制；MCP 配置两边各配一份（§02/§04） |
| **互相审查** | CC 改完 → `claude mcp add codex -- codex mcp-server` → 让 Codex 审 diff；反向把 diff 喂 `codex exec "review..."`。两模型盲区不同，互审性价比极高（§04/§06） |
| **对照实验** | 同起点开两个 worktree，CC 和 Codex 各做同一任务：比速度、比质量、比风格——选型焦虑的终极解法是实测（§05） |
| **迁移同居** | 新工具用 `/import`（CC: `/import codex`；Codex: `/import` 选 Claude Code）拉齐配置，再人工核对权限语义（§02） |
| **主副分工** | CC 当编排台（上下文管理+文件改动），Codex 当外援（MCP 调用或云端任务），各扬所长（§04/§05） |

## 8.3 学生场景

### 今晚课设 due（3 小时急救流程）

```text
1. /clear 课设-DUE今晚                    # 干净会话
2. /init 或直接贴作业要求 + "先只读代码，出修复计划"   # plan 先行
3. 按 plan 改 → /verify 跑通              # 验证闭环
4. /code-review --max-findings 5          # 抓低级错误
5. /export 课设-DUE今晚-过程.md            # 导出"设计思路"给报告用
```
Codex 等价：`/new` → `/plans` → 执行 → `/review` → `/export`。

### 电赛赛前两周（2027 国赛可用）

```text
worktree A：视觉（OpenCV 目标识别）
worktree B：控制（PID 调参，hook 保护不误烧参数）
worktree C：上位机 + 技术报告
主会话：每天 /recap 三线进度，汇总风险清单
赛前 48h：冻结新功能，全员只修 bug；每晚 git tag 存档
```

### 大创中期检查（报告周）

```text
1. 会话 A：整理实验数据 → 出图（matplotlib 统一模板）→ 结果表
2. 会话 B（/branch）：按中期模板起草报告，引用 A 的图
3. /security-review 检查附带的代码包有没有泄密/遗留密钥
4. /export 问答记录 → 附"AI 使用说明"（诚信要求，见 §09.7）
```

### 期末周（多科并行）

```text
每科一个命名会话（/title 或 /clear 课设-xxx）；
复习资料生成：贴课件大纲 → "生成考点清单和自测题"（杂活用 low effort 省钱）；
作业代码：先自己写 → 让 Agent 只做 review（ Learning output style 也行），
防"拐杖化"（§01.6）。
```
