# 岗位评分与申请优先级规则

本规则从 2026-08-19 起使用 v2。评分同时考虑真实性、时效、个人匹配、技能差距、申请可行性和岗位质量，不能只因“与当前所学相关”就推荐，也不能只因“标题热门、数量多”就判断容易拿到。

## 六项评分

| 维度 | 分数 | 评分事实 |
|---|---:|---|
| 真实性 A | 0–5 | 5：公司官网/官方 ATS 具体职位页，主体和申请入口可核验；4：官方校招/学校就业页面且可追溯；3：主流平台具体 JD 但无原始页；2：二次转载或信息不全；1：来源不明；0：诈骗、虚假或主体不可核验。 |
| 时效性 T | 0–5 | 5：0–3 日内发布/更新且可申请；4：4–7 日；3：8–30 日或日期不明但当日明确可申请；2：31–60 日；1：超过 60 日或入口异常；0：明确关闭/截止。 |
| 个人匹配 M | 0–5 | 5：当前主线或相邻方向、现有/本学期作品可证明主要任务、城市与学生条件无冲突；4：方向吻合且缺口一学期内可补；3：相邻方向但需新项目；2：只有少量技能重合；1：主要靠学历标签或兴趣猜测；0：方向和硬条件均不符。研究型 AI/RL 在没有实验室、独立代码和可复现实验时 M≤2。 |
| 技能差距 G | 0–5 | 0：已有证据覆盖核心任务；1：补 1–2 个小任务；2：一个月内可补；3：需要一个学期或完整新项目；4：要求高年级/长期经验/多项核心缺失；5：学历、年级、周期等硬性不满足。分数越高，差距越大。 |
| 申请可行性 F | 0–5 | 5：在校生、地点、周期、到岗和申请入口均明确可行；4：仅一项待确认；3：两项待确认；2：城市/周期可能冲突；1：关键信息大量缺失；0：明确不符合或已关闭。 |
| 岗位质量 Q | 0–5 | 5：核心研发任务、明确代码/数据/测试/部署闭环、带教或独立模块、成果可迁移；4：真实工程任务明确，但带教/交付边界有一项未披露；3：普通开发或测试开发，能形成可验证能力；2：辅助开发、短期外包/交付、任务边界模糊；1：提示词运营、纯标注、装配刷机、机械重复测试、销售支持；0：收费、诈骗或明显虚假。 |

## 不同方向的质量门槛

- **AI 应用：** 只有职责包含 Python 服务、数据处理、检索/工具调用、固定评测、异常处理或部署中的至少两项，Q 才能达到 3；只写提示词、标注、低代码搭建、客服自动化或培训交付时 Q≤2。
- **嵌入式/Linux：** 只有职责包含代码、驱动/协议、调试、测试开发、性能/可靠性或真实模块交付，Q 才能达到 3；只做装配、焊接、刷机、巡检或重复手工测试时 Q≤2。
- **后端/系统、ROS2、边缘部署：** 必须存在代码任务和可验证交付；只有“了解/协助/配合”且无具体模块时 Q≤2。
- 公司名气、薪资和热门标签不能单独提高 Q。

## v2 优先级计算

`P = 3A + 3T + 6M + 3F + 4Q + (5 - G)`，满分 100，保留整数。

| 优先级 | 条件 | 行动 |
|---|---|---|
| P0 | `P≥80`，且 `A≥4`、`T≥3`、`M≥4`、`F≥4`、`Q≥4`、`G≤2`，通过硬门槛 | 24 小时内人工复核并决定是否投递。 |
| P1 | `65–79`，且 `A≥3`、`F≥3`、`Q≥3`、无红线 | 72 小时内补信息、调整简历并决定是否投递。 |
| P2 | `50–64`，或质量/可行性仍待补证 | 作为学习需求或机会观察，不抢占主投时间。 |
| P3 | `<50`、`Q≤1` 或任一红线 | 保留审计记录并暂停，不投递。 |

无原始链接、明确关闭、非在校生可投、收费/诈骗风险的记录不得进入 P0/P1。Q=2 的岗位即使总分较高也最高为 P2。

## v1 历史兼容

2026-08-18 及以前的台账 P 使用旧公式 `4A + 4T + 9M + 2F + (5-G)`，不批量回写历史。岗位下一次重新核验时，补充 Q、改用 v2，并在岗位台账的“方向与质量索引”标记评分版本。日报比较 P0/P1 时必须区分 v1 与 v2，不能直接混算。

## 去重与更新

1. 先比较 ATS 职位 ID；相同则合并。
2. 再比较规范化原始链接：移除追踪参数、片段和末尾 `/`，统一协议和域名大小写。
3. 最后比较公司、岗位、城市规范化指纹；职责或城市实质不同则保留两条。
4. 合并时保留最早发现日和全部可追溯来源，更新最后核验日、状态、Q、评分版本和日报引用。
5. 已投递或跟进岗位重新发现时只更新；关闭岗位保留历史，不重新推荐。
