## P1 会话管理三件套 ★

- **目标**：建立"一课一会话"的肌肉记忆。
- **前置**：两个工具都能正常启动。
- **步骤提示**：CC 里 `/clear 课设-xxx` → 随便聊两句 → `/rename` → `/recap` → `/export test.md`；Codex 里 `/new 课设-xxx` → `/title` → 退出 → `/resume` 找回。
- **验收标准**：
  - [ ] 两个工具各有一个命名会话，且能 `/resume` 找回
  - [ ] 导出过一份对话文件
  - [ ] 能说出 /clear 与 /compact 的取舍

## P2 上下文手术 ★

- **目标**：学会诊断与压缩，告别"爆窗恐慌"。
- **步骤提示**：在会话里连续讨论 10+ 轮让上下文涨起来 → CC `/context` 看占用大头（MCP？记忆文件？）→ 先把关键结论粘贴到 `notes.md` → `/compact 保留 notes 里对应思路和剩余 TODO` → 追问一个早前细节验证记忆保留度。
- **验收标准**：
  - [ ] 说出你上下文的三大占用项
  - [ ] 完成一次带指示的压缩且关键信息未丢
  - [ ] 建立"70% 就压"的触发习惯

## P3 回退与分支 ★★

- **目标**：把"改砸了"从事故变成可逆操作。
- **步骤提示**：建个测试仓库 → 让 Agent 改坏一个函数 → CC `/rewind` 分别试"仅代码/代码+对话"两种回退 → Codex `/undo` → 再试 `/branch`（CC）与 `/fork`（Codex）走一条激进路线后回主线。
- **验收标准**：
  - [ ] 理解 rewind（对话+代码）与 undo（仅文件）差异
  - [ ] 完成一次"分支试错→回主线"闭环
  - [ ] 发现至少一个 rewind 不覆盖的场景（Bash 产物/手工编辑）

## P4 防误删 hook ★★

- **目标**：写出你的第一个"硬保证"。
- **步骤提示**：照 §3.2.3 实例 1 配 PreToolUse hook → 让 Agent 执行 `rm -rf ./test-dir` 观察拦截 → 换 `mkdir` 观察放行 → 加一条 allow 规则放行 `rm ./tmp/*`（精确白名单）。
- **验收标准**：
  - [ ] hook 实测拦截 rm -rf 并给出 deny 理由
  - [ ] 正常命令不受影响
  - [ ] 能解释 exit 2 阻断与 permissionDecision JSON 两种返回方式

## P5 第一个双平台 skill ★★

- **目标**：把一个重复流程固化成两边通用的资产。
- **步骤提示**：选一个你每周至少做两遍的流程（如"数据出图"）→ 写 SKILL.md（含 `$ARGUMENTS`、`allowed-tools`、`argument-hint`）→ CC 放 `.claude/skills/`，Codex 放 `.agents/skills/`（去掉 CC 专有字段）→ 两边各调用一次。
- **验收标准**：
  - [ ] 两边都能 `/你的技能名` 唤起
  - [ ] 参数传入生效
  - [ ] 把技能文件提交进你的技能仓（git）

## P6 MCP 接入 ★★

- **目标**：打通 USB-C 总线。
- **步骤提示**：CC `claude mcp add --transport http ...`（建议 Context7 文档库）→ 提一个"XX 库怎么用"的问题观察它查文档 → Codex 侧配同一 server → `/mcp`（CC）/ `/mcp verbose`（Codex）诊断一次。
- **验收标准**：
  - [ ] 两边各完成一次经 MCP 的真实调用
  - [ ] 能说出 local/project/user 三种 CC 作用域区别
  - [ ] 用 /context 对比装 MCP 前后的上下文开销

## L7 同任务双工具对照实验 ★★★

- **目标**：用实测代替选型焦虑，顺便产出对比笔记。
- **步骤提示**：`git worktree` 建两个相同起点 → 任务选"给现有代码加一个小功能+测试"（2 小时内可完成）→ A 树 CC（plan mode 先出方案），B 树 Codex（`/plans`）→ 记录：耗时/轮数/token 花费/代码质量/改了哪些文件 → `git diff` 对比两树产出。
- **验收标准**：
  - [ ] 填完一张六维对比表
  - [ ] 总结出"这类任务谁更快/谁更稳"的**具体到任务类型**的结论
  - [ ] 笔记发布到你的知识站（VitePress）

## L8 CC 编排 Codex ★★★

- **目标**：跑通"主代理+外援"的混编。
- **步骤提示**：`claude mcp add codex -- codex mcp-server` → CC 里先自己改一个函数 → 对话："用 codex 工具让 Codex review 我刚才的改动，把发现带回来" → 双方发现列表对照。
- **验收标准**：
  - [ ] CC 会话内成功调用 codex 工具并拿到回复
  - [ ] 记录双方发现的重叠点与独有发现
  - [ ] 能说出这个模式什么时候值得用（要第二意见时）

## L9 双向迁移演习 ★★

- **目标**：把"切换成本≈0"变成亲身体验。
- **步骤提示**：CC `/import codex` → Codex `/import` 选 Claude Code → 检查两边 MCP/指令文件落点 → 建 AGENTS.md-only 的共享项目验证 CC 回退读取。
- **验收标准**：
  - [ ] 完成双向 import 并列出迁了什么、没迁什么
  - [ ] CC 在无 CLAUDE.md 项目里正确读到 AGENTS.md
  - [ ] 知道权限语义需人工核对（import 不管这个）

## S10 课设急救全流程 ★★

- **目标**：把 §08.3 流程真走一遍（选一个真实的小课设/作业）。
- **验收标准**：
  - [ ] 按五步流程完成：清场→plan→执行→review→导出
  - [ ] 产出：可用代码 + 过程记录 md（报告素材）
  - [ ] 用时比裸做明显缩短，且你能讲清每步为什么

## S11 论文代码复现 ★★★

- **目标**：跑通 §9.4 四步复现工作流。
- **步骤提示**：选一篇有开源代码的入门级论文（信号处理/数值计算方向最佳）→ 严格按四步：只读侦察→跑通→验证图表→换数据。
- **验收标准**：
  - [ ] 本地复现出论文至少一张关键图
  - [ ] 有一页"复现记录"（依赖/坑/与原文差异分析）
  - [ ] 把流程封装成 skill（喂给下一个复现任务）

## S12 电赛/数模脚手架 ★★★

- **目标**：预演 2027 电赛的核心工作流（无板子也能练）。
- **步骤提示**（二选一）：A. 视觉线——让 Agent 搭 OpenCV 靶识别管线（读图→二值化→轮廓→测距估算），你自己标定；B. 数模线——`/batch` 对 20 组参数做扫描出对比图。全程 git 管理，参数改动可回退。
- **验收标准**：
  - [ ] 产出可运行的脚手架 + 一份"赛场化清单"（离线依赖/预案）
  - [ ] 经历至少一次"改砸→/rewind 或 worktree 救回"
  - [ ] 写下三条"赛前要固化的 skill"清单

---

**毕业标准**：12 个全勾 + 每个练习的复盘笔记进知识站。到那天，你已经超过绝大多数"只会聊天式使用"的用户——而这只花了一个半月。
