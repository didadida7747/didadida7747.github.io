# 05 · 多代理 · 并行 · 云端：一个人怎么带一个代理团队

> 本域命令约 18 条。七段式：①概念 → ②CC 详解 → ③Codex 详解 → ④对照 → ⑤联动 → ⑥学生视角 → ⑦验收

---

## 5.1 本域解决什么问题（工具无关）

- **上下文隔离**：让子代理去读 5000 行测试日志、全库检索，主会话只收回摘要——主上下文不被垃圾淹没。这是"为什么需要多代理"的第一性原因，其次才是并行提速。
- **并行三形态**：① 本地多会话（多个终端窗口各干一件事）；② 会话内子代理（主代理派活）；③ 云端农场（托管容器里成批跑）。复杂度递增，按需取用。
- **任务粒度**：独立子任务（A/B 两模块互不依赖）才适合并行；强耦合步骤拆并行只会打架。

## 5.2 Claude Code 详解

### 5.2.1 Subagents（子代理）

- **是什么**：带独立上下文窗口、独立工具与权限的 Markdown 定义代理。**核心收益是上下文隔离**，其次才是并发。
- **定义位置**（优先级高→低）：`--agents` CLI JSON（会话级）> `.claude/agents/`（项目）> `~/.claude/agents/`（用户）> 插件自带。

```markdown
---
name: test-runner
description: 运行 pytest 并只返回失败用例摘要。在需要跑测试时主动使用。
tools: Bash(pytest *), Read
model: haiku
---
你是测试执行器。运行 `pytest -q`，失败时只报告：失败用例名、断言差异、最可能原因（3 行内）。
```

**frontmatter 关键字段**：`name`/`description`（必填，description 决定自动委派）、`tools`/`disallowedTools`、`model`（sonnet/opus/haiku/inherit）、`permissionMode`、`maxTurns`、`memory`（持久记忆）、`skills`、`mcpServers`、`hooks`、`effort`、`isolation: worktree`（v2.1.50，子代理跑在独立工作树）、`background`、`color`。

**调度方式**：① 自动——Claude 按 description 委派；② 显式——对话里点名，或 `@agent-test-runner` @-提及（保证执行）；③ `claude --agent <名>` 整个会话用某代理。内置三个：**Explore**（快速只读检索）、**Plan**、**general-purpose**。

**上限**：嵌套默认 3 层；并发默认 20（`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`）；每会话 200 个。子代理默认后台运行，完成后可 SendMessage 恢复（保留历史）。

### 5.2.2 命令卡片

#### `/agents` — 创建与管理子代理
- **作用**：v2.1.197 起改为**自然语言引导式**——直接说"帮我建一个跑 MATLAB 仿真的子代理"，它生成文件。

#### `/list-agents` — 列出可通信对象（别名 `/peers`）
- **作用**：列出可发消息的 subagent / teammate / 在线会话（v2.1.224+）。

#### `/background [提示]` — 当前会话转后台代理（别名 `/bg`）
- **作用**：把当前活儿丢后台，终端空出来。启动时 `claude --bg "任务"` 同效。

#### `/tasks` — 后台任务面板（别名 `/bashes`）
- **作用**：查看后台 Bash / 后台会话 / 已完成的 subagent。配合 `Ctrl+B` 把正在跑的命令后台化。

#### `/subtask <任务>` — 派生继承上下文的子代理
- **作用**：复制当前对话状态给一个 forked 子代理去干，主会话继续。

#### `/batch <指令>` — 拆批并行（内置技能）
- **作用**：把一个指令拆成 5-30 个独立单元，在**并行 worktree 子代理**里执行后汇总。
- **场景**："把这 20 个数据文件各自的异常值检测跑一遍"——典型embarrassingly parallel。
- **坑**：只适合真正独立的单元；单元间有依赖就别用。

#### `/loop [间隔] [提示]` — 周期性重复执行（别名 `/proactive`）
- **作用**：按间隔重复跑某提示。场景：每 10 分钟检查一次训练 loss。

#### `/schedule [描述]` — 云端定时任务（别名 `/routines`）
- **作用**：管理云端定时任务。

#### `/workflows` — 工作流进度视图
- **作用**：查看/暂停/恢复动态工作流（脚本化编排子代理拓扑，配合 `/workflow-authoring` 技能）。

#### worktree：`claude -w [名字|#PR]` — 一键隔离工作树
- **作用**：自动建 git worktree 开新会话（支持 PR/MR URL，v2.1.233 支持 GitLab），配 `--tmux` 可多窗口。
- **场景**：**本地并行的正确姿势**——3-5 个 worktree 各跑一个会话，各管一个任务，互不踩脚。

### 5.2.3 长尾速览

| 命令/能力 | 一句话 |
|---|---|
| `/stop` | 停止已附加的后台会话 |
| `claude agents`（CLI） | 多会话统一视图（tmux/iTerm2/进程内 teammate） |
| `claude attach/logs/stop/respawn/rm <id>` | 后台会话管理五件套 |

## 5.3 Codex 详解

#### `/agents` — 多智能体控制
- **作用**：启用/控制多智能体（0.110.0）；CLI 侧 `codex agents` 是**多任务仪表盘**（0.149.0）：搜索/启动/停止任务、置顶（0.162.0）。

#### `/ps` — 后台进程
- **作用**：查看当前后台进程（0.76.0）。

#### `/worktree` — 工作树隔离（实验，0.154.0）
- **作用**：为新会话/分叉创建隔离 git worktree；CLI 对应 `--worktree`。

**spawn_agent 机制**（子代理）：
- 0.85.0 角色预设 spawn；0.90.0 协作模式 beta；0.91.0 起**上限 6 个**并行子代理；0.107.0 线程可分叉成子代理；0.117.0 路径式寻址（`/root/agent_a`）。
- 与 CC 差异：CC 子代理是 Markdown 文件定义、数量上限宽松、生态成熟（VoltAgent 合集 100+ 现成子代理）；Codex 偏运行时动态 spawn、上限严格但管理轻。

#### `codex queue` — 向运行中会话投递消息（0.149.0）
- **作用**：不进入会话也能给本地/远程会话塞任务。

#### Codex Cloud — 云端并行农场
- **是什么**：在 OpenAI 托管容器里并行跑任务的 Web 代理，适合一批互不依赖的任务（依赖升级、批量重构）；与本地共享账号与仓库环境。
- **衔接命令**：`codex cloud list`（看云端任务）→ `codex cloud open`（网页查看）→ `codex cloud apply`（把产出应用到本地分支）或 `codex cloud push`（直接推 PR）；CLI 也能发起新云任务（`--cloud "任务"` 对应 CC）。
- **配合 GitHub**：仓库集成支持 @codex 提及自动开工。

### 5.3.1 长尾速览

| 命令 | 一句话 |
|---|---|
| `codex remote-control` | 启动可远程控制的无头 app-server（0.130.0；`pair` 配对码 0.143.0） |

## 5.4 对照表

| 能力 | Claude Code | Codex | 判断 |
|---|---|---|---|
| 子代理定义 | Markdown 文件（.claude/agents/），frontmatter 丰富 | spawn_agent 运行时创建（上限 6） | CC 生态成熟可复用；Codex 轻量 |
| 并行批处理 | `/batch`（worktree 子代理 5-30 单元） | 无直接对应，用 Cloud 多任务替代 | CC 本地强；Codex 云端强 |
| 本地隔离并行 | `-w` worktree + tmux，3-5 会话 | `/worktree` + `codex agents` 仪表盘 | **趋同**，都可用 |
| 云端并行 | `--cloud`、`/schedule` | Codex Cloud 完整闭环（list/apply/push） | Codex 更成熟 |
| 定时/循环 | `/loop` `/schedule` | `/goal`（长目标）+ 云任务 | 侧重不同 |
| 后台管理 | `/tasks` + attach/logs/stop | `/ps` + codex agents 仪表盘 | 都可用 |

## 5.5 联动工作流

1. **CC 规划 + Codex 云执行**：CC 的 plan mode 出详细方案 → 写成 prompt 丢给 Codex Cloud 并行跑 3 个变体 → `codex cloud apply` 拉回对比 → CC 里定稿。适合"多方案择优"。
2. **同任务双工具对照实验**：同一 worktree 起点，CC 和 Codex 各开一个 worktree 做同一任务——直接对比两家的工程风格与质量（§10 练习 L7 就是这个）。
3. **跨工具编排**：CC 通过 `codex mcp-server`（§04.4.2）把 Codex 当执行器，实现"主代理 + 外援"混编。

## 5.6 学生何时用得上

- **电赛赛前并行分工**（直接可抄）：worktree A 会话写视觉（OpenCV），worktree B 写电机控制，worktree C 写上位机+文档，主会话当"队长"整合——三个任务代码独立，正适合并行；
- **数模国赛**：`/batch` 把 20 组参数扫描拆给并行子代理；结果回来出图；
- **大创/科研**：Codex Cloud 挂一批"读论文代码复现"任务，回来看 `codex cloud list` 逐个 apply；
- **期末周**：本地多会话各管一科，`/title` 命名防串台。
