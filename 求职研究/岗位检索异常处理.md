# 异常处理规则

所有异常都要写入当日日报的“搜索失败/核验摘录”，并同步台账状态；不以猜测填补缺失信息。

| 情况 | 当日动作 | 台账状态与后续 |
|---|---|---|
| 原始链接失效、403、登录墙或页面打不开 | 保留发现链接、访问时间、错误现象；从公司招聘官网、官方校招页或 ATS 搜索岗位名一次。 | 找到替代原始页则更新；找不到标记 `待核验`，次日重试一次；连续两天失败且无关闭证据时仍为 `待核验`（备注“原始链接失效”），不推荐投递；仅有明确关闭/截止证据才标记 `已关闭`。 |
| 搜索源失败、限流或无结果 | 记录来源、查询词、失败原因和是否执行备用来源；当天可写“0 个新增”。 | 不把旧岗位重新计为新增；下次运行优先切换官方来源或降低搜索频率。 |
| 某一方向篮子查询失败或核验达到上限 | 在方向可得性统计将覆盖标为`部分`或`失败`，记录实际完成的查询和上限。 | 不把该方向的 0 当作岗位为零；两周结论中排除或降权该日样本。 |
| 发现重复岗位 | 按 [评分规则](评分规则.md) 的 ID、原始链接、指纹顺序比对。 | 只更新既有条目；在日报记录“合并至 ID”，不重复计数。 |
| 公司、城市、在校生条件、发布时间或申请状态不完整 | 缺少字段写“未披露”；不得凭常识补全。 | `A`、`T`、`M`、`F` 不得因未知加分，状态为 `待核验`；未补齐前不进入 P0/P1。 |
| 岗位质量无法判断 | 摘录具体职责、交付物、代码/数据/测试/部署和带教事实；不要用公司名气或技术关键词代替。 | `Q` 留空或按保守值记录；Q<3 不进入“高质量开放”，待补证后再评分。 |
| AI 应用岗位只有提示词、标注、低代码或培训交付 | 保留岗位事实和来源，不把标题当作工程职责。 | Q≤2，最多 P2；若同时收费或主体不明，标记 `疑似风险`。 |
| 嵌入式岗位只有装配、刷机、巡检或重复手工测试 | 区分测试开发/调试代码与纯手工执行，记录可验证的工程任务。 | 纯辅助岗位 Q≤2，最多 P2；不因专业匹配自动进入 P1。 |
| 岗位已关闭或截止 | 保存关闭证据和最后核验时间。 | 标记 `已关闭`，停止推荐；若同公司有新 ATS 职位 ID，作为新岗位处理。 |
| 疑似诈骗、收费或岗位内容异常 | 不点击可疑文件、不提交个人信息、不付款；记录公开证据。 | 标记 `疑似风险`，`A=0`、`F=0`、`P3`，不再推荐。 |
| 评分依据不足或模型判断冲突 | 列出缺少的事实，不用“感觉”拉高分数。 | 降为 `待核验`，由本人或下一轮核验决定。 |

## 决策时效规则（2026-08-31 审计新增）

1. `开放待投` 状态连续存在超过 7 天而未变更时，当日运行必须在日报“今日待办”置顶提示本人决策到期。
2. 本人决策后，岗位必须落入四种状态之一：`已投递`（附日期）、`暂停`（本寒假不投，写明原因，如周期不符转暑期候选）、`待核验`（写明缺什么、由谁补）、`已关闭`。`开放待投` 不得作为决策后的长期停留状态。
3. “不投”是有效结论：记录原因后停止该岗位的 P1 72 小时循环，不再重复提示；仅当岗位状态、周期或本人城市分级变化时重新评估。

## 数据质量检查清单

每日结束前确认：

1. 每条 `开放待投` 均有可访问的原始链接、当日核验时间和明确申请状态；
2. 每条新增/更新记录都从日报链接回台账，并在台账链接回对应日报；
3. 台账没有相同 ATS ID、规范化原始链接或规范化指纹的两条开放记录；
4. 分数、优先级、Q、评分版本、下一步和状态彼此一致；
5. 每个固定方向都有方向统计行，且覆盖失败与无新增没有混写；
6. 未发生自动投递、自动发信或自动上传个人资料。
