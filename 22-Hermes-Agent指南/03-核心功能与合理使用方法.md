# 03 · 核心功能与合理使用方法

> 逐项：是什么 → 正确用法 → 学生场景示例 → 已知问题与风险。
> 【官方】= 官方文档原文；【社区】= 用户观点；【编者推断】= 写作方判断。
> 调研截止 2026-10-20。

---

## 0. 总原则（【官方】Tips）

1. **先跑通一次完整对话，再叠加 gateway / cron / skills / 语音 / 路由**。
2. 提示词要具体、前置上下文（贴报错堆栈直接给 agent）。
3. 重复指令写进项目根 `AGENTS.md`（每会话自动注入）；人格写 `~/.hermes/SOUL.md`。
4. 不可信代码一律 Docker / Daytona 后端跑。
5. 危险命令审批第一次选「session」而非「always」。
6. 聊天平台会话不主动重置，自然节点用 `/new` 收口（让记忆与 session_search 的学习循环真正生效）。

---

## 1. 记忆（Memory）

### 是什么【官方】

有界、人工策展的持久记忆，两个文件，存于 `~/.hermes/memories/`：

- `MEMORY.md`：agent 个人笔记，**2,200 字符 ≈ 800 token**
- `USER.md`：用户档案，**1,375 字符 ≈ 500 token**

会话启动时作为**冻结快照**注入 system prompt；agent 用 `memory` 工具 add / replace / remove。会话级历史另由 SQLite `~/.hermes/state.db` + FTS5 全文搜索承载（`session_search` 工具）。可选外部记忆 provider：Honcho / Mem0 / Hindsight / OpenViking。

### 正确用法【官方】

- 想让它记住时明说：「remember this for next time」。
- 写满时工具返回错误让 agent 自行合并条目（不静默丢弃）；建议容量 >80% 时主动整理。
- 核对记忆是否真写入：

```bash
cat ~/.hermes/memories/MEMORY.md
```

- `/journey`（CLI/TUI/Desktop）查看学习时间线，可剪枝、修正已学内容。
- 记忆按 profile 隔离；**不要两个 agent 进程共用同一个 HERMES_HOME**。

### 学生场景示例【编者推断】

- 把"我是本校大一、电子信息类、用 Windows+WSL2、惯用 DeepSeek、代码风格偏好"写进 USER.md，以后任何会话不用重复自我介绍。
- 课程项目笔记："信号与系统作业用 MATLAB；PID 课程实验用 STM32 HAL 库"——跨会话续聊项目时直接生效。

### 已知问题【社区】

- 小模型（<30B）常"嘴上说记住了但没调 memory 工具"——一定要 `cat` 文件核对。【官方·注意事项】
- **记忆膨胀**：~200 次对话后 SQLite 库达 280MB，有 `/compress` 但无自动压缩。【个人体验·andrew.ooo】\<https://andrew.ooo/posts/hermes-agent-nous-research-self-improving-review/>
- FTS5 检索偶尔拉到不相关内容。【CSDN 一粒黑子，墨衍分发文，可旁证】\<https://blog.csdn.net/u014354882/article/details/160173016>
- 无法导出"关于我的一切"单文件，GDPR / 隐私友好性不足。【dplooy】
- 会话中途写入的记忆**不影响当前会话**（冻结快照），下一会话才生效——别指望"现在说的它立刻记住"。【官方】
- 省钱开关：后台 self-improvement review 默认复用主模型热缓存；可路由到更便宜模型（官方称成本约低 3–5×），可用 `auxiliary.background_review.max_input_tokens` 封顶单次输入 token；可 `enabled: false` 完全关闭自动 review。【官方】

## 2. 技能（Skills）

### 是什么【官方】

按需加载的程序化知识文档，符合 **agentskills.io 开放标准**；主目录 `~/.hermes/skills/`。记忆存"事实 what"，技能存"流程 how"。三级渐进式披露（列表→全文→引用文件）控制 token 成本。

### 正确用法【官方】

```bash
# /skill-name 斜杠命令直接调用
# 从文档/代码库/对话/整本书自动创作 skill
/learn <来源>
# 从 Skills Hub 安装
hermes skills search
hermes skills install <name>
```

- 长期重复工作流（5 步以上）值得存成 skill。
- 项目级 skill 不自动加载：仓库里的 `.hermes/skills/` 需先 `hermes skills trust` 信任；安装前做安全扫描，危险内容进隔离区（quarantine）。
- 后台 Curator 会对自建 skill 做 active→stale→archived 生命周期管理并提议合并/修补。

### 学生场景示例【编者推断】

- 把"实验室环境配置流程""课程大作业提交格式"这种每次都要做的步骤做成 skill，一次 `/learn` 之后永远复用。
- 从 GitHub 克隆一个项目后 `/learn` 它的 README，agent 就"懂"这个项目了。

### 已知问题（本项目最需要警惕的坑）【社区·三方互证】

- **自进化 skill 会固化错误流程**：agent 几乎总认为自己做对了，即使输出有错也把错误经验固化成 skill；你手动改好一个 bug，下次它又按旧 skill 把错误改回去——power user 称之为"噩梦"。来源：Reddit 高赞转述 \<https://www.cnblogs.com/haibindev/p/19881562>；腾讯云 3 个月弃用文 \<https://cloud.tencent.com/developer/article/2702804>；andrew.ooo"skill 质量 hit-or-miss、有时过度具体（如'每周二 9:32 部署'）需手动清理"。
- **应对（综合社区与官方机制）**：
  1. 定期审查 `~/.hermes/skills/` 目录，手动修剪/删除劣质 skill；
  2. 用 `/journey` 剪枝错误的学习条目；
  3. 可关闭自动 review（见记忆节开关），改为人工 `/learn`；
  4. 多项目用 profile 隔离，避免 skill 库互相污染（【社区】抖音多 agent 经验：单全能 agent 30 天记忆池污染 → 角色隔离，`hermes profile create <名> --clone`）\<https://www.iesdouyin.com/share/video/7637915770097257770>。
- **自学习默认关闭**：要 `hermes config set memory.persistent true` + `skills.autogen true` 才激活——首次使用最常见的"惊喜"（我装的怎么不会自我进化）。【dplooy】
- 工具定义本身占 ~50% 输入 token；内置工具太多用不到又没方便开关（约占 15% token）。【dplooy / 腾讯云】

## 3. Cron 定时任务

### 是什么【官方】

`cronjob_manage` 工具 + `/cron` + `hermes cron` CLI；**由 gateway 守护进程每 60 秒 tick 执行**。

### 正确用法【官方】

- 自然语言直接说："每天早 9 点查 HN 发 Telegram 摘要"，agent 自动建 job。
- 调度格式：相对延迟（`in 30m`）、间隔（`every 2h`）、标准 cron 表达式（`0 9 * * *`）、ISO 时间戳。
- 可挂 0–多个 skill、可投递到任意聊天平台、支持无 LLM 的 `no_agent` 脚本模式、支持 webhook 事件触发。
- job 可钉模型（`--pin`）；失败自动重试（网络/DNS 问题在 5/15/30 分钟后重跑，零 API 调用不计费）。
- 未跑完的 job 中断后停在 paused 状态等人工，不会自动重跑。
- 建议 `/sethome` 指定主聊天，cron 结果才有投递目的地。

### 学生场景示例【编者推断】

- 每天 8:00 自动汇总 HN / GitHub Trending / arXiv 相关方向论文，推送到 Telegram，早八路上看。
- 每周日晚 10 点提醒整理本周项目进度并更新 memory。
- 课程结项前每天检查一次依赖构建是否通过（no_agent 脚本模式省 token）。

### 安全关键（【官方】必须遵守）

- **cron 会话命中危险命令时默认 `deny`**（无人值守无人审批）；`approvals.mode: off` / YOLO 在 cron 下也不生效（除人工 `approve` 显式开启）。
- **cron 运行的会话默认不能再创建 cron job**（防失控循环），需 `cron.allow_agent_scheduling: true` 才放开——学生保持默认即可。
- 权限最小化：给 cron 的任务别挂写权限大的 skill。

## 4. 工具网关（Nous Tool Gateway）

### 是什么【官方】

Nous 托管的工具后端，**付费订阅功能**，一个 OAuth 覆盖四类工具：web 搜索与全文抽取；图像生成（FAL 目录 / Krea 2 / FLUX 2 / GPT Image / Nano Banana / Seedream / Ideogram 等）；TTS（OpenAI 音色）；云端浏览器自动化（Browser Use 无头 Chromium）。

### 正确用法【官方】

```bash
hermes setup --portal        # 一键开
# 或逐工具选「Nous Subscription」
hermes tools
```

- **非锁定**：每工具可混用（如 web+图像走网关、TTS 用自己的 ElevenLabs key）。
- 订阅过期则网关工具停用，需续订或切回直连 key。
- 高级用户可自托管兼容网关（`TOOL_GATEWAY_DOMAIN` 等 env 覆盖）。
- Modal serverless 终端是**另购 add-on**，不在默认网关包内。
- **Nous Portal 具体价格档位本次未抓取**（官方只写 paid-subscription），请查 Nous Portal 官网定价页，本指南不给编造单价。

### 学生场景【编者推断】

- 预算有限可不开 Portal：web 搜索用 Tavily（社区教程提到月 1000 次免费）或 DuckDuckGo；本地模型无 web 工具时留一个便宜云模型做 web access provider。

## 5. 消息网关（Messaging Gateway）

### 是什么【官方】

单个后台进程连所有平台、跑会话、跑 cron、投递语音消息。平台覆盖（20+）：Telegram、Discord、Slack、WhatsApp、Signal、SMS、Email、Home Assistant、Mattermost、Matrix、DingTalk、**Feishu/Lark**、WeCom、**Weixin（微信）**、BlueBubbles(iMessage)、**QQ**、Yuanbao、Teams、LINE、ntfy、IRC、SimpleX、Google Chat 等。

### 正确用法【官方】

```bash
hermes gateway setup     # 交互配置
hermes gateway start     # 启动
hermes gateway install    # 装用户服务（macOS launchd / Linux user service）
# 装开机自启系统服务需要 sudo，学生机器上不建议；用户级服务已够用
```

### 安全关键（【官方】必须遵守）

- **默认拒绝所有不在允许名单 / DM 配对的用户**；绝不要在有终端权限的 bot 上开 `GATEWAY_ALLOW_ALL_USERS=true`。
- DM 配对码一次性、1 小时过期；admin / 普通用户两级权限（普通用户只能用白名单内斜杠命令）。
- 投递有持久化 delivery ledger，崩溃后不丢回复（至少一次语义）。

### 网关封号风控（重点，【社区】+【官方文档口径】）

- **优先 Telegram / Discord / 飞书**：这些平台有正式 bot API，风控风险低。
- **微信 / WhatsApp 走第三方桥接扫码**，有封号风险：
  - 【社区·个人体验】抖音用户因 Grok Bot 封号导致工作流丢失，转用开源 Hermes。\<https://www.iesdouyin.com/share/video/7695121437635513650>（注：该页 2026-10-20 抽查返回 404，观点来自调研原始记录）
  - 【社区】WhatsApp 走非官方桥接有封号风险，官方文档建议专用号码、不群发、不主动 outbound（官方 whatsapp 文档，hermes-agent.ac.cn，中文镜像站）。
  - 【社区】微信接入依赖第三方扫码，有风控风险；抖音教程普遍建议"私信审批、禁群聊、设主管频道"。\<https://www.iesdouyin.com/share/video/7629262488365796646>
- **做法**：用小号 / bot token；不用主号扫码；不拿 bot 干批量群发。

### 学生场景【编者推断】

- 宿舍场景：笔记本合盖没法常驻？两种解法——① 旧笔记本 / 便宜 VPS（社区实测 $5 VPS 即可常驻，见 04 文件）跑 `hermes gateway install` 用户服务；② Modal serverless 后端（空闲休眠）。
- 远程派任务：手机 Telegram 发"帮我查一下 XX 报错"，宿舍电脑上的 agent 回。

### 已知问题【社区】

- Telegram `409 Conflict` getUpdates：同一个 bot token 多端开会冲突，只留一个 gateway 实例。\<https://www.betterclaw.io/blog/hermes-agent-not-working>
- gateway 必须常驻主机：休眠只省后端计算，不省 gateway 进程。\<https://andrew.ooo/posts/hermes-agent-nous-research-self-improving-review/>
- gateway 连 Telegram 超时需配 `HTTPS_PROXY`。【CSDN 一粒黑子】

## 6. 隐私与安全边界（学生必知）

【官方·Security 页八层防御】：用户授权（允许名单+DM 配对）→ 危险命令审批 → 文件写入安全（denylist + 可选 write sandbox `HERMES_WRITE_SAFE_ROOT`）→ 容器隔离（Docker/Singularity/Modal/Daytona/Vercel Sandbox）→ MCP 凭据过滤 → 上下文文件扫描（防 prompt 注入）→ 跨会话隔离 → 输入消毒。

- 审批模式：`smart`（默认）/ `manual` / `off`；另有不可覆盖的硬线黑名单（`rm -rf /`、fork bomb、mkfs、dd 写裸盘等，YOLO 也拦）。
- 受保护路径：`~/.ssh/`、`~/.aws/`、`~/.kube/`、`.env`、OAuth token 等一律禁止 agent 写入/读取。
- **容器后端内会跳过危险命令检查**（容器即边界）——容器镜像要自己锁好。
- 数据出域两条路径：(a) 你选的模型 provider（对话内容发往 OpenAI/Anthropic/Nous 等）；(b) 若开 Tool Gateway，工具调用经 Nous 基础设施。**不用 Portal、全 BYOK + 本地模型时，对话与记忆可完全不出本机**【编者推断，基于各页配置机制】。
- 消息网关有 `privacy.redact_pii: true`，开启后转发给模型的聊天标识符哈希化。【官方】
