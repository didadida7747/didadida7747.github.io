# 30 分钟快速上手

目标：今天就能用 Codex 做一个小而可控的真实任务，并知道怎么检查它有没有乱改。

## 0. 先确认你要用哪个入口

| 入口 | 适合你现在做什么 | 先学优先级 |
|---|---|---|
| Codex App | 图形界面、多任务、看 diff、管理项目和任务 | 最高 |
| Codex CLI | 终端内读项目、改代码、跑命令、脚本化 | 第二 |
| IDE Extension | 在 VS Code / Cursor / Windsurf 旁边改代码 | 第三 |
| Codex Cloud / GitHub | 云端跑任务、生成 PR、远程继续 | 进阶 |

建议：先用 Codex App 跑通 3 个小任务，再补 CLI。你当前目标是“熟悉操作”，不是一开始折腾 Cloud、MCP 或第三方模型。

## 1. 第一次任务只做读项目

复制这个提示词：

```text
请先不要修改任何文件。

请阅读当前项目，输出一份项目理解报告：
1. 这个项目主要用来做什么
2. 目录结构和关键文件
3. 可以安全修改的文件
4. 不应该随便动的文件或配置
5. 如果要做一个小练习任务，建议先做哪一步

只输出报告，等我确认后再继续。
```

验收标准：

- 它有没有先读 `README.md`、目录结构和关键文件。
- 它有没有明确“不修改文件”。
- 它有没有标出不确定项，而不是编造命令。

## 2. 第二个任务只做一个小改动

适合新手的任务：

- 给 README 增加一段使用说明。
- 修正文档里的错别字或路径。
- 给一个静态 HTML 页面改标题、按钮文案、移动端样式。
- 给一个脚本增加 `--help` 或更清晰的错误提示。

复制这个提示词：

```text
请做一个小步修改，范围只限于：
【写明文件或目录】

目标：
【写明一个具体目标】

要求：
1. 先说明你准备改哪些文件
2. 不要修改无关文件
3. 修改后读回关键文件确认
4. 如果项目有测试或构建命令，请运行；没有就说明无法运行的原因
5. 最后给我总结 diff 和风险
```

## 3. 第三个任务学会检查

复制这个提示词：

```text
请进入检查阶段，不要继续新增功能。

请按顺序完成：
1. 检查本次改动涉及哪些文件
2. 总结每个文件为什么需要改
3. 检查是否有无关修改
4. 如果有测试、构建或静态检查命令，请运行并报告结果
5. 如果不能运行，请说明缺少什么环境
6. 给出是否可以提交的结论
```

你要重点看：

- 是否只改了计划内文件。
- 是否有大段删除。
- 是否引入新依赖。
- 是否把密钥、路径、账号信息写进文件。
- 是否把“没跑测试”说成“已验证”。

## 30 分钟结束时你应该掌握

- 能区分 ChatGPT 问答和 Codex 执行任务。
- 能让 Codex 先读项目、再小步修改、最后检查。
- 能看懂任务、diff、权限和测试输出。
- 知道复杂任务先用计划模式或让它先出计划。
