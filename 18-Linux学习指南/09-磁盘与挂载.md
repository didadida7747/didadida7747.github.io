# 第9章 磁盘与挂载

> 学完这章，你能看懂磁盘到底是怎么组织的，能用 `df` 和 `du` 找出"是谁把我磁盘吃满了"，还能搞明白 WSL2 那个越涨越大的 `ext4.vhdx` 文件怎么压回去。

## 本章你将学会

- 看懂 `/dev/sda`、`nvme0n1p1` 这种设备名
- 理解分区、文件系统、挂载点三个概念
- 用 `lsblk`、`df -h`、`du` 看清磁盘使用情况并揪出大文件
- 知道 `mount` / `umount` / `/etc/fstab` 是干嘛的（知道就行，别乱动）
- 理解 swap 是怎么回事
- 搞懂 WSL2 的 `ext4.vhdx` 文件在哪、为什么只增不减、怎么压缩
- 理解 `df -i` 的 inode 耗尽问题
- 知道云服务器扩容大概是什么流程

## 为什么需要它

你迟早会撞上这两个场景：

1. 敲任何命令都报 `No space left on device`（磁盘满了），但你不知道是谁吃的。
2. WSL2 用了半年，发现 Windows 上那个 `ext4.vhdx` 文件占了 60GB——可你在 Linux 里 `df -h` 明明只用了 20GB。

这章就是解决这两个问题。磁盘在 Linux 里是个有点抽象的东西，因为你平时 `ls` 看到的 `/` 根本不是一块真硬盘，是系统把硬盘分区"挂"到目录树上来的结果。我们一步步拆。

---

## 9.1 设备命名：/dev/sda 和 nvme0n1p1

Linux 把所有硬件设备都当成文件，放在 `/dev/` 目录下。硬盘也不例外。常见命名规则：

| 名字 | 什么意思 |
|---|---|
| `/dev/sda` | 第一块 SATA/SCSI 硬盘（a = 第一块，b = 第二块……） |
| `/dev/sda1` | 第一块硬盘上的第 1 个分区 |
| `/dev/sdb2` | 第二块硬盘上的第 2 个分区 |
| `/dev/nvme0n1p1` | 第一块 NVMe 固态盘上的第 1 个分区（现在新笔记本基本都是这种） |
| `/dev/nvme0n1p2` | 同一块 NVMe 盘的第 2 个分区 |
| `/dev/sr0` | 光驱（基本见不到了） |

> 📌 **注意：WSL2 里你看到的硬盘是虚拟出来的。** 你真正的物理硬盘在 Windows 那边，WSL 给你分了一块虚拟磁盘文件（就是那个 `ext4.vhdx`），挂成 `/dev/sd` 或类似的设备。所以在 WSL 里 `fdisk -l` 看到的不是你笔记本的真硬盘。

---

## 9.2 分区、文件系统、挂载点：三个概念一次讲清

一块物理硬盘要能用，得经过三步：

1. **分区**：把一块大硬盘切分成几块逻辑上的"小盘"。比如 512GB 的盘切成一个 100GB 给系统、一个 400GB 给数据。
2. **文件系统**：每个分区上要"格式化"成一种文件系统格式，Linux 最常用的是 **ext4**。没有文件系统，操作系统不知道怎么在这堆扇区上存文件、找文件。
3. **挂载**：把格式化好的分区接到目录树的某个空目录上，这个目录叫**挂载点**。比如把"根分区"挂到 `/`，把"数据分区"挂到 `/data`。

这就是为什么 Linux 没有 C 盘、D 盘的概念——所有分区最终都融入一棵从 `/` 开始的目录树，你 `cd /data` 就相当于"进入那个数据分区"。

```bash
$ lsblk
NAME    MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
sda       8:0    0  256G  0 disk
├─sda1    8:1    0  512M  0 part /boot/efi
└─sda2    8:2    0 255.5G  0 part /
```

`lsblk`（list block devices）把所有块设备和挂载点画成树。上面这台机器一块 256G 的盘，分两个区：512M 的 EFI 引导分区挂到 `/boot/efi`，剩下一大块挂到 `/`。

> 💡 **小技巧：在 WSL2 里你跑 `lsblk`，大概长这样：**
> ```text
> NAME   MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
> sda      8:0    0  256G  0 disk
> └─sda1   8:1    0  256G  0 part /
> ```
> 就一个根分区，简单干净——WSL 帮你管好了，不用自己分区。

## 9.3 `df -h`：看磁盘还剩多少

`df`（disk free）告诉你**每个挂载点用了多少、还剩多少**：

```bash
$ df -h
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda2       256G   20G  224G   9% /
tmpfs           3.9G     0  3.9G   0% /dev/shm
```

逐列：

| 列 | 含义 |
|---|---|
| Filesystem | 哪个设备 |
| Size | 总大小 |
| Used | 已用 |
| Avail | 还能用多少 |
| Use% | 用了百分之几 |
| Mounted on | 挂在哪 |

> 📌 **注意：当 Use% 冲到 100%，你敲任何写文件的命令都会报 `No space left on device`。** 这时候别慌，先看是哪个分区满了——别一上来就删东西。

### `df -i`：inode 也会满

还有一种少见但恶心的情况：磁盘空间看着没满，但就是写不进去。这是 **inode 耗尽**了。

每个文件在文件系统里除了占磁盘空间，还要占一个 **inode**（记录文件名、大小、权限、位置的那个元数据块）。如果你在某个目录里建了几十万个小文件（比如缓存目录），空间可能才用了几个 G，但 inode 全用光了——新文件一个都建不了。

```bash
$ df -i
Filesystem      Inodes  IUsed  IFree IUse% Mounted on
/dev/sda2      16777216 500000 16277216    3% /
```

看 `IUse%`。它要是 100%，就是 inode 问题——得去找那个几十万个小文件的目录删掉，而不是删大文件。

---

## 9.4 `du`：揪出是谁吃了磁盘

`df` 告诉你"哪个分区满了"，`du`（disk usage）告诉你"这个目录里谁最占地方"。

```bash
# 看当前目录总大小，human-readable
$ du -sh
```

`-s` 是 summary（只总结一层，不递归展开），`-h` 是人类可读。

排查"是谁把磁盘吃满了"的标准姿势：

```bash
# 从根开始扫，每个一级目录占多大；2>/dev/null 是把"权限不够"的报错丢到垃圾桶
$ sudo du -sh /* 2>/dev/null | sort -h
```

这行命令拆开讲：

- `sudo du -sh /*`：对 `/` 下的每个一级目录（`/etc`、`/home`、`/var`……）算总大小
- `2>/dev/null`：stderr 重定向到 `/dev/null`（黑洞），不然会刷一堆 Permission denied
- `| sort -h`：按人类可读数字排序（`-h` 能认识 K/M/G），最大的排最后

然后你看到 `/var` 占了 30G，就 `sudo du -sh /var/* | sort -h` 往下钻一层，直到找到罪魁祸首。

> 💡 **小技巧：在 WSL2 里，最常见的"莫名其妙占空间"是 Docker 镜像日志、`~/.cache`、或你之前删错了一个正在被进程占着的大文件（下一行讲）。**

> 📌 **注意：`/var/log` 也是磁盘杀手常客。** 很多程序日志默认不轮转，跑几个月能吃掉几个 G。`sudo du -sh /var/log/*` 扫一眼，真要清日志用 `logrotate` 或直接 `sudo truncate -s 0 日志文件`（不要直接 `rm`，进程还拿着文件句柄）。

> 📌 **注意：删了文件但磁盘空间没释放？** 因为那个文件可能正被某个进程打开着。Linux 下 `rm` 只是删了目录项，文件真正释放要等所有打开它的进程都关闭。解决办法：找到那个进程重启它，或者 `lsof | grep deleted` 看哪些文件被删了还被占着。

## 9.5 `mount` / `umount` / `/etc/fstab`

手动挂载一个 U 盘或额外硬盘：

```bash
# 把 /dev/sdb1 挂到 /mnt/usb 这个空目录上
$ sudo mount /dev/sdb1 /mnt/usb

# 用完了卸下来
$ sudo umount /mnt/usb
```

> ⚠️ **警告：挂载点必须是个空目录，不然原来那个目录里的东西会被"遮住"看不见。** 而且 umount 的时候，你当前工作目录不能在这个挂载点里面，不然会报 `device is busy`。

**`/etc/fstab`** 是个配置文件，里面列了"开机自动挂载哪些分区、挂到哪、用什么参数"。改错一行，**下次开机直接起不来**。

> ⚠️ **强警告：编辑 `/etc/fstab` 之前，先备份一份：**
> ```bash
> $ sudo cp /etc/fstab /etc/fstab.bak
> ```
> 改完用 `sudo mount -a` 测试能不能正常挂载，**确认没报错再重启**。在 WSL2 里你基本不需要碰 fstab——WSL 自己管根分区。在真正的云服务器上加数据盘时才会用到。现在只要知道这个文件是干嘛的，**别手贱去改**。

> 💡 **小技巧：** 你可以 `cat /etc/fstab` 看一眼长什么样，就当阅读理解，不要编辑。每行大概是六个字段：`<设备>  <挂载点>  <文件系统>  <挂载参数>  <dump频率>  <开机检查顺序>`。看到一堆 `/dev/disk/by-uuid/xxxx` 这种 UUID 形式的设备名别慌，那是系统自动生成的，比写 `/dev/sdb1` 更稳（设备名有时候会因为插拔顺序而变，UUID 永远不变）。

## 9.6 swap：内存不够时的救兵

上一章 `free -h` 里见过 Swap 那一行。它是什么？是硬盘上划出来一块空间，当物理内存真不够用时，内核把暂时不用的内存页写到 swap 里，腾地方给急用的程序。

```bash
$ free -h
               total        used        free      shared  buff/cache   available
Mem:           3.8Gi       1.5Gi       1.0Gi       200Mi       1.3Gi       2.1Gi
Swap:          1.0Gi          0B       1.0Gi
```

Swap 用得不多是好事；如果 Swap 长期被吃满，说明物理内存真不够了。

WSL2 的 swap 是你在 `.wslconfig` 里配的（第 2 章讲过），默认一般给物理内存的 25%。

### tmpfs：内存当磁盘用

你 `df -h` 时会看到一行 `tmpfs`：

```text
tmpfs           3.9G     0  3.9G   0% /dev/shm
```

这是 **tmpfs**——它不占硬盘，直接用你的物理内存当临时文件系统。放进去的东西机器一重启就没了，速度极快。用途：临时缓存、共享内存（你以后跑数据库、Docker 会碰到）。你不用管它，知道"它不是真磁盘"就行。

## 9.7 WSL2 专题：那个 `ext4.vhdx` 是怎么回事

这是 WSL 用户最常问的问题，专门讲。

### 它在哪

你 WSL 里看到的整个 Linux 文件系统（`/home`、`/etc`……），在 Windows 上其实就是一个**虚拟磁盘文件**，后缀 `.vhdx`。Ubuntu 24.04 的默认路径大概在：

```
C:\Users\fjbsllc\AppData\Local\Packages\CanonicalGroupLimited.Ubuntu24.04LTS_79rhkp1fndgsc\LocalState\ext4.vhdx
```

（你的具体路径可以 PowerShell 里 `wsl --list -v` 看发行版名字，再去 `%LOCALAPPDATA%\Packages\` 下找对应的 Canonical 目录。）

在 Windows PowerShell 里看它多大：

```powershell
Get-ChildItem "$env:LOCALAPPDATA\Packages\CanonicalGroupLimited.Ubuntu24.04LTS_79rhkp1fndgsc\LocalState\ext4.vhdx" | Select-Object Name, @{N='SizeGB';E={[math]::Round($_.Length/1GB,1)}}
```

这个数字和你 WSL 里 `df -h` 看到的 Used 一对比，差额就是"僵尸空闲空间"。

### 为什么它只增不减

这是 vhdx 这种**动态扩展磁盘**的特性：它向 Windows 申请空间时只会越涨越大，你在 Linux 里删了文件，vhdx 文件本身**不会自动缩小**——Linux 那边释放的空间只是标记成"空闲"，文件大小不变。

所以你会看到：Linux 里 `df -h` 说用了 20G，但 Windows 上这个 vhdx 文件有 60G。多出来的 40G 是历史上用过、现在标记为空闲但没还给 Windows 的空间。

### `/mnt/c` 的权限现象

你在 WSL 里 `ls -l /mnt/c/Users/...` 会发现 Windows 的文件全都显示成 777：

```text
drwxrwxrwx 1 root root  512 Oct 13 10:00 /mnt/c/Users
```

这是故意的——Windows 文件系统 NTFS 没有 Linux 的 rwx 权限概念，WSL 用 drvfs 挂载时统一给个宽松权限。**所以你在 `/mnt/c` 下改 chmod/chown 都是徒劳的**，别浪费时间。这也是为什么第 12 章会强调"代码要放在 Linux 侧（`~/`），不要放在 `/mnt/c`"。

### 怎么压缩 vhdx

**步骤（在 Windows PowerShell 里操作，不是在 WSL 里）：**

1. **先关掉 WSL：**
   ```powershell
   wsl --shutdown
   ```

2. **方法一（推荐，WSL 2.x 新命令，2024 年后版本支持）：**
   ```powershell
   wsl --manage Ubuntu-24.04 --set-sparse true
   ```
   （注意：发行版名字要和你 `wsl --list` 看到的一致。这个命令让 vhdx 变稀疏，空闲块自动还给 Windows。）

3. **方法二（传统 diskpart 压缩）：**
   ```powershell
   diskpart
   ```
   进入 diskpart 后依次敲：
   ```text
   select vdisk file="C:\Users\fjbsllc\AppData\Local\Packages\CanonicalGroupLimited.Ubuntu24.04LTS_79rhkp1fndgsc\LocalState\ext4.vhdx"
   attach vdisk readonly
   compact vdisk
   detach vdisk
   exit
   ```

> ⚠️ **警告：压缩之前先把 WSL 里重要的东西备份一下。** 压缩理论上无损，但 vhdx 文件操作始终有风险。另外，压缩前最好在 WSL 里先 `sudo fstrim -a`（让 Linux 那边把真正空闲的块标记一下），这样压缩效果更好。

> 📌 **注意：`wsl --unregister Ubuntu-24.04` 是删除整个发行版，不是压缩。** 别敲错。真要 unregister 之前一定先 `wsl --export` 备份成 tar。

## 9.8 云服务器扩容是个啥流程

以后你租云服务器（阿里云/腾讯云学生机），一开始一般给 40G 系统盘，用着用着不够了怎么办？大概流程是（概念，不用现在做）：

1. 在云控制台点"扩容磁盘"，把 40G 在线扩到 100G。
2. 回到服务器里，用 `growpart` 和 `resize2fs` 把这个扩容了的分区和文件系统"撑开"。
3. `df -h` 确认多出来的空间生效了。

整个过程对你透明，不用重装系统。具体命令等你真有学生机了再查，现在知道有这么回事。

> 📌 **注意：扩容流程里那两个命令（`growpart` 和 `resize2fs`），名字先眼熟一下：**
> ```bash
> # 假设新挂上来的盘是 /dev/vdb，分区 1
> $ sudo growpart /dev/vdb 1
> $ sudo resize2fs /dev/vdb1
> ```
> 第一步把分区表"撑开"到新的物理大小，第二步把 ext4 文件系统"撑满"这个分区。WSL 里你不用做，但云服务器运维这是高频操作。

## ⚠️ 危险操作与安全红线

- **`/etc/fstab` 改错 = 系统起不来。** 改之前备份，改完 `mount -a` 测试。
- **`mkfs.ext4 /dev/sdXX`（格式化）会把整个分区数据抹掉。** 确认你选的设备名再按回车。
- **`rm -rf` 对挂载点是真删。** 删之前 `df -h` 确认你在哪个分区里。
- **WSL 的 vhdx 文件不要在 Windows 里直接删。** 要删发行版用 `wsl --unregister`，不要手动删文件。
- **不要在 WSL 里尝试 `fdisk` 分区、`mkfs` 格式化你自己的虚拟磁盘**——WSL 会崩溃。这一章的磁盘命令你在 WSL 里只看不练真分区，练手用 `df`、`du`、`lsblk` 这些只读命令。

## 常见报错与排查

| 现象 | 原因 | 解决 |
|---|---|---|
| `No space left on device` | 磁盘满了 | `df -h` 找满的分区，`du -sh /*` 找大文件 |
| 空间没满但写不进去 | inode 满了 | `df -i` 看 IUse%，找几十万小文件的目录 |
| 删了大文件磁盘还是满 | 文件被进程占着没释放 | `lsof | grep deleted`，找到进程重启 |
| Windows 上 vhdx 巨大 | WSL vhdx 只增不减 | `wsl --shutdown` 后用 diskpart compact 或 `--set-sparse` |
| `/mnt/c` 下 chmod 不生效 | drvfs 统一权限 | 正常，别折腾；代码放 Linux 侧 |
| `umount: device is busy` | 当前目录在挂载点里 | `cd` 到别的目录再 umount |
| `mount: /mnt/xxx: mount point does not exist` | 挂载点目录没建 | `sudo mkdir -p /mnt/xxx` |

## 动手练习

1. 跑 `lsblk`，对着输出画出你 WSL 的磁盘结构：设备名、分区、挂载点。
2. 跑 `df -h`，报告你根分区总共多大、用了多少、还剩多少。
3. 跑 `sudo du -sh /* 2>/dev/null | sort -h`，找出 `/` 下最大的三个目录，逐层下钻看看是谁。
4. 跑 `df -i`，看你根分区 inode 使用率是多少。
5. 在 WSL 里 `sudo fstrim -a`（安全操作，告诉 SSD 哪些块空闲），然后 Windows 那边 `wsl --shutdown`，观察 vhdx 文件大小有没有变化（可对比前后大小）。
6. （选做，有学生机再做）在云服务器上跑 `lsblk`、`df -h`，对比和 WSL 的输出有什么不同。

## 本章小结

| 命令/概念 | 一句话作用 |
|---|---|
| `lsblk` | 列出磁盘和分区树 |
| `df -h` | 看每个分区用了多少 |
| `df -i` | 看 inode 用了多少 |
| `du -sh 目录` | 看某个目录占多大 |
| `du -sh /* 2>/dev/null \| sort -h` | 排查大文件标准姿势 |
| `mount /dev/sdX /mnt/xxx` | 手动挂载 |
| `umount /mnt/xxx` | 卸载 |
| `/etc/fstab` | 开机自动挂载表（别乱动） |
| swap | 磁盘上当虚拟内存用 |
| ext4.vhdx | WSL 的整个 Linux 文件系统 |
