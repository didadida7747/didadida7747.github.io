## 3. 自建 vs 调用 API 的盈亏平衡（假设驱动，需用户替换为实际数字）

### 3.1 假设

- 对标模型：gpt-oss-120b（同等能力级别的开源模型）。
- 第三方 API 价格参考：Groq 为 $0.15/MTok 输入、$0.60/MTok 输出（[聚合：aipricing.guru 等](https://www.aipricing.guru/groq-pricing/)；**Groq 官方页未显示具体数字**，[未核实]）。
- 自建硬件：1 张 H100 云租赁，按中位价 $3.38/hr（来源见 2.3）。
- 假设：月运行 720 小时（24×30）。
- 假设：该卡实际服务吞吐（**未核实，需实测**）。

### 3.2 计算

- 月固定成本（计算）：$3.38 × 720 ≈ **$2,434/月**（不含人力、运维、备份、流量）。
- 如按 API 输出价 $0.60/MTok 对照，盈亏平衡月 token 量（计算）：$2,434 ÷ $0.60 per M ≈ **4,057M tokens/月**，约 **1.35 亿 tokens/天**，平均约 **1,560 tok/s 持续输出**。
- 如按 API 输入价 $0.15/MTok 对照（纯输入场景），盈亏平衡约 16.2 亿 tokens/月（计算）。

### 3.3 结论（有条件）

- 只有在**持续高负载**（接近满载吞吐）时，自建才可能比 API 便宜；单卡日均几千万 token 以下，API 通常更划算（计算+假设）。
- 如果用 H200/B200 或价格更高的 API（如闭源前沿模型），盈亏平衡点会移动，需要重算。
- 未计入：工程人力、模型升级维护、高可用冗余（通常需要至少 2 卡）、数据合规成本。这些往往是自建最大的隐性成本（**常识，未附来源**）。

## 5. 隐私、合规、数据驻留、企业采购

### 5.1 OpenRouter 的 ZDR（Zero Data Retention）

- ZDR 指的是**上游模型供应商**的数据留存政策：启用后，只路由到声明零留存的 endpoint。可在账户、模型组、guardrail 或单次请求层面设置。来源：[OpenRouter ZDR 文档](https://openrouter.ai/docs/guides/features/zdr)（搜索摘要引用）。
- 政策按 endpoint 判断而非按公司判断；无法确认的 endpoint 会被视为留存并可能用于训练。
- ZDR **不覆盖**：联网搜索、plugin/tool、提示词缓存（[聚合说明](https://openrouter.uwarp.design/openrouter-zdr)）。 **[未核实]**
- OpenRouter 自身默认不保存 prompt/response 内容，除非主动开启日志；但仍保存 token 数、延迟、模型、费用等元数据（搜索摘要引用的 OpenRouter 文档）。
- 文档存在矛盾：一篇第三方分析称 provider 日志概览页与 ZDR 页说法不一致。 **[未核实]**，采购前应直接读官方文档原文。

## 6. 适用场景：什么时候选开源自建

**倾向选开源自建的情况（需先满足其中一条以上并算清账）**
1. 数据不允许出境或必须内网运行（政务、医疗、金融等），且无法接受 ZDR 类承诺。
2. 调用量足够大、持续接近满载，使固定成本摊薄后低于 API（参考第 3 节的盈亏平衡）。
3. 需要对模型做微调、改权重、或长期锁定某个版本，不接受第三方随时下线或改版。
4. 需要极低延迟或离线运行（如 Mac/消费级显卡上的本地助手）。

**不建议自建的情况**
1. 调用量低、波动大（API 按量付费更划算）。
2. 没有 GPU 运维与模型运维能力。
3. 需要最前沿的闭源模型能力（开源模型通常落后一个版本或更多；**此判断为常识，未附来源**）。

**许可证使用建议**
- 如果是长期商用产品：优先 Apache 2.0 / MIT 模型；Llama 社区许可证需专门评估月活门槛与品牌署名要求；使用 gpt-oss 需阅读附加使用政策原文。
