2.2 爆发方向 vs 内卷方向

爆发方向（需求旺盛）
  • Agent开发：多智能体协作、工具调用、工作流编排
  • AI编程/Copilot：代码大模型、DevOps自动化

  • 数据标注/AI训练师：门槛低，可替代性强

2 真实面经高频考点（按类别）

以下考点来自牛客2025-2026年AI应用开发/Agent岗公开面经统计，标注来源。

考点频率排名（牛客统计）： RAG相关合计175次（检索增强生成107+RAG 40+信息检索26+RAG评估2）> Agent架构 > Python/Go基础 > 操作系统/计网 > MySQL/Redis > 大模型原理 > 项目深挖
RAG / 检索增强生成（第一考点） ▶
Q: 详细解释RAG从索引、召回到生成的完整过程
标准链路：文档加载→分块(chunking)→Embedding向量化→存入向量库→查询时query向量化→相似度检索→取Top-K相关chunk→拼入prompt→LLM生成回答
Q: RAG有哪些分类？
Naive RAG（基础版）/ Advanced RAG（预处理+后处理优化）/ Modular RAG（模块化可插拔）；按模态分：纯文本RAG vs 多模态RAG
Q: 多模态RAG怎么实现？伪多模态和真多模态区别？
伪多模态：图片转文字描述(用BLIP等)后走文本RAG；真多模态：直接用CLIP等跨模态Embedding做图文联合检索。CLIP用于真多模态RAG，因为它对齐了图文语义空间。
Q: RAG怎么评估？最重要的指标是什么？
检索指标：召回率(Recall@K)、精确率、MRR、NDCG；生成指标：Faithfulness（忠实度，是否基于检索内容）、Answer Relevancy。最重要的是Faithfulness——防止幻觉。
Q: RAG怎么评估？RAGAS和DeepEval有什么区别？【2026新增高频】
RAG评测分两层：
① 检索层：Recall@K（召回率）、Precision@K、MRR、NDCG——用标注好的"问题-相关文档"对测。
② 生成层：Faithfulness（忠实度，回答是否基于检索内容，防幻觉）、Answer Relevancy（回答与问题的相关度）、Context Precision/Recall。
工具：DeepEval（18k+ stars）——类似pytest的LLM评测框架，可写单元测试测RAG/Agent，支持幻觉/忠实度/准确率指标，CI/CD集成。RAGAS——专做RAG评测的框架，自动生成faithfulness/answer_relevancy/context_precision/context_recall四个指标。
面试加分：说得出"我用DeepEval写了X条评测用例，faithfulness从70%提升到88%"比只说"我测了效果"强10倍。
Q: 传统RAG有什么痛点？GraphRAG怎么做？
痛点：chunk语义割裂、长距离依赖丢失、无法处理多跳推理。GraphRAG：先从文档抽取实体关系构建知识图谱，查询时不仅检索chunk还检索图结构上下文，适合全局摘要和多跳问题。

Agent / 智能体 ▶
Q: Agent的核心组成是什么？
Planning（规划/分解任务）+ Memory（短期对话记忆+长期知识）+ Tools（工具调用）+ Action（执行）
Q: ReAct模式是什么？
Reasoning + Acting交替进行：Thought（思考下一步）→ Action（调用工具）→ Observation（观察结果）→ 循环直到得出答案
Q: 多智能体协作有哪些模式？什么时候需要多Agent？
三种场景：①任务可拆成独立专业模块（前端/后端/测试各一个Agent）；②需要独立验证（一个生成方案另一个审查，避免自评偏差）；③可并行执行（同时查多个数据源再合并）。关键不是角色名，而是分工是否真的解耦。
Q: 多轮对话Agent怎么解决状态爆炸/上下文溢出？
方案：摘要压缩历史对话；滑动窗口只保留最近N轮；外部存储历史（向量库/数据库），需要时检索；分层记忆（短期working memory + 长期episodic memory）
Q: Agent怎么调试？【2026新增高频】
Agent最难的不是写出来，是跑不对时怎么定位问题。
工具：① LangSmith（LangChain官方）——可视化追踪Agent每一步的输入/输出/token消耗/延迟，哪一步选错工具一目了然；② Langfuse（开源自托管替代）；③ Photon——Agent专项调试，可回放失败轨迹。
调试思路：先开详细日志打印每一步Thought→Action→Observation，再用LangSmith定位是哪一步：是工具调用参数错了？还是LLM选错了工具？还是观察结果解析失败？
面试答题框架："Agent出问题通常三类：①工具调用层（参数/超时/解析失败）→加重试和降级；②推理层（LLM选错工具/死循环）→加最大步数限制和反思；③状态层（上下文溢出/状态不一致）→用LangGraph的checkpoint持久化。"
Q: LangGraph的状态管理怎么做？【2026新增高频】
LangGraph（42k+ stars）用"状态图"(State Graph)编排Agent：定义一个State对象（字典/Pydantic模型）作为全局共享状态，节点(node)是函数接收State返回更新，边(edge)决定下一步走哪个节点。
核心概念：①State——跨节点共享的数据结构（对话历史、中间结果、工具返回）；②节点——执行一个动作（调LLM/调工具/做判断）；③条件边——根据State内容动态路由（if/else分支）；④Checkpoint——每步自动保存状态，支持中断后恢复、人机交互打断。
vs裸LangChain：LangChain Chain是线性的，LangGraph支持循环/分支/并发/持久化，做ReAct Agent和多步任务的工程化首选。面试能说出"用LangGraph的StateGraph+条件边+checkpoint"就是加分项。

🧪 微调效果判断与推理优化（2026新增高频考点） ▶
Q: 怎么判断微调效果好不好？【2026新增高频】
不能只看loss曲线！三层判断：
① 训练侧：loss曲线是否收敛（train loss下降但eval loss不降=过拟合）、学习率warmup是否合理、LoRA rank/alpha是否合适。
② 自动评测：用OpenCompass（司南评测平台）或lm-evaluation-harness测MMLU/CMMLU/HumanEval等benchmark，对比微调前后分数变化。业务场景自建测试集（50-200条标注数据）。
③ 人工评测：找业务方标注100条典型case，按准确性/有用性/安全性打分。自动指标涨了但人工觉得变差=说明benchmark和真实业务脱节。
面试加分：能说出"我微调后MMLU涨了X分，但人工评测发现业务场景效果下降，原因是测试集和业务分布不一致"——这说明你真做过。
Q: vLLM推理优化做了什么？为什么快？【2026新增高频】
vLLM（92k+ stars）核心优化：
① PagedAttention——像操作系统管理虚拟内存页一样管理KV Cache，消除显存碎片，显存利用率从20-40%提升到90%+；
② Continuous Batching（连续批处理）——请求不等凑齐一批才处理，新请求随时插入正在运行的batch，GPU利用率拉满；
③ Prefix Caching——相同system prompt的KV Cache复用；
④ 张量并行/流水线并行——多卡跑大模型。
对比：HuggingFace Transformers原生推理是静态batch+无KV Cache优化，vLLM吞吐高10-20倍。应用开发方向了解原理即可，推理岗需深入到PagedAttention实现。
Q: LLaMA-Factory和ms-swift怎么选？
LLaMA-Factory（75k+ stars）——带WebUI，一行命令启动，支持100+模型，中文文档友好，适合快速上手做SFT/LoRA。ms-swift——阿里ModelScope出品，GRPO/RLHF链路更全，做对齐方向选它。本科就业做应用项目选LLaMA-Factory即可。
来源：vLLM GitHub | LLaMA-Factory GitHub | OpenCompass GitHub | 牛客2026届大模型岗面经综合
大模型原理 ▶
Q: Transformer的自注意力机制原理？
Q/K/V三个矩阵，Attention(Q,K,V) = softmax(QK^T/√d_k)V。缩放因子√d_k防止点积过大导致梯度消失。
Q: SFT / RLHF / DPO分别是什么？
SFT：监督微调，用标注数据教模型遵循指令；RLHF：人类反馈强化学习，训练奖励模型+PPO优化；DPO：直接偏好优化，跳过奖励模型直接用偏好数据优化，更简单稳定。
Q: 大模型的灾难性遗忘怎么解决？
方案：混合训练（新数据+旧数据）、LoRA/QLoRA（只微调少量参数）、正则化（EWC等）、回放机制
Q: 为什么需要温度(temperature)？top-p和top-k区别？
温度控制随机性：低温度更确定，高温度更多样。top-k只从概率最高的k个token采样；top-p从累计概率达到p的token集合采样（动态截断）。

7.2 如何识别外包/劳务派遣（通用方法）

面试时一定要确认的问题
  • 劳动合同跟谁签？——如果不是和目标公司直签，就是派遣/外包
  • 五险一金谁缴纳？按什么基数？——第三方缴纳=派遣/外包
  • 工号/工牌是什么样的？——入职前问清楚
  • 岗位描述里有没有"驻场""项目制""乙方"？——有则大概率外包
  • 招聘方是HR还是猎头？——猎头招的研发岗很多是外包岗
判断口诀：正式工 = 跟公司签合同 + 公司交社保 + 纳入公司管理体系；劳务派遣 = 跟第三方签合同 + 派到某公司工作；外包 = 乙方公司招聘 + 驻场甲方做项目。
