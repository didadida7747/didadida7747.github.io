# 术语速查表：读源码前的黑话预习

> 读 Agent/LLM 源码会撞到的高频术语。不求背下来，混个脸熟，读到时回来查。

## Agent 层（harness 侧）

**harness（挽具/执行框架）**
模型外面那层"壳"：负责组装上下文、调用模型、执行工具、管理权限和循环。模型是马，harness 是缰绳和马鞍。Claude Code 的核心竞争力大半在 harness 而非模型。

**Agent Loop / 主循环**
`调模型 → 模型要调工具 → 执行工具 → 结果回填 → 再调模型`，循环直到模型不再要求调工具。整个 Agent 编程的全部秘密就是一个 while 循环 + 边界条件。

**Tool Use / Function Calling**
模型不直接执行动作，而是输出一个结构化的"我要调 xx 工具、参数是 xx"，由 harness 代为执行。这是所有 Agent 的基石接口。

**System Prompt（系统提示词）**
每次请求都放在最前面的人设+规则+环境信息。Claude Code 的系统提示词包含静态规则 + 动态注入（当前目录、git 状态、平台信息、CLAUDE.md 内容）。

**Context Window / 上下文窗口**
模型一次能"看到"的全部内容（对话历史+系统提示词+工具结果），有上限（如 200K tokens）。上下文管理 = 决定这有限的注意力里放什么。

**Compaction / 压缩**
上下文快满时，把旧对话总结成摘要替换原文，腾出空间。Claude Code 的 `/compact` 与 auto-compact。

**CLAUDE.md / AGENTS.md**
项目级"记忆文件"，每次会话自动注入。CLAUDE.md 是 Claude Code 的叫法，AGENTS.md 是多家工具推动的开放标准。

**Subagent（子代理）**
主 Agent 用 Task 工具派生出的独立 Agent，有自己干净的上下文，干完活只把最终结论带回主线。价值 = 上下文隔离 + 并行。

**Hook（钩子）**
用户配置的、在生命周期事件（如工具调用前/后）自动执行的 shell 命令，可以拦截、修改、否决 Agent 的行为。

**MCP（Model Context Protocol）**
Anthropic 开源的"给模型接工具"的标准协议，相当于 USB-C：任何工具按协议实现，就能接进任何支持 MCP 的客户端（Claude Code/Cursor 等）。

**Skill（技能）**
一个带 `SKILL.md` 的文件夹，按需加载的操作手册。渐进式披露：先只给模型看名字和描述（省 token），模型判断需要才读全文。

**Plan Mode（计划模式）**
只允许只读工具（看代码不让改代码），产出计划交给用户批准后才开始动手。

**Permission Mode（权限模式）**
default（危险操作要问）/ acceptEdits（自动接受编辑）/ bypassPermissions（全部放行，即 `--dangerously-skip-permissions`）等档位。

**Vibe Coding**
Karpathy 2025 年 2 月造的词：完全用自然语言指挥 AI 写码、几乎不看代码本身的编程方式。

**Context Engineering（上下文工程）**
prompt engineering 的升级版：不仅写提示词，而是系统地设计"每一步该让模型看到什么"——包括检索、压缩、记忆、工具结果裁剪。

## 模型层（以 DeepSeek 为主）

**MoE（Mixture of Experts，混合专家）**
把 FFN 换成 N 个"专家"，每个 token 只激活其中 k 个。参数量大但计算量小，"671B 总参 / 37B 激活"就是这个意思。

**MLA（Multi-head Latent Attention，多头潜在注意力）**
DeepSeek 的招牌：把 KV 缓存压缩到一个低维 latent 向量，推理时的显存开销降到传统 MHA 的几十分之一。代价：kernel 实现极难（所以开源了 FlashMLA）。

**KV Cache**
自回归推理时缓存的历史 K/V 矩阵。长上下文时代它是显存杀手，MLA/稀疏注意力都是为了杀它。

**MTP（Multi-Token Prediction，多 token 预测）**
一次训练/推理预测多个未来 token。推理时可做投机解码，DeepSeek-V3 报告提速约 1.8 倍。

**FP8 训练**
用 8bit 浮点数做前向/反向传播。省一半显存和带宽，但数值精度极其难搞，DeepSeek 的细粒度量化（tile 级 scaling）是关键创新。

**DualPipe / EP / PP / DP**
并行策略：DualPipe=双向流水线并行（通信与计算重叠，零气泡）；EP=专家并行（MoE 专用）；PP=流水线并行；DP=数据并行。

**GRPO（Group Relative Policy Optimization）**
DeepSeek 的强化学习算法：同一题采样一组答案，用组内相对比较当优势，省掉价值网络（critic）。

**RLHF / R1-Zero / 蒸馏**
RLHF=用人类反馈做强化学习；R1-Zero=不经过监督微调、纯强化学习逼出推理能力；蒸馏=让大模型生成数据教小模型。

**Aha Moment**
R1 论文里著名的现象：模型在纯 RL 训练中自发学会在回答中途说 "Wait, wait..."（等等，我刚才想错了）——反思行为是涌现的，没人教。

**投机解码（Speculative Decoding）**
小模型先猜一串 token，大模型一次验证多个，验证通过的直接收下，从而一次前向出多个 token。

**PagedAttention**
vLLM 的核心：像操作系统管内存分页一样管 KV cache，几乎消除显存碎片，吞吐暴涨。

## 基建层

**Kernel / 算子**
GPU 上的最小计算单元（如一次注意力计算）。FlashMLA/DeepGEMM 都是手写 CUDA kernel。

**RDMA / NVLink / InfiniBand**
显卡之间的通信通道。NVLink=同机高速互联；RDMA/IB=跨机网络。MoE 训练时跨机通信是大瓶颈（DeepEP 就是为它而生）。

**SGLang / vLLM / TensorRT-LLM**
推理服务框架：把模型变成高吞吐的 API。vLLM 通用王，SGLang 结构化输出和 MoE 推理强。

**Benchmark 基准**
SWE-bench（真实 GitHub issue 修 bug）、Aider Polyglot、LiveCodeBench、GPQA 等。读论文先看它在哪个榜、什么设置。
