# 06 · 审查 · 验证 · 自动化 · CI：让 Agent 自己闭环，让人不在场也安全

> 本域命令约 15 条。七段式：①概念 → ②CC 详解 → ③Codex 详解 → ④对照 → ⑤联动 → ⑥学生视角 → ⑦验收

---

## 6.1 本域解决什么问题（工具无关）

- **Agent 会一本正经地错**：编造不存在的 API、边界条件漏判、跑通了主路径挂了边角。**产出必须闭环验证**——要么跑真实构建/测试，要么第二个视角审。
- **无人值守两形态**：① 无头（headless）——命令行一次性执行，程序消费输出；② CI——代码仓库流水线里自动触发。两者共同的难点是**权限收口**（§03）与**结构化输出**（本域）。
- **结构化输出是自动化的接口**：让人读的是 Markdown，让程序读的是 JSON Schema 约束的 JSON——这是把 Agent 嵌进脚本/流水线的关键。

## 6.2 Claude Code 详解

### 6.2.1 审查与验证

#### `/code-review [级别] [--fix] [--comment] [--max-findings n] [目标]`（别名 `/review`）
- **作用**：正确性 bug 审查体系（v2.1.223-243 把旧 /review 并入多级体系）。
- **级别**：普通本地审查；`ultra` = 云端多代理深度审查（= `/ultrareview`，Pro/Max 每月 3 次免费额度）。
- **参数**：`--fix` 让它顺手修；`--comment` 发到 PR；`--max-findings` 控制条数防噪音。
- **示例**：
```text
/code-review --max-findings 5
/code-review ultra 当前分支 vs main
```

#### `/simplify [目标]` — 可简化点审查（非 bug）
- **作用**：4 个并行代理专找"能写得更简单的地方"。
- **场景**：课设答辩前把"过度设计"清一遍。

#### `/verify` — 构建-运行-观察验证（内置技能）
- **作用**：真实构建、运行、观察应用行为来验证改动（不是只看代码）。首次会教它你的项目怎么启动（`/run-skill-generator`）。

#### `/run` — 启动并驱动你的应用
- **作用**：让 Agent 自己把应用跑起来看改动效果（dev server、交互程序都行）。

#### `/security-review` — 安全审查
- **作用**：对分支 diff（vs 默认分支）做安全审查。**场景**：课设要公开上 GitHub 前，扫一遍有没有泄密/注入风险。

### 6.2.2 无头模式 `claude -p`

| 参数组 | 关键参数 | 说明 |
|---|---|---|
| 输出 | `--output-format text\|json\|stream-json` | json 含 `result`/`session_id`/`total_cost_usd`；stream-json 首行 `system/init`（模型/工具/MCP 清单，可做 CI 门禁） |
| 结构化 | `--json-schema '<schema>'` | 输出进 `structured_output` 字段 |
| 权限收口 | `--permission-mode auto` + `--permission-prompts none` | **官方推荐的无人值守组合**（v2.1.259+）；`--dangerously-skip-permissions` 仍在但仅限容器 |
| 上限 | `--max-turns` / `--max-budget-usd` | 防失控烧钱，学生必备 |
| 提示词 | `--append-system-prompt` / `--system-prompt` | 追加 vs 整体替换（-file 用文件） |
| 续话 | `--continue` / `--resume` 在 -p 下同样可用 | |
| 干净启动 | `--bare` | 跳过一切自动发现，官方推荐脚本场景用（需 `ANTHROPIC_API_KEY`） |

**官方四实例**（可复制改用）：
```bash
# 1) 管道式：diff 喂进去做拼写检查
git diff main | claude -p "you are a typo linter. report filename:line for each typo"

# 2) 无人值守：自动模式 + 不弹窗
claude -p "Update the dependency pins and run the tests" --permission-mode auto --permission-prompts none

# 3) PR 安全审查，JSON 输出
gh pr diff "$1" | claude -p --append-system-prompt "You are a security engineer. Review for vulnerabilities." --output-format json

# 4) 提交日志摘要
git log --oneline -20 | claude -p "summarize these recent commits"
```

**Agent SDK**（原 Claude Code SDK，v2.0.0 更名）：TypeScript/Python 包，提供结构化输出、`canUseTool` 审批回调、流式回调、`interrupt()`——写自己的代理应用时用。

### 6.2.3 长尾速览

| 命令/能力 | 一句话 |
|---|---|
| `/run-skill-generator` | 教 /run /verify 怎么启动你的项目（一次性配置） |
| `claude ultrareview [target] --json` | CLI 版云端深审 |
| GitHub Actions / GitLab CI 官方指南 | CI 集成文档（code.claude.com/docs） |
| `claude setup-token` | 生成长期 CI 令牌 |

## 6.3 Codex 详解

#### `/review` — 独立审查面板
- **作用**：0.64.0 起 detached 模式（独立面板，不打断主对话）。审查模式：未提交改动 / 当前分支 vs base 分支 / 指定 commit / 自定义审查 prompt。
- **个性化**：审查规则可用 AGENTS.md 类指令定制（官方 "Customize what Codex reviews"）。
- **CLI 侧**：`codex review`。
- **示例流程**：`/review` 选 base branch → 出结构化发现 → 回主会话让 Codex 修 → 复审。

#### `codex exec [PROMPT]` — 无头自动化
| 参数 | 说明 |
|---|---|
| `--json` | JSONL 事件流（thread.started / item.* / turn.completed），程序好消费 |
| `-o/--output-last-message FILE` | 最后一条助手消息写文件 |
| `--output-schema FILE` | JSON Schema 结构化输出（0.132.0） |
| `--sandbox` / `--skip-git-repo-check` / `--images` | 环境控制 |
| prompt+stdin 混合输入 | 0.118.0 起 |
| `codex exec resume --last` / `codex exec fork` | 续跑/分叉无头会话（0.148.0） |

**三实例**：
```bash
# 1) 无头修 lint 并留结果
codex exec --sandbox workspace-write --skip-git-repo-check \
  -o /tmp/last-message.txt "修复仓库中所有 ESLint 报错并跑通测试"

# 2) 事件流供程序消费
codex exec --json "总结 src/ 最近的改动风险点" | jq -c 'select(.type=="item.completed")'

# 3) 带 schema 的可机读结果
codex exec resume --last --output-schema schema.json
```

#### `codex apply` — 应用补丁
- **作用**：把 Codex 产生的补丁（尤其云端任务的产出）应用到本地分支。

#### CI：openai/codex-action
- **是什么**：官方 GitHub Action（`openai/codex-action@v1`），CI 里跑 Codex：任务打补丁、发 PR、自动 review。配套安全指南（权限收紧）。
- **典型**（Cookbook autofix 教程）：CI 挂了 → Action 触发 Codex 修 → 自动开 PR 供人审。

### 6.3.1 长尾速览

| 命令 | 一句话 |
|---|---|
| `codex cloud apply/push` | 云端审查/修复结果落本地或推 PR（§05） |
| `/mcp verbose` | MCP 全量诊断（排查工具接入问题） |
| `/status` 里看线程预估成本 | 跑批前先看价 |

## 6.4 对照表

| 能力 | Claude Code | Codex | 判断 |
|---|---|---|---|
| 代码审查 | `/code-review` 多级 + ultra 云端深审 | `/review` detached 面板 + 自定义审查 prompt | CC 深度大；Codex 面板体验好 |
| 行为验证 | `/verify` `/run`（跑起来看） | 靠沙箱内 exec + 测试 | CC 有专门的"验证技能" |
| 无头执行 | `claude -p`（stream-json、--json-schema） | `codex exec`（JSONL、--output-schema、resume/fork） | **能力等价**，语法不同 |
| 无人值守权限 | auto mode + `--permission-prompts none` | workspace-write + never / `--approve-for-me` | 都必须配预算/轮数上限 |
| CI | 官方 Actions 指南 + Agent SDK | codex-action（官方 Action） | 都是官方方案 |
| 预算控制 | `--max-budget-usd` | `/status` 看额度 + 云任务配额 | CC 显式，Codex 靠额度面板 |

## 6.5 联动工作流

1. **双工具互审**：CC 改完 → `claude mcp add codex -- codex mcp-server`（§04）→ 让 Codex 审 CC 的 diff；反向同理（把 CC 的产出 diff 喂 `codex exec review`）。**两个模型的盲区不同，互审性价比极高。**
2. **CI 双保险**：主流水线放一家的自动修复，PR 审查放另一家——避免单模型系统性盲区。
3. **互为备胎**：无头脚本里做 fallback：`claude -p ... || codex exec ...`（额度/限流时自动切换）。

## 6.6 学生何时用得上

- **课设交付前三连**：`/code-review --max-findings 5` → `/verify`（真实跑一遍）→ `/security-review`（上 GitHub 前扫密钥/漏洞）；
- **批量改作业代码**：`codex exec` 一条命令给 10 个 OJ 题解仓库统一换代码风格（配 `--output-schema` 收结构化结果）；
- **对拍脚本**（算法题/数模）：写好暴力解，让 Agent 无头生成随机数据 + 跑对拍——找反例效率起飞；
- **报告图表自动化**：`claude -p "读 results.csv 出 5 张图"` 进脚本，实验一跑完图自动出。
