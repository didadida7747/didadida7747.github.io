# 02 · 安装与配置

> 原则：以官方一手信息为准；raw 素材之间矛盾时并列注明。所有命令可直接复制。
> 调研截止 2026-10-20。当前一等安装运行在 Python 3.14，最新 release v0.22.2（2026-10-15）。

---

## 1. 系统要求与依赖（【官方】Installation 页）

- 前置：Git、curl、tar、SHA-256 工具。Windows 缺 Git 时，安装脚本会自动暂存验证过的 Git for Windows（**不替换系统 Git**）。
- 安装脚本做的事：clone 源码 → bootstrap uv → 交给 PM 准备运行时；PM 提供固定版本的 Python、Node.js、npm、ripgrep、FFmpeg。
- Python：**当前一等安装运行在 Python 3.14**；pyproject 声明 `>=3.11,<3.15`——这只是为了让旧 Python 能跑 updater，**不承诺 3.11–3.13 的运行时支持**。
- 官方明确告诫：**不要用 `pip install hermes-agent` 代替受管安装。**
- 【社区】抖音教程补的依赖清单（2026-06-11，仅据视频摘要，供旁证）：git、uv、Python ≥3.11、Node.js 22（浏览器自动化用）、ripgrep、ffmpeg（TTS 转码）。\<https://www.iesdouyin.com/share/video/7650015036354322067>

### 安装布局（【官方】）

| 环境 | 代码目录 | 启动器 | 用户数据 |
|---|---|---|---|
| POSIX（Linux/macOS/WSL2） | `~/.hermes/hermes-agent/` | `~/.local/bin/hermes` | `~/.hermes/` |
| Windows 源码版 | `%LOCALAPPDATA%\hermes\hermes-agent\` | — | `%LOCALAPPDATA%\hermes\` |
| Docker | `/opt/hermes/` | — | 挂载 `/opt/data/` |

- 桌面包：macOS 仅 Apple Silicon（x86 不支持）；Windows 走 `.appinstaller` + 签名 MSIX，另有 Microsoft Store 独立分发通道。
- 额外安装方式：Android/Termux（签名 APT 源，aarch64）、Docker、Nix（**已降级为 best-effort，不再显式支持**）。

| 来源 | 说法 |

| 【官方·英文 README】 | "**Native Windows runs Hermes without WSL — CLI, gateway, TUI, and tools all work natively**"、"**Native Windows is fully supported**" |

| 【官方·中文文档首页】 | "Windows（原生，PowerShell）— *早期测试版*" |

【编者推断】中文文档首页很可能未同步英文文档的最新口径，"早期测试版"大概率是过期说法。**本指南建议：以英文官方页为准（完全支持），但你应知道中文页仍写着"早期测试版"**——若 Windows 原生遇到问题，回退到 WSL2 是更稳的选择。社区实测也长期以 WSL2 为主路径（见第 4 节）。

## 3. 标准安装命令（【官方】四处一致，逐字）

Linux / macOS / WSL2：

```bash
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
```

Windows（原生，PowerShell）：

```powershell
iex (irm https://hermes-agent.nousresearch.com/install.ps1)
```

> 来源：GitHub README Quick Install、中文文档首页、英文 Installation 页、快速入门页，四处逐字一致。
> 注意 raw-02 记录部分视频沿用旧地址 `https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh`；**以官方页当前给的域名 `hermes-agent.nousresearch.com` 为准**。

## 4. WSL2 路径（学生重点：Windows 笔记本照做）

【官方】WSL2 与 Linux 完全相同，跑上面的 install.sh 即可；数据目录 `~/.hermes`。

### 步骤（综合【官方】+【社区】学生可照做流程）

1. 以管理员身份打开 PowerShell，安装 WSL2（若已有可跳过）：

```powershell
wsl --install
```

   重启电脑，按提示设置 Ubuntu 用户名和密码。【社区】抖音 0 基础教程口径：管理员 PowerShell → 重启 → 设用户名密码。\<https://www.iesdouyin.com/share/video/7632277282031275315>

2. 进入 WSL2 终端，装官方一键命令：

```bash
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
```

3. 让 `hermes` 命令可用（装完报 command not found 时）：

```bash
source ~/.bashrc
```

   【社区·个人体验】BetterClaw 作者自述：install 脚本没报错、敲 `hermes` 却 command not found，折腾 3 小时，最后就是 `source ~/.bashrc` 一行解决。\<https://www.betterclaw.io/blog/hermes-agent-not-working>

4. 验证：

```bash
hermes
```

成功标志（【官方】快速入门）：横幅显示所选模型 → 无错误回复 → 工具可用 → 对话可多轮。

### WSL2 排错清单（【社区】掘金 吴佳浩Alben 实战，RTX 5090 + 96GB + Win11 + WSL2，v0.8.0 时期，2026-04）

来源：\<https://juejin.cn/post/7628894338689024015> 【精读·个人体验，高价值】

| 症状 | 原因 | 解法 |
|---|---|---|
| WSL2 里 git clone 报 `GnuTLS recv error` | WSL2 网络/ TLS 偶发问题 | 重试或换网络环境；有教程建议国内镜像源提速 |
| Python 依赖安装超时 | 大包下载超时 | `export UV_HTTP_TIMEOUT=300` 再装 |
| WSL2 访问 Windows 端 Ollama 不通 | 绑定地址 + Windows 防火墙 | Windows 端 `OLLAMA_HOST=0.0.0.0`；**Windows 会自动创建 ollama.exe 的 Block 规则，必须手动进防火墙删 Block 规则** |
| 模型 <64K 上下文启动报错 | 硬性上下文要求（见第 6 节） | 见第 6 节 |

> 注意：掘金文写于 v0.8.0（2026-04），当时"官方明确不支持原生 Windows，必须 WSL2"。这与 2026-10 英文页"fully supported"已变化，**以当前英文页为准，WSL2 仍是最稳路径**。

## 5. Windows 原生路径（PowerShell）

```powershell
iex (irm https://hermes-agent.nousresearch.com/install.ps1)
```

- 【官方】数据目录 `%LOCALAPPDATA%\hermes\`（代码 `%LOCALAPPDATA%\hermes\hermes-agent\`）。
- 【官方·已知坑】Windows Defender / 杀软常把捆绑的 `uv.exe` **误报为木马**。README 给出 gh attestation 核验方法与加白名单方法。
- 【社区】Windows 安装实操视频（B站，WSL2 环境，1.8 万播放）：\<https://www.bilibili.com/video/BV19zNj6EEch/> 【未看，仅据标题】
- 【官方·最佳实践】Windows 用户写文件时显式用 UTF-8 编码，避免 cp125x 编码坑。\<https://hermes-agent.nousresearch.com/docs/guides/tips>

## 6. 首次配置：模型 provider 与 API key（【官方】快速入门）

### 最快路径

```bash
hermes setup --portal
```

一次 Nous OAuth 登录 = 模型 provider + Tool Gateway 全开。这是官方对新用户的首推一句话。

### 其他入口

```bash
hermes model      # 交互式选 provider / 模型
hermes setup      # 全量配置向导
```

### 配置存哪（【官方】）

- 密钥 → `~/.hermes/.env`
- 非密钥配置 → `~/.hermes/config.yaml`
- `hermes config set` 自动写入正确文件，不要手改错文件。

### 支持的 provider（【官方】原文表格）

Nous Portal（订阅制 300+ 模型）、OpenAI Codex 订阅（设备码 OAuth）、Anthropic（Max OAuth 或 API key）、OpenRouter、Z.AI(GLM)、Kimi/Moonshot（国际/中国区）、Arcee AI、GMI Cloud、MiniMax（OAuth/国际/中国区）、阿里云 DashScope(Qwen)、Hugging Face、AWS Bedrock、Kilo Code、OpenCode Zen、OpenCode Go、DeepSeek、NVIDIA NIM、GitHub Copilot、Vercel AI Gateway、**Custom Endpoint**（vLLM/SGLang/Ollama 等任何 OpenAI 兼容 API）。

### 硬性上下文要求（【官方】）

- **至少 64,000 token 上下文窗口**，不满足会被拒绝启动。
- 本地模型（Ollama）需 `-c 65536`：

```bash
ollama run qwen2.5:32b -c 65536
```

- 【社区·排坑】掘金作者用 32K 模型时报错，用 sed 改 `context_length: 65536`——作者明说这是"骗过检查"，实际模型仍 32K，长对话会遗忘。**建议读者不要骗检查，换 ≥64K 的模型。**
- 【社区】第三方教程站提到 Ollama 默认 context 仅 2048 也要手动扩。\<https://hermes-agent.wulu.ai/> 【摘要】

### 本地模型（Ollama 等社区实测）

- 【社区·个人体验】掘金：RTX 5090 + 96GB 内存，WSL2 内 Hermes，Windows 端 Ollama 跑 Qwen3.5-35B 量化版；跨网络打通需 `OLLAMA_HOST=0.0.0.0` + 删防火墙 Block 规则。
- 【社区·生态外围】抖音 Ollama 本地部署教程称可"无缝对接 OpenClaw 和 Hermes"免费跑智能体。\<https://www.iesdouyin.com/share/video/7638987492082994474>
- 【官方/社区互证·限制】本地模型**无法用 web 工具**：本地模型过不了 web backend 检查，web 搜索/浏览静默失效，需留一个云模型做 "web access provider"。\<https://www.betterclaw.io/blog/hermes-agent-not-working>
- 【编者推断】学生场景：有 24GB+ GPU 可考虑 32B 本地模型做隐私场景；否则更现实的成本方案是 DeepSeek / Kimi / GLM / OpenRouter 等便宜云模型（见 06 文件成本说明）。

## 7. 更新通道注意事项（重要）

【官方 issue #58746】「hermes update should target the latest stable release, not main」（2026-07-05 开，2026-10-15 关闭）：\<https://github.com/NousResearch/hermes-agent/issues/58746>

- 核心问题：`hermes update` **默认拉 `main` 分支**（每日未发布改动），跟 CLI 提示跑更新的用户无意中进了"开发通道"，随后开 bug issue。
- 生产事故实例（评论者 tboome33）：钉在 release tag `v2026.7.20` 的自托管安装，点 dashboard 更新按钮后被静默切到 main（越过 420 个未发布 commit），且该版本 updater 杀 dashboard 进程后不重启，导致 502。
- 官方处置：已并入既有 release channel 工作（#24938、#34528），问题于 2026-10-15 关闭。

【编者推断·建议】
- 学习/尝鲜：随意跟更新。
- 跑 cron / 网关常驻的"准生产"：**钉 release tag，不要随手点 dashboard 上的更新按钮**；更新前先看 releases 页 changelog。
- API 在 v0.x 间约每两周 breaking change，生产使用 pin 版本（dplooy）。

## 8. 卸载 / 重装（编者整理）

【官方】数据默认全部落在 `~/.hermes/`（POSIX）或 `%LOCALAPPDATA%\hermes\`（Windows）：密钥 `.env`、配置 `config.yaml`、会话 `state.db`、记忆 `memories/`、cron `jobs.json`、日志 `logs/`。

【编者推断】干净卸载 = 删除上述数据目录 + 删除启动器（`~/.local/bin/hermes` 或 Windows 对应入口）；素材中**未抓到官方卸载命令的原文**，此步骤为按目录结构推断，重装前建议备份 `~/.hermes/memories/` 与 `jobs.json`。
