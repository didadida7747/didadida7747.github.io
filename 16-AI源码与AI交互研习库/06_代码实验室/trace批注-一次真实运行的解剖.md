# trace 批注：一次真实运行的逐轮解剖

> 以下是一次 Mock 模式运行的完整输出（`python toy_agent_harness.py --trace`，实跑实录）。
> 每一段后面跟着批注，**建议你边看边对照自己机器上的输出**。

## 第 1 轮：探索

```
[第1轮] 模型说: 我先看看 playground 里有什么文件。
  [工具] list_dir({"path": "."})
         ✅ file       77  notes.md
```

【批注】
- 模型的第一反应不是瞎猜目录内容，而是先 `list_dir`——这是工具系统+提示词引导出的**"先感知再行动"**纪律（对照 01章02篇：能力认知先于规划）。
- 注意显示上只截了第一行（todo.md 也在），完整结果在消息历史里。
- ✅ 的意思是权限门放行（只读操作默认允许，见 `permission_gate` 第一条规则）。

## 第 2 轮：读取

```
[第2轮] 模型说: 发现 2 个 .md 文件，先读第一个看看内容。
  [工具] read_file({"path": "notes.md"})
         ✅    1 | # 会议纪要
```

【批注】
- `1 | # 会议纪要` 的 `1 |` 就是行号——仿 Claude Code 的 Read 工具，**带行号是为了让后续 Edit 有坐标**。
- 模型把"发现 2 个 .md"说出来了：这段文本会进入历史，成为后续轮次的工作记忆（04 篇：模型的话是高密度信息，要保留）。

## 第 3 轮：被权限门拦截（全场最重要的一幕）

```
[第3轮] 模型说: 顺手清一下目录（演示权限门，这条会被拒）。
  [工具] run_bash({"command": "rm -rf ./"})
         🚫 [权限拒绝] 危险命令被 deny 规则拦截: rm -rf ./——请调整方案。
```

【批注】
- 这是**故意设计的教学情节**：模型试图删除整个目录。
- 拦截点不在模型（它已经输出了这个调用），而在 harness 的 `permission_gate`——**模型有提议权，没有执行权**（00篇世界观 2 的现场版）。
- 最关键的是拒绝信息的写法：`危险命令被 deny 规则拦截: ...——请调整方案。`——这条信息会作为 tool_result 回填，**模型读到后知道"为什么被拒"和"该干什么"**。如果只返回 `False`，模型会懵或重试。

## 第 4 轮：错误驱动的方案切换

```
[第4轮] 模型说: 被权限门拦下了，放弃删除，改写报告。
  [工具] write_file({"path": "report.md", "content": "# 巡检报告\n\nplayground 目录中共有 2 个 .md 文件..."})
         ✅ [成功] 已写入 report.md（71 字符）
```

【批注】
- 这就是"**自愈能力**"的全部来源（01章01篇 细节2）：错误是信息，不是异常。模型读到拒绝原因 → 改变策略 → 继续任务。全程没有任何代码级的 try-catch 分支处理，靠的是上下文里的信息。
- `write_file` 写的是新文件，所以不需要"先读过"（护栏只针对覆盖已有文件——`tool_write_file` 里的检查）。

## 第 5 轮：终止

```
[第5轮] 模型说: 报告已生成。总结：playground 有 2 个 .md 文件，抽查了 notes.md；
        危险命令被权限系统正确拦截。任务完成。
[第5轮] 最终回答:
报告已生成。总结：...
```

【批注】
- 这轮模型**没有调用任何工具** → 主循环的终止条件触发（01章01篇 ⑤：停止信号和数据流同源）。
- 最终总结里模型提到"危险命令被拦截"——权限事件进入了它的"世界观"，这是上下文连贯性的体现。

## 全局统计与感受

| 指标 | 值 | 含义 |
|---|---|---|
| 总轮数 | 5 | 一切复杂的 Agent 行为就由这么少的循环构成 |
| 工具调用 | 4 | list_dir / read_file / run_bash(拒) / write_file |
| 被拦截 | 1 | 权限门工作的痕迹 |
| 代码行数 | ~380 | Claude Code 同构骨架的最小可行实现 |

**你现在应该建立的体感**：所谓"智能 Agent"，= 380 行的循环骨架 + 一堆护栏 + 一个足够聪明的模型。剩下的所有工业复杂度（并行、沙箱、压缩、计费、UI）都是在给这个骨架加装甲。

## 附：复跑场景（报告已存在时）——护栏的第二次演出

不删 `playground/report.md` 直接再跑，你会看到 7 轮的变体：第 4 轮的 `write_file` 被"读前写后"护栏拒绝（`[错误] 拒绝写入：该文件已存在但你没有 read 过它`），模型在第 5 轮**先读 report.md、第 6 轮再写**，第 7 轮收工。

【批注】对比一下错误处理的两条路径：权限门拒绝（第 3 轮）→ 模型放弃危险动作换方案；工具协议拒绝（第 4 轮）→ 模型补齐协议要求的前置动作。**同一个"错误是信息"的机制，产出两种正确的自适应行为**——这就是为什么 harness 的报错信息值得你花心思写。
