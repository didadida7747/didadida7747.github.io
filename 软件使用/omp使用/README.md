# OMP 使用知识库

OMP（Oh My Pi）是开源的终端 AI 编程代理。它源于 Pi，并在此基础上提供多模型/多供应商接入、LSP、调试、子代理、MCP、扩展和项目记忆等能力。它不是模型本身：实际回答质量、可用性、费用和数据处理范围都取决于你接入的模型服务。

## 推荐阅读顺序

1. `omp-learning/00-start-here.md`：判断是否真的需要 OMP，并完成安全的首次启动。
2. `omp-learning/01-quickstart.md`：在一个具体项目中完成“只读 -> 小改动 -> 验证”。
3. `omp-learning/02-command-cheatsheet.md`：常用启动方式、会话命令和排障思路。
4. `omp-learning/03-advanced-map.md`：多模型、规则、MCP、LSP/DAP、子代理等何时值得使用。
5. `omp-learning/reference/source-index.md`：核验安装、登录、配置和当前能力的官方来源。

## 什么时候该用它

- 需要比较或切换多个模型/API 提供商。
- 想研究终端代理如何接入 LSP、调试器、子代理或自定义扩展。
- 已经有一套项目规则/skills，希望在不同代理工具之间复用。

不建议把它作为第一次接触 AI 编程代理的默认入口。对明确的日常工程任务，优先选择本目录总指南推荐的 Codex 或 Grok Build；当“多模型和可定制运行时”确实是需求时再用 OMP。

## 使用底线

- 在具体项目目录启动，不要在磁盘根目录或混杂资料目录中运行。
- 首轮先只读：让它找 README、构建文件、测试命令、约束和关键模块。
- 不把 API Key、Token、Cookie、密码或私钥写进项目规则、文档或提示词。
- 不因代理声称“完成”就跳过 `git diff`、测试、构建和硬件实测。
- 对删除、批量替换、提交、联网、部署和外部写入保持人工确认。
