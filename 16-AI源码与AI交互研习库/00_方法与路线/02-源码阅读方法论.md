# 源码阅读方法论：怎么读才不会读三行就睡着

> 大多数人读源码失败，不是能力问题，是方法问题：一上来就想"从 main 函数开始通读"，被 10 万行代码淹死。
> 这篇给你一套我验证过的流程，专门针对 AI/Agent 类项目。

## 一、先建立一个认知：你读源码的目的不是"看懂每一行"

读源码有三种目的，方法完全不同：

| 目的 | 方法 | 产出 |
|---|---|---|
| 学设计 | 只读骨架，忽略实现细节 | 一张架构图 + N 条设计取舍笔记 |
| 学实现 | 精读 1-2 个核心模块的每一行 | 能复现的算法理解 |
| 改代码/调试 | 顺着数据流追 | 修改点定位 |

本库 90% 的场景是**学设计**。学设计不需要读懂每一行，只需要回答一个问题：
**"如果是我来造这个东西，我会遇到什么困难？作者是怎么解决的？还有没有别的解法？"**

## 二、五步读法（针对 Agent/LLM 类项目）

### 第 1 步：先读 README 里的"动机"，不是"功能"

打开仓库先别看代码，问自己三个问题：
- 作者为什么要做这个？（解决什么痛点）
- 它和已有方案的区别是什么？（diff = 设计理念所在）
- 作者自己最得意的点写在哪儿？（通常 README 加粗/置顶）

例：DeepSeek 把 FlashMLA/DeepEP/DeepGEMM 全部开源，README 里写的是"我们开源不是因为它完美，而是因为开源应该成为行业常态"——这句话本身就是理解他们技术选型的钥匙（MHA→MLA 这种激进取舍，只有真正在乎成本效率的团队才做得出来）。

### 第 2 步：找"数据的流动路径"，而不是文件目录

Agent 类项目的主干永远是一条数据流：

```
用户输入 → 组装上下文 → 调 LLM → 解析输出 → 执行动作 → 结果回填 → 再调 LLM → ... → 最终回复
```

你要做的就是在这条链上各找到一个落点文件。找法：
- 全局搜 `system prompt` / `systemPrompt` / `SYSTEM_PROMPT` —— 找到上下文组装处
- 全局搜 `tool_use` / `tool_calls` / `function_call` —— 找到循环核心
- 全局搜 `while` / `maxTurns` / `max_turns` —— 找到循环边界

**在开源项目里做这件事**：Gemini CLI 里对应 `packages/core/src/core/client.ts` 和 `geminiChat.ts`；Aider 里对应 `aider/coders/base_coder.py` 的 `run_one`。本库 02 章的文档已经帮你把这条路踩好了。

### 第 3 步：骨架读完再填肉，永远带着"反事实"读

反事实思维 = 读到一处设计就问"如果去掉它会怎样？"

```
看到 Claude Code 的 Edit 工具要求"必须先 Read 过文件才能 Edit"
→ 反事实：不强制会怎样？
→ 推理：模型会凭训练记忆瞎改文件 → 改错行 → 反复失败烧 token
→ 结论：这不是功能，是护栏。harness 的很多代码都是护栏。
```

每条反事实推理都值得记进你的笔记。这就是"批注"的本质。

### 第 4 步：只精读一个模块，读穿它

选一个小而完整的模块（比如 Aider 的 edit format、minbpe 的 BPE），**逐行**读穿，包括测试用例。读穿一个模块后你会获得一种"手感"：知道作者是怎么命名、怎么拆函数、怎么写防御性代码的。这个手感会迁移。

### 第 5 步：输出。没有输出 = 没读

输出形式按性价比排序：
1. 一张流程图（手画也行）
2. 三条"我不同意作者"的观点（能说出不同意的理由，说明真读懂了）
3. 一份改过的代码（练习题级别的就行）
4. 一篇笔记发出去

## 三、针对"闭源项目"怎么办：Claude Code 的读法

Claude Code 本体是混淆打包的 js，读不了原文，但有四条替代路径（本库 01 章全部在用）：

1. **读它的"行为化石"**：系统提示词泄露版、工具描述、`claude --help`、配置文件 schema——这些是能直接看到的设计。
2. **读逆向工程仓库**：`ShareAI-Lab/claude-code-source-code-deep-dive`（中文，把混淆代码还原成可读讲解）、`Yuyz0112/claude-code-reverse`（提取出的提示词与工具定义）。
3. **读开源同构实现**：Gemini CLI、OpenCode、Codex CLI 是同一套思想的公开代码。思想相通，读公开的。
4. **读官方博客**：Anthropic 工程博客的几篇核心文章就是作者本人讲设计理念，含金量高于任何第三方猜测。
5. **（2026 年起新增）读泄露源码**：Claude Code 因 npm source map 泄露了完整 TypeScript 源码（约 51 万行），GitHub 有归档镜像（搜索甄别）；知乎/CSDN 有成体系的中文拆解专栏。读它请自重：学设计，不搬运代码。

## 四、常见失败模式自查

- **收集癖**：star 了 50 个仓库，一个没读。→ 解法：同时最多精读 1 个仓库。
- **完美主义**：前面没看懂就不敢往后看。→ 解法：源码允许"螺旋式阅读"，第一遍只求 60% 懂，回头第二遍自然懂。
- **只读不跑**：以为看懂了，一动手全错。→ 解法：06 章代码实验室就是为这个准备的。
- **在错的层次较劲**：在学架构的阶段纠结一行正则。→ 解法：先问"这一行属于哪条数据流"，不属于当前关注的流就跳过。

## 五、把这套方法变成肌肉记忆的检查清单

每次开一个新仓库，依次打勾：

- [ ] README 的动机段落读了吗？
- [ ] 这条数据流的 5 个落点文件找齐了吗？
- [ ] 写下至少 3 条【为什么这样设计】了吗？
- [ ] 写下至少 1 条【我不同意】了吗？
- [ ] 有没有跑起来或写个最小实验？
- [ ] 输出了吗？
