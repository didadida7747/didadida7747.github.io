# Grok Bot 完整使用指南（个人智能体系列 · 03）

> 读者：中国高校计算机/电子信息专业同学。目标是把 Grok Bot 真正用起来、不踩坑。
> 信息基准日期：2026-10-20。本产品迭代极快，价格与功能以官方页面为准，文中均标注信息日期。

---

## 1. 一句话定位

**Grok Bot 是 xAI（现对外亦用 SpaceXAI 名义）推出的「常驻云端数字员工」：你在 App 里创建若干有岗位、有记忆的 Bot，每个 Bot 共用一台一直开机的云端电脑（带浏览器、文件系统、终端），你可以用聊天/语音/群聊/手机/X 帖子把任务派给它，它像人一样在真实网站和软件里干活，遇到密码、验证码、发邮件、付钱这类关键动作才停下来等你批准。**

- 它不是 Grok 聊天机器人换皮。聊天机器人回答你问题，它替你上岗干活：你合上笔记本，它在云上继续跑。[腾讯云开发者社区，2026-10-09]
- 形态类比：长得像微信，每个联系人都是一个 AI 员工；你拉的是「岗位」而不是「问题」。[腾讯云开发者社区，2026-10-09]
- 发布背景：早期测试版于 **2026 年 8 月 12–13 日** 发布（马斯克收购 Cursor 后的首个产品，内部代号 Sand）；2026 年 10 月 8 日官宣可原生搜索/阅读/监控 X。[智源社区，2026-08-13]（注：本指南早期背景传闻的「2025 年 10 月发布」经核实不成立，以此处为准。）

## 3. 30 分钟上手最短路径（从注册到跑通第一个任务）

按顺序做，不要跳：

1. **下载安装**：电脑浏览器打开 `x.ai/bot`，下载对应系统的桌面端（macOS/Windows/Linux）；手机在 App Store / Google Play 搜 Grok Bot 安装。
2. **登录**：打开 App → 选「创建账号」或直接用 Grok / X / Cursor 账号登录 → 浏览器完成认证 → 自动跳回 App。
3. **（若有旧订阅）关联档位**：Settings → Usage & Billing → 点「Link SuperGrok Heavy」之类的关联按钮，把你已有的 Cursor Pro / SuperGrok 权益接上。[腾讯云教程，2026-10]
4. **建第一个 Bot**：首次启动会自动新建一个 Bot；给它起名，例如「课代表小郭」。它若弹窗问你要不要连接 Gmail，第一次可以先跳过。
5. **写岗位描述**：点 Bot 右上角设置，填三字段——名称 / 岗位名 / 描述。**关键是描述**：写「你是什么岗、对谁负责、产出什么」，不要写操作步骤（步骤用第 8 节的 Skill 教）。
6. **发第一个任务**：在对话框粘贴下面这段，发送：
   ```
   你是我的课程资料整理员。任务：打开浏览器，搜索「嵌入式系统 STM32 PID 控制入门」，
   挑 3 篇中文高质量教程，整理成一份 Markdown 笔记存到你的资料库里，每条附原文链接，
   完成后把笔记链接发给我。
   ```
7. **看它干活**：点右侧 Bot 面板的「电脑」标签，能实时看到它在云桌面里开 Chrome、点页面——这是它和普通聊天 AI 最大的区别。
8. **处理审批**：若它要发邮件、删文件、登录某网站，会弹出审批卡；点「只放行这一次」即可继续。**永远不要把密码/验证码直接贴进聊天框**——官方设计了安全输入框，凭证输入后遮蔽显示、不进对话记录。[腾讯云教程，2026-10]
9. **手机接管验证**：手机 App 登同一账号，找到同一个 Bot，发一句「把刚才那份笔记重新发我一份」——能收到就说明手机端链路通了。
10. **存成例行任务（可选）**：对这个 Bot 说：「把刚才这套搜索整理流程存成 Skill，以后我说出『找资料+关键词』就照做」——成功流程一键沉淀。

## 4. 各端安装与登录详解

### 4.1 桌面端（macOS / Windows / Linux）

1. 访问 `x.ai/bot` → 下载页按系统选安装包 → 安装。
2. 首次打开界面是「毛坯房」风格，分三栏：
   - **左栏**：Bot 列表与群聊列表（注意：不是常见的对话列表）。点「+」可新建 Bot 或群聊。
   - **中栏**：对话工作区，支持粘贴文字/链接/图片/本地文件，支持多条消息连发；语音输入快捷键 **Ctrl / Cmd + D**。
   - **右栏**：Bot 属性区，三个标签——详情（例行任务）、资料库（该 Bot 产出的文件都在这）、电脑（云桌面，最重要）。
3. 登录方式：Grok 账号 / X 账号 / Cursor 账号，浏览器 OAuth 认证后回跳。
4. 关联订阅：Settings → Usage & Billing。[腾讯云教程，2026-10]

### 4.2 手机端（iPhone / iPad / Android）

- 与桌面端连的是**同一批 Bot、同一批对话、同一台云电脑**。
- 手机端三件事最常用：①出门后远程发任务；②弹出审批时随手批；③需要登录/短信验证码时，你在手机上接管那一步，做完点交还控制权。[腾讯云教程，2026-10]
- **已知边界**：手机 App 不能像国产手机助手那样直接控制你手机里的其他 App（不能点你手机上的携程、微信）。它操控的是云端电脑里的浏览器。[36氪实测，2026-10-13]

### 4.3 X（推特）里的入口

1. 在 Grok Bot 设置里先**绑定你的 X 账号**（非所有地区可用）。
2. 在任意帖子或回复里 **@你的bot名**，主 Bot 就会接到一个任务，并公开回复一句确认。
3. 2026-10-08 起官方宣布 Grok Bot **原生支持搜索、阅读、监控 X**（追反馈、跟突发话题、做周报），不需要再装 X 连接器。[腾讯云教程，2026-10-09]

## 5. 创建 Bot（数字员工）完整流程

### 5.1 三个设置字段怎么填

| 字段 | 写法 | 反面教材 |
|---|---|---|
| 名称 | 好记、带角色感：`课代表小郭`、`盯梢老王` | `Bot1` |
| 岗位名（primary job） | 一句话职位：`课程资料研究员` | 空着 |
| 描述（description） | **常设岗位视角**：「你负责监控 X 上 AI agent 方向的动态，每天整理 5 条要闻发进群；遇到疑似官宣第一时间 @我」 | 「第一步打开浏览器，第二步搜索……」（步骤清单） |

官方建议：描述写成「岗位契约」，而不是操作手册；Bot 有跨轮记忆和文件，步骤类流程要用「演示」教它（见 5.4）。[continuumcode.ai，2026-08]

### 5.2 「干活的 Bot」和「回答问题的 Bot」分开建

社区实战经验：不要建一个全能 Bot。把执行型（跑流程、出文件）和咨询型（随问随答）拆开，互相不污染记忆。[腾讯云教程，2026-10]

### 5.3 命名即规格

从零建 Bot 时，你起的名字（如 `Data Dan`、`Slide Sonya`）会被系统用来自动推断岗位并推荐配套技能，省去手写大段 system prompt。[人人都是产品经理，2026-10-17]

### 5.4 Teach a Task：录屏示教（核心黑科技）

适合教它「没有 API 的网站怎么操作」：

1. 在云电脑视图里点「录制技能 / Teach a Task」，顶部出现绿色横幅 `X is watching and learning`。
2. 你像平时一样在浏览器里操作一遍（最长 **10 分钟**，不录麦克风）。
3. 录完 Bot 自动把你的点击轨迹抽象成一份 SOP 步骤清单，起草成 Skill 给你审。
4. 审核通过后写入该 Bot 的技能库，以后一句话即可复现整套操作。[人人都是产品经理，2026-10-17；腾讯云教程，2026-10]

### 5.5 模板市场：站在别人肩膀上

- 官方 Marketplace 有按分类排列的现成 Bot 模板（反馈聚类、晨间简报、收件箱分诊等），一键添加。
- 自己调好的 Bot 可在设置页右下角「分享为模板」→ 先存私有版 → 确认带走内容（指令、非个人化记忆、自带 Skill/插件、例行任务、连接器配置）→ 发布生成链接。
- 模板是「配方」不是克隆：别人拿到的是独立副本，不含你的隐私记忆。[mem0 指南，2026-09-28；腾讯云教程，2026-10]

## 6. 拉人机混编群聊与 @ 分工

### 6.1 建群规则

- 左栏点 New → 选 **2–6 个 Bot** 拉成群，你自己也在群里。
- 群里 @ 某个 Bot 点名派活；不 @ 直接说话，Bot 们自己判断谁接。
- **群聊盲区（重要坑）**：审批请求、登录/密钥请求、邮件与 Slack 草稿预览**不会出现在群聊里**——涉及这些的事必须回到一对一对话处理。[腾讯云教程，2026-10-09]

### 6.2 推荐分工范式（社区标杆）

范式 A · 内容流水线（腾讯云教程作者亲测）：

```
群成员：你 + X监控Bot + 选题分析Bot + 写稿Bot + 审稿Bot
规则一句话：每个环节做完，@下一个人交活。
```

实际跑通的流程：X 监控 Bot 每小时抓一轮 X 上 AI 热点 → 群里发 6 条简报 → 选题分析 Bot 挑 3 个选题并 @你拍板 → 你选定后它整理时间线/原话/正反方观点 → @写稿 Bot → 写稿初稿 @审稿 Bot → 审稿按「事实、立场、来源、时效」四项打回 → 改二稿、附事实清单（每条事实挂来源链接，挂不上标「未核实」）→ 通过后你再提口味意见迭代到满意。[腾讯云教程，2026-10-09]

范式 B · 个人公司制（抖音创作者实战）：

```
AI线：AI运营Bot + 视频Bot
占星线：占星运营Bot + 占星大师Bot
共用：写作Bot、图片Bot、成果管理Bot
财政大臣：专管额度与预算
总管Bot：中国时间早8点推候选选题，晚8点汇报成果
人只做三件事：定方向、批选题、最后拍板
```
[抖音，2026-10-13]

范式 C · 主管 Bot（Manager Agent）：在群里再拉一个「经理 Bot」，它主动向你提问、梳理任务依赖、编排定时 Routine 工作流。[人人都是产品经理，2026-10-17]

### 6.3 群聊的已知摩擦

社区实测吐槽：总管 Bot 改不了面板里的截止时间；书稿日报得手动转进群；Bot 之间吵起来最后还是要人拍板。**别指望零干预，把群聊当「需要你当产品经理的初级团队」来带。**[人人都是产品经理，2026-10-05 转载]

## 7. 手机远程发任务、步骤批准与验证码接管

### 7.1 远程派活

手机 App 与桌面同账号同数据。在教室、在路上直接发消息派任务，Bot 在云电脑上开工。

### 7.2 审批机制（Auto-Review）

- 默认开启，由独立的审查 Agent 按你写的规则判断：放行 / 拦下 / 交给你。
- 自定义规则写法（自然语言）：「当 Grok Bot 想要替我回复邮件，它应该先询问」。规则冲突时，「先询问」优先。[腾讯云教程，2026-10-09]
- 高危动作（发信、发布、购买、删除）会弹审批卡，三个选项：**只放行这一次 / 总是放行 / 拒绝**。审批卡在聊天里一直等你；无人值守时（例行任务、事件触发、别的 Bot 唤起的）**约 10 分钟过期，过期动作不执行**，要让 Bot 重试。
- 本机命令控制：Bot 在**你自己电脑**上跑命令时，默认每次问你，可改为「总是允许 / 从不允许」；注意该设置管不住它在云电脑上的行为。

### 7.3 验证码/登录接管流程

1. Bot 在云电脑里登录某网站，碰到密码、passkey、两步验证、支付、身份核验时停下来求助。
2. 通知你 → 你在手机或桌面弹出的**安全密钥输入框**里完成那一步（密码被遮蔽、不进对话）。
3. 你告诉它「继续」，它接着干活。
4. **铁律：不要把密码和验证码直接贴进聊天框。**[腾讯云教程，2026-10-09]

## 8. 操控电脑执行任务：流程与边界

### 8.1 它的「电脑」是什么

- 每个账号下的 Bot **共用同一台云端电脑**：桌面里一个 Chrome、一个文件夹、一个终端，本质是云端 Linux VM。
- 浏览器登录态、文件、命令行凭据**全部共享**：你在云电脑上登录过一次，所有 Bot 都能用。代价：给一个 Bot 的权限 = 给全部 Bot。[腾讯云教程，2026-10-09；人人都是产品经理，2026-10-17]
- 你可以随时打开云桌面看它点了什么、输了什么；文件在右侧「资料库」集中找。

### 8.2 任务执行标准链路

```
派任务（聊天/语音/群聊/X @）
  → Bot 在云电脑浏览器/终端里执行（可看屏旁观）
  → 遇高危动作 → 审批卡等你
  → 遇登录墙 → 请你接管那一步
  → 产出文件进资料库 + 消息通知你
  → 满意就说「把这套存成 Skill」
```

### 8.3 连接器优先于浏览器乱点

- 有官方 Marketplace 连接器的服务（1Password、Notion、Canva、Gmail、GitHub 等）**一律走连接器**，比让它在网页上点点点可靠得多；没有连接器的服务才让它用浏览器模拟人操作。
- 同时支持 **MCP 服务器**（和 Cursor 同一套标准）、插件、Skill；同一服务可连多个账户（个人邮箱+工作邮箱）。[腾讯云教程，2026-10-09]

### 8.4 云电脑的运维选项

- 装新版保留文件 / 重置（从上一次快照重建，最近改动可能丢）。[腾讯云教程，2026-10-09]

## 9. 在 X 中 @bot 触发任务

1. 设置里绑定 X 账号（地区限制存在，绑定入口灰掉即不可用）。
2. 发帖或回复里 @ 你的 bot 名 → 主 Bot 开始一个任务 → 它在帖子下公开回一句确认。
3. 原生 X 监控（2026-10-08 起）：让 Bot 盯官宣、追话题反馈、自动出周报，无需连接器。[腾讯云教程，2026-10-09]
4. 风险视角提醒：官方接入 X 的第一版列出的动作**全是「读」**（读帖子、读趋势），尚未放开自动发推；且 Bot 登录用的是你的 X 身份，等于把账号身份交给它操作。[抖音科技评论，2026-09-06]

## 11. 实战场景（≥6 个，指令可直接复制）

> 以下指令按你的实际信息替换括号内容即可。预期效果均来自社区实测或产品设计逻辑。

### 场景 1：每天盯官网/官宣，发新公告就喊你

## 13. 翻车点与限制（社区实测血泪）

1. **稳定性差**：时不时不响应、界面卡死，社区多人遇到，解决办法是重置云电脑（从上一快照重建，近期改动会丢）。[腾讯云教程，2026-10-09]
2. **手机端不能操控手机 App**：想让它帮你在手机上比机票价格？做不到。它只在云端电脑的浏览器里干活；国内订票 App 页面它打不开或读不到登录后报价。[36氪实测，2026-10-13]
3. **登录墙 = 你的时间墙**：凡是要登录才看得到的内容（票价、账单、内网），都得你本人先登录或接管一次。
4. **群聊有盲区**：审批、登录、密钥请求不进群聊，群里把任务聊嗨了卡住你都看不见。[腾讯云教程，2026-10-09]
5. **审批 10 分钟过期**：挂着例行任务离开，回来晚了审批自动作废，动作不执行，得让 Bot 重试。
6. **上下文有限**：官方指南自己承认 Bot 上下文装不下复杂流程，长任务要每天提醒自己；「紧急模式」每 5 分钟查一次记录，很烧额度，只真紧急时用。[腾讯云教程引官方 guides，2026-10-09]
7. **共享云电脑 = 共享风险面**：一个 Bot 登录过的网站，所有 Bot 都能用。
8. **国内替代品很多**：豆包工作、WorkBuddy 等同类能力（云电脑、定时任务、多 Agent）国内直连可用；Grok Bot 对你的独特价值主要在 X 生态与 Cursor 联动。[36氪，2026-10-13]

## 14. 隐私与授权风险（必读）

1. **它登录用的是你的身份**：走官方连接器是「专用钥匙」；走浏览器模拟人登录，等于把你的账号身份（Cookie、会话）托管在云上。敏感账号（网银、学校统一身份认证）建议**先不连**。[抖音科技评论，2026-09-06]
2. **凭证沙箱**：官方设计密钥/密码走遮蔽输入框与隔离沙箱（1Password 机制），云电脑读不到明文——配合这个机制用，不要图省事把验证码贴进聊天。[人人都是产品经理，2026-10-17]
3. **自动审核是「模型读规则」，不是硬锁**：规则由独立审查 Agent 按自然语言规则判断，信任基础是模型照办；高危动作一律开「先询问」。[腾讯云教程，2026-10-09]
4. **记忆可审查可遗忘**：Bot 长期记忆存在加密存储里，你可以随时检查它记住了什么，并指令它「忘掉某项目相关的所有委托」。[人人都是产品经理，2026-10-17]
5. **分享模板前自查**：发布模板会带走指令、Skill、例行任务、连接器配置——确认不含个人化记忆再发布。
6. **大学生特别注意**：学校邮箱/教务系统的授权边界要自己守好；涉及真实金钱的购买动作，审批卡永远选「只放行这一次」。

## 15. 附录 A：大学生 30 天养成路线

别一次建十个 Bot，按这个节奏来：

**第 1 周：只养一个 Bot**
- 建 1 个「学习助手 Bot」，用免费额度跑通场景 2（长文转中文笔记）和场景 6（资料调研）。
- 每天观察它的云电脑操作 10 分钟，练习「看屏 + 接管」手感。
- 目标：搞清楚审批卡、资料库、Skill 这三个核心物件在哪。

**第 2 周：加例行任务**
- 给它挂 1–2 个例行任务（场景 1 盯官宣 / 场景 3 日报）。
- 故意制造一次「先询问」规则（例如：凡要打开新网站先问我），感受 Auto-Review 怎么工作。
- 目标：让它在你上课时自动跑，你只在审批时花 10 秒。

**第 3 周：拉第二个 Bot 进群**
- 建群：学习助手 + 写作 Bot，跑通场景 4 的流水线前两步。
- 试一次 Teach a Task：把你常做的一个网页操作（如从教务网导出课表）录一遍给它看。
- 目标：体会「@ 交接」和群聊盲区（审批不进群）。

**第 4 周：决定要不要付费**
- 翻一下免费额度 7 天内用了多少、跑了几个任务、哪次它翻车了。
- 如果一周真用掉大半额度 → 走 Cursor Pro（$20，本来写代码就值）或 The X Subscription Premium（$30）。
- 如果一个月只用了两次 → 不付费，把它当重型武器用。

## 16. 附录 B：常见问题 FAQ

**Q1：免费版能创几个 Bot？**
A：未检索到官方具体数字；社区教程中用户同时养 4–7 个 Bot 无数量抱怨。（截至 2026-10-20 未能从公开信源核实上限。）

**Q2：Bot 之间能互相发消息吗？**
A：能。群聊里一个做完会自动 @下一个；两个 Bot 之间还有专属后台线程对账细节。[人人都是产品经理，2026-10-17]

**Q3：它会自己发推特吗？**
A：接入 X 的第一版官方动作全是「读」（读帖子、监控趋势），未放开自动发帖。[抖音科技评论，2026-09-06]

**Q4：手机上能审批吗？**
A：能，手机端和桌面端共享同一批审批队列；但无人值守产生的审批约 10 分钟过期，过期要让 Bot 重试。[腾讯云教程，2026-10-09]

**Q5：重置云电脑会丢什么？**
A：从上一个快照重建，最近未入快照的改动可能丢失；Bot 的长期记忆与 Skill 是独立持久化的。[腾讯云教程，2026-10-09；人人都是产品经理，2026-10-17]

**Q6：可以连学校的内网/VPN 网站吗？**
A：未检索到官方支持说明。云电脑在 xAI 的基础设施里，访问校园内网大概率不通；含内网的任务建议让它做「公开资料部分」，内网部分自己补。

**Q7：一个 Bot 最多挂几个例行任务？**
A：社区教程记录为单 Bot 50 个，每个保留最近 20 次运行，两次运行至少间隔 5 分钟。[腾讯云教程，2026-10-09，社区经验]

**Q8：它用的是哪个大模型？**
A：黑箱。官方称按任务自动路由（被点名的有 Grok 自家、Claude Opus 5.5、Midjourney、Suno），用户看不到也选不了。[36氪，2026-10-13]

**Q9：和 OpenClaw / Hermes（个人开源 Agent）比差在哪？**
A：社区观点：OpenClaw/Hermes 要自己买 Mac mini 或常开电脑；Grok Bot 的电脑在云上、免自托管，但稳定性与登录墙问题更多。[抖音，2026-09-02]

**Q10：会泄露我聊天内容吗？**
A：官方设计上凭证走遮蔽沙箱；但 Bot 能看到你贴进聊天的一切——贴任务描述可以，贴密码和验证码不行。[人人都是产品经理，2026-10-17]
