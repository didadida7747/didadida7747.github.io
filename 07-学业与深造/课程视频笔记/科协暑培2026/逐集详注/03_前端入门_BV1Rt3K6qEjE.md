## 知识整理

### 前端知识地图：四层模型

前端分四层：表达层（HTML 负责结构语义，CSS 负责样式布局与响应式）→ 行为层（JavaScript/TypeScript 让页面动起来）→ 框架层（React/Vue 用组件化组织界面，理清状态与 UI 的关系）→ 工程层（npm、Vite、git、部署，解决项目组织、依赖、构建与上线）。推荐学习顺序即按层推进：静态页面 → 让页面动起来 → 学组件 → 工程化与上线。

讲者建议用"论文卡片搜索页"一个项目贯穿四步：HTML/CSS 摆出标题/搜索框/卡片 → JS 实现搜索、筛选、空状态提示 → React/Vue 组件化 → Vite 创建项目、npm run dev / npm run build，最后 deploy 到 GitHub Pages。

### 浏览器运行原理五步

浏览器可理解成渲染 + 执行引擎。输入 URL 后五步：①请求（DNS 找服务器地址，HTTP 拿 HTML/CSS/JS 资源）→ ②解析（HTML 解析成 DOM 树，CSS 解析成 CSSOM——前者是页面结构树、后者是样式规则树）→ ③执行 JS（可修改 DOM、请求数据、响应用户事件）→ ④渲染（layout 计算元素位置大小、绘制、图层合成上屏）→ ⑤交互（点击/输入/滚动触发事件，更新状态后重新渲染）。要点：HTML/CSS/JS 不是孤立三门语法，而是在浏览器里有机组合改变页面状态。

排查方法论（互动题）：按钮看得见、样式正常但点击无反应——能看见说明 HTML/CSS 大概率生效，先开 console 看报错，再查事件绑定与状态更新。核心是先判断问题发生在哪一层，而不是通读代码。

### 状态驱动的 UI：框架的本质

页面可理解成状态——搜索词、选中标签、加载中、错误、结果为空都是状态，"页面长什么样是取决于当前的状态的"。传统写法是找到 DOM 手动改（手动 innerHTML 塞卡片），小页面没问题，项目一复杂就混乱；框架思路是"状态变化、UI 自动更新"，开发者只需维护 state。"现代框架的本质可能是去帮你管理这个状态到 UI 的映射。"组件（搜索框、卡片、筛选）组合成页面；框架真正解决的是状态和交互变多后代码如何保持清晰。

### 构建流程五环节与名词表

构建工具把方便开发的代码变成适合浏览器加载的文件。环节：源码（src 目录）→ 依赖（package.json 记录依赖和脚本，npm install 安装）→ 开发（dev server 本地预览，保存后浏览器几乎立即更新）→ 构建（npm run build 压缩、拆包、优化，输出到 dist）→ 部署（把 dist 静态文件放到服务器或 GitHub Pages 等静态托管）。npm 负责装依赖、记录 scripts、管理 package.json；Vite dev server 是本地开发服务器，支持模块热更新。

这一节与 vibe coding 直接相关：AI 只给代码不够，必须问清文件结构、如何装依赖、如何启动、如何构建、如何验收，否则会得到"看起来很对但深处出问题"的代码。

### Vibe coding 四步法与六要素 prompt 模板

不能无脑 vibe——AI 是助手，不能完全替代架构师和测试。反例 prompt"帮我做一个好看的网页"太空泛：没说风格、给谁用、解决什么问题，没给技术约束，没说数据（来源、字段、loading/error/empty 状态），也没说验收标准。好的 prompt "并不是说一句愿望然后就等着抽奖，而是更可以看做一个小型的需求文档"。四步：规划（目标用户、做什么、不做什么）→ prompt（明确技术栈、页面结构、数据交互、输出形式）→ 验收（真正 npm 装依赖跑起来，检查交互和 console 报错）→ 迭代（提具体问题如"卡片间距更近""移动端单列"，而非"再好看一点"）。

完整 prompt 六类信息：项目目标（做什么给谁用、功能/不做什么）、技术栈（框架、构建工具、JS/TS、样式方案）、页面结构（header/main/filter/card/footer）、数据状态（mock data 还是 API、字段、三个边界态）、交互体验（用户能做什么、做完看到什么）、输出验收（输出哪些文件、怎样启动、什么标准算完成）。

选型速查：React 适合组件与状态、课程项目常用；Vue 模板语法直观、对初学者友好；Next.js 像正式产品雏形（路由、SSR），入门不必急。构建工具：无构建适合单文件 demo；Vite 启动快、贴近真实项目、课堂常用。语言：JS 适合初学；TS 字段函数类型清楚、更适合与 AI 配合。样式：普通 CSS 传统易理解；CSS Modules 适合组件化项目。数据：mock data 不依赖网络适合课堂；JSON 文件模拟真实数据；API 最接近真实但要处理请求失败、加载中、跨域。输出：单 HTML 适合 5 分钟 demo；App.tsx+CSS 适合现场替换；完整目录适合课后模板。

结尾的观点："当我们用 AI 去写前端的时候，其实没有在放弃思考，而是说把思考前置了。"

## 编者补充

- 编者补充（跨集联系）：数据部分"mock data → JSON 文件 → API（含请求失败/加载中/跨域处理）"的递进，与第 4 讲后端的 API 设计构成同一条 HTTP 链路的客户端/服务端双视角，宜对照阅读。
- 编者补充（行动线）：按贯穿项目路径动手一遍——HTML/CSS 静态页 → JS 搜索/筛选/空状态 → React 或 Vue 组件化 → Vite + npm run dev/build + GitHub Pages 部署；完成后用六要素模板 vibe 一个改进版，严格走规划→prompt→验收→迭代。
- 编者补充（缺口）：讲座口头过了构建五步，但未现场演示从零创建 Vite 项目的完整命令序列（如 npm create vite）；git 只在工程层提了一句，需靠第 1 讲或其他教程补齐。
