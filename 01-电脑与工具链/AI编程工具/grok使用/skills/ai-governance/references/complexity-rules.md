# 复杂度判定规则

将本文件作为 G1 的唯一机械判定表。边界模糊时向上取整。

## 判定前置

- 用搜索或目录检查列出实际涉及文件，不估算。
- 查询公共组件、工具、基类或中间件的引用数。
- 明确是否触碰数据库、接口、权限、资金和部署。
- 信息不足时输出“依据不足，继续调查”，不强行评级。

## 硬条件

| 编号 | 条件 | 命中判据 |
|---|---|---|
| H1 | 涉及文件不少于 5 个 | 列出实际文件后计数 |
| H2 | 修改数据库结构 | 表、字段、索引、约束或迁移变化 |
| H3 | 新增或修改对外接口 | endpoint、请求/响应、状态码或公开契约变化 |
| H4 | 权限、认证或鉴权 | 角色、权限点、登录态或越权校验变化 |
| H5 | 资金、计费、订单或库存 | 金额、扣减、支付、对账或库存状态变化 |
| H6 | 修改公共模块 | 被至少 3 处引用的组件、工具、基类或中间件 |
| H7 | 引入新依赖 | 新库、服务、中间件或外部运行时 |
| H8 | 跨端或多服务协同 | 前后端或多个服务需要同步契约 |
| H9 | 构建、部署、CI 或环境配置 | Docker、流水线、环境变量或构建脚本变化 |
| H10 | 业务口径不明 | 规则、边界或优先级存在 C 类问题 |

## 等级规则

按顺序判断：

```text
命中 H2 / H4 / H5 任一项                 -> 至少中等，不可下调
命中 4 项以上，或实际涉及文件不少于 15 个 -> 大
命中 1 至 3 项                            -> 中等
命中 0 项、涉及文件不多于 2 个且纯局部    -> 小
命中 0 项、单文件、不多于 20 行且无分支变化 -> 微小
其余边界                                  -> 向上取整为中等
```

## 降级

- 只能由用户明确提出，AI 不主动建议。
- 记录用户原话、跳过项和剩余风险。
- H2/H4/H5 即使降级，也必须保留影响范围、风险和回滚方案。
