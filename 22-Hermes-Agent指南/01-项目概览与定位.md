## 3. 能力边界（它能做什么 / 不能做什么）

### 能做（【官方】逐项核验为真）

- 跨会话持久记忆：`MEMORY.md` + `USER.md` + SQLite（FTS5）会话全文搜索。
- 从经验中自我创建 / 改进 skills：后台 self-improvement review、Curator、`/learn`。
- cron 定时任务：`cronjob_manage` 工具、`/cron`、`hermes cron` CLI。
- 工具网关（付费）：web 搜索与全文抽取、图像生成、TTS、云端浏览器自动化。
- 消息网关：单进程连 20+ 平台（Telegram/Discord/Slack/WhatsApp/Signal/Email/DingTalk/**Feishu/Lark**/**Weixin**/**QQ**/Teams/LINE 等），可装 systemd / launchd 服务常驻。
- 模型无关：Nous Portal、OpenAI、Anthropic、OpenRouter、DeepSeek、Kimi、GLM、MiniMax、DashScope(Qwen)、Bedrock、GitHub Copilot、以及任何 OpenAI 兼容端点（含 Ollama 本地）。

### 边界 / 不擅长（【社区】多方互证）

- **不是专用 coding agent**：写代码场景，Claude Code / Codex / Cursor / Windsurf 仍领先。腾讯云连续 3 个月用户公开弃用，结论"个人 AI 助手 Hermes 非常合适，写代码还是用专门工具"。\<https://cloud.tencent.com/developer/article/2702804>
- **小模型跑不动 agent**：7B 模型多步任务第三步就胡说八道，需要 32B+ 或旗舰云模型才流畅。【软文口径但与他源吻合】CSDN \<https://blog.csdn.net/u014354882/article/details/160173016>；【个人体验】andrew.ooo 称 24GB GPU 跑 32B 可用。
- **API 在 v0.x 间不稳定**：约每两周 breaking change，生产使用要 pin 版本。【社区】dplooy \<https://www.dplooy.com/blog/hermes-agent-nous-researchs-self-learning-ai-runtime>

## 4. 与同类项目的关系

> 社区有对比的才写；未核实的不补。

### vs OpenClaw（最常被对比，社区资料充分）

| 维度 | Hermes Agent | OpenClaw |
|---|---|---|
| Star 量级 | 255.3k（2026-10-20，官方核验） | ~388k（andrew.ooo 2026-08 口径）/ 345k+（dplooy 口径） |
| 强项 | 自进化 skill 闭环、持久记忆原生、serverless 后端、安全 CVE 记录好 | 插件/skill 生态更大、多智能体更成熟、24+ 消息平台 |
| 生态 | 通过 **agentskills.io 开放标准**互通；`hermes claw migrate` 一键从 OpenClaw 导入 SOUL.md / memory / skills / API key | — |

- 【社区】第三方评测站共识：Hermes 开箱即用、记忆原生；OpenClaw skill 生态更大、多智能体更强。一句话：**"OpenClaw 是你部署给用户的，Hermes 是你部署给自己的"**（dplooy）。\<https://www.dplooy.com/blog/hermes-agent-nous-researchs-self-learning-ai-runtime>
- 【社区·二手转述】Reddit / YouTube / X 共识：两者**互补而非取代**——Hermes 当高级规划器，跑在 OpenClaw 工具之上。PANews \<https://www.panewslab.com/zh-hant/articles/019d7b37-e1c9-71a8-9af7-74cdf1efa8fd>
- 【社区】OpenClaw 官方有专门对比页：\<https://docs.openclaw.ai/start/why-openclaw/openclaw-and-hermes-agent>（raw-02 引用，本指南未读原文）。
- 【社区】安全姿态对比：截至 2026-04，Hermes 零 agent 相关 CVE，同期 OpenClaw 4 天爆出 9 个 CVE（含 CVSS 9.9）。dplooy。

### vs Claude Code / Codex / Cursor（编码工具）

- 【社区】定位不同：后三者是专用 coding agent；Hermes 是通用、模型无关、conversational-agent-first 的个人助手。2026-06 后各家厂商自家 agent 能力追上来，原 Hermes 用户有流失（腾讯云）。

### vs Aider / smolagents / AutoGen / Coze / Dify

- 【社区】Aider / smolagents / AutoGen 是框架/库，面向开发者写程序；Hermes 是端用户产品（andrew.ooo）。
- 【社区·软文口径】Coze 纯云端 SaaS、Dify Docker Web 可视化；Hermes 本地/VPS 自部署、CLI/TUI、隐私优先。来源：CSDN 文火冰糖（墨衍分发文，判定搬运+杜撰结合，仅作观点背景）\<https://blog.csdn.net/hiwangwenbing/article/details/162350506>。
- 【编者推断】Aider 本指南素材中无直接对比帖，仅作类别提示，不展开。

## 5. 成熟度与争议（客观呈现，不站队）

### 活跃度（官方核验，2026-10-20）

- Open issues **16,267** / Closed 19,767；最新 issue 编号已到 **#141,833**（当天新开）；commits 56,818。\<https://github.com/NousResearch/hermes-agent/issues>
- 【编者推断】真实高活跃项目，但伴生大量每日 regression；open issues 积压增长比关闭快（andrew.ooo 复核：8 月时 open 36,370，10-18 为 16,028，作者自己标注口径前后不一）。
- 【社区·第三方实测】mrkeyoor 在 fresh Debian 沙箱实测（2026-09-28，commit 9a0a162）：安装 111 秒，拉 **1209 个 npm 包、占 1452 MB**；npm audit 报 **15 个漏洞（11 high / 3 moderate / 1 low）**；无 root build/test script；仓库 16,537 文件 / ~311 万行代码。当时（v0.21.5）open 队列合计 **45,710**（14,149 issues + 31,561 PRs）。\<https://mrkeyoor.com/repos/hermes-agent/>

### 争议一：issue #10232 抄袭质疑与删帖封人

时间线（【GitHub 一手记录】）：\<https://github.com/NousResearch/hermes-agent/issues/10232>

- 2026-04-15，用户 SunJun8 开 issue，原标题 *"Genuine Question: Did We Just Witness the World's Most Sophisticated 'Ctrl+C, Ctrl+V'?"*，质疑代码疑似大量复制其他项目。
- 2026-04-27，teknium1（Nous 核心）以 "not planned" 关闭，打 P3Low 标签。
- 2026-05-17，Nous 批量 block 4 个用户（NyaMisty、SunJun8、Lei-huang7、zhangleyan），删除其全部评论；teknium1 把 issue 标题改为一个句点 "."。
- 2026-05-28，用户 lc-nyovchev 回应："记录永远删不掉。你要么善意回应质疑，要么做这种笨拙的掩盖动作，后者看起来很糟。"

- 【社区·HN】该事上了 Hacker News：*"Nous Research edits GitHub issue to remove plagiarism claims about Hermes Agent"*（simonmysun，8 分 1 评论），为 HN 上热度第 3 的 Hermes 相关话题。
- 【编者推断】原始质疑正文与评论已被删，**"到底抄了哪个项目、哪部分代码"无法核实**，这是本争议的关键缺口；删评论+封人+改标题的操作记录仍在，社区批评"掩盖"的说法有据可查；但抄袭本身是否成立，同样无证据可断。两边的说法与来源都摆在这里。

### 争议二：Star 水分质疑

- 【社区·二手转述】博客园海滨code 转述 Reddit 高赞帖：新注册账号集中发模板化推广帖、措辞高度雷同，有人直接用 "likely using bots"。作者表态："我没证据 star 一定是刷的，但保持合理怀疑不是坏事。"（他附 GitHub Trending 截图：周 +53,110 star / 总 91.1K，2026-04-17）。\<https://www.cnblogs.com/haibindev/p/19881562>
- 【编者推断】不同来源 star 口径差异极大：95K（dplooy 2026-10 文）→ 237K（andrew.ooo 2026-08 复核）→ 254.8K（mrkeyoor 2026-09-29）→ 255.3K（官方组织页 2026-10-20）。暴涨速度客观存在，"是否有刷量"属无法证实的合理怀疑；本指南采用官方实时值 255.3k，旧文数字引用时均注明其文章日期。

### 争议三：代币化 / Web3 背景

- 见上文第 2 节。媒体判断：链上非官方 NOUS 代币 + token 计价融资 + 冷启动推广贴雷同，三者叠加使社区对"冷启动基础设施/空投预期"有合理怀疑（PANews）。【编者推断】同上，属合理怀疑而非定论。

### 争议四：自进化 skill"固化错误经验"（产品设计缺陷，多方互证）

- 【社区·二手转述】Reddit 高赞吐槽：agent 几乎总认为自己做对了，**即使输出有错也会把错误经验固化成 skill**；你手动改好一个 bug，下次它又按旧 skill 把错误改回去，power user 称之为"噩梦"。
- 与腾讯云专业造轮子（"自进化太快拦不住"）、andrew.ooo（自动生成 skill 质量 hit-or-miss）**三方互证**。详见 03、05 文件。

## 6. 一句话定位（【编者推断】）

Hermes Agent 是当前开源个人 agent 赛道里"记忆 + 自进化 skill"这条路线的标杆实现，适合愿意接受快速迭代、用它当"自己的 7×24 AI 秘书"的学生/个人开发者；不适合想要稳定生产工具、或主要为了写代码的团队。
