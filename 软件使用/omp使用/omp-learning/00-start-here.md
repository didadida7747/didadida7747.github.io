# 00 - 从这里开始

目标：先确认 OMP 的定位和成本边界，再在一个可回滚的小项目中完成首次只读任务。本文不要求你现在安装或配置任何 API Key。

## 先区分三个东西

| 名称 | 是什么 | 你要负责什么 |
|---|---|---|
| OMP | 开源终端编程代理运行时 | 安装、权限、项目规则、扩展与最终验收 |
| 模型服务 | 例如 OpenAI、xAI、Anthropic、Google 或兼容 API | 登录/API Key、费用、额度、可用性和数据政策 |
| 项目目录 | 被代理读取和可能修改的代码/文档 | 范围、Git 状态、测试命令和敏感文件边界 |

OMP 官方资料列出多供应商、模型回退链、LSP、DAP 和子代理等能力。它们是进阶能力，不是“第一次启动”的必要条件。

## 安装前检查

1. 选一个没有重要未提交改动，或已完成备份/提交的小项目。
2. 确认能在该项目中查看 `git status`、运行基本构建或测试。
3. 明确你将使用的模型服务，以及是否愿意承担对应 API 或订阅产生的费用。
4. 不要复制不明教程里的密钥配置、代理地址或“跳过权限”参数。

## Windows 安装与检查

OMP 官方 README 当前给出的 Windows PowerShell 安装命令为：

```powershell
irm https://omp.sh/install.ps1 | iex
```

安装脚本会从网络下载并执行内容。运行前先确认来源是 `omp.sh`，安装后重新打开 PowerShell，再在任意普通目录检查：

```powershell
omp --version
omp --help
```

如果命令无法识别，先重新打开终端并检查安装提示，不要立刻把不明目录永久加入 PATH。若已有 Bun 环境，官方 README 也提供 `bun install -g @oh-my-pi/pi-coding-agent`；两种方式选一种即可，避免重复安装后混淆版本。

## 首次启动：只读，不改文件

```powershell
cd D:\path\to\your-project
omp
```

进入交互界面后先输入：

```text
先不要修改任何文件。请读取 README、目录结构、构建/包管理文件、测试说明和项目规则，输出：
1. 项目用途；
2. 关键目录和入口；
3. 最小构建或测试命令；
4. 不应该随便修改的文件；
5. 你下一步建议读取的文件。

只输出报告，等我确认后再继续。
```

验收：它应说明证据来源和不确定项；如果项目没有测试，不应编造测试已通过。

## 登录、模型与凭据

模型登录和供应商配置会随版本变化。先在 OMP 内查看帮助与登录入口（例如输入 `/help`，再按当前界面提示查看 `/login`、模型选择和配置），或查 [官方 Providers 文档](https://omp.sh/docs/providers)。

不要把 Key 直接发给代理，也不要写进仓库的 `README.md`、`AGENTS.md`、`models.yml` 示例或 PowerShell 历史。若确实需要 API Key，使用服务商与 OMP 当前文档推荐的本机凭据机制，并确认它不被 Git 跟踪。
