# 01 · 高效交互方法论

> 本篇解决"地基"问题：先建立对 AI 的正确心智模型，再掌握 10 条被 OpenAI、Anthropic、Google 三家官方指南和各平台高赞内容共同验证的核心方法，最后给出提问框架速查与选用建议。
>
> 来源标注：【官方】OpenAI / Anthropic / Google 指南；【视频】Karpathy、吴恩达、Anthropic 官方课程；【社区】中文社区经验帖。链接均见 [04-工具与资源清单](/21-AI交互能力提升/04-工具与资源清单)。

## 一、先建立 5 个心智模型

心智模型错了，学再多模板也是歪的。

1. **AI 在"接话"，不在"懂你"。** 大语言模型的工作机制是根据你给出的文字预测最可能的下文。你没写出来的背景、身份、真实意图，它只能靠猜——而且猜得信心十足。所以"它怎么连这都不懂"的时刻，几乎都是"我没说清"的时刻。（科普中国《AI 不是"懂你"，它是在"接话"》）
2. **AI 需要 token（文字）来思考。** 模型不是直接"蹦答案"，而是一个字一个字地生成。复杂问题要求它"分步推理 / 先列思路再给结论"，相当于给它草稿纸；直接要答案等于让它心算压轴题。（Karpathy《Deep Dive into LLMs》）
3. **AI 会"幻觉"，且会"讨好"。** 它可能编造不存在的事实、法条、文献；同时倾向于附和你的立场（sycophancy），哪怕你的前提是错的。所以核实与"防迎合"是固定工序，不是可选项。（吴恩达 2026 提示词课程、Anthropic 文档）
4. **上下文窗口有限且会"分心"。** 对话越长、主题越杂，模型对早期信息的注意力越弱。不同任务要开新对话；长对话中途要主动小结、重申要求。（Karpathy《How I use LLMs》）
5. **把 AI 当"聪明但完全不知情的新同事"，而不是许愿池或搜索引擎。** 新同事能力很强，但你要交代：你是谁、为什么做、要什么、交付成什么样、什么不能碰。这一条是所有方法论的总纲。（Anthropic 黄金法则：把 prompt 拿给不了解任务的同事看，他困惑，模型也会困惑）

## 二、10 条核心方法

### 方法 1：指令清晰、具体、可验收

说清三件事：**要什么结果、什么约束、什么格式**。把"帮我写个策划案"改成"写一份线下活动策划案：时长半天、预算 3000 元以内、面向 20 人学生社团，重点输出流程表和物料清单，用表格呈现"。（腾讯云社区、OpenAI 官方）

### 方法 2：给角色与身份

一句"你是一名有 10 年经验的嵌入式工程师，擅长用通俗比喻给大一学生讲课"，会同时设定知识范围、表达风格和详略程度。
> 注：少数派 2026 年的纠偏文章指出，角色设定对"事实准确性"类任务在现代模型上帮助已有限，但对**写作、风格、教学、评审**类任务依然非常有效，不要神化也不要弃用。

### 方法 3：主动给上下文（背景 / 参考资料）

- 提问前先交代：我是谁（"物理系大二，已学完微积分和线代"）、给谁用、什么场景、已有材料。
- 有参考文本时直接喂原文，并加一句"**只依据我提供的材料作答，材料中没有的请明确说明**"（grounding，可显著降低幻觉）。Anthropic 实测：长文档放在 prompt 顶部、问题放在最后，效果更好。

### 方法 4：给示例（few-shot）

光描述"我要什么风格"往往不如直接给 1–3 个"输入 → 输出"范例。官方建议示例要**相关且多样**，并用标签或分隔符包起来。示例足够清楚时，甚至可以省掉一大段指令描述。（Google、Anthropic 官方）

### 方法 5：用分隔符 / 标题把 prompt 分区

复杂指令用 Markdown 标题或 XML 风格标签分段，避免模型把"参考资料"误当"指令"执行：

```
# 角色
……
# 背景
<context>……</context>
# 任务
……
# 输出格式
……
# 输入
<input>……</input>
```

OpenAI 推荐的系统消息分区顺序：Identity（身份）→ Instructions（规则，含"绝不做什么"）→ Examples（示例）→ Context（数据，放最后）。

### 方法 6：复杂任务先拆解，先定骨架再填细节

- 大任务拆成子步骤：先要大纲 → 确认大纲 → 逐节展开 → 汇总润色。36氪 的复盘案例明确指出"一次性把完整需求喂进去行不通，要先定骨架再调细节"。
- 能并行的子任务（如让 AI 同时给 3 个方案）并行生成，再让它对比聚合。（Google 官方：链式 prompt、并行后聚合）

### 方法 7：让模型分步思考并自检

- 复杂推理加："请先列出推理步骤，再给结论"；
- 交付前加："完成后请对照以下标准逐项自检：①…… ②……，发现不符自行修改"。
- 写作类任务可用"草稿 → 按标准审查 → 按审查意见修改"的链式流程，每一步质量都更可控。（Anthropic 官方）

### 方法 8：迭代追问，而不是一次定生死

- 正确预期：**第一版通常只是草稿，第三、四轮输出往往才最好**，像跟设计师改稿。（掘金实战帖、Karpathy）
- 高质量追问的写法是精准定位问题："第 2 部分太笼统，请补充具体数据；第 3 部分删掉，改成时间线；整体语气从书面改成口语"，而不是重复一遍原问或只说"不行重写"。
- 出错时优先"回滚"——把上一版满意的内容贴回来继续改，而不是在错误版本上越缠越乱。

### 方法 9：管好对话，选对工具

- **按主题开新对话**：一个对话只做一件事，避免上下文互相污染（Karpathy 的核心习惯之一）。
- 让合适的工具干活：查实时信息用联网搜索；算数、处理表格用代码执行；长文档让它"先通读再问答"；需要带出处的报告用深度研究类功能。把 AI 当搜索引擎问"今天星期几、某手机多少钱"是典型的工具错配。

### 方法 10：防讨好 + 沉淀资产

- **防讨好**：在自定义指令里写明"先检查我的问题有无错误前提，不要迎合；不同意直接指出并给依据；区分事实与观点"。需要客观评审时，让它先制定评分标准、再打分，并要求"分数不许虚高"。
- **沉淀资产**：把验证有效的指令、角色设定、输出模板存进自定义指令（Custom Instructions）或个人 prompt 库；把好对话固化为可复用的 GPTs / 项目，而不是每次从零开始。

## 三、提问框架速查（背 1 个即可，别贪多）

社区流传的框架本质相同：**强迫你把"角色、背景、任务、格式"说全**。下表按从简到繁排列。

| 框架 | 要素 | 适用场景 | 出处 |
|---|---|---|---|
| **RTF** | Role 角色 / Task 任务 / Format 格式 | 日常快速提问，新手第一个该掌握 | 少数派《用好 ChatGPT，一个人就是一个团队》（2024-01，URL 未获取） |
| **五词公式** | 背景 / 目标 / 材料 / 限制 / 格式 | 普通人日常场景，口语化、零门槛 | 抖音 [视频链接](https://www.iesdouyin.com/share/video/7676800617310363067) |
| **R-C-O** | Role 角色 / Context & Constraints 背景与约束 / Output 输出格式 | 通用，强调"背景与约束是最重要的一环" | 少数派 2026-01 文章（URL 未获取） |
| **CO-STAR** | Context 上下文 / Objective 目标 / Style 风格 / Tone 语气 / Audience 受众 / Response 响应格式 | 写作、内容创作、对表达质量要求高的任务；源自新加坡 GovTech，作者凭此获 2023 新加坡 GPT-4 提示词大赛冠军 | [华东师大开发者平台](https://developer.ecnu.edu.cn/vitepress/llm/prompts.html)、[清华社教材 PDF](https://www.tup.com.cn/upload/books/yz/117780-01.pdf) |
| **ROSES** | Role 角色 / Objective 目标（单一可衡量）/ Scenario 场景（约束边界）/ Expected Solution 预期输出 / Steps 步骤 | 复杂任务，显式规定推理步骤 | [CSDN 详解](https://blog.csdn.net/qq_64296768/article/details/158425296) |
| **BROKE** | Background 背景 / Role 角色 / Objective 目标任务 / Key Results 关键结果 / Evolution 进化（迭代调整） | 有明确目标的营销、项目类任务 | [框架汇总帖](http://m.toutiao.com/group/7578780421048058409/) |
| **RICE** | Role 角色 / Instruction 指令 / Context & Constraint 上下文约束 / Example 示例 | 专业写作、行业分析 | 同上 |
| **TRACE** | Task / Role / Background / Action / Context / Example | 复杂项目方案 | 同上 |
| **CRISPE** | Capacity & Role 能力角色 / Insight 背景洞察 / Statement 任务声明 / Personality 个性 / Experiment 实验 | 创意与写作 | [ITPUB 博客](http://m.blog.itpub.net/70043027/viewspace-3061414/) |
| **KISS**（复盘专用） | Keep 保持 / Improve 改进 / Start 开始 / Stop 停止 | 对话复盘、周复盘 | [苏米客](https://xmsumi.com/detail/1726) |

**选用建议（避免选择困难）：**

- 新手：日常用 **RTF / 五词公式**，写作用 **CO-STAR**，复杂任务用 **ROSES**——三个封顶。（与 01库手册「四段式 / CO-STAR / LangGPT」口径的映射：四段式≈RTF；LangGPT 与 ROSES 二选一即可，不必都学。）
- 框架是检查清单，不是枷锁：简单任务不必硬凑每个要素（ROSES 作者同样如此提醒）。
- 与其换框架，不如把同一个框架用熟、并对照它做复盘。

## 四、一个"合格开场"长什么样（综合示范）

以"让 AI 帮你改一份 STM32 课程设计报告"为例：

```
# 角色
你是一名高校电子信息专业的讲师，熟悉 STM32 开发与本科课程设计评分标准，
擅长用通俗语言指出问题。

# 背景
我是电子信息专业大一学生，这是我第一次写课程设计报告（报告见附件）。
报告题目是"基于 STM32 的温湿度采集系统"，评分占比：原理 30%、
硬件设计 20%、软件流程 20%、测试与分析 20%、格式规范 10%。

# 任务
1. 先通读报告，按上面五项评分占比给我打分并说明扣分点；
2. 只针对扣分最严重的三项，给出具体修改建议（引用我的原文）；
3. 不要替我重写报告，只给建议和示例片段。

# 输出格式
评分表（Markdown 表格）+ 三条修改建议（每条含：问题、原因、示例改法）。

# 约束
- 只依据我提供的报告内容评价，不要编造我没写的内容；
- 如果报告信息不足以判断某项，请明确写"信息不足"。
```

这个开场同时用到了方法 1–7。**你不需要每次写这么长——但第一次复盘时你会发现，过去的自己连其中三分之一都没做到，这就是进步的起点。**
