# 《提问的智慧》How To Ask Questions The Smart Way

> 原版作者：Eric S. Raymond（ESR）与 Rick Moen ｜ 中文版维护：ryanhanwu
> 中文版阅读：\<https://github.com/ryanhanwu/How-To-Ask-Questions-The-Smart-Way>（README 即正文，35.7k+ star）

## 这份文档是什么

一篇写于互联网社区时代、至今仍在生效的**提问方法论**。它从回答者的视角出发，讲清楚一件事：**在技术社区里，什么样的提问能得到快速、高质量的回答，什么样的提问会被直接忽略甚至被嘲讽**。

需要先校准预期：原文语气以"严厉"著称（开篇就警告"别问符合以下特征的问题"），读的时候取其方法论、放其语气——今天的对象不只是邮件列表里的黑客，还有 GPT、Claude、助教、群友和 Stack Overflow。

## 核心主张（目录层面的结构）

1. **提问之前**——先自己动手：
   - 用搜索引擎搜过、读过手册和 FAQ、自己试错过，才轮到提问；
   - 很多"问题"在这一步就消失了——这也是最高效的解法。
2. **提问时**——让回答者容易帮你：
   - 选对渠道（官方 issue、邮件列表、群、AI，各有分工）；
   - **标题要精确**："在用 VS Code + uv 环境跑 SI100+ lecture00 时 `uv sync` 报 `No `pyproject.toml` found`"，而不是"求助！python跑不起来"；
   - 提供完整上下文：环境（系统/版本）、做了什么、期望什么、实际发生什么、复现步骤、你已尝试过什么。
3. **如何解读回答**——别人给线索不等于给答案，沿着线索自己走完最后一公里；问题解决后回帖补充结论，让后来者受益。
4. **如果收到敷衍的回答**——先反思自己的提问是否给了足够信息，而不是先怪社区冷漠。

## 最重要的三条（翻译成 2026 年的用法）

| 原文主张 | 2026 年落地 |
|---|---|
| 提问前先做功课，不做伸手党 | 先搜、先让 GPT 解释报错、先读文档前三屏，带着"我试过 A、B 都不行"再来问 |
| 问题要具体、可复现 | 问 AI 同理：贴**最小可复现代码 + 完整报错 + 环境**，而不是截图 + "怎么办" |
| 尊重回答者的时间 | 别让助教/群友替你写作业；描述目的而非你锁定的错误方法（"筷子喝汤"问题） |

第三条正是 SI100+ Lec.02 讲的"**描述目的而非方法**"——你不是来验证自己预设的工具对的，你是来解决问题的。

## 为什么大二这一年特别要读

1. **你未来四年的提问对象主要是 AI 和助教**：GPT 的回答质量完全由你的提问质量决定——这份文档就是"提示词工程"的 1990 年代原型；
2. **实验室和实习的第一印象**：提问得法的新人会被认为"教起来省心"，提问不得法的会被默默降级处理；
3. **它是免费的社交资产**：在群里、在 issue 区、在 Office Hour，会提问 = 更快的答案 + 更好的声誉。

## 怎么用

- 全文约半小时读完，**读一遍建立原则即可，不必背**；
- 真正的价值在执行：每次要提问前，快速自查三件事——①我搜过/AI 过了吗？②我的标题和上下文能让人不追问就动手帮吗？③我有没有描述目的而不是锁定方法？
- 遇到"收到敷衍回答"的情况，回来重读第 4 节，先自省再行动。
