# 练习题：改造你的 harness（按难度递增）

> 四道题对应 Agent 开发的四个核心能力。做完前两道你就超过 90% 的"Agent 概念了解者"；做完全部四道，你具备自研 Agent 的入场资格。
> 全部基于 [toy_agent_harness.py] 改造，建议先 `git init` 或复制副本再动手。

## 练习 1（热身）：给 harness 加一个新工具

**任务**：加一个 `search_text` 工具——在 playground 所有 .md 文件里搜关键词，返回"文件名:行号:该行内容"。

**要求**：
1. 在 `TOOLS` 注册（写好 description——回忆 02篇原则5：描述即提示词工程）
2. `TOOL_PARAMS` 加参数声明
3. `permission_gate` 里给它配规则（只读 → 放行）
4. Mock 策略不用改（真模型会自己发现并使用它——用 `--api` 模式验证）

**验收**：问模型"report.md 里提到了几次权限"，它能用新工具回答。

**你将学到**：工具系统的扩展流程 = 声明+schema+权限三处落笔；以及为什么工具越好用，模型行为越聪明。

## 练习 2（核心）：把权限门升级成"规则配置"

**任务**：现在权限规则硬编码在 `permission_gate` 函数里。把它改成读配置：

```json
// permissions.json（和脚本同目录）
{
  "allow": ["list_dir", "read_file", {"tool": "write_file", "path_prefix": "report"}],
  "deny":  [{"tool": "run_bash", "contains": ["rm", "del ", "format"]}]
}
```

**要求**： deny 优先于 allow；`--mode yolo` 跳过 deny 之外的一切询问；被拒时的理由信息要包含命中的规则。

**验收**：不修改代码、只改 json，就能让"删除 todo.md 的 write 操作"被放行/被拒。

**你将学到**：03篇的 settings 分层思想——**权限必须可配置、可审计，而不是写死在代码里**；deny 优先是所有权限系统的铁律。

## 练习 3（最有含金量）：实现"真·压缩"

**任务**：现在 `_maybe_compact` 只是把旧工具结果换成占位符（微压缩）。把它升级成 Claude Code 式的 **auto-compact**：

**要求**：
1. 加一个 `estimate_context_tokens(messages)` 函数（提示：中文≈2字符/token，英文≈4字符/token，比现在的一刀切准）
2. 阈值触发时，把**除最近 2 轮外**的全部历史交给 LLM 总结成结构化摘要（保留：任务目标/已做决定/关键文件/当前状态/下一步——回忆 04篇思考题 2 的答案）
3. 摘要以一条 `user` 消息身份替换旧历史，前缀注明 `[上下文已压缩]`
4. `--compact-demo` 模式下验证：压缩后模型依然能写出正确的 report.md

**验收**：压缩触发的轮次打印前后 token 估算对比；最终产出质量不因压缩而崩。

**你将学到**：04篇的全部内容变成手感。做完这道题，你就理解了为什么"上下文管理是 Agent 工程的半壁江山"。

## 练习 4（毕业设计）：写一个最小的 MCP Server

**任务**：把练习 1 的 search_text 工具改造成 MCP server，让真实的 Claude Code（而不是 toy harness）调用它。

**要求**：
1. 用 Python 官方 SDK（`pip install mcp`）或手写 stdio JSON-RPC（更好玩）
2. 实现 `initialize` / `tools/list` / `tools/call` 三个方法
3. 在 Claude Code 里 `claude mcp add` 注册，然后让它调用你的工具

**你将学到**：MCP 的协议本质（02章02篇）；以及把工具"一次编写、处处运行"（CC/Cursor/Windsurf 都能用）的生态价值。

## 做完之后

把你的改造版本用起来：给它接你的真实 API，让它每周巡检一个真实目录/日志/笔记库。**用自己写的 Agent 解决自己的问题，是这项学习最好的收官。**
