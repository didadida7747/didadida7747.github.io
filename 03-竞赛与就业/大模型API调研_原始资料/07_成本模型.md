## 1. 计费基本单位：token

### 1.1 token 是什么
token 是模型处理文本的最小“计量块”，大约相当于一个词的一部分。英文通常 1 个词约 1.3 个 token；中文按字计算，不同模型差异很大。API 按“每百万 token（MTok / 1M tokens）”计价，输入和输出分开算。

### 1.2 中文 token 换算（无官方统一数字，仅作估算）
| 来源 | 换算 | 说明 |
|---|---|---|
| DeepSeek 官方 Token 文档（https://api-docs.deepseek.com/quick_start/token_usage/ ，搜索摘要） | 约 1 汉字 ≈ 0.6 token | 文档较旧，仅作参考 |
| 2026 年一份速查表（tokenestimate.com，搜索摘要） | 1 汉字 ≈ 0.6–1.2 token | 第三方估算 |
| 第三方 token 计数工具（搜索摘要） | DeepSeek ≈ 0.6 token/字；Qwen ≈ 1.65 字/token | Claude 无官方中文比例 |
| arXiv 2604.14210（搜索摘要） | 中文约 1.96–2.72 字/token（跨分词器） | 论文测得 GPT-4o 系分词器对中文约多耗 15%；Qwen2 约多 2.5%；GLM 中文比英文更省 |
| 第三方测试（BigGo，搜索摘要） | Claude 旧分词器 中/英 比值 1.11–1.64；GPT-4o o200k 约 1.0–1.35；DeepSeek-V3 最低 0.65 | 测试样本 22 段，**未核实其方法** |

**结论（未核实处已标注）**：中文按字计费，粗略估算用 **0.6–1.2 token/字**；不同厂商差异可达 ±50%。正式预算前请用各家官方计数工具实测（Claude 用 token counting 接口；OpenAI 用 tiktoken；Qwen/DeepSeek 用其官方分词器或返回的 usage 字段）。

### 1.3 Claude 新分词器（tokenizer）变化
- Claude 4.7 及之后模型使用新分词器；Sonnet 4.6 及更早模型仍用旧分词器。
- 官方说法：同一段文本约多 **30%** token，具体随内容和工作负载而变（来源：Anthropic 文档，经搜索摘要转述，https://platform.claude.com/docs/en/about-claude/pricing 及 token-counting 页）。
- 更早版本的官方文档给出范围：约 **1.0–1.35 倍**，定价页提示最多约 **35%** 更多（来源：第三方对 2026 年 6 月文档的分析，搜索摘要）。
- 第三方实测：真实内容上测得 **1.47 倍**（https://www.claudecodecamp.com/p/i-measured-claude-4-7-s-new-tokenizer-here-s-what-it-costs-you，搜索摘要，**未核实**）。
- 含义：**单价没变，但同样的 prompt 实际消耗 token 变多**，预算要按新分词器重新测量。
- 注意：我未能直接打开 token-counting 官方页（被地域跳转拦截），以上“30%”来自搜索摘要，**需二次核实**。

### 1.4 输入 / 输出价格比
- 以本次抓取的 Anthropic 价格为例：输出/输入比均为 **5 倍**（Sonnet 5.5：$2 / $10；Opus 5.5：$4 / $20；Haiku 5.5 ≤100K：$0.10 / $0.50）。
- DeepSeek：V4.1-Flash 输出/输入（cache miss，off-peak）= $0.6 / $0.15 = **4 倍**；V4-Pro = $1.98 / $0.66 = **3 倍**。
- 阿里 qwen3.7-plus（0–256K）：输入 2 元 / 输出 8 元 = **4 倍**；qwen3.5-flash 0–128K：0.2 / 2 = **10 倍**。
- 火山 Doubao-Seed-2.1-pro：输入 6 元 / 输出 30 元 = **5 倍**。
- 结论：常见比例在 **1:3 到 1:8** 之间，与你的假设一致；个别小模型可到 1:10。

### 1.5 Reasoning / Thinking token 计费
- 推理 token 按**输出**价格计费，且**不在返回文本中可见**，但会计入账单。
- 阿里 qwen-plus 的价格就区分“非思考”与“思考”模式：思考模式 0–128K 输入 8 元 / 输出 24 元（**对比非思考 2 / 12**，注意页面表格中的对应关系需以控制台为准）。
- 实操：报账单时要看 `usage` 字段中的 reasoning/thinking token 数，而不是只看答案长度。
- 来源：阿里百炼计费页（https://help.aliyun.com/zh/model-studio/billing-for-model-studio）；OpenAI 与 Anthropic 的 reasoning 计费规则**未核实**（官方页未能抓取）。

## 5. 成本估算方法与算例

### 5.1 通用公式

```
月成本 = Σ_类型 [ (Token数 / 1,000,000) × 单价 ]

单次请求成本 =
    未命中输入 × 输入价
  + 缓存写入 × 输入价 × 写入倍数（Anthropic 5 分钟 1.25，1 小时 2）
  + 缓存命中 × 输入价 × 命中倍数（Anthropic 0.1）
  + 输出 × 输出价
  + 推理 token × 输出价（不可见但计费）

月成本 = 单次成本 × 月请求数 × （1 + 重试率）
```

### 5.2 算例假设（所有价格为本稿第 0 节所示来源，未额外核实）
- 价格取自 Anthropic 官方页（抓取当日）：Sonnet 5.5 $2/$10，缓存读取 $0.10；Haiku 5.5 ≤100K $0.10/$0.50，缓存读取 $0.01；Opus 5.5 $4/$20，缓存读取 $0.20。
- 不计缓存写入的额外成本（稳定前缀连续调用时写入次数很少），不计推理 token，不计工具费用。
- 月按 30 天计。

**算例 A：客服 RAG（日 1 万次对话）**
- 每次输入 3,000 token：其中 2,000 为稳定前缀（系统提示 + 知识库片段），1,000 为本次问题；每次输出 400 token。
- 月请求 30 万次：输入合计 9 亿 token（900 MTok），输出 1.2 亿 token（120 MTok）。

| 模型 | 无缓存 | 有缓存（前缀命中） | 说明 |
|---|---|---|---|
| Sonnet 5.5 | $1,800 + $1,200 = **$3,000** | 前缀 600 MTok×$0.10 = $60；新内容 300 MTok×$2 = $600；输出 $1,200；合计 **≈ $1,860** | 缓存约省 38% |
| Haiku 5.5 | $90 + $60 = **$150** | 前缀 600 MTok×$0.01 = $6；新内容 300 MTok×$0.10 = $30；输出 $60；合计 **≈ $96** | 缓存约省 36% |
| Opus 5.5 | $3,600 + $2,400 = **$6,000** | 前缀 600 MTok×$0.20 = $120；新内容 300 MTok×$4 = $1,200；输出 $2,400；合计 **≈ $3,720** | 缓存约省 38% |

> 注：Sonnet 5.5 的有缓存行已按公式重算为约 $1,860；Opus 5.5 的缓存读取价（$0.20 = 0.05×）与 Sonnet 5.5 的读取价（$0.10 = 0.05×）一致，但 Haiku 5.5 读取为 0.1×，三者比例**不统一**，见第 9 节。

**算例 B：代码 Agent（单任务 20 轮工具调用，上下文逐轮累积）**
- 初始上下文 1 万 token，每轮新增 3,000 token（工具结果、代码），每轮输出 1,000 token。
- 第 k 轮输入 ≈ 10k + 3k×(k−1)，20 轮合计输入约 **77 万 token**（非线性：轮数翻倍，总输入约增至 4 倍）。
- Sonnet 5.5：
  - 无缓存：77 万×$2/M ≈ **$1.54** 输入 + 2 万输出×$10/M = $0.20 → **≈ $1.74/任务**
  - 有缓存（前 76 万按 0.1× 读取，新增 6 万按 $2 计，每轮增量按 $2.50 写入）：读取 ≈ $0.15 + 新增输入 ≈ $0.12 + 写入 ≈ $0.15 + 输出 $0.20 → **≈ $0.65/任务**
- 结论：**不做缓存，代码 Agent 的成本随轮数近似平方增长**；稳定前缀 + 缓存可把单任务成本降到约 1/3。

**算例 C：批量数据标注（100 万条，每条输入 300 token、输出 20 token 标签）**
- 输入 3 亿 token，输出 2,000 万 token。

| 方案 | 计算 | 合计 |
|---|---|---|
| Haiku 5.5 实时 | 300 MTok×$0.10 + 20 MTok×$0.50 | $30 + $10 = **$40** |
| Haiku 5.5 批处理（50%） | 同上 ×0.5 | **$20**（批处理为官方页 50% 折扣） |
| DeepSeek V4.1-Flash 谷价未命中 | 300 MTok×$0.15 + 20 MTok×$0.6 | $45 + $12 = **$57**（仅按价格表，未计分时段与缓存） |

### 5.3 长文档总结（补充）
- 100 篇 × 5 万 token，输出 2,000 token/篇：输入 500 万 token，输出 20 万 token。
- Sonnet 5.5：500 万×$2/M + 20 万×$10/M = **$12**；Haiku 5.5：500 万×$0.10/M + 20 万×$0.5/M = **$0.60**（单篇 5 万 token 未超过 Haiku 的 100K 阈值，全部按 ≤100K 档计）。
- DeepSeek V4.1-Flash 谷价：500 万×$0.15/M + 20 万×$0.6/M ≈ **$0.87**，峰价约 $1.74。

### 5.4 自建 vs API 盈亏点（粗算）
- 按 H100 **$3.84/GPU·小时**（OCPI 加权均价，未核实）计算，单卡 24 小时全月 ≈ **$2,803/月**。
- 若 API 平均价按 **$2/M tokens**（混合输入输出），盈亏点 ≈ 2,803 ÷ 2 = **1,400 MTok/月**，相当于平均吞吐约 **540 token/秒** 持续运行（全月满载）。
- **以上吞吐数字是假设，实际取决于模型大小、并发、批大小，未核实**。低利用率时 API 更划算；高且稳定的流量才适合自建。

## 6. 成本优化手册（思路与依据）

| 手段 | 做法 | 依据 |
|---|---|---|
| 模型路由 / 级联 | 简单问题走小模型（如 Haiku 5.5），复杂问题再升级 | 第 5 节算例：小模型单价约为大模型 1/10–1/20 |
| 稳定前缀 | 把系统提示、工具定义、知识库放在最前面并保持字节级一致 | 缓存命中价约 0.1×（Anthropic 官方页；DeepSeek 为 1/10，官方页） |
| 提示词压缩 | 删除冗余示例，只保留必要字段 | 直接降低输入 token |
| 输出长度控制 | 设置 max_tokens，要求简短格式 | 输出价约为输入价 3–8 倍 |
| 批处理 | 不需实时响应的任务走 Batch | 50% 折扣（Anthropic 官方页；阿里官方页） |
| 错峰调用 | DeepSeek 谷时段（UTC 非高峰）调用 | 谷价为峰价一半（官方页） |
| 蒸馏与小模型 | 用大模型产出数据训练小模型 | 未核实具体成本收益 |
| 控制 Agent 上下文 | 定期压缩/摘要历史；工具结果截断 | 算例 B：上下文累积导致成本非线性增长 |
| 监控 token 用量 | 记录 usage 中的缓存命中、推理 token | 第 1.5、1.3 节 |
