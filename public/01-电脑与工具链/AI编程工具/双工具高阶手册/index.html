02 · 上下文 · 会话 · 记忆 CC 17 卡Codex 14 卡

上下文窗口经济学：该出现的时候让该在的东西出现。会话是资产，记忆是长期规则。此处收高频卡，全量见 02 章 MD。

Claude Code 高频卡

/compact [指示] 压缩上下文▸

场景：上下文告急但不想丢连续性；里程碑后主动压。

示例：/compact 保留滤波器参数修改思路和测试结果

坑：压缩必失真——关键结论先写进文件；共识是 60-70% 就压。

/context 上下文体检▸

场景：变笨/变贵时先体检；装 ZCF/MCP 后查谁偷吃 token。坑：MCP 工具定义是大户，不常用的摘掉。

/rewind 回退检查点▸

作用：对话和/或代码回退到某次提问前（空输入双击 Esc 同效）。

坑：Bash 产物、手工编辑、子代理编辑不在快照；约 30 天清理；不能替代 git。

/branch / /fork 分支与后台副本▸

branch：分叉会话试激进方案，原会话还在；fork：副本丢后台跑任务，当前继续。

/resume / `/clear` / `/recap` / `/export`▸

一课一会话：clear 时顺手命名 → resume 找回 → recap 热身 → export 把方案讨论变成报告素材。

/goal 长期目标▸

示例：/goal 所有单元测试通过且覆盖率≥80%。长实验防跑偏。

/memory / `/init` / `/import codex` 记忆三件套▸

init 生成 CLAUDE.md；memory 编辑各级+看 auto memory；import 可直接吃 Codex 配置。

坑：CLAUDE.md 是软约束，红线用 hooks（§03）。

/model `/effort` `/fast` `/advisor`▸

省钱双旋钮：杂活降模型+降 effort；advisor 让第二个模型当顾问找茬。

Codex 高频卡

/new / `/resume` / `/title`▸

new 可命名并置顶（0.146.0）；resume 选择器可按时间排序、归档（0.148.0）。

/undo 撤销文件改动▸

与 CC /rewind 差异：undo 只回滚文件不回滚对话——保留它对任务的理解，换个说法重做。

/fork / `/side` / `/goal`▸

fork 分叉试错；side 侧聊问小问题不污染主上下文（对应 CC 的 /btw）；goal 长期目标。

/init / `/import` / `/export` / `/archive`▸

init 生成 AGENTS.md；import（0.145.0+）可迁入 Claude Code/Cursor 的设置、MCP、插件、会话与记忆；export 出 Markdown；delete 前先 export。

/model + reasoning effort▸

0.164.0 支持内联参数（模型+力度+速度）；TUI Alt+,/. 快调力度。默认模型 GPT-6.1 Sol。

03 · 权限 · 安全 · 沙箱 · Hooks

一句话：CLAUDE.md 管建议，Hooks 管纪律。自主权是刻度盘，按任务给权限。

Claude Code：7 种权限模式

模式行为场景
default逐工具首次询问陌生仓库
acceptEdits自动接受编辑自己课设日常
plan只读规划先方案后动手
auto分类器审核，常规免问无人值守留底线
dontAsk会弹的一律拒CI
bypassPermissions全跳过仅限容器/VM

规则求值：deny → ask → allow，deny 永远最优先。语法示例：Bash(npm run *)、WebFetch(domain:github.com)、mcp__github__*、Agent(model:opus)。

防误删 hook（可直接抄）

{
  "hooks": { "PreToolUse": [{
    "matcher": "Bash", "if": "Bash(rm *)",
    "hooks": [{ "type": "command",
      "command": "jq -r '.tool_input.command' | grep -qE 'rm +(-[a-z]+ +)*-[rf]{1,2}' && echo '{\"permissionDecision\":\"deny\",\"reason\":\"禁止递归/强制删除\"}' || exit 0"
  }]}]}}

exit 0 放行、exit 2 阻断；也可输出 permissionDecision JSON。CC 33 个 hook 事件速查见 03 章 MD。注意：CC 沙箱原生 Windows 不支持，需要走 WSL2。

Codex：审批 × 沙箱矩阵

sandbox \ approvaluntrustedon-requeston-failurenever
read-only（默认）最保守只读少问只读几乎不问只读自动
workspace-write可写多问—--full-auto自动跑工作区
danger-full-access全权限（+never = 旧 --yolo，仅限容器）

/permissions（0.89.0 取代 /approvals）可存 profiles：作业模式 / 课设模式 / 脚本模式一键切；0.147.0 --approve-for-me 自动批准"对我安全"的操作。

同一安全目标两边怎么配

目标CCCodex
只读出方案--permission-mode planread-only + untrusted
日常写自己项目acceptEdits + deny 危险命令--full-auto
无人值守auto + --permission-prompts noneworkspace-write + never

04 · 技能 · 扩展 · MCP

把重复流程固化成资产（skills），把外部世界接进来（MCP），打包分发（plugins）。自定义命令→技能是两个框架共同的收敛方向（Codex 的 ~/.codex/prompts 已弃用）。

SKILL.md 一个例子覆盖 90% 语法

---
name: lab-report
description: 把实验数据目录变成图表齐全的报告初稿
argument-hint: "[数据目录]"
allowed-tools: Bash(python *), Read, Write
context: fork            # 隔离子代理执行，不污染主对话
---
把 $ARGUMENTS 下的数据出图（先 !`ls $ARGUMENTS` 看清单），按学校模板生成报告。

关键：$ARGUMENTS/$1 参数占位；!`cmd` 动态注入 shell 输出；disable-model-invocation: true 让危险技能只能人手动调；paths 限定自动触发范围。

MCP：两边都是 client，Codex 兼做 server

操作Claude CodeCodex
加 HTTP serverclaude mcp add --transport http 名 URL --header ...[mcp_servers.名] + HTTP/OAuth（0.77+）
加 stdio serverclaude mcp add 名 -- 命令 参数codex mcp add
作用域local（默认）> project（.mcp.json 入 git）> user用户/项目 config.toml 分层
⭐ 王牌联动：CC 调 Codex▸
claude mcp add codex -- codex mcp-server

Codex 把自己暴露为 MCP server（codex / codex-reply 两个工具）。之后 CC 当总编排，Codex 当第二意见/执行器："让 codex 工具以 xhigh review 当前 diff"。

插件与应用▸

/plugins 市场分区（Curated/Workspace/Shared）；/presets 10 槽存复用 prompt（0.164.0）；/apps 连接器 $ 引用；/experimental 实验面板。

output styles▸

Proactive（少问快干）/ Concise / Learning（留 TODO(human) 让你动手——防拐杖化官方工具）；自定义放 ~/.claude/output-styles/。

学生组合推荐：Context7（治编造 API）+ Playwright（网页验证）+ GitHub MCP（作品集）。

05 · 多代理 · 并行 · 云端

子代理的第一收益是上下文隔离（5000 行日志留在子代理，只回摘要），其次才是并行。独立子任务才并行，强耦合拆开只会打架。

CC：subagents + 编排族▸

定义：.claude/agents/*.md（frontmatter：description 决定自动委派、tools 限权、model、isolation: worktree）；调度：自动委派 / @agent-名 / claude --agent。

命令：/agents（自然语言建）、/background、/tasks、/subtask、/batch（5-30 单元 worktree 并行）、/loop、/schedule。

上限：嵌套 3 层 / 并发 20 / 每会话 200。

Codex：spawn_agent + Cloud▸

spawn_agent 上限 6；codex agents 多任务仪表盘；codex queue 给运行中会话投消息；/ps 看后台。

Codex Cloud：云端容器并行农场 → codex cloud list / apply / push 把产出拉回本地或推 PR。

worktree：本地并行的正确姿势▸

CC：claude -w 任务A [--tmux]（支持 PR URL）；Codex：/worktree / --worktree。3-5 个树各跑一会话，互不踩脚。

联动工作流

玩法做法
CC 规划 + Codex 云执行CC plan 出方案 → 丢 Codex Cloud 并行 3 变体 → cloud apply 拉回对比 → CC 定稿
同任务对照实验同起点两个 worktree，CC/Codex 各做一个任务，git diff 对比产出（§10 L7）
跨工具编排CC 经 codex mcp-server 把 Codex 当外援（§04）

电赛并行分工模板（视觉/控制/上位机三 worktree + 主会话当队长）见 08 章 MD。

06 · 审查 · 验证 · 自动化 · CI

Agent 会一本正经地错——产出必须闭环验证；无人值守必须权限收口 + 预算上限。

/code-review 多级审查▸

/code-review --max-findings 5；ultra=云端多代理深审（Pro/Max 每月 3 次免费）；--fix 顺手修。/simplify 找过度设计；/verify 真实构建运行观察；/security-review 公开仓库前必扫。

/review detached 审查面板▸

独立面板不打断主对话；模式：未提交改动 / vs base 分支 / 指定 commit / 自定义 prompt；审查规则可用 AGENTS.md 个性化；CLI 侧 codex review。

无头：claude -p▸
claude -p "..." --permission-mode auto --permission-prompts none --max-budget-usd 2

输出 --output-format json/stream-json；结构化 --json-schema；脚本场景推荐 --bare。管道用法：git diff | claude -p "typo linter"。

无头：codex exec▸
codex exec --json "..." | jq -c 'select(.type=="item.completed")'

--output-schema FILE 结构化输出（0.132.0）；-o FILE 存最后回复；codex exec resume --last 续跑；CI 用官方 openai/codex-action@v1。

联动：双工具互审（两模型盲区不同）；无头脚本 fallback：claude -p ... || codex exec ...。学生三连：交付前 code-review → verify → security-review。

📅 成长时间线（复利）▸

💰 成本与账号（2026-10 核查）▸

⚖️ 学术诚信与保密（红线）▸
