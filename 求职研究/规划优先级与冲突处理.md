# 规划优先级与冲突处理

本文件解决一个常见问题：**多份计划都写了"下一步"，究竟听谁的？** 生成每日、每周或阶段任务时，先按这里判断文档层级，不允许把旧计划中搁置的方向（如 ROS2、飞控、FPGA 或强化学习）自动叠加到当前计划。

## 文档优先级

从高到低依次为：

1. **最新明确决定与课程的真实期限：** 只影响明确提出的范围；课程任务有期限时优先，但不自动改写长期职业主线。
2. **当前学期执行计划：** 决定本学期阶段、时间预算和项目闸门。
3. **当前求职画像与岗位证据：** 个人筛选标准、岗位可得性与竞争矩阵及方向可得性统计。它们决定方向比例是否需要调整。
4. **大学整体规划、岗位地图和技术栈清单：** 用于解释长期方向，不能覆盖当前学期的阶段闸门。
5. **项目卡、能力矩阵、申请资料和专题手册：** 只在当前计划选中相应方向后提供做法，不自行产生任务。
6. **旧基线、历史日报和历史每日任务：** 只用于追溯当时判断，不得作为未来任务来源。

## 任务生成规则

1. 先确定当前处于学期计划的哪个阶段，再读取项目真实状态和课程期限。
2. 每天只设一个主要交付物和至多一个次要能力块；不能因为文档中出现过某技术就把它加入当天任务。
3. 主线冲刺期内，主线项目优先于暂存方向；只有自己主动恢复、课程期限，或主线项目有明确依赖时，才把暂存方向放回当天任务。
4. 新增 ROS2、FPGA、飞控、边缘部署、复杂多 Agent 或新的 AI/RL 项目前，必须写出触发证据：当前项目闸门、岗位样本或课程期限。没有触发证据就留在候选池。
5. 岗位标题多不等于容易拿到；只有两周样本中的原始页、在校生可投、高质量开放和城市分布支持时，才调整项目和投递比例。
6. 若两份文档冲突，以更高层级和更新时间较新的文件为准，并在任务中写明"忽略了哪份旧指令及原因"。
7. **断档恢复协议：** 每日任务断档超过 3 天时，不逐日补生成缺失日期的任务文件；直接按周复盘口径恢复——读取最后一次任务文件之后的实际产出，重算当前闸门位置，生成当天的任务，并在任务文件中注明断档天数。断档本身不构成重派旧任务的理由。

## 历史文件的边界

- 原始基线文件（最早的整体计划）不再直接调度，只作追溯。
- 口径变更前的历史日报与变更后的统计不直接混算。
- 每日总控中已过去日期的任务文件是历史执行记录；不能复制其中的旧主线作为未来默认模板。
