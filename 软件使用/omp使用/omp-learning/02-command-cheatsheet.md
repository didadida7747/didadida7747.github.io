# 02 - OMP 命令与操作速查

以下以当前 OMP 官方 README 为依据。终端界面快捷键、slash command、模型名称和配置字段更新较快，使用前以 `omp --help`、交互界面的 `/help` 和官方文档为准。

## 外部命令

| 目的 | 命令 | 说明 |
|---|---|---|
| 查看版本 | `omp --version` | 安装或更新后先核对实际版本 |
| 查看命令帮助 | `omp --help` | 当前版本的唯一可靠参数入口 |
| 进入交互式代理 | `omp` | 必须在目标项目目录启动 |
| 传入首轮问题 | `omp "先只读分析这个项目"` | 仍建议在提示中写明“不修改” |
| 启动 RPC 模式 | `omp --mode rpc` | 给其他程序通过标准输入输出驱动；进阶用途 |
| 启动 ACP 模式 | `omp acp` | 用于支持 ACP 的编辑器集成；先确认编辑器支持情况 |

不要凭别的教程猜测 `--yes`、`--dangerously-skip-permissions` 等参数是否存在或行为如何。高风险权限选项即使当前版本提供，也只应在可信仓库、明确范围、可回滚的任务中使用。

## 交互界面中的常用动作

| 目的 | 建议做法 |
|---|---|
| 查当前版本支持的功能 | 输入 `/help`，按界面给出的命令列表操作 |
| 配置或登录模型服务 | 按 `/help` 中的登录/模型入口和 [Providers 文档](https://omp.sh/docs/providers) 操作 |
| 切换模型或角色模型 | 先确认当前模型、费用和权限，再使用当前界面支持的选择方式 |
| 查看与压缩会话 | 从 `/help` 查询当前版本的会话和上下文命令；压缩后复核任务目标仍在上下文中 |
| 代码审查 | OMP README 提到 `/review`，但先用小改动试验，并人工核对 diff 与测试 |
| 子代理 | 只在任务可拆分且每个子任务都有清晰输出/边界时使用 |

## 配置文件与规则

官方 README 提到全局模型配置可位于 `~/.omp/agent/models.yml`，并且 OMP 能发现多种其他工具已有的规则、skills 与 MCP 配置。对 Windows 来说，`~` 通常对应你的用户目录，但具体路径和文件格式应以当前版本实际输出及官方文档为准。

实践建议：

- 先让现有项目的 `AGENTS.md`、README、测试命令成为唯一真实来源。
- 再引入一项 OMP 特性，并做一次可验收的测试。
- API Key 放在本机安全凭据位置；配置文件若含敏感内容，加入 `.gitignore` 并检查 `git status`。
- 不把全局模型配置复制到每个项目，不要把某个 relay 的地址或密钥当成通用教程。
