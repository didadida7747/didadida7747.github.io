# 第7章 进程与任务管理

> 学完这章，你能一眼看清"系统里现在都在跑什么"，能优雅地或强制地结束一个卡死的程序，还能让你的后端服务在终端关掉之后继续活着。

## 本章你将学会

- 理解什么是进程、PID、PPID、父子进程
- 用 `ps aux` 和 `ps -ef` 看清所有正在跑的程序
- 读懂 `top` / `htop` 的每一行，看懂 load average 什么意思
- 说清楚 `kill 15` 和 `kill 9` 的本质区别，什么时候该用哪个
- 用 `killall` / `pkill` 按名字杀进程
- 掌握前台后台、`&`、`jobs`、`fg`、`bg`、`Ctrl+Z`、`Ctrl+C`
- 用 `nohup` 和 `disown` 让进程脱离终端
- 用 `free -h`、`uptime`、`lsof -i :端口` 做基础体检

## 为什么需要它

你写完一个后端服务，跑起来，然后……终端一关，服务就没了。这是每个新手第一次部署都会撞的墙。更糟的情况：某个程序写崩了，把 CPU 吃满了，你想杀它都不知道杀哪个。再比如，启动一个端口被占用的服务，报错 `Address already in use`，你怎么知道是谁占着？

这一章就是教你当"系统的监工"：谁在跑、吃了多少资源、不听话怎么收拾。后端开发 80% 的线上问题，定位思路都是"先看进程"。

## 7.1 什么是进程

你写的程序（比如一个 `python app.py`）只是硬盘上的一个文件。当它被运行起来，操作系统给它分配内存、CPU 时间片、打开文件句柄……这个"跑起来的程序实例"就叫**进程（process）**。

每个进程有一个唯一编号，叫 **PID**（Process ID）。系统启动时第一个进程叫 `systemd`，PID 永远是 1。

进程不是凭空出现的，它是被另一个进程启动的。启动它的那个叫**父进程**，它的 PID 记在这个进程的 **PPID**（Parent PID）字段里。比如你在终端里敲 `python app.py`：你的 shell（bash）是父进程，`python` 是子进程。你把 shell 关了，子进程通常也会跟着收到信号死掉——这就是为什么"关掉终端服务就没了"。

```bash
$ echo $$
1234
```

`$$` 是 shell 内置变量，表示当前 shell 自己的 PID。记住这个号，待会儿有用。

## 7.2 `ps`：看一眼进程快照

`ps`（process status）给你一份"当前进程的快照"。它有两种经典用法，输出格式不一样但内容差不多：

```bash
$ ps aux
```

`aux` 三个选项拆开是：`a` 所有用户的进程、`u` 显示属主和详细信息、`x` 包括没有终端的后台进程。在 Linux 上这种 BSD 风格选项**前面没有短横线**。输出长这样：

```text
USER         PID  %CPU %MEM    VSZ   RSS TTY   STAT START   TIME COMMAND
root           1  0.0  0.2 168000 12000 ?     Ss   Oct12   0:05 /sbin/init
yourname    1234  0.0  0.3  18000 15000 pts/0 Ss   10:20   0:00 -bash
yourname    5678  5.0  1.5 920000 60000 pts/0 Sl   10:30   0:02 python app.py
yourname    9999  0.0  0.1  20000  3000 pts/0 R+   10:35   0:00 ps aux
```

逐字段解释：

| 字段 | 示例 | 含义 |
|---|---|---|
| USER | yourname | 进程属主 |
| PID | 5678 | 进程号，杀进程就靠它 |
| %CPU | 5.0 | 占用 CPU 百分比 |
| %MEM | 1.5 | 占用物理内存百分比 |
| VSZ | 920000 | 虚拟内存大小（KB），一般不看 |
| RSS | 60000 | **物理内存**占用（KB），这个才实在 |
| TTY | pts/0 | 在哪个终端上；`?` 表示没有终端（后台服务） |
| STAT | Sl | 进程状态，下面细讲 |
| START | 10:30 | 什么时候启动的 |
| TIME | 0:02 | 累计占用 CPU 时间 |
| COMMAND | python app.py | 启动命令 |

`STAT` 那一列的常见值：

| 状态 | 含义 |
|---|---|
| `R` | Running，正在跑 |
| `S` | Sleeping，睡了（在等事件，比如网络请求），大部分进程平时都是 S |
| `Z` | Zombie，僵尸进程（父进程没收尸，基本不用管） |
| `s`（小写） | 是会话首进程（终端里开的那个 shell） |
| `l`（小写） | 多线程 |
| `+` | 在前台进程组里 |

另一种 SysV 风格写法，**前面有短横线**：

```bash
$ ps -ef
UID          PID    PPID  C STIME TTY          TIME CMD
root           1       0  0 Oct12 ?        00:00:05 /sbin/init
yourname    1234       1  0 10:20 pts/0    00:00:00 -bash
yourname    5678    1234  5 10:30 pts/0    00:00:02 python app.py
```

和 `ps aux` 差不多，区别是它多列了 **PPID**（父进程 PID）——这个信息在排查"谁把谁拉起来的"时特别有用。

> 💡 **小技巧：`ps` 天生配合 `grep` 用。** 比如找你的 python 进程：
> ```bash
> $ ps aux | grep python
> ```
> 但这样会把 `grep python` 自己也列出来。想排除自己：
> ```bash
> $ ps aux | grep [p]ython
> ```
> 原理是 `[p]ython` 这个正则能匹配 `python`，但匹配不到字符串 `grep [p]ython` 本身。

## 7.3 `top` 与 `htop`：实时监控

`ps` 是快照，`top` 是动态实时刷新的视图：

```bash
$ top
```

进入之后界面大概长这样：

```text
top - 10:40:00 up  2:20,  1 user,  load average: 0.25, 0.18, 0.10
Tasks: 120 total,   1 running, 119 sleeping,   0 stopped,   0 zombie
%Cpu(s):  5.0 us,  2.0 sy,  0.0 ni, 92.5 id,  0.0 wa,  0.0 hi,  0.5 si
MiB Mem :   3900.0 total,   2100.0 free,    800.0 used,   1000.0 buff/cache
MiB Swap:   1024.0 total,   1024.0 free,      0.0 used.

PID USER      PR  NI    VIRT    RES  %CPU %MEM  TIME+ COMMAND
5678 yourname  20   0  920.0m  60.0m  5.0  1.5   0:02.30 python
```

逐行讲：

- **第一行 `top - ... load average: 0.25, 0.18, 0.10`**：这是**负载均值**，分别是过去 1 分钟、5 分钟、15 分钟系统上"等着跑"的进程数。怎么判断高不高？看你 CPU 有几个核——`nproc` 能查。负载数值 < CPU 核数说明很闲；持续 > 核数说明忙不过来。比如你 4 核 CPU，load 2.0 完全没事；1 核 CPU，load 2.0 就说明有两个进程排队等。
- **第二行 Tasks**：总进程数、几个在跑、几个在睡、几个僵尸。
- **第三行 %Cpu(s)**：CPU 使用情况。`us` 用户程序占多少，`sy` 内核占多少，`id` 空闲百分比。你只需要盯着 `id`——它要是经常个位数，CPU 就满了。
- **第四五行 Mem / Swap**：物理内存和交换分区使用情况（下一章细讲 swap）。
- **下面进程列表**：默认按 CPU 占用排序。在 `top` 里按 `P` 按 CPU 排，按 `M` 按内存排，按 `q` 退出。

### htop：更好看的 top

`top` 是系统自带，但界面古老。**htop** 是它的现代替代品，彩色、有鼠标、能直接看进程树：

```bash
$ sudo apt install htop
$ htop
```

htop 里几个常用键：`F6` 选排序字段，`F9` 杀进程（会让你选信号），`q` 退出。不强制用 htop，但装上你就回不去了。

> 📌 **注意：`uptime` 命令就是把 top 第一行单独拎出来：**
> ```bash
> $ uptime
>  10:40:00 up 2 days,  3:20,  1 user,  load average: 0.25, 0.18, 0.10
> ```
> 以后看服务器一眼负载，敲这个最快。

## 7.4 `kill`：给进程发信号

"kill 这个进程"这个说法其实不准确——`kill` 的本质是**给进程发一个信号（signal）**。信号是操作系统给程序的短消息，比如"你该退出了""你被按下了 Ctrl+C""你家窗口大小变了"。

最常用的两个信号：

| 信号编号 | 名字 | 含义 | 程序能忽略吗 |
|---|---|---|---|
| 15 | SIGTERM | "请你优雅地退出"（默认信号） | 能——程序可以捕获它，先保存现场再退 |
| 9 | SIGKILL | "立刻消失，不许反驳" | **不能**——内核直接干掉，进程没机会清理现场 |

```bash
# 默认发 15（SIGTERM），让进程自己收拾东西退出
$ kill 5678

# 实在不听话，发 9
$ kill -9 5678
```

> ⚠️ **警告：`kill -9` 是核武器，不是常规武器。** 它不给程序任何保存数据、关闭文件、释放锁的机会。数据库被 `kill -9` 可能直接损坏数据；你自己写的程序被 `kill -9` 可能留下临时文件、端口没释放。**正确顺序永远是：先 `kill 15`，等几秒，没死再 `kill -9`。**

两个按名字杀的兄弟：

```bash
# 杀掉所有叫 python 的进程（给它们发 15）
$ killall python

# 按名字模式杀，比如杀掉所有名字里带 "node" 的
$ pkill node

# pkill 最常用：杀占用某端口的进程，配合 lsof（后面讲）
$ pkill -f "python app.py"
```

| 命令 | 区别 |
|---|---|
| `kill PID` | 精确杀一个进程号 |
| `killall 名字` | 杀所有叫这个名字的进程 |
| `pkill 模式` | 按名字模式杀，`-f` 可以匹配完整命令行 |

> 💡 **小技巧：你在终端里按 `Ctrl+C`，本质就是给前台进程发了一个 SIGINT（信号 2）。** 所以"按 Ctrl+C 退不出来"的程序，你开另一个终端 `kill -9` 它就行。

## 7.5 前台、后台与作业控制

这一节是后端部署的命根子。你在终端里跑 `python app.py`，终端就被它占住了，你啥也干不了。想一边跑服务一边敲别的命令？就得把它放到后台。

### `&`：扔到后台

```bash
$ python app.py &
[1] 5678
```

`[1]` 是**作业号**（job number），`5678` 是 PID。这个 `python` 现在在后台跑着，终端回来了，你能继续敲命令。但注意——它的输出还是会打印到终端上，而且你一旦关掉终端，它还是会死。

### `jobs` / `fg` / `bg` / `Ctrl+Z`

先把这个组合讲清楚：

```bash
$ sleep 1000
```

`sleep 1000` 会在前台睡 1000 秒，啥也干不了。现在：

1. 按 `Ctrl+Z` —— 把前台进程**暂停**，扔回后台：
   ```text
   ^Z
   [1]+  Stopped                 sleep 1000
   ```
2. `jobs` 看当前终端有哪些作业：
   ```bash
   $ jobs
   [1]+  Stopped                 sleep 1000
   ```
3. `bg %1` 让这个暂停的作业在后台**继续跑**：
   ```bash
   $ bg %1
   [1]+ sleep 1000 &
   ```
4. `fg %1` 再把它拎回前台：
   ```bash
   $ fg %1
   sleep 1000
   ```
5. 现在它在前台，你想终止它，按 `Ctrl+C`。

> 📌 **注意：`Ctrl+Z` 不是杀掉，是暂停。** 很多新手按了 Ctrl+Z 以为程序结束了，关终端走人——结果这个进程还在系统里挂着（虽然是暂停状态）。不想要它了，`fg` 拉回来再 `Ctrl+C`，或者直接 `kill %1`。

### `nohup` 与 `disown`：让进程不怕终端关闭

前面说过，子进程会跟着父进程（终端）死。原因是终端关闭时会给所有前台/后台作业发 SIGHUP（hang up，挂起）信号。想让它忽略这个信号？用 `nohup`：

```bash
$ nohup python app.py &
[1] 5678
nohup: ignoring input and appending output to 'nohup.out'
```

`nohup` 让程序忽略 SIGHUP，输出自动写到当前目录的 `nohup.out`。现在你关掉这个终端、甚至退出登录，`python` 都会继续跑。

另一个办法是 `disown`：

```bash
$ python app.py &
$ disown
```

`disown` 把这个作业从 shell 的作业列表里**摘除**，shell 关掉时就不会给它发 SIGHUP 了。区别是 `disown` 是"先启动再摘"，`nohup` 是"启动时就包裹一层"。

> 💡 **小技巧：以后部署后端服务，真正的做法不是 nohup——而是用 systemd 把它注册成服务（第 13 章讲）。** systemd 帮你管开机自启、崩溃自动重启、日志收集，比 nohup 强一个量级。现在你先知道 nohup 这个应急手段就行。

## 7.6 内存与负载：`free -h`

```bash
$ free -h
               total        used        free      shared  buff/cache   available
Mem:           3.8Gi       1.2Gi       1.0Gi       200Mi       1.6Gi       2.3Gi
Swap:          1.0Gi          0B       1.0Gi
```

重点看 **`available`** 那一列——它才是"现在还能给新程序用多少内存"。别被 `free` 那一列骗了，Linux 会把空闲内存拿来做磁盘缓存（`buff/cache`），这部分需要时立刻能让出来。所以"free 很少"不等于内存不够，看 `available`。

Swap 是磁盘上的一块空间，内存真不够用时系统会把暂时不用的内存页换出去。Swap 用得很多说明物理内存吃紧——在 WSL2 里尤其要注意，因为换出去到磁盘很慢。

## 7.7 `lsof`：谁占着这个端口

后端开发每天遇到的报错：

```text
OSError: [Errno 98] Address already in use
```

"端口被占了"。谁占的？用 `lsof`（list open files）查：

```bash
$ sudo lsof -i :8000
COMMAND  PID USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
python  5678 yourname    3u  IPv4  12345      0t0  TCP *:8000 (LISTEN)
```

看到了，PID 5678 的 python 占着 8000 端口。不想让它跑了就 `kill 5678`。

> 📌 **注意：WSL2 里 `lsof` 可能没装。** 没有就 `sudo apt install lsof`。后面第 10 章讲网络时你还会用另一个命令 `ss -tlnp` 干同样的事。

## 7.8 `/proc`：内核暴露出来的信息窗口

你第 3 章见过 `/proc`，知道它里面没有真实文件——是内核实时拼出来的。这里挑两个常用的：

```bash
# 看某个进程的详细状态，把 5678 换成实际 PID
$ cat /proc/5678/status
$ ls -l /proc/5678/cwd    # 这个进程当前在哪个目录
$ cat /proc/cpuinfo | grep "model name"   # CPU 型号
$ cat /proc/meminfo       # 内存信息（free 命令就是读它）
```

排障手册（第 15 章）里你会经常回来翻 `/proc`。现在只要知道"进程的一切都在 `/proc/<PID>/` 里"就行。

## 7.9 两个预告

**`systemctl`** 是现代 Linux 管理服务的命令（启动/停止/开机自启/查日志），它管的就是 PID 1 那个 `systemd`。这东西内容很多，我们放到**第 13 章「服务与部署入门」**系统讲。现在你只要知道：以后想"让我的 python 服务开机自启、崩了自动拉起"，不是靠 nohup，是靠 systemd。

**`crontab`** 是定时任务命令（"每天凌晨 3 点跑一次备份脚本"）。语法有点坑，我们放到**第 11 章 Shell 脚本编程**里和备份脚本一起讲。

## ⚠️ 危险操作与安全红线

- **`kill -9` 最后手段，不是第一反应。** 先 TERM，等 5 秒，再 KILL。
- **`kill -9 -1` 会杀掉你能杀的所有进程（包括自己）。** 别乱敲。
- **`pkill -f` 匹配的是完整命令行。** 想清楚再按回车，`pkill -f python` 会把你 VS Code 里跑的所有 python 都干掉。
- **`kill 0` 或对 PID 1 操作** 会让系统直接挂掉。PID 1 是 systemd，别碰它。
- **`Ctrl+Z` 之后别忘了收拾。** 留一堆 Stopped 作业在后台，重启终端才发现。
- **不要在生产服务器上随手 `kill -9` 数据库进程。** 可能要你赔数据。

## 常见报错与排查

| 现象 | 原因 | 解决 |
|---|---|---|
| `Address already in use` | 端口被别的进程占着 | `sudo lsof -i :端口` 找到 PID，kill 掉，或换个端口 |
| `kill: (PID) - No such process` | 进程已经死了 | 它已经自己退了，不用管 |
| `kill: Operation not permitted` | 这个进程是别人/root 的 | 前面加 `sudo` |
| `Ctrl+C` 按了没反应 | 程序卡死在系统调用里 | 开另一个终端 `kill -9 PID` |
| 关终端后服务就死 | 没用 nohup/systemd | 用 `nohup ... &`，或第 13 章学 systemd |
| `load average` 很高但 CPU 看着闲 | 多半是 I/O 等待，不是 CPU 瓶颈 | `top` 里看 `%wa` 那一列；磁盘慢就查磁盘 |
| `lsof: command not found` | 没装 | `sudo apt install lsof` |

## 动手练习

1. 开两个终端。在终端 A 里跑 `sleep 600`，在终端 B 里用 `ps aux | grep sleep` 找到它的 PID。
2. 在终端 B 里 `kill <PID>`（信号 15），切回终端 A 看 sleep 是不是自己退了。
3. 重新跑 `sleep 600 &`，然后 `jobs`、`kill %1`，观察作业消失。
4. 跑 `python3 -m http.server 8000 &`，另开终端 `lsof -i :8000` 确认它占着端口，然后 `kill` 掉它。
5. 跑 `nohup sleep 1000 &`，然后**关掉这个 WSL 终端窗口**，重新打开一个，`ps aux | grep sleep` 看它还在不在。对比一下不加 nohup 会怎样。
6. 敲 `uptime`、`free -h`、`nproc`，对着自己机器解释一下 load average 高不高、内存还剩多少。

## 本章小结

| 命令/概念 | 一句话作用 |
|---|---|
| `ps aux` / `ps -ef` | 看进程快照（后者多一列 PPID） |
| `top` / `htop` | 实时监控（htop 更好看） |
| `uptime` | 看负载均值和运行时间 |
| `free -h` | 看内存，盯 `available` 列 |
| `kill PID` / `kill -9 PID` | 发 TERM / KILL 信号 |
| `killall 名` / `pkill 模式` | 按名字杀 |
| `命令 &` | 扔后台 |
| `jobs` / `fg %1` / `bg %1` | 看作业 / 拎回前台 / 后台继续 |
| `Ctrl+Z` / `Ctrl+C` | 暂停作业 / 终止前台进程 |
| `nohup 命令 &` | 关掉终端也不死 |
| `lsof -i :端口` | 查谁占着端口 |
