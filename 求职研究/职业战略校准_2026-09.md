# 职业战略校准：一次方向选择的决策范例

适用阶段：大二上至 2027 年寒假。本文是一份方向选择的解释层范例；具体任务由[四周验证计划](./四周验证计划_2026-09.md)这类短期计划生成。

## 一、最新决定

- **就业取向：** 当前按本科毕业直接就业准备；是否读研保留到获得课程、项目、实习和岗位反馈后再判断。
- **核心诉求：** 收入与成长优先，同时寻找自己愿意长期投入的工作内容；不再为了“发挥专业优势”强迫自己选择通信、射频、FPGA 或嵌入式。
- **近期目标：** 2027 年寒假前完成一次有效方向收敛、一个可复现的主项目、一页简历和第一轮真实申请，争取获得实习、助研或团队项目协作经历。
- **方法：** 用短周期、同一验收尺度测试后端/系统开发、音视频工程、AI 工程服务三个相邻方向；9 月底只确定下一阶段主线，不决定终身职业。

## 二、对 Claude 方案的判断

### 值得保留

1. **先试再选。** 当前缺的是实际开发体验，不是更多职业名词；限时实验比根据想象下注更可靠。
2. **实习和真实协作优先。** 能读代码、交付模块、接受评审的经历，通常比多个教程项目更能证明工程能力。
3. **一个项目讲深。** 项目要能说明问题、取舍、个人贡献、测试、失败和改进，不能只列技术栈。
4. **利用学校资源。** 校友、实验室、就业平台和同学网络是获取信息与机会的渠道优势，应主动使用。

### 必须修正

| 原建议 | 问题 | 修正口径 |
| --- | --- | --- |
| 以“避开双非”为选方向标准 | 招聘不是按学校层次分隔的赛道；学校只能提高部分筛选和资源概率 | 选择“自己愿意做、岗位存在、本科可进入、能形成证据”的方向 |
| 给出确定的应届和五年薪资区间 | 城市、公司、级别、年份和统计口径不明，不能作为可靠决策数据 | 收入只作为方向维度之一，以真实岗位、校友访谈和自己拿到的面试/offer 数据校准 |
| 本科算法岗“基本没戏” | 过度绝对；工程型算法/应用算法存在本科入口，但研究型岗位门槛确实高 | 寒假不主投研究算法；有实验室、竞赛或可复现实验后再升级 |
| 一周做分布式 KV，随后做 Kafka+Raft | 对当前基础和时间预算过大，容易得到跟做代码而非可信能力 | 先做单机服务、持久化、并发、故障和基准测试，再按岗位需求逐层增加分布式内容 |
| 做实时美颜 SDK、百人对战且直接写性能数字 | 工程量过大，指标若非自己实测会变成简历风险 | 音视频先做可复现转码/处理管线；任何性能数字必须附环境、输入和测量方法 |
| 黑客松“参加即可写大厂名” | 单纯参与信号弱，容易给人借品牌包装的印象 | 只有入选、获奖，或有可公开交付且个人贡献清楚时才作为独立简历项 |
| 文档 PR 作为高价值开源贡献 | 可学习协作流程，但技术筛选信号有限 | 优先做与主项目相关的复现、测试、bug 修复或小功能；是否合并和技术内容比项目名更重要 |
| 9-12 月每周投入 45 小时、刷 200 题、海投 100 家 | 与已确认的每周 20-23 小时总预算冲突，且容易牺牲课程与申请质量 | 课外职业投入 9-11 小时；寒假前 30-40 道复盘题、20-30 次定向申请/联系 |

## 三、方向定位

### 1. 主候选：后端/系统开发

近期用“后端/系统开发”作为求职标签，而不是直接自称“基础架构”。本科实习入口更多来自服务端、平台工具、数据处理和系统开发；进入后再用并发、网络、存储、性能与可靠性逐步向基础架构靠近。

最低证据：一个有持久化、输入校验、幂等/重试、日志、测试和基准数据的服务；能解释一次故障定位和一次设计取舍。

### 2. 差异化候选：音视频工程

该方向兼有软件工程、C/C++、性能和部分信号处理门槛，适合用低成本实验判断兴趣。第一阶段不做播放器内核、美颜 SDK 或 WebRTC 全栈，只验证自己是否愿意处理格式、编解码参数、管线、性能和兼容性问题。

最低证据：一条可批处理的 FFmpeg 媒体管线，包含元数据探测、参数预设、错误处理、测试样本和不同设置下的质量/速度/体积对比。

### 3. 邻接候选：AI 工程服务

Agent 不再是 9 月唯一主线，但现有设想可以作为一次软件工程实验。价值来自数据、检索、引用、拒答、评测、接口和异常处理，而非“调用了大模型”。如果对这些工程环节有持续兴趣，可并入后端主线或进一步观察 AI 平台/推理服务。

最低证据：受限资料问答 CLI，带可定位引用、正确拒答、至少 10 条固定样例和失败分类。

### 4. 暂缓方向

- 嵌入式、通信、射频、FPGA：若已明确缺少兴趣，不再作为默认学习或主投方向；已有证据保留。
- 研究型 CV/NLP/推荐/RL：寒假第一段不主投；以课程任务、实验室机会和可复现实验作为重新评估条件。
- 游戏客户端：并非否定其收入或前景，而是当前会引入 C#/Unity/UE 等独立技术栈；没有明确兴趣证据前，不挤占本轮三个实验。

## 四、“学历优势”的正确用法

学校品牌是概率放大器，不是岗位护城河。应把它转化为四种实际动作：

1. 用课程成绩和基础课表现通过本科筛选，并保留保研/读研选择权。
2. 每月完成 2-3 次校友、实验室或技术社团信息访谈，询问真实工作、招聘门槛和可参与任务。
3. 优先获取有评审反馈、团队协作和真实用户的项目机会，而不是只做孤立 demo。
4. 用校内竞赛和企业活动寻找队友、评审与机会；不把“参加过”本身当作能力证明。

## 五、简历资产优先级

| 层级 | 资产 | 进入简历的门槛 |
| --- | --- | --- |
| S | 有真实代码任务的实习、助研、团队项目 | 能说明自己负责的模块、评审/协作、测试和结果 |
| A | 可复现的深度项目、技术型开源贡献、高含金量竞赛结果 | 有代码、运行入口、测量数据、失败记录和第三方反馈 |
| B | 黑客松成品、校级竞赛获奖、课程项目 | 有公开交付或奖项，且个人贡献可核验 |
| C | 参与证明、教程复现、文档 PR、刷题数量 | 只作为学习记录；通常不单独占简历条目 |

参加竞赛、黑客松或开源任务前必须同时满足：与当前主线相关；能产生代码/数据/评审证据；两周内可形成最小交付，或明确替代同等项目时间。仅为凑名称的活动不参加。

## 六、寒假前成功标准

截至 2027 年寒假，优先级从高到低为：

1. 课程不失守，保留就业和读研两种选择。
2. 选定一个主投方向和一个相邻备选；选择依据包含开发体验、岗位样本和外部反馈。
3. 完成一个陌生人可复现、自己可讲 10-15 分钟的主项目。
4. 完成一页简历、两个岗位版本和 20-30 次定向申请/团队联系。
5. 完成 30-40 道基础算法题并二刷 70%；不追逐题量数字。
6. 至少形成一项第三方信号：实习/助研/协作、技术 PR 合并、竞赛获奖/入选、或真实用户反馈。没有合适机会时不强行凑项。

“拿到实习 offer”是冲刺目标，不是唯一成功标准。寒假净到岗约 4-6 周，许多企业日常实习要求连续 3 个月以上，因此同时接受短期协作、实验室任务、学期内远程/每周到岗和大二暑期候选。

## 七、方向决策规则

9 月底按七项各 1-5 分评分，并为每项附一条证据：主动投入、受挫耐受、学习速度、成果成就感、岗位供给、本科可进入性、收入/成长代理信号。收入代理信号只允许来自可追溯 JD、校友访谈或真实面试反馈。

- 最高方向至少比第二名高 3 分，且项目完成度达到最低证据线：升级为 10-12 月主线。
- 分差不足 3 分：选择岗位供给更广、公共底座复用更多的后端/系统开发作为默认主线，另一个方向每两周保留 2 小时验证。
- 三个方向均低于 21/35：不硬选，使用 10 月前两周补一次网络安全、客户端或实验室真实任务的低成本访谈/实验。
- 任何方向不得仅凭薪资传闻、学校标签或一段顺利教程升级。
