# 02 · 上下文 · 会话 · 记忆：Agent 的工作记忆怎么管

> 本域命令约 27 条。七段式：①概念 → ②CC 详解 → ③Codex 详解 → ④记忆体系与对照 → ⑤联动迁移 → ⑥学生视角 → ⑦验收

---

## 2.1 本域解决什么问题（工具无关）

- **上下文窗口经济学**：模型的"工作记忆"有限且按 token 计费。塞太满会变贵变笨（注意力稀释），塞太少它不知道项目背景。上下文管理的本质是**在该出现的时候让该在的东西出现**。
- **会话是资产**：一次课设/实验的对话记录含大量决策依据，丢了就要重新对齐。会话管理（命名、恢复、分叉、导出）就是把对话变成可复用资产。
- **记忆是长期规则**：构建命令、代码风格、禁区这类"每轮都成立"的事实，应该沉淀到记忆文件里自动加载，而不是每次重说。

## 2.2 Claude Code 命令详解（交互层 + 模型层 + 上下文层）

### 卡片：高频逐条

#### `/clear` — 清空上下文开新会话（别名 `/reset` `/new`）
- **作用**：丢弃当前对话上下文，从干净状态开始；可加名字给旧会话打标签方便 `/resume` 找回。
- **适用场景**：切换到完全无关的新任务；当前会话已被压缩多次、"记忆"很糊时，不如 /clear 后靠记忆文件和计划文档重启。
- **示例**：
```text
/clear 课设-信号系统
```
- **坑**：比 /compact 更彻底也更"失忆"——任务进行中别乱用；重要思路先 /export 或写进文件。

#### `/compact [指示]` — 手动压缩对话为摘要
- **作用**：把历史对话浓缩成摘要释放窗口；可带指示指定保留重点。
- **适用场景**：上下文告急但不想丢任务连续性；完成一个里程碑后主动压。
- **示例**：
```text
/compact 保留当前滤波器参数的修改思路、已跑通的测试结果和剩余 TODO，实现细节可压缩
```
- **坑**：压缩必然失真——把关键结论提前写进文件（或 CLAUDE.md）再压；社区共识是上下文用到 60-70% 就主动压，别等爆。

#### `/context [all]` — 上下文占用可视化诊断
- **作用**：彩色网格展示 system prompt / MCP / 记忆文件 / 对话各占多少 token，并给优化建议。
- **适用场景**：感觉"它变笨了"、响应变慢变贵时，先做体检；配置了 ZCF/MCP 后检查谁偷吃了上下文。
- **示例**：
```text
/context
```
- **坑**：MCP 工具定义是大户——不常用的 server 摘掉；`all` 查看完整明细。

#### `/rewind` — 回退到检查点（别名 `/checkpoint` `/undo`）
- **作用**：把**对话和/或代码**回退到之前某次提问前的状态（空输入时双击 Esc 也进此菜单）。每轮自动快照，每会话保留最近 100 个，随会话持久化。
- **适用场景**：Agent 改砸了想反悔；想对同一问题换种问法（只回退对话）；想保留代码只撤对话。
- **示例**：
```text
/rewind
```
- **坑**：只快照 Claude 的文件工具改动——**纯 Bash 命令产生的改动、你手工的编辑、子代理的多数编辑不在覆盖范围**；约 30 天后清理（`cleanupPeriodDays` 可调）；官方明确"不能替代 git"。

#### `/resume [会话]` — 恢复历史会话（别名 `/continue`）
- **作用**：按 ID/名字打开会话选择器继续干活；v2.1.285 起还能附加到正在运行的后台会话。
- **适用场景**：昨天课设写到一半；多个课程/项目并行时靠命名快速切换。
- **示例**：
```text
/resume 课设-信号系统
```
- **坑**：恢复的是当时的上下文快照，期间代码若被别的会话改过要先对齐。

#### `/branch [名字]` — 从当前位置分叉会话副本
- **作用**：复制当前会话状态成新分支并切入，原会话仍可 `/resume`。
- **适用场景**："我想试试激进方案，但不想弄脏当前进度"——分叉出去试错，失败就回原会话。
- **示例**：
```text
/branch 尝试-IIR方案
```
- **坑**：与 /rewind 的区别：rewind 是回退，branch 是保留两条时间线；分叉出的分支各自独立演化。

#### `/fork [提示]` — 把对话复制成后台会话
- **作用**：当前会话继续工作，同时把副本丢到后台带着提示跑（v2.1.25+ 缓存保留，成本低）。
- **适用场景**：让后台副本去调研/写文档，前台继续改代码。
- **示例**：
```text
/fork 调研三种窗函数的旁瓣衰减对比，输出成 markdown
```
- **坑**：后台会话在 `/tasks` 里看；结果要主动要回来。

#### `/recap` — 一行式会话摘要
- **作用**：生成当前会话的极简摘要（离开 3 分钟以上回来也会自动生成）。
- **适用场景**：隔了几天回会话快速热身；给同学讲"我们干到哪了"。
- **示例**：
```text
/recap
```

#### `/export [文件名]` — 导出对话为纯文本
- **作用**：把对话导出成文件。
- **适用场景**：把"思路讨论"沉淀成课程报告素材/学习笔记；备份重要决策过程。
- **示例**：
```text
/export 信号系统-方案讨论-1024.md
```

#### `/goal [条件|clear]` — 设定跨轮次长期目标
- **作用**：设定一个 Claude 持续朝向工作的目标，跨多轮生效。
- **适用场景**：跑数小时的数据实验、重构长任务——防止多轮后"忘了初心"。
- **示例**：
```text
/goal 所有单元测试通过且覆盖率不低于 80%
```

#### `/memory` — 编辑各级记忆文件
- **作用**：打开各级 CLAUDE.md 编辑、开关 auto memory、查看已沉淀的记忆条目。
- **适用场景**：项目刚开始时写入构建/测试命令；发现它反复犯同一个错时写进记忆。
- **示例**：
```text
/memory
```
- **坑**：CLAUDE.md 是"软约束"（建议），会被忽略——真正的红线用 hooks（§03）。

#### `/init` — 生成 CLAUDE.md
- **作用**：扫描仓库生成项目记忆文件初稿；检测到 Codex/Gemini 配置时会推荐 `/import`。
- **适用场景**：新项目第一次用；克隆了别人的仓库想让它快速理解。
- **示例**：
```text
/init
```

#### `/import [codex|gemini|cursor]` — 从其他编码代理导入配置
- **作用**：把别的工具的指令/配置导入成 CLAUDE.md 体系。
- **适用场景**：你 .codex 里已有积累，想让 CC 也享受同一套规则（联动重点，见 §2.5）。
- **示例**：
```text
/import codex
```

#### `/model [模型]` — 切换模型
- **作用**：切换默认模型（方向键还能调 reasoning effort；`s` 仅本会话生效）。
- **适用场景**：重活用 Opus 级，轻活用 Sonnet/Haiku 级省钱；`-p` 无头模式指定模型需 v2.1.205+。
- **示例**：
```text
/model sonnet
```

#### `/effort [级别]` — 推理力度（low/medium/high/xhigh/max/auto/ultracode）
- **作用**：控制思考深度（v2.1.76+）。auto 让框架自己判断。
- **适用场景**：竞赛压轴 debug 用 high；批量跑重复小任务用 low 省钱。
- **示例**：
```text
/effort auto
```

#### `/fast [on|off]`、`/advisor [模型|off]` — 快速模式与第二模型顾问
- **作用**：`/fast` 切换 fast mode（Opus 4.6 起，即时生效）；`/advisor` 启用一个第二模型作为"顾问工具"，主模型干活时可以问它。
- **适用场景**：fast 适合节奏快的迭代；advisor 适合"让另一个模型盯着我这个模型的方案找茬"。
- **坑**：advisor 是 v2.1.x 新能力，行为以 `/help` 实测为准。

## 2.3 Codex 命令详解

### 卡片：高频逐条

#### `/new [名字]` — 开新对话（别名 `/clear`）
- **作用**：清空上下文开新线程；0.146.0 起支持命名并置顶。
- **示例**：
```text
/new 课设-信号系统
```
- **坑**：与 CC 的 /clear 同位；命名习惯两边保持一致，方便管理。

#### `/compact` — 手动压缩上下文
- **作用**：压缩对话摘要释放窗口；GPT-5.1-Codex-Max 起为原生一等公民（native compaction）。
- **示例**：
```text
/compact
```
- **坑**：同 CC——先落盘关键结论再压。

#### `/fork` — 从当前对话分叉新分支
- **作用**：分叉出副本继续；保留草稿与排队输入；0.146.0 支持从分页历史中分叉、临时分叉。
- **适用场景**：同 CC /branch 的"试错不弄脏主线"场景。
- **示例**：
```text
/fork
```

#### `/undo` — 撤销 Codex 对工作区的文件改动
- **作用**：回滚 Codex 做的**文件改动**（不回滚对话本身）。
- **适用场景**：改砸了先 undo 文件，再在原对话里换个说法让它重做（保留它对任务的"理解"）。
- **坑**：与 CC /rewind 的区别——Codex 的 undo 只管代码不管对话；CC 两样都能退。

#### `/resume` — 打开会话恢复选择器
- **作用**：按创建/更新时间排序浏览并恢复历史会话（0.99.0），可归档/恢复（0.148.0）；0.65.0 起成为斜杠命令。
- **示例**：
```text
/resume
```

#### `/side` — 侧聊：快速提问不打断主任务
- **作用**：开一个侧边小会话问问题，主任务上下文不被污染（0.122.0）。
- **适用场景**：干活中途想问"MATLAB 里这段报错啥意思"——问完就关，主对话干干净净。
- **示例**：
```text
/side Python 里 np.convolve 和 scipy.signal.fftconvolve 该用哪个？
```
- **对应物**：CC 的 `/btw`。

#### `/goal [目标]` — 长期目标
- **作用**：设定/暂停/恢复跨轮次目标（0.128.0 持久化，0.133.0 默认启用）。
- **示例**：
```text
/goal 本周内把数据结构课设的 AVL 树部分做完并通过全部测试
```

#### `/title [标题]`、`/rename` — 会话命名
- **作用**：`/title` 手动改名（0.128.0）；`/rename` 自动建议标题（0.150.0）。
- **示例**：
```text
/title 电赛-视觉组-上位机
```

#### `/export` — 导出对话
- **作用**：导出 Markdown 到剪贴板或文件（0.148.0）。
- **示例**：
```text
/export
```

#### `/archive`、`/delete` — 会话归档与删除
- **作用**：归档旧会话（0.136.0）；删除（0.140.0，带确认并清理子代理）。
- **坑**：delete 不可恢复，课设资料先 /export 再删。

#### `/init` — 生成/完善 AGENTS.md
- **作用**：扫描仓库生成项目指令文件，配合"Customize instructions"流程。
- **示例**：
```text
/init
```

#### `/import` — 迁移其他工具配置
- **作用**：0.140.0 引入，0.145.0 起可从 **Cursor、Claude Code** 迁移设置、MCP、插件、会话与记忆。
- **示例**：
```text
/import
```

#### `/model [模型]` — 切换模型与推理力度
- **作用**：0.164.0 起支持内联参数直接设置 model、reasoning effort、speed；TUI 里还有 `Alt+,`/`Alt+.` 快调 effort。
- **示例**：
```text
/model gpt-6.1-sol xhigh
```
- **坑**：默认模型已是 GPT-6.1 Sol（0.161.0 起）；自定义供应商时注意 `wire_api` 匹配（§07 CLI 参数表）。

#### `/personality` — 助手性格
- **作用**：切换回答风格（0.94.0 转稳定，默认 friendly）；对应 CC 的 output styles（但 CC 更丰富，见 §04）。

## 2.4 记忆体系对照（本域的重头戏）

### CLAUDE.md 体系（Claude Code）

| 层级 | 位置 | 用途 |
|---|---|---|
| ① 企业策略 | `C:\Program Files\ClaudeCode\CLAUDE.md`（Windows） | 企业管控，你用不到 |
| ② 用户级 | `~/.claude/CLAUDE.md`（+`~/.claude/rules/`） | 你的个人偏好：语言、代码风格，跨项目生效 |
| ③ 项目级 | `./CLAUDE.md` 或 `./.claude/CLAUDE.md` | 项目构建/测试命令、架构约定；**无 CLAUDE.md 时自动回退读 AGENTS.md**（`/config` 可设两者同读） |
| ④ 本地私有 | `./CLAUDE.local.md`（gitignore） | 不想提交给队友的个人配置 |
| ⑤ Auto memory | `~/.claude/projects/<项目>/memory/` | Claude 自动写入的 MEMORY.md 索引 + user/feedback/project/reference 四类主题文件（默认本地开启） |

- **imports 语法**：CLAUDE.md 里写 `@path/to/file.md` 引入其他文件（最深 4 跳；含空格路径用 `\ `；行首反引号可阻止导入）。
- **条件规则**：`.claude/rules/*.md` 无 frontmatter = 每轮加载；带 `paths:` frontmatter = 碰到匹配文件才加载（省上下文）。
- **实践红线**：单文件 < 200 行；写具体可验证的（"测试用 `pytest -q`"而非"注意质量"）；定期 `/doctor prompt-audit` 审计过时写法。

### AGENTS.md 体系（Codex）

- **发现机制**：从当前目录向上逐级找到仓库根，最后回退全局 `~/.codex/AGENTS.md`。
- **就近覆盖**：多个文件同时适用时，**离被编辑文件更近的优先**——天然支持 monorepo/多课程目录各自设规则。
- **最佳写法**（官方口径）：短小、可执行——仓库结构、构建/测试命令、规范、约束四要素。

```text
<!-- AGENTS.md 示例（信号系统课设仓库根目录） -->
# 项目
数字信号处理课设：FIR/IIR 滤波器设计与验证（MATLAB + Python 双实现）

# 构建与测试
- Python 端：pytest -q（测试在 tests/）
- MATLAB 端：matlab -batch "run_all_tests"

# 约定
- 所有滤波器设计函数必须附频率响应验证图
- 不修改 data/ 原始数据
- 提交信息用中文，格式：课设: <改动摘要>
```

### 两套体系正面对照

| 能力 | Claude Code | Codex | 备注 |
|---|---|---|---|
| 项目记忆文件 | CLAUDE.md（读不到时回退 AGENTS.md） | AGENTS.md | **写一份 AGENTS.md，两边通吃** |
| 层级 | 企业→用户→项目→本地→auto memory | 全局→仓库根→逐级子目录 | Codex 就近覆盖，CC 就近叠加（更具体者胜） |
| 条件加载 | `.claude/rules/` + paths frontmatter | 无对应（靠目录拆分） | CC 更细 |
| 自动沉淀 | auto memory（默认开） | memory 模式（0.121.0+，可关） | |
| 治理命令 | `/memory` `/init` `/doctor prompt-audit` | `/init` | |

## 2.5 双工具联动与迁移

1. **规则文件共享**（零成本）：项目里只写一份 `AGENTS.md`——CC 读不到 CLAUDE.md 时自动回退读它，Codex 原生读它。或者在 CLAUDE.md 里 `@AGENTS.md` 导入。
2. **CC ← Codex**：CC 里执行 `/import codex`，导入 Codex 的指令与配置。
3. **Codex ← CC**：Codex 里执行 `/import`（0.145.0+），迁移 Claude Code 的设置、MCP、插件、会话与记忆——**双向都有官方投奔通道**，切换成本接近零。
4. **会话资产互通**：两边 `/export` 出的 Markdown 可互相归档进你的知识库；会话本体不互通。
5. **/compact 时机共识**（社区公认）：用到 60-70% 主动压；里程碑/测试通过后压；切换子任务前压；更彻底的做法是 /clear 后靠记忆文件 + 计划文档重启。

## 2.6 学生何时用得上

- **一课一会话**：每门课设单独会话并用 `/title`（Codex）或 `/clear 课设-xxx` 命名（CC），期末周多线并行不串台；
- **/export 是论文素材机**：和 Agent 讨论方案的过程导出后就是报告的"设计思路"章节初稿；
- **/goal 管长实验**：跑几小时的信号处理仿真/训练脚本，挂上目标让它自己盯；
- **/side、/btw 管碎片问题**：干活时冒出的语法疑问走侧聊，不污染主任务；
- **记忆文件写"老师的要求"**：把课程的具体验收要求（命名规范、报告格式）写进 AGENTS.md，每次生成都自动遵守。
