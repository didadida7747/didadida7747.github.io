# 第2章 WSL2 从零搭好环境

> 这是整个教程最重要的一章。跟我一步一步做，做完你就拥有了一个和云服务器几乎一模一样的 Linux 环境，后面所有章节都在这个环境里练。

## 本章你将学会

- 说清楚 WSL 是什么、WSL1 和 WSL2 的区别
- 检查你的 Windows 版本和 CPU 虚拟化是否满足要求
- 用一条 `wsl --install` 装好 Ubuntu 24.04，完成首次初始化
- 用 `wsl` 系列命令管理你的 Linux（列出、切换、关机、备份）
- 在 Ubuntu 里开启 systemd、把 apt 源换成清华源
- 装好 Windows Terminal 和 VS Code 的 WSL 扩展，用 `code .` 在图形界面里编辑 Linux 文件
- 搞清楚 Windows 和 Linux 两边文件怎么互相访问、为什么代码要放在 Linux 侧
- 处理内存占用、网络代理等常见问题
- 独立解决 0x800701bc、0x80370102、忘记密码这三个经典报错

## 2.1 为什么用 WSL，而不是双系统或虚拟机

你可能听过学 Linux 要"装个虚拟机"或者"装双系统"。这两条路现在都不推荐了：

- **双系统：** 要在 Windows 和 Linux 之间重启切换，传个文件都麻烦，学习成本全浪费在折腾系统上。
- **虚拟机（VMware/VirtualBox）：** 笨重、占资源、和 Windows 之间复制粘贴都要装增强工具。
- **WSL（Windows Subsystem for Linux）：** 微软官方做的"在 Windows 里原生跑 Linux"的方案。启动快、内存按需占用、和 Windows 文件互通、复制粘贴天然支持。微软自己都把它当程序员的一等公民在推。

> 📌 **注意：WSL 不是虚拟机，也不是模拟器。** WSL2 内部确实跑了一个轻量级的真 Linux 内核（由微软编译维护），但它和 Windows 是无缝集成的——你在 Windows Terminal 里敲个命令就进去了，关掉窗口它就停了，不占后台资源。

## 2.2 WSL1 和 WSL2 的区别

WSL 有两代，你只用 WSL2，但得知道区别，免得网上老教程把你绕晕：

| | WSL1 | WSL2 |
|---|---|---|
| 实现方式 | 翻译层，把 Linux 系统调用翻译成 Windows 的 | 真内核，跑在一个轻量虚拟机里 |
| 性能 | 文件 I/O 慢 | 快很多 |
| 系统调用兼容性 | 部分程序跑不了 | 几乎完整，Docker 都能跑 |
| 网络 | 和 Windows 共享 IP | 有自己的虚拟网卡（localhost 自动转发） |
| 结论 | 已淘汰 | **我们用这个** |

现在新装的 WSL 默认就是 WSL2，你不用手动选。

## 2.3 装之前先检查两件事

### 2.3.1 Windows 版本

`wsl --install` 这条一键命令需要 **Windows 10 2004 版本及以上，或者 Windows 11**。你既然在 Win11 上，基本没问题。想确认的话：按 `Win+R`，输入 `winver` 回车，弹出来的窗口看一眼版本号就行。

### 2.3.2 CPU 虚拟化是否开启

WSL2 需要 CPU 支持并开启虚拟化（Intel 叫 VT-x，AMD 叫 AMD-V）。现在的电脑基本都支持，但有些笔记本出厂在 BIOS 里是关着的。

检查方法：按 `Ctrl+Shift+Esc` 打开任务管理器 → "性能"标签 → 点左边的"CPU"，右边看右下角：如果写着"虚拟化：已启用"，就 OK；如果写"已禁用"，你得进 BIOS 打开（开机时狂按 F2 / Del / F12，不同主板不一样，找到 Virtualization / VT-x / SVM 字样打开）。

> 💡 **小技巧：** 也可以直接跳到下一步执行 `wsl --install`，如果虚拟化没开，它会在最后报 0x80370102 错误，到时候再进 BIOS 开也不迟——本章最后"常见报错"那节会讲。

## 2.4 正式安装：wsl --install

这一步要在**管理员权限的 PowerShell** 里做：

1. 点开始菜单，搜 `PowerShell`
2. 右键点 "Windows PowerShell"，选 **"以管理员身份运行"**
3. 在弹出的蓝色窗口里，敲：

```powershell
wsl --install
```

回车。这条命令会自动做四件事：

1. 启用"适用于 Linux 的 Windows 子系统"和"虚拟机平台"两个 Windows 功能
2. 下载并安装 WSL2 内核
3. 把默认版本设为 WSL2
4. 下载并安装 Ubuntu（默认就是最新 LTS）

整个过程看网速，大概 5-20 分钟。中间**不要关窗口**。装完它会提示你重启电脑。

> ⚠️ **警告：`wsl --install` 会改动 Windows 的系统功能（启用两个可选组件），这是官方标准操作，放心照做即可。但请务必在管理员 PowerShell 里执行，普通权限跑这条命令会报错。**

### 2.4.1 重启之后

重启电脑后，系统会自动弹出一个 Ubuntu 窗口（如果没弹，去开始菜单搜 "Ubuntu" 点开）。它第一次启动要初始化 1-2 分钟，然后提示你：

```text
Installing, this may take a few minutes...
Please create a default UNIX user account. The username does not need to match your Windows username.
For more information visit: https://aka.ms/wslusers
Enter new UNIX username:
```

这里让你设一个 **Linux 用户名**：

- 建议全小写，比如你的名字拼音 `zhangsan`
- 不要和 Windows 用户名一样也行，无所谓
- **不能用 root**（root 是保留的管理员账号）

然后它让你输密码：

```text
New password:
```

输密码时屏幕上**一个字符都不显示**，这是 Unix 的传统设计，不是卡死。盲打你的密码，回车，再输一遍确认。

> 📌 **注意：这个 Linux 用户密码就是你以后所有 `sudo` 命令要输的密码。** 它和你的 Windows 开机密码完全是两回事，可以设成一样的方便记忆，但本质是独立的。务必记牢——忘了会很麻烦（本章后面有救回来的方法）。

设完你会看到：

```text
Installation successful!
```

以及一个欢迎信息，最后停在你熟悉的提示符：

```text
zhangsan@DESKTOP-XXXX:~$
```

恭喜，你的 Linux 已经能用了。

## 2.5 wsl 管理命令速查

上面是在 Ubuntu 里面。但 WSL 本身是 Windows 的一个功能，管理它要回到 **Windows 的 PowerShell（不用管理员也行）** 里敲 `wsl` 开头的命令。这些命令你会反复用，记一张表：

| 命令（在 PowerShell 里敲） | 作用 |
|---|---|
| `wsl --list --verbose`（简写 `wsl -l -v`） | 列出装了哪些发行版、各自版本和状态 |
| `wsl --shutdown` | 关掉所有 WSL 实例（相当于重启 Linux） |
| `wsl --install -d Ubuntu-24.04` | 再装一个指定发行版 |
| `wsl --set-default Ubuntu-24.04` | 设为默认发行版（敲 `wsl` 时进去的那个） |
| `wsl --set-version Ubuntu-24.04 2` | 把某个发行版切换到 WSL2 |
| `wsl --unregister Ubuntu-24.04` | **注销并删除**这个发行版（危险！见警告） |
| `wsl --export Ubuntu-24.04 D:\backup\ubuntu.tar` | 把整个 Linux 导出成一个 tar 备份文件 |
| `wsl --import NewUbuntu D:\wsl\ext4 D:\backup\ubuntu.tar` | 从备份文件导入恢复 |

试一下 `wsl -l -v`，你应该能看到类似：

```text
  NAME            STATE           VERSION
* Ubuntu-24.04    Running         2
```

`*` 表示这是默认发行版，VERSION 是 2 就对了。

> ⚠️ **警告：`wsl --unregister Ubuntu-24.04` 会把这个发行版里的所有文件、你装的软件、你的数据全部删除，且不可恢复！** 它不是"卸载"，是"格式化整个 Linux"。除非你明确知道自己在做清理，否则不要敲。想备份就先用 `wsl --export` 导出一份。

### 2.5.1 为什么要学会 wsl --shutdown

改了 WSL 配置文件（后面的 `.wslconfig`、`wsl.conf`）之后，改动不会立刻生效，必须 `wsl --shutdown` 把所有 WSL 关掉，再重新打开 Ubuntu 窗口，配置才会加载。很多人改了配置没生效，就是忘了这一步。

## 2.6 开启 systemd

systemd 是现代 Linux 的"服务管家"（管理开机自启、后台服务，第 13 章细讲）。Ubuntu 桌面版默认开了它，但 **WSL 默认是关的**。将来你要跑 Docker、要装数据库服务，最好现在就打开。

方法是编辑一个叫 `/etc/wsl.conf` 的配置文件。我们先用 nano（第 5 章会教它）：

```bash
$ sudo nano /etc/wsl.conf
```

输入你的密码。然后把下面这段完整敲进去：

```ini
[boot]
systemd=true
```

按 `Ctrl+O` 然后回车保存，`Ctrl+X` 退出。

然后回到 **PowerShell**，执行：

```powershell
wsl --shutdown
```

等 10 秒，再重新打开 Ubuntu。验证一下：

```bash
$ systemctl list-unit-files | head -5
```

如果列出一堆 `.service` 文件而不是报错，说明 systemd 已经开了。

> 📌 **注意：`wsl.conf` 是 Linux 侧的配置文件，放在 Ubuntu 里面的 `/etc/` 目录。它和后面要讲的 `.wslconfig`（Windows 侧）是两个文件，别搞混——一个管 Linux 内部，一个管 WSL 这个虚拟机本身的资源。**

## 2.7 apt 换源——本章最容易踩坑的一步

Ubuntu 默认的软件下载服务器在国外，`apt install` 一个东西可能要等半天。国内大学网尤其慢。所以我们要把软件源换成清华大学（或阿里）的镜像。

**重点来了：Ubuntu 24.04 改了源文件的写法。** 网上绝大多数老教程教你改 `/etc/apt/sources.list`，但在 24.04 上，默认文件在 `/etc/apt/sources.list.d/ubuntu.sources`，格式也变了。我两种都教你。

### 2.7.1 先确认你是哪种格式

```bash
$ ls /etc/apt/sources.list.d/
```

如果里面有个 `ubuntu.sources` 文件，你就是新格式；如果 `/etc/apt/sources.list` 这个文件本身里写着一堆 deb 行，你就是旧格式。24.04 默认是新格式。

### 2.7.2 新格式（24.04 默认）：改 ubuntu.sources

先备份原文件：

```bash
$ sudo cp /etc/apt/sources.list.d/ubuntu.sources /etc/apt/sources.list.d/ubuntu.sources.bak
```

然后编辑：

```bash
$ sudo nano /etc/apt/sources.list.d/ubuntu.sources
```

把里面内容**全部删掉**，换成下面这段（清华源）：

```deb822
Types: deb
URIs: https://mirrors.tuna.tsinghua.edu.cn/ubuntu/
Suites: noble noble-updates noble-backports
Components: main restricted universe multiverse
Signed-By: /usr/share/keyrings/ubuntu-archive-keyring.gpg

Types: deb
URIs: https://mirrors.tuna.tsinghua.edu.cn/ubuntu/
Suites: noble-security
Components: main restricted universe multiverse
Signed-By: /usr/share/keyrings/ubuntu-archive-keyring.gpg
```

存盘退出（`Ctrl+O` 回车，`Ctrl+X`）。

> 📌 **注意：`noble` 是 Ubuntu 24.04 的代号。** 如果你以后装的是别的版本，这个词要换成对应的代号（22.04 是 jammy，20.04 是 focal）。我们固定用 24.04，所以 noble 不用动。

### 2.7.3 旧格式（老版本 Ubuntu）：改 sources.list

如果你的系统是旧格式，文件在 `/etc/apt/sources.list`。同样先备份：

```bash
$ sudo cp /etc/apt/sources.list /etc/apt/sources.list.bak
$ sudo nano /etc/apt/sources.list
```

把内容全删，换成：

```list
deb https://mirrors.tuna.tsinghua.edu.cn/ubuntu/ noble main restricted universe multiverse
deb https://mirrors.tuna.tsinghua.edu.cn/ubuntu/ noble-updates main restricted universe multiverse
deb https://mirrors.tuna.tsinghua.edu.cn/ubuntu/ noble-backports main restricted universe multiverse
deb https://mirrors.tuna.tsinghua.edu.cn/ubuntu/ noble-security main restricted universe multiverse
```

> 💡 **小技巧：** 想用阿里云源就把 `mirrors.tuna.tsinghua.edu.cn` 整体替换成 `mirrors.aliyun.com`，其他一样。

### 2.7.4 换完之后：update 和 upgrade

换源不是改完就完事，要让系统重新读一遍软件列表：

```bash
$ sudo apt update
```

`update` 只是"更新软件清单"，不真的装东西。看到一堆 `Get:xx https://mirrors.tuna... noble InRelease` 就说明源生效了。然后：

```bash
$ sudo apt upgrade
```

这条才是"把已装软件升级到最新版"。它会列出要升级的包，问你是否继续，输 `Y` 回车。第一次 upgrade 可能要几分钟。

> 📌 **注意：`update` 和 `upgrade` 是两条命令，作用完全不同——update 刷新清单，upgrade 真正升级。** 很多新手只敲 update 以为升完了。第 8 章会专门讲 apt。

## 2.8 Windows Terminal 安装与配置

WSL 默认弹出的那个 Ubuntu 窗口其实挺难用（不能多标签、字体丑、不能调大小）。微软有个专门的终端叫 **Windows Terminal**，强烈建议装。

打开 Microsoft Store（开始菜单搜"商店"），搜 "Windows Terminal"，点安装。免费。装完以后，开始菜单里打开它，它会自动检测到你的 Ubuntu，并在顶部标签栏提供一个下拉菜单，里面有 Ubuntu。

**把 Ubuntu 设为默认打开项：** 打开 Windows Terminal → 顶部下拉箭头 → "设置" → 左边"启动" → "默认配置文件" 选 "Ubuntu"。以后一开终端直接进 Linux。

**换个好看点的字体：** 还是在设置里，选到 Ubuntu 那个配置文件 → "外观" → "字体"，推荐装个 Cascadia Code 或者 Meslo LG Nerd Font（后面装 powerlevel10k 之类会用到）。新手用默认的 Cascadia Mono 也完全够。

## 2.9 VS Code + WSL 扩展：图形化编辑 Linux 文件

在终端里改代码当然可以，但写项目时还是想要 VS Code 的自动补全、调试。微软官方方案叫 **WSL 远程扩展**：

1. 在 Windows 上装好 VS Code（去 code.visualstudio.com 下载安装包，一路下一步）
2. 打开 VS Code，左边扩展图标（`Ctrl+Shift+X`），搜 `WSL`，装那个 "WSL"（微软官方出的）扩展
3. 回到 Ubuntu 终端，`cd` 到你的项目目录，敲：

```bash
$ code .
```

第一次它会在 Linux 里装一个 server 组件，等一两分钟，然后 VS Code 窗口会弹出来——注意这个窗口标题栏左边有个绿色的角标写着 `WSL: Ubuntu-24.04`，说明它编辑的是 Linux 文件，不是 Windows 文件。

> 💡 **小技巧：`code .` 里那个 `.` 是"当前目录"的意思。** 这条命令等价于"用 VS Code 打开当前文件夹"。

## 2.10 Windows 和 Linux 文件互访——最重要的实践原则

这一节是新手最容易走弯路的地方，请认真读。

### 2.10.1 从 Windows 看 Linux 文件

打开文件资源管理器，在地址栏输入：

```text
\\wsl.localhost\Ubuntu-24.04\home\你的用户名
```

回车，你就能像浏览普通文件夹一样看到 Linux 家目录里的东西。（老写法 `\\wsl$` 也能用，微软现在推荐 `\\wsl.localhost`，两者等价。）

### 2.10.2 从 Linux 看 Windows 文件

Windows 的 C 盘在 Linux 里被挂载成了 `/mnt/c/`，D 盘就是 `/mnt/d/`：

```bash
$ ls /mnt/c/Users/你的Windows用户名/Desktop
```

这样你在 Linux 里也能访问到 Windows 桌面上的文件。

### 2.10.3 关键原则：你的代码要放在 Linux 侧

> ⚠️ **警告（性能坑，不是删东西，但会让你怀疑人生）：千万不要把项目代码放在 `/mnt/c/` 下面开发！**

也就是说，不要在 Windows 的 `D:\code\myproject` 里写代码然后在 WSL 里访问 `/mnt/d/code/myproject`。反过来，要在 Linux 家目录 `/home/你的用户名/myproject` 里开发，需要时用 `\\wsl.localhost` 从 Windows 看。

原因：跨文件系统访问（从 Linux 访问 Windows 的 NTFS 盘）要经过一层翻译，I/O 性能差 5-10 倍。Node 的 `node_modules`、Python 的虚拟环境、Git 仓库里几万个小文件，放在 `/mnt/c` 下会慢到你怀疑人生，还会有文件权限错乱、行尾符 CRLF 问题。

> 📌 **记住一句话：代码放 Linux 家目录，下载的安装包放 Windows 侧随便。** 需要在 Windows 里编辑时，用 `\\wsl.localhost` 看；需要在 Linux 里访问 Windows 文件（比如你下载好的安装包），再走 `/mnt/c/`。

## 2.11 网络：localhost、代理、镜像模式

### 2.11.1 localhost 自动转发（默认就是好的）

WSL2 默认开启了 localhost 转发。意思是：你在 Linux 里跑一个 Web 服务监听 8000 端口，然后在 Windows 浏览器里访问 `http://localhost:8000`，**直接就能打开**。不用记什么 IP。这是 WSL2 最爽的特性之一。

### 2.11.2 WSL2 走 Windows 的代理（常见做法）

很多同学在 Windows 上开着 Clash/v2ray 之类的代理，装完 WSL 发现 `apt update` 还是慢、`git clone` GitHub 超时。因为 WSL2 默认不自动用 Windows 的代理。

旧办法（NAT 模式下）要查 Windows 主机的 IP，然后在 Linux 里 `export https_proxy=...`，比较麻烦。**Win11 22H2 之后微软给了一个更省事的方案：镜像网络模式（mirrored）。**

### 2.11.3 开启镜像模式：编辑 .wslconfig

注意这个文件在 **Windows 侧**，不在 Linux 里。路径是 `C:\Users\你的Windows用户名\.wslconfig`（也就是 `%UserProfile%\.wslconfig`）。

用记事本新建这个文件（如果不存在），写入：

```ini
[wsl2]
networkingMode=mirrored
```

保存，然后 PowerShell 里 `wsl --shutdown`，重新打开 Ubuntu。镜像模式下：

- WSL2 和 Windows 共享同一个 localhost
- Windows 上开的代理，WSL 里直接就能用，只需在 Linux 里告诉它代理端口：

```bash
$ export https_proxy=http://127.0.0.1:7890
$ export http_proxy=http://127.0.0.1:7890
```

（7890 换成你自己代理软件的实际端口。）这种 `export` 只对当前终端窗口有效，想永久生效要写进 `~/.bashrc`，第 12 章会讲。

> 📌 **注意：镜像模式不是必开的。** 你如果不需要走代理、不需要从局域网访问 WSL，用默认的 NAT 模式就挺好。本节是给有代理需求的同学准备的，看不懂就先跳过。

## 2.12 用 .wslconfig 限制内存和 CPU

WSL2 默认会**动态占用**你 Windows 一半左右的内存。你电脑 16G 内存，WSL 可能吃掉 8G。想限制它，还是编辑上面那个 Windows 侧的 `.wslconfig`：

```ini
[wsl2]
memory=4GB
processors=4
swap=2GB
localhostForwarding=true
```

含义：给 WSL 最多 4G 内存、用 4 个 CPU 核、2G 交换空间。改完照例 `wsl --shutdown` 重启生效。

> 💡 **小技巧：** 想查 WSL 当前吃了多少内存，在 Linux 里敲 `free -h`（第 7 章细讲）。

## 2.13 备份与迁移

`wsl --export` 和 `wsl --import` 在 2.5 节那张表里了。这里给你一个完整的备份动作：

在 PowerShell 里：

```powershell
wsl --shutdown
wsl --export Ubuntu-24.04 D:\wsl-backup\ubuntu-backup.tar
```

这会把整个 Linux 打包成一个 tar 文件存到 D 盘。将来你系统崩了、或者想换电脑：

```powershell
wsl --import Ubuntu-24.04 D:\wsl\ext4 D:\wsl-backup\ubuntu-backup.tar
```

> ⚠️ **警告：导出/导入时，旧的发行版最好先 `wsl --unregister` 再导入新的，否则名字冲突。而 unregister 会删数据——所以顺序一定是：先 export 备份 → 确认 tar 文件存在 → 再 unregister → 再 import。** 备份没确认成功之前，绝不 unregister。

## 常见报错与排查（重点收藏）

| 现象 | 原因 | 解决 |
|---|---|---|
| `wsl --install` 后提示 `0x800701bc` | WSL2 内核没装上 | PowerShell 里跑 `wsl --update`，装完重启 |
| 启动时报 `0x80370102` / 提示虚拟机器无法启动 | CPU 虚拟化没在 BIOS 里开 | 重启进 BIOS，把 Intel VT-x / AMD SVM 打开（参考 2.3.2） |
| 提示 `Virtual Machine Platform` 相关错误 | Windows 功能没启用 | 管理员 PowerShell 跑 `wsl --install` 会自动修；手动可在"启用或关闭 Windows 功能"里勾上"虚拟机平台" |
| 忘记 Linux 密码 | 没办法直接找回，但可以重置 | 见下面 2.14.1 |
| 改了 wsl.conf / .wslconfig 不生效 | 没重启 WSL | PowerShell 跑 `wsl --shutdown` 再开 |
| `apt update` 报各种 Hash 错 / 锁文件 | 上次 apt 没退干净 | `sudo rm /var/lib/apt/lists/lock` 前先确认没有 apt 在跑；一般 `sudo apt update` 重试即可 |
| Windows 访问 `\\wsl$` 打不开 | WSL 没在运行 | 先打开一下 Ubuntu 窗口让它启动，再访问 |

### 2.14.1 忘记密码怎么办

不用重装。在 **Windows PowerShell** 里（不是 Ubuntu 里）：

```powershell
wsl -d Ubuntu-24.04 -u root
```

这会以 root 身份直接进 Linux，不需要密码。进去之后：

```bash
# 注意这里提示符是 #，因为你是 root
passwd 你的用户名
```

按提示输两遍新密码，然后：

```bash
exit
```

回到普通用户，新密码就生效了。

## ⚠️ 危险操作与安全红线

- > ⚠️ **`wsl --unregister` 删整个发行版数据，不可恢复。** 备份在前，删除在后。
- > ⚠️ **`sudo apt` 换源、改 `/etc/wsl.conf` 这些操作都要 sudo。** 改之前先 `cp` 一份 `.bak` 备份，改坏了能 `sudo cp 文件名.bak 文件名` 恢复。
- > ⚠️ **不要在 `/mnt/c` 下做项目开发。** 性能差、权限乱、行尾符坑，三连。

## 动手练习

1. 跑通 `wsl -l -v`，确认你的 Ubuntu-24.04 是 Running 状态、VERSION 是 2。
2. 在你的家目录 `mkdir myfirstproject`，然后 `cd myfirstproject`，敲 `code .`，确认 VS Code 弹出来且标题栏有 WSL 标记。
3. 把 apt 源换成清华源，跑 `sudo apt update && sudo apt upgrade`，全程不报错。
4. 编辑 `~/.wslconfig` 把内存限制成 3GB，`wsl --shutdown` 后重启，在 Linux 里 `free -h` 确认。
5. 故意练一遍"忘记密码"流程（先设个临时密码再重置回来），把这个救命操作记住。
6. 从 Windows 资源管理器用 `\\wsl.localhost\Ubuntu-24.04` 打开你的家目录，新建一个空文件夹，再回 Linux 里 `ls` 看看能不能看到。

## 本章小结

| 命令 / 操作 | 作用 |
|---|---|
| `wsl --install` | 一键安装 WSL2 + Ubuntu |
| `wsl -l -v` | 查看已装发行版状态 |
| `wsl --shutdown` | 重启 WSL（改配置后必做） |
| `wsl --export/--import` | 备份 / 恢复整个 Linux |
| `/etc/wsl.conf` | Linux 侧配置，开 systemd |
| `%UserProfile%\.wslconfig` | Windows 侧配置，限内存、网络模式 |
| 改 `ubuntu.sources`（新）或 `sources.list`（旧） | 换清华/阿里源 |
| `sudo apt update && sudo apt upgrade` | 刷新清单 + 升级 |
| `code .` | 用 VS Code 打开当前目录 |
| `\\wsl.localhost` / `/mnt/c` | Windows ↔ Linux 文件互访 |
