## 二、提炼出的可落地优化点

从 15 个对象中提炼出 **6 个可落地且不破坏零依赖**的优化点：

| # | 优化点 | 来源 | 实现方式（stdlib） |
|---|---|---|---|
| 1 | **时间衰减热度评分** | kabi-digest | `apply_time_decay()`：有 published_at 的条目叠加新鲜度因子 `1/(1+age*0.25)`，温和乘性衰减 |
| 2 | **平衡配额防霸屏** | Horizon | `build_top()` 中 `top_balance_per_source`：同一原始板块最多占 TOP 榜 N 条 |
| 3 | **推送通知模块** | ntfy + apprise + ai-radar | `notify()`：`ntfy://` `bark://` `webhook://` 三种 URL-scheme，每个通道一个 urllib POST，失败自动跳过 |
| 4 | **RSS 订阅输出** | DailyHotApi | `render_rss()`：生成 RSS 2.0 XML，可用任意 RSS 阅读器订阅 |
| 5 | **链接可达性校验** | B站 Codex 矩阵 | `check_top_links()`：可选开关，对 TOP 榜 URL 并发 HEAD，挂掉标⚠️ |
| 6 | **HTML 各源状态面板** | DailyHotApi | render_html 中新增 src-panel：每个源显示成功状态+条数，失败标✗删除线 |

### 未采纳的设计及理由

| 设计 | 来源 | 未采纳理由 |
|---|---|---|
| collect/generate 两阶段拆分 | kabi-digest | v2 是"一次跑一次出报"模型，与 Windows 定时任务+登录补跑的调度方式匹配；拆成两阶段会增加用户操作复杂度，收益不大 |
| published/index.json 跨次去重 | kabi-digest | v2 已有"与昨日 JSON 快照对比标 NEW"机制，功能重叠；72h 去重会导致持续多天的重要事件被误杀 |
| Profile 路由系统 | Horizon | 本项目只有一个"科技"profile，不需要多 profile 路由；平衡配额已吸收其最有价值的部分 |
| per-source 缓存 TTL | glance/DailyHotApi | 脚本每天只跑一次（07:30），同一次运行内各源只请求一次，缓存收益为零；多次手动 --force 时也应该拿最新数据 |
| 抽取表达式引擎（CSS/XPath/JSONPath） | changedetection.io | 需要第三方解析库（lxml/cssselect），违背零依赖；现有正则+html.parser 已够用 |
| 直接引入 apprise 库 | apprise | 90+ 通道的库本身不小，违背零依赖；其 URL-scheme 思想已用 ~60 行 stdlib 重写迷你版 |
| 引入 n8n/Docker/OpenCLI | B站多个视频 | 重组件，与零依赖本地脚本定位完全不符 |
| X/Twitter cookie 抓取 | ai-radar (B站) | 反爬严格，cookie 易失效，维护成本高；现有 8 板块已覆盖足够信息 |

## 三、实际改了什么

### tech_radar.py（v2 → v3，约 +280 行）

1. **文件头**：更新为 v3，新增 v3 功能清单和参考项目
2. **DEFAULT_CONFIG**：新增 `notify`（空列表）、`check_links`（false）、`top_balance_per_source`（5）
3. **6 个 fetch 函数**：新增 `published_at` 字段（IT之家/HN/arXiv/S2/HF/RSS，能拿到时间的源）
4. **`apply_time_decay()`**（新函数）：时间衰减热度评分，kabi-digest 经验
5. **`build_top()`**：新增平衡配额逻辑，Horizon 经验
6. **`notify()`**（新函数）：ntfy/bark/webhook 三通道推送，ntfy+apprise 经验
7. **`check_top_links()`**（新函数）：可选链接 HEAD 校验，B站 Codex 矩阵经验
8. **`render_rss()`**（新函数）：RSS 2.0 输出，DailyHotApi 经验
9. **`top_card_html()`**：新增 ⚠️链接失效 徽章
10. **`render_html()`**：新增各源状态面板（src-panel）+ CSS 样式；footer 更新为 v3
11. **`main()`**：调用 apply_time_decay → check_top_links → 写入 RSS XML → 推送通知；argparse 版本号 v3

### 零依赖验证

修改后代码仅使用 Python 3 标准库：`argparse` `glob` `html` `json` `math` `os` `re` `sys` `time` `urllib` `xml.etree` `concurrent.futures` `datetime` —— 与 v2 完全相同，**未引入任何第三方依赖**。

### v2 功能不回退验证

- ✅ 8 板块并发采集（IT之家/热搜/HN/arXiv+S2/HF/GitHub/掘金/RSS）
- ✅ 热度归一化（rank 型 + log 数值型）
- ✅ 跨源聚类（Jaccard 0.40）+ 共振标记
- ✅ NEW 标记（历史快照对比）
- ✅ 可选 AI 今日解读（OpenAI 兼容）
- ✅ HTML/MD/JSON 三输出
- ✅ 容错（单源失败跳过、arXiv 406 降级 S2）
