# 第 13 章 服务与部署入门

> 学完这章，你写的 Flask/Node 应用不再是"只在我自己终端能跑"——它能在后台常驻、能通过域名访问、能崩了自动重启，甚至能打包成 Docker 镜像一键搬到任何机器上。

## 本章你将学会

- 明白什么是云服务器、安全组、密钥登录
- 用 `systemctl` 管理服务，能自己写一个 `.service` 文件
- 用 `journalctl` 看服务日志
- 装 Nginx、托管静态页面、做反向代理
- 把你的 Flask 应用用 Nginx 反代跑起来
- 装 Docker、跑容器、写简单的 Dockerfile 和 docker-compose
- 所有练习都在 WSL 本地能完成，云服务器部分标了"有学生机再做"

## 13.1 云服务器概念（有学生机再做）

你写的应用要让外网用户访问，不能靠你自己的笔记本——你关机了网站就没了。所以需要一台**一直在云上开机的 Linux 机器**，这就是云服务器。

| 名词 | 是什么 |
|---|---|
| ECS / CVM | 阿里云/腾讯云对"云服务器"的叫法（华为叫 ECS、阿里叫 ECS、腾讯叫 CVM） |
| 镜像 | 服务器的"操作系统模板"。**选 Ubuntu 24.04 LTS**，和你 WSL 里的一模一样，命令通用 |
| 公网 IP | 外网能找到这台机器的地址，比如 `120.55.xx.xx` |
| 安全组 | 云上的防火墙。默认只开 22（SSH），你要用 80/443 端口要在控制台**手动放行** |
| 密钥对 | 云上推荐用 SSH key 登录，禁用密码登录（防爆破） |
| 学生机 | 阿里云/腾讯云对大学生有优惠，1 核 2G 一年几十块，用来练手足够 |

> 📌 **注意：** 这一章**所有操作先在你 WSL 里练**。等你真买了学生机，把同样的命令在云上跑一遍就行——命令完全一样，唯一区别是云上要在控制台配安全组放行端口。

学生机入口（按需查看）：

- [阿里云高校学生权益](https://www.aliyun.com/activity/ecs/student-benefits)
- [腾讯云云+校园](https://cloud.tencent.com/act/campus)

登录云服务器的标准姿势：

```bash
# 买完服务器，下载下来那个 .pem 私钥
$ chmod 600 ~/Downloads/xxx.pem
$ ssh -i ~/Downloads/xxx.pem ubuntu@你的公网IP
```

> ⚠️ **警告：** 云服务器的 SSH 端口暴露在公网，**第一件事是把密码登录关掉、只留密钥登录**，不然过几天就被暴力破解拖去挖矿。具体配置查第 10 章 SSH 那节。

## 13.2 systemd：让程序在后台常驻

你在 WSL 里跑 `python app.py`，终端一关程序就死了。真实服务器上你不可能一直开着终端。**systemd** 就是 Linux 的"服务管家"——你告诉它"把这个程序跑起来，崩了自动拉起来，开机自己启动"，它就负责。

### unit（单元）是什么

一个服务在 systemd 眼里叫一个 **unit**，通常是一个 `.service` 文件。比如你装 Nginx，系统自动生成了一个 `nginx.service`。

### systemctl 常用命令（背下来）

```bash
$ systemctl start nginx        # 启动
$ systemctl stop nginx         # 停止
$ systemctl restart nginx      # 重启
$ systemctl status nginx       # 看状态（最常用）
$ systemctl reload nginx       # 不中断地重载配置（nginx 改配置后用）
$ systemctl enable nginx       # 开机自启
$ systemctl disable nginx      # 取消开机自启
$ systemctl is-active nginx    # 一句话答"跑没跑"
```

> 📌 **注意：** 这些命令都需要 root 权限（加 `sudo`）。WSL2 里默认已开启 systemd（第 2 章配过 `wsl.conf`），可以直接用。

`status` 输出长这样，重点看前几行：

```text
● nginx.service - A high performance web server and reverse proxy server
     Loaded: loaded (/lib/systemd/system/nginx.service; enabled)   # enabled = 开机自启
     Active: active (running) since ...                            # active (running) = 在跑
   Main PID: 12345 (nginx)
      Tasks: 3
     Memory: 2.1M
```

绿点 = 在跑；红点 `inactive` 或 `failed` = 没跑或崩了。

### journalctl：看服务日志

以前日志都在 `/var/log/xxx.log`，systemd 的服务日志统一在它自己的数据库里：

```bash
$ journalctl -u nginx           # 看 nginx 的全部日志
$ journalctl -u nginx -f        # 实时跟踪（像 tail -f）
$ journalctl -u nginx -n 50     # 最近 50 行
$ journalctl -u nginx --since "1 hour ago"   # 最近 1 小时
$ journalctl -xe                # 看系统级报错（排错先跑这个）
```

> 💡 **小技巧：** 服务起不来？先 `systemctl status xxx` 看最后几行，再 `journalctl -u xxx -n 50` 看完整日志，90% 的原因写在里面（端口被占、路径错、权限不够）。

### 自己写一个 .service 文件（把 11 章的脚本托管起来）

我们把 11 章那个 `disk_check.sh` 改成一个"开机自启 + 每小时跑一次"的服务。但更典型的例子是——把你的 Flask 应用做成服务。先看一个完整的 `.service` 长什么样：

```bash
$ sudo nano /etc/systemd/system/hello-flask.service
```

写入：

```ini
[Unit]
Description=My Flask Hello App
After=network.target

[Service]
User=yourname
WorkingDirectory=/home/yourname/projects/hello-flask
ExecStart=/home/yourname/projects/hello-flask/.venv/bin/python app.py
Restart=always
RestartSec=3
Environment=PORT=5000

[Install]
WantedBy=multi-user.target
```

逐行讲解：

| 段落 | 行 | 含义 |
|---|---|---|
| `[Unit]` | `Description=` | 一句话描述，status 里显示 |
| | `After=network.target` | 等网络起来之后再启动 |
| `[Service]` | `User=yourname` | 用哪个用户跑（**别用 root 跑应用！**） |
| | `WorkingDirectory=` | 启动前先 cd 到这个目录 |
| | `ExecStart=` | **要跑的命令，必须写绝对路径**（连 python 解释器都要绝对路径，因为 systemd 环境干净） |
| | `Restart=always` | 崩了自动重启（生产必备） |
| | `RestartSec=3` | 崩了等 3 秒再拉起来（防疯狂重启） |
| | `Environment=` | 注入环境变量 |
| `[Install]` | `WantedBy=multi-user.target` | "多用户模式"（命令行）下自启 |

启用它：

```bash
$ sudo systemctl daemon-reload         # 改了 .service 文件必须先 reload
$ sudo systemctl start hello-flask
$ sudo systemctl enable hello-flask    # 开机自启
$ sudo systemctl status hello-flask
$ journalctl -u hello-flask -f          # 看实时日志
```

> ⚠️ **警告：** 改了 `.service` 文件后**必须** `sudo systemctl daemon-reload`，不然 systemd 还在用旧配置。新手最常忘这步，改完半天不生效。

> 📌 **注意：** 你的 Flask 代码里 `app.run(host='0.0.0.0', port=5000)`，生产环境其实不该直接用 Flask 内置服务器（性能差），后面 13.5 节会讲用 gunicorn/uvicorn。

## 13.3 日志体系 `/var/log` 与 `tail -f`

systemd 管的服务用 journalctl，但很多程序还是会往 `/var/log/` 写文件。速查表：

| 路径 | 里面有什么 |
|---|---|
| `/var/log/syslog` | 系统综合日志（Ubuntu/Debian） |
| `/var/log/auth.log` | 登录、sudo、SSH 认证 |
| `/var/log/nginx/access.log` | Nginx 每个请求 |
| `/var/log/nginx/error.log` | Nginx 错误 |
| `/var/log/dpkg.log` | apt 装包记录 |

最常用就一招——**实时看**：

```bash
$ tail -f /var/log/nginx/access.log
```

`tail -f` 是"滚动跟踪"，新日志立刻滚出来。你部署完一个网站，浏览器访问一次，回终端就能看到这条请求。`Ctrl+C` 退出。

## 13.4 Nginx：Web 服务器与反向代理

Nginx 是世界上用得最多的 Web 服务器（一半以上的网站都在用）。两个主要用途：

1. **托管静态网页**（HTML/CSS/JS 文件直接给浏览器）
2. **反向代理**（把外部请求转发给你后台的 Flask/Node 应用）

### 安装

```bash
$ sudo apt install -y nginx
$ sudo systemctl status nginx
```

装好后它已经在跑了。浏览器开 `http://localhost`（WSL 会自动转发到 Windows），你能看到 Nginx 欢迎页。

### 常用命令

```bash
$ sudo nginx -t                  # 检查配置文件语法（改完配置先跑这个！）
$ sudo systemctl reload nginx    # 平滑重载配置
$ sudo systemctl restart nginx  # 重启
```

> 📌 **注意：** 改 Nginx 配置后**永远先 `sudo nginx -t`**，看到 `syntax is ok`、`test is successful` 再 reload。不然语法错误会把 Nginx 搞挂。

### 配置文件结构

```text
/etc/nginx/
├── nginx.conf              # 主配置（一般不动）
├── sites-available/        # 所有站点配置写在这里
│   └── default             # 默认站点
└── sites-enabled/          # 启用的站点（是 sites-available 的软链接）
    └── default -> ../sites-available/default
```

套路：在 `sites-available/` 写配置，然后在 `sites-enabled/` 建个软链接启用它。删站点就删软链接。

### 实战 1：托管一个静态页面

```bash
# 1. 建个网站目录
$ mkdir -p ~/mysite
$ echo "<h1>Hello from Nginx!</h1>" > ~/mysite/index.html

# 2. 写配置
$ sudo nano /etc/nginx/sites-available/mysite
```

写入：

```nginx
server {
    listen 80;
    server_name localhost;

    root /home/yourname/mysite;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }
}
```

逐行讲：

| 行 | 含义 |
|---|---|
| `listen 80` | 监听 80 端口（HTTP 默认端口） |
| `server_name localhost;` | 哪个域名/主机名来的请求走这个配置（本地用 localhost） |
| `root /home/...` | 静态文件根目录 |
| `index index.html;` | 默认首页 |
| `location / { try_files ... }` | 请求来了先找文件，找不到返回 404 |

启用：

```bash
$ sudo ln -sf /etc/nginx/sites-available/mysite /etc/nginx/sites-enabled/mysite
$ sudo nginx -t
$ sudo systemctl reload nginx
```

浏览器开 `http://localhost` 就能看到你的页面了。

> ⚠️ **警告：** Nginx 进程是用 `www-data` 用户跑的，你 `~/mysite` 这个目录它得能读。如果浏览器开出来 403 Forbidden，检查 `/home/yourname` 这个目录的权限——你家目录默认 700，Nginx 进不来。解决：把网站放在 `/var/www/`，或者给家目录加执行权限 `chmod o+x /home/yourname`。

### 实战 2：反向代理 Flask 应用

这是后端部署最经典的姿势：**用户访问 80 端口 → Nginx 接收 → Nginx 转发给本机 5000 端口的 Flask 应用**。

为什么这么麻烦，不直接让 Flask 暴露在 80？

- 80 是特权端口，绑它要 root
- Flask 内置服务器性能差，不该直接面对公网
- Nginx 能做静态文件、HTTPS、限流、负载均衡——让 Flask 专心写业务

假设你 Flask 还跑在 5000 端口（用 13.2 的 systemd 服务）。写 Nginx 配置：

```bash
$ sudo nano /etc/nginx/sites-available/myflask
```

```nginx
server {
    listen 80;
    server_name localhost;

    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

逐行讲：

| 行 | 含义 |
|---|---|
| `proxy_pass http://127.0.0.1:5000;` | 把所有请求转发给本机 5000 端口的 Flask |
| `proxy_set_header Host $host;` | 告诉后端"用户原始访问的域名是什么" |
| `X-Real-IP` / `X-Forwarded-For` | 把用户真实 IP 传给后端（不然 Flask 看到的都是 127.0.0.1） |

启用：

```bash
$ sudo ln -sf /etc/nginx/sites-available/myflask /etc/nginx/sites-enabled/myflask
# 把默认站点删掉，不然 localhost 会被 default 抢走
$ sudo rm /etc/nginx/sites-enabled/default
$ sudo nginx -t
$ sudo systemctl reload nginx
```

现在浏览器开 `http://localhost`，请求就到 Flask 了。

> 💡 **小技巧：** 改完 Nginx 配置后，**永远先 `sudo nginx -t`**。它会告诉你哪个配置文件哪一行有问题：
>
> ```text
> nginx: [emerg] unknown directive "proxy_passs" in /etc/nginx/sites-enabled/myflask:8
> nginx: configuration file /etc/nginx/nginx.conf test failed
> ```
>
> 看到 `emerg`（紧急）+ 具体文件和行号，直奔那行改就好。别 reload 一个语法错的 Nginx——它会拒绝启动，你的网站直接挂。

### Nginx 常用 location 匹配规则（了解）

| 写法 | 匹配什么 |
|---|---|
| `location /` | 所有请求（兜底） |
| `location /api/` | 以 `/api/` 开头的路径 |
| `location = /hello` | **精确匹配** `/hello`（不多不少） |
| `location ~ \.php$` | 正则匹配，以 `.php` 结尾的 |

实际项目里常见的是"静态资源走 Nginx、接口走后端"：

```nginx
server {
    # 静态文件直接给浏览器（图片、CSS、JS）
    location /static/ {
        root /home/yourname/projects/hello-flask;
    }

    # 其他都转给 Flask
    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
    }
}
```

这样 `/static/logo.png` 直接由 Nginx 返回文件，`/api/login` 才转到 Flask——省后端力气。

### 负载均衡概念（了解即可）

当你一台服务器扛不住，可以跑 3 个 Flask 实例（5001/5002/5003），Nginx 配置：

```nginx
upstream flask_backend {
    server 127.0.0.1:5001;
    server 127.0.0.1:5002;
    server 127.0.0.1:5003;
}

server {
    location / {
        proxy_pass http://flask_backend;
    }
}
```

Nginx 自动把请求轮询分给三个实例。这就是"负载均衡"——以后做大了再细研究。

### 看 Nginx 日志（部署完第一件事）

部署完网站，**第一件事是打开两个日志实时跟踪**，然后在浏览器里点几下：

```bash
# 终端 1：看访问日志（哪个 IP 请求了哪个路径）
$ sudo tail -f /var/log/nginx/access.log

# 终端 2（或用 tmux 分屏）：看错误日志
$ sudo tail -f /var/log/nginx/error.log
```

你浏览器访问一次 `http://localhost/`，access.log 就会立刻滚出一行：

```text
127.0.0.1 - - [13/Oct/2026:20:30:01 +0800] "GET / HTTP/1.1" 200 512 "-" "Mozilla/5.0..."
```

拆给你看：

| 字段 | 含义 |
|---|---|
| `127.0.0.1` | 客户端 IP |
| `GET / HTTP/1.1` | 请求方法 + 路径 + 协议 |
| `200` | **状态码**（200 成功、404 找不到、502 后端挂了、403 权限不够） |
| `512` | 返回字节数 |

**状态码是你排错的第一信号**——浏览器看到的是 200 还是 502，决定了你往下查 Nginx 还是查后端。

### HTTPS 与 certbot（概念）

真实网站要 `https://`（绿色小锁）。流程：

1. 你有个域名（比如 `example.com`）解析到你服务器 IP
2. 用 **certbot**（Let's Encrypt 免费证书）自动申请证书
3. certbot 自动改 Nginx 配置，把 80 跳转 443，加载证书

```bash
$ sudo apt install -y certbot python3-certbot-nginx
$ sudo certbot --nginx -d example.com
```

WSL 本地练不了这步（你没有公网域名），有学生机+域名时再做。

### 防火墙 ufw：本地也建议了解

云服务器上你在控制台配安全组，**但服务器内部还有一层防火墙 ufw**。本地 WSL 一般不用动（反正没暴露公网），但有学生机时这是必配的：

```bash
$ sudo ufw status              # 看状态（默认 inactive）
$ sudo ufw allow OpenSSH       # 先放行 SSH！不然你自己都连不上了
$ sudo ufw allow 80            # 放行 HTTP
$ sudo ufw allow 443           # 放行 HTTPS
$ sudo ufw enable              # 开启
$ sudo ufw status verbose      # 看规则
```

> ⚠️ **警告：** 开启 ufw 之前**必须先 `sudo ufw allow OpenSSH`**，否则防火墙一启，你的 SSH 连接直接被切断，再也登不上服务器。这是新手第一次配云服务器最经典的惨剧。

## 13.5 把 Flask 应用用 gunicorn 跑生产

Flask 自带的 `app.run()` 是开发用的。生产环境要用 **gunicorn**（Python 的 WSGI 服务器）：

```bash
$ source ~/projects/hello-flask/.venv/bin/activate
(.venv) $ pip install gunicorn
(.venv) $ gunicorn --bind 127.0.0.1:5000 app:app
```

意思是：绑定 5000 端口，加载 `app.py` 里叫 `app` 的那个 Flask 对象。

然后改 13.2 那个 `.service` 里的 `ExecStart`：

```ini
ExecStart=/home/yourname/projects/hello-flask/.venv/bin/gunicorn --bind 127.0.0.1:5000 app:app
```

`daemon-reload` + `restart` 一下。这样就是正经的生产部署了：Nginx(80) → gunicorn(5000) → Flask 代码。

**gunicorn 多开几个 worker**（利用多核）：

```bash
$ gunicorn --bind 127.0.0.1:5000 --workers 3 app:app
```

`--workers 3` = 开 3 个进程处理请求。经验公式是 `2 × CPU核数 + 1`，4 核机器开 9 个 worker 差不多。初学不用纠结，1 个 worker 也能跑。

> 📌 **注意：** 改完 systemd 里的 `ExecStart` 后，永远要 `sudo systemctl daemon-reload && sudo systemctl restart 服务名`，两步缺一不可。

Node 应用同理，用 **uvicorn**（FastAPI）或直接 `node app.js`，systemd 把它包起来就行。

### 附：Node 应用部署实例

如果你写的是 Node 后端（Express/Koa），套路一模一样。假设你有个 Express 项目：

```bash
$ cd ~/projects/my-node-app
$ npm install            # 装依赖
$ node app.js            # 假设它监听 3000
```

写成 systemd 服务 `/etc/systemd/system/my-node.service`：

```ini
[Unit]
Description=My Node App
After=network.target

[Service]
User=yourname
WorkingDirectory=/home/yourname/projects/my-node-app
# 注意：nvm 装的 node 有自己的路径，必须用绝对路径
ExecStart=/home/yourname/.nvm/versions/node/v22.0.0/bin/node app.js
Restart=always
Environment=NODE_ENV=production
Environment=PORT=3000

[Install]
WantedBy=multi-user.target
```

> 📌 **注意：** `ExecStart` 里的 node 路径要先 `which node`（在你正常激活的终端里）查出来，**粘贴绝对路径**——systemd 环境干净，找不到 nvm 配的 PATH。

Nginx 反代配置把 `proxy_pass` 改成 `http://127.0.0.1:3000` 就行，其他完全一样。

## 13.6 Docker：容器化部署

### 为什么需要 Docker

你肯定遇到过这种情况："我本地跑得好好的，怎么到服务器就报错？"——因为你本地 Python 3.12、服务器 Python 3.10，装的库版本也不一样。

**Docker 把你的应用 + 它需要的所有环境（Python 版本、库、系统依赖）打包成一个"镜像"**，搬到任何装了 Docker 的机器上跑，**行为完全一样**。这就是"我本地能跑，在你电脑上也一定能跑"的终极答案。

三个核心概念：

| 名词 | 类比 |
|---|---|
| 镜像 image | 安装光盘（只读模板，比如 "Python 3.12 + Flask 3"） |
| 容器 container | 装出来的那台"电脑"（镜像跑起来的实例，可以跑多个） |
| 仓库 registry | 应用商店（Docker Hub，别人上传的镜像在这下载） |

### 在 WSL2 Ubuntu 装 Docker

```bash
# 官方一键脚本（比 apt 源里的版本新）
$ curl -fsSL https://get.docker.com | sudo sh

# 把当前用户加进 docker 组，以后用 docker 不用 sudo
$ sudo usermod -aG docker $USER

# 退出当前 shell 重新进一次（让组生效）
$ exit
# 重新打开终端

# 验证
$ docker --version
Docker version 27.x.x

# 跑个 hello world
$ docker run hello-world
```

> 📌 **注意：** WSL2 不需要装 Docker Desktop，直接在 Ubuntu 里装 docker-ce 就行（更省内存）。

### 常用命令

```bash
# 跑一个 nginx 容器
$ docker run -d -p 8080:80 --name mynginx nginx
# -d       后台跑（detached）
# -p 8080:80  把容器的 80 端口映射到本机 8080
# --name   给容器起个名字
# nginx    用哪个镜像（本地没有就自动从 Docker Hub 拉）

$ docker ps                # 看正在跑的容器
$ docker ps -a             # 包括已停止的
$ docker images            # 看本地有哪些镜像
$ docker logs mynginx      # 看日志
$ docker exec -it mynginx bash    # 进容器里开个 bash（排查用）
$ docker stop mynginx      # 停
$ docker rm mynginx        # 删（要先 stop）
$ docker rmi nginx         # 删镜像
```

浏览器开 `http://localhost:8080`，就能看到这个 nginx 容器给你的欢迎页。

### `-v`：把本地目录挂进容器

容器里的文件一删就没。你想让 Nginx 服务你本地的网页文件：

```bash
$ docker run -d -p 8080:80 -v ~/mysite:/usr/share/nginx/html --name mynginx2 nginx
```

`-v 本地路径:容器内路径`：把本地 `~/mysite` 挂到容器里 Nginx 的默认网页目录。以后你改本地 `~/mysite/index.html`，容器里立刻生效。

### Dockerfile：把自己的应用打包成镜像

在 Flask 项目根目录建个 `Dockerfile`（没后缀）：

```dockerfile
# 基础镜像：官方 Python 3.12
FROM python:3.12-slim

# 工作目录
WORKDIR /app

# 先拷依赖文件（利用 Docker 缓存，改代码不重装依赖）
COPY requirements.txt .
RUN pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r requirements.txt

# 拷代码
COPY . .

# 暴露 5000 端口
EXPOSE 5000

# 启动命令
CMD ["gunicorn", "--bind", "0.0.0.0:5000", "app:app"]
```

构建并跑：

```bash
$ docker build -t hello-flask .
$ docker run -d -p 5000:5000 --name flask01 hello-flask
$ docker ps
$ curl http://localhost:5000
```

### docker compose：一键跑多个容器

真实项目通常要跑：你的应用 + MySQL + Redis。一个个 `docker run` 太累，用 **docker compose** 写个 `docker-compose.yml` 一键起。

```bash
$ sudo apt install -y docker-compose-v2   # Ubuntu 24.04 这个包
```

在项目根目录建 `docker-compose.yml`：

```yaml
services:
  web:
    build: .
    ports:
      - "5000:5000"
    depends_on:
      - redis

  redis:
    image: redis:7-alpine
```

跑：

```bash
$ docker compose up -d        # 后台启动所有服务
$ docker compose ps
$ docker compose logs -f web
$ docker compose down         # 停掉并删容器
```

这样在任何一台装了 Docker 的机器上，`git clone` → `docker compose up -d`，网站就起来了。这就是容器化的终极便利。

> 💡 **小技巧：** `docker compose` 的所有子命令都要在那个有 `docker-compose.yml` 的目录下跑，不然它找不到配置文件。如果你在别的目录，加 `-f /path/to/docker-compose.yml` 指定路径。

### 数据持久化：MySQL 容器里的数据不能丢

跑数据库容器最关键的一件事——**容器删了数据不能跟着没**。所以数据库要用 volume 挂出来：

```bash
$ docker run -d \
    --name mydb \
    -e MYSQL_ROOT_PASSWORD=123456 \
    -v /home/yourname/mydata:/var/lib/mysql \
    -p 3306:3306 \
    mysql:8
```

`-v 本地目录:容器目录` 把 MySQL 的数据目录挂到你本地 `/home/yourname/mydata`。以后就算容器 `docker rm` 删了，重新跑一个挂载同一个目录的新容器，**数据还在**。

> ⚠️ **警告：** 跑数据库、Redis 这类有状态的容器，**第一件事就是 `-v` 挂数据目录**。不然容器一重启，里面的数据全没。

### 清理 Docker 垃圾

用久了 Docker 会占很多磁盘（无用镜像、停止的容器、构建缓存）：

```bash
$ docker system df              # 看 Docker 占了多少
$ docker system prune           # 清掉停止的容器、无用网络、悬空镜像
$ docker system prune -a        # 连没用的镜像一起清（慎用，下次要重新拉）
$ docker volume prune           # 清没用的 volume
```

> ⚠️ **警告：** `docker system prune -a` 会把你**所有没在跑的镜像**都删掉。你下次跑 `docker run` 就得重新 `docker pull`。生产环境慎用。

## 13.7 部署一个真实小应用（完整流程串一遍）

把前面所有东西拼起来：

1. **写 Flask 应用**（`~/projects/hello-flask`，用 12 章的代码）
2. **建 systemd 服务** `/etc/systemd/system/hello-flask.service`，用 gunicorn 跑在 5000
3. **`sudo systemctl enable --now hello-flask`** 启动 + 自启
4. **写 Nginx 反代配置** `/etc/nginx/sites-available/myflask`，80 转发到 5000
5. **软链接启用 + `nginx -t` + reload**
6. **浏览器开 `http://localhost`** 看到你的应用
7. （可选）**写 Dockerfile + compose**，打包给别人跑

## ⚠️ 危险操作与安全红线

> ⚠️ **警告：** 永远不要用 root 跑你的应用（`User=root`）。一旦应用有漏洞，别人拿到的就是 root 权限。用普通用户跑。

> ⚠️ **警告：** 云服务器的安全组默认只开 22。你要跑网站才开 80/443，**不要图方便把所有端口（0-65535）都开放**。

> ⚠️ **警告：** Docker 容器挂 `-v` 时，路径写错可能把本机重要目录覆盖。先小范围试。

> ⚠️ **警告：** `docker rm -f $(docker ps -aq)` 这种批量删容器的命令，会把你所有容器都干掉。新手别复制粘贴网上这种一行命令。

> ⚠️ **警告：** systemd 服务里 `ExecStart` 一定要用绝对路径。相对路径在 cron/systemd 环境下找不到。

## 常见报错与排查

| 现象 | 原因 | 解决 |
|---|---|---|
| `curl localhost:5000` 拒绝连接 | Flask 没跑或绑了 127.0.0.1 | `systemctl status xxx`，`ss -lntp` 看端口在不在 |
| 浏览器开 Nginx 是 502 Bad Gateway | Nginx 找不到后端 | 后端(5000)没跑、或 Nginx 配置 `proxy_pass` 写错 |
| Nginx 403 Forbidden | 静态目录权限不够 | `chmod o+x /home/yourname`，或放 `/var/www/` |
| `nginx -t` 报错 | 配置语法错 | 看报错最后几行提示哪个文件哪一行 |
| `docker: permission denied` | 当前用户不在 docker 组 | `sudo usermod -aG docker $USER` 然后重开终端 |
| `bind: address already in use` | 5000 端口被占 | `ss -lntp \| grep 5000` 找到占用进程杀掉 |
| systemd 服务 `failed` | 看日志 | `journalctl -u xxx -n 50` |
| 云上网站外网打不开 | 安全组没放行 80 | 去云控制台安全组加 80/443 入站规则 |
