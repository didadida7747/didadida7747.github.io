# 开源之夏与开源贡献指南（2027 暑假 OSPP 前置弹药库）

> 定位：时间轴把 **2027 大二暑假「开源之夏 OSPP」** 列为第一份实习的关键路径（见本 README 第五节），本篇给出从"现在"到"中选结项"的完整弹药：活动机制、时间线、proposal 写法、贡献入门、对口项目清单、简历写法。
> 核验：GitHub star 均为 2026-10-03 API 实查；OSPP/GSoC 时间线为官方页面快照，**2027 届一切以官网当年公告为准**。

## 一、开源之夏 OSPP 是什么

| 项 | 内容 |
|---|---|
| 官网 | https://summer-ospp.ac.cn/（帮助文档 blog.summer-ospp.ac.cn，含学生指南与申请书模板） |
| 主办 | 中国科学院软件研究所"开源软件供应链点亮计划"，华为深度参与【以官网当年公告为准】 |
| 机制 | 社区发布课题 → 学生选课题沟通导师 → 提交项目申请书（+简历）→ 导师评审 → 中选公示 → 暑期开发（含中期考核）→ 结项考核（产出须以 PR 合并进社区仓库）→ 奖金 + 结项证书 |
| 门槛 | 年满 18 周岁的高校在校学生（本/硕/博均可），报名需学生资格证明；2025 年每人限报 1 个课题【快照】 |
| 奖金 | 基础难度 8000 元 / 进阶 12000 元（税前，通过结项考核发放）【快照】 |
| 规模 | 2025 届：182 社区 / 565 课题 / 2290 人报名；2024 届中选约 518 人——**粗算约 4 人竞争 1 个课题位，冷门社区课题中签率明显更高，选课题比海投关键**【快照】 |

|---|---|

## 二、Proposal 怎么写（决定中选的核心交付物）

**官方模板**：学生指南（blog.summer-ospp.ac.cn → 参与指南）附申请书模板，各社区发布文均指向它。

**五要件**：
1. 个人信息 + 技术栈/项目经历；
2. 对课题的理解与需求分析；
3. **技术方案**（架构/流程图/技术选型——越具体越好）；
4. 开发计划与里程碑（对齐中期/结项节点）；
5. 预期成果与风险评估。

**经验要点**（多份经验帖交叉结论）：
- 预留 1 周以上打磨；**提前在社区群与导师沟通、先给社区提 1-2 个小 PR 表诚意**；
- 中选者与落选者的最大差距 = "实现细节具体 + 画了流程图 + 分阶段计划"；
- 写完请导师预审。

**经验帖入口**（未核验-建议搜索）：知乎《可以给打算独自参加开源之夏的学生党开发者一些指南吗？》《如何评价中科院开源之夏及其含金量？》；B站"开源之夏 申请书"（官方约 34 分钟 proposal 写法视频）、"开源之夏 经验分享"；xjtu.app《开源之夏申请寄了，总结下经验教训》；播客"开源面对面"。

## 四、开源贡献入门路径（现在就开始）

| 名称 | 链接 | 定位 | 核验 |
|---|---|---|---|
| **firstcontributions** | github.com/firstcontributions/first-contributions | 第一次提 PR 的标准教程（含中文文档），走完 fork→branch→commit→PR 全流程 | ✅ 56,189★ / 110,349 fork |
| Good First Issue | goodfirstissue.dev | 按语言筛热门项目的入门 issue（Python 90 / Go 68 个项目） | ✅ 可访问 |
| Up For Grabs | up-for-grabs.net | "适合认领的独立小任务"项目目录 | ✅ 可访问 |
| GitHub 原生搜索 | `label:"good first issue" language:go state:open`（加 `no:assignee` 找没人认领的） | 不依赖第三方站 | 通用方法 |

**进阶路径**：修 typo/补文档 → 复现修复小 bug → 认领 good first issue → 改功能/性能优化 → OSPP 课题。**每一步留下可引用的 PR 链接。**

**怎么选"值得贡献"的项目**：最近 commit < 3 个月；issue 有人回复、PR 合并周期短；有 CONTRIBUTING.md 与行为准则；社区有活跃微信群/Discord；维护者对新人 PR 态度友好。**优先国内活跃社区**（无时差，且多为 OSPP 参与社区——一次投入两处回报）。

**PR 礼仪**：先读 CONTRIBUTING.md；一个 PR 只做一件事；描述清晰并关联 issue（`Fixes #123`）；提交前跑通 lint/CI；review 意见逐条回复不情绪化；被搁置 2 周以上礼貌 ping。

## 六、开源经历怎么进简历

- **一行公式**：项目名 + 角色 + 可验证结果。例：「开源之夏结项（XX 社区）：独立实现 XX 模块，3 个 merged PR（+2k 行），通过中期/结项考核获结项证书及奖金」；
- 简历筛选看量化指标：merged PR 数、star、issue 处理数；
- **GitHub profile 打理**：建 `用户名/用户名` 仓库写 profile README；置顶 2-3 个真实项目；贡献绿格子保持稳定趋势；**绝不买 star/互刷**（面试官明确视为扣分项）；
- OSPP 结项的五重加分：官方结项证书可验证；导师可出内推/推荐信；经历真实工程流程（code review/CI）；课题可选 RAG/Agent 方向直接对齐目标岗位；结项报告 = 面试项目复盘材料。
- 配套：简历成稿方法见 [简历项目写法](#/doc/d055) 与 [项目实操指南](#/doc/d077)。
